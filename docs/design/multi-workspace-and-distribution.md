# Agent 自主跨工作区与 Varin 分角色发行

设计与实施状态 · 2026-11-18。[设置预览，打开「工作区 → 会话示例」](settings-preview/index.html#workspaces)

## 首批落地与边界

- **工作位置。** 桌面、网页和移动端共用当前 Agent 服务的常用位置设置；普通新会话可采用服务起点，显式来源及显式纯聊天仍优先。登记项目保留登记身份；普通目录按资源端身份和工作区识别，同名同路径不会合并，离线也不会回退到协调端。设置编辑先合并最新读到的列表，但不是跨客户端 CAS。
- **分支默认与临时读取。** 原生会话在两次 Run 之间可以把分支默认改为已授权的实时目录或纯聊天。Catalog 按修订比较并提交，活动 Run、受限子任务和隔离视图不允许用这条入口切换。原生模型也可通过 `work_locations` 发现已保存的可用实时位置，在同一轮将 `file_read` 指定到另一处；该请求只获得所选目录的只读权限，操作和后续引用保留原 owner。没指定位置仍沿用本次请求的默认，不会随临时读取而改变。任意路径发现、跨位置写入和启动命令、模型主动切换默认以及跨设备交接仍是下文的设计目标，不以读成功代替这些能力。
- **桌面发行。** 完整版和轻客户端共用同一个工作台产物、Electron 壳及连接／恢复页面。未连接时仍可使用现有连接界面，但不会发起工作台请求或绕开 Host 鉴权；已保存的中继在工作台挂载前恢复。现有发行 CI 为 Windows、macOS、Linux 装配角色及匹配架构，完整版仍是缺省；轻量包不带本地 Host、内核或资源驱动。在现行未签名 macOS 发布策略下，轻客户端提供手动安装，Windows/Linux 的更新选择独立角色清单。装配与清单测试不代替正式安装或真机更新。
- **资源节点。** 独立启动入口和完整 Host 复用已有的配对、Documents、Storage 和资源内核。资源节点不启动会话或 Agent worker，只声明已接入的实时目录能力。Docker 通过现有构建/验证/发布流水线的独立目标和数据卷装配，不修改标准镜像或原 Compose 的含义。原生安装器、桌面／浏览器节点能力和实际跨机器部署仍需分别验收。

## 一件工作可以用几台机器

用户在笔记本上对云端的 Varin 说：“测试机昨晚的构建挂了，去看下日志，在开发机修好，再送回去跑。”一次会话应能完成这件事。对话、模型请求和任务进度归云端 Agent 服务。测试机读取日志并运行测试，开发机修改源文件。用户可以关闭笔记本，稍后从手机接着看；如果笔记本也提供了资源，其在线状态单独体现。

设计分两步落地。先让原生 Agent 在一次运行里按操作选择工作位置，用今天的完整 Host 就能贯通这条路径。再把同一套资源服务裁成节点发行物，方便只想贡献文件、命令或桌面的机器安装。两步共用连接协议、资源身份与持久状态。

## 工作位置、项目和默认值

**工作位置**是某个资源服务上的目录或执行视图。用户看到“测试机 · 构建日志”，展开可看路径。内部沿用来源 owner、工作区登记和具体视图身份。同一路径字符串可以出现在不同 Host 上，同一项目也可以有多个隔离副本。设备改名、SSH 连接在界面中归组，均保留原绑定。

项目可以引用一个工作位置，并提供模型偏好、可信指令、技能和项目 MCP。用户也能直接使用已授权设备上的普通目录。把目录保存为常用位置只影响查找和展示。普通实时目录的相对路径从这里开始，绝对路径的范围由资源端实际授权决定；只读快照和隔离副本各自保留原有视图。

常用位置和普通新会话的起点由当前 Agent 服务的设置保存，同一服务的桌面、网页和手机看到同一份选择。项目位置继续引用项目的原登记；独立收藏只存名称与来源定位。目标节点解释自己的路径、解析默认 Shell。误把前端的「本机」当成 Agent 或资源端的「本机」，会使云端服务在错误的设备上解释同一条路径，故输入框和操作详情使用实际设备名。

| 起步场景 | 采用的位置 |
| --- | --- |
| 用户为本次工作明确选了设备和目录 | 使用这次选择，包括普通文件夹和指定副本。 |
| 从项目发起，未另选位置 | 使用项目登记的来源。远端项目由远端解析。 |
| 普通新会话，无项目也无指定位置 | 使用用户为当前 Agent 服务选的起始位置；缺省用该服务的默认目录。桌面本地服务通常从用户主目录开始，官方 Compose 从挂载的 `/home/varin/workspaces` 开始。 |
| Bot 直接会话、派发任务 | Bot 的缺省位置是自己的家目录。派发沿用现有的显式项目、来源 Agent、分类默认和父来源选择。Bot 可以在本轮临时使用另一个位置。 |
| 继续已有会话 | 使用该分支已经选定的来源，或保留显式的纯聊天状态。更改新会话偏好只影响以后创建的会话。 |

输入框下方复用原文件夹入口。无项目且沿用默认时只显示「默认」，展开后可见实际设备和目录。选定项目显示「studio-pc - launch-site」，选定普通目录显示「测试机 - 构建日志」。分支处于纯聊天时沿用其无文件来源的语义。查看文件面板、更换 Shell 视图或临时读取远端日志，都不会触发位置变更。已经选定的位置离线时保留名称并显示原因，用户可选别处继续。

## Agent 如何发现、使用和切换

给模型一个按需查询工作位置的入口，复用 Host 连接、项目登记和已保存目录。允许按设备名、项目名或目录搜索，也能在已授权设备上解析未收藏的目录。结果只给名称、必要的设备与路径、相关能力或不可用原因，以及可用于后续调用的短引用。遇到同名项时展示能区分它们的设备和路径。内部 Host ID、端点指纹、配对凭据和原始探测数据留在执行端。位置目录变化通过工具结果按需呈现，保持系统提示和工具定义的前缀稳定。

对模型而言有两种动作。**临时使用**是在现有按路径读写、搜索或启动命令的工具上给一个可选位置。省略时沿用当前落点。**切换位置**是明确变更本会话后续工作的落点，用户入口和模型工具走同一条分支操作。模型可根据用户意图选择，使用已授予能力时无需为每次跨机操作重新确认。下面的引用和参数名用于说明交互，最终 wire 定义随原工具协议设计。

| 用户意图 | 工具应做什么 | 用户看到什么 |
| --- | --- | --- |
| “看看测试机最新日志” | 找到日志目录，向文件读取传入该位置和相对路径。 | 过程行显示「测试机 · 读取 build.log」。输入框下方仍是原工作位置。 |
| “在开发机修好，再送回去跑” | 在开发位置编辑，走现有文件或附件传输交付到测试位置，再在测试位置启动命令。 | 文件改动和进程各标自己的设备。后续可凭进程引用看输出，即使会话已转到别处。 |
| “接下来就在测试机上修” | 切换分支默认位置，后续省略位置的文件与命令调用使用新落点。 | 文件夹入口更新为「测试机 - 构建日志」，会话继续。 |

例如，模型拿到“测试机 / 构建日志”的短引用后，可以用 `file_read({location: "位置引用", path: "build.log"})` 做这次临时读取。同时发出的 `file_read({path: "package.json"})` 仍读当前开发位置。以后使用返回的 `file:8` 继续操作时，直接采用这个引用的原视图和版本。这种调用方式也适用于没有绑定项目的普通会话。

凭已有文件、进程或环境引用继续操作时，由引用定位原对象。一次写入若同时给出不相符的显式位置，直接返回目标冲突。跨设备交付显式表达两个端点，由源端固定要发送的内容、目标端写入并确认；移动还要按原版本条件删除源文件。模型无需搬运文件正文或把一台机器的绝对路径传给另一台。[跨设备文件处理](../../packages/web/application-host/lib/workspace/resource-files.ts)

## 执行归属与恢复

会话所在的 Agent 服务拥有分支、模型请求和 Operation（一次工具操作）。资源节点拥有在该设备上发生的文件事务、启动的进程和本地执行回执。两者复用已有 Catalog、Storage 与配对关系。落地时要改的是“从哪里取本次操作的来源”，仅给前端增加选择器，或在工具参数里追加一个设备名，均无法完成这件事。

| 在什么时候确定 | 保存在哪里，用于什么 |
| --- | --- |
| 新会话首次使用起始位置 | 用户偏好放在现有设置，分支记录实际选中的来源。既有分支优先恢复原来源。旧数据可从已保存的 launch 读取，保留显式无来源与尚未作出选择的区别。 |
| 一次模型请求开始 | 与现有请求准备一起固定本次默认位置、可信项目配置和可用工具。一次模型响应即使并发发起多个调用，省略位置的调用仍有确定的落点。 |
| 工具操作受理 | 根据显式位置、固定资源引用或该请求的默认位置解析目标。按需准备该来源的文件或进程权限，将解析出的 owner、视图与 Operation 一起持久化，再交给实际执行端。按引用读取旧文件仍带原版本。 |
| 改变后续默认位置 | 由分支状态的原写入方记录变更，客户端和 Agent 共用现有修订冲突机制。输入框反映已确认的位置，下一次模型请求取新默认值。同批调用若要立即访问另一位置可显式指定。 |
| 重试、取消或从断线中恢复 | 查原操作和原目标回执，沿原进程引用取消或读输出。已派发而结果未知时显示待协调。目标离线不会把命令改投当前默认机器。 |

现有桥接已支持以原操作身份向远端执行、观察和取消。多位置实现要把这条绑定贯通到本地执行、远端执行、过程展示、恢复及历史导出，不能在其中某一段再从“该 Run 的主来源”倒推目标。不同位置各自按需取得和释放资源；仍有进程或未结回执的来源保留到原 owner 确认收尾。会话回退、分叉或恢复时，分支从对应历史位置继承默认值，已经执行的外部副作用继续沿现有恢复合同处理。[远端桥接](../../packages/web/application-host/lib/kernel/managed-source-bridge.ts) · [资源授权](../../kernel/crates/varin-kernel/src/storage/source_authorities.rs) · [模型资源引用](../../kernel/crates/varin-runtime/src/catalog_model_references.rs)

**权限随任务与目标共同确定。** 位置发现只列出主体可见的结果。能读某个目录、能写某个文件、能在该设备启动系统进程是不同能力，具体调用继续受原任务权限与目标节点授权约束。只读子任务不能靠换设备取得写能力；隔离写任务对副本的编辑不能因路径相同落到 live 原件。确实需要向副本以外交付时，走已有显式交付或整合路径。断连、撤权和发现了同名新节点也不能扩大旧授权。

**项目配置按用途进入上下文。** 临时看日志只读取所选文件，不加载那个项目的系统指令、技能、语言服务或 MCP。转入一个已登记项目持续工作时，下一次模型请求按它的信任状态准备适用的项目资源。切到普通目录只采用该来源实际适用的配置。会话的组织分类、Bot 身份和已发出的请求保持各自归属。浏览器标签页、Computer Use 桌面及其控制权也独立于文件位置。

**外部 Harness 单独声明能力。** 原生 Varin 首先支持上述语义。对 Codex 等外部 CLI，沿用执行器与工作目录须匹配的约束。能由适配器路由的文件调用按其协议声明；CLI 自行启动的 Shell 仍在 CLI 所在设备运行。目标机器需要独立执行时，可按已登记项目派发、复用目标侧会话并交接文件。界面只在后端确实能改变执行落点时提供对应操作。[外部 Agent 现状](../external-agents.md)

## 发行形态与装配

用三个可组合的角色组织构建与启动：客户端呈现工作台，Agent 服务运行会话与模型，资源节点提供选定的文件、命令、桌面或浏览器能力。完整桌面版和标准服务器版继续提供开箱即用的组合。对已有安装，先复用其现有资源接口，无需为了跨工作区重新安装。

| 发行形态 | 安装与运行内容 | 典型用途 |
| --- | --- | --- |
| 完整桌面版 | Electron、前端、Agent 服务、配套内核与本机资源能力。共用一个数据根及相应 owner。 | 下载一个安装包，就能在本机开始工作。仍可连接其他服务和节点。 |
| 桌面轻客户端 | 工作台、桌面窗口、通知、连接选择、客户端设置和更新。包内省去本地 Agent Host、内核和资源驱动。离线或首次启动时能打开连接与恢复界面。 | 在笔记本访问云端服务。同机另装节点即可按需提供本地资源。 |
| Agent 服务 | 无界面原生运行或标准应用镜像。包含会话、模型、Bot、调度和配套内核；标准镜像继续能提供 Web 界面及挂载目录。 | 一台服务器运行总助手。已有 Docker 用户继续沿现有应用镜像与数据卷升级。 |
| 资源节点 | 原生安装或节点镜像。复用 Host 的配对、资源路由，以及所启用能力依赖的 Documents、Storage、进程执行或桌面驱动。节点保存自己的身份、授权、文件版本、进程和回执。 | 开发机贡献现用工具链，测试容器贡献可复现环境。运行节点无需配置模型账号，也无需启动会话调度、Bot 和记忆服务。 |

轻客户端与资源节点可在同机分别启停。连接远端 Agent 是客户端侧的操作；让远端 Agent 使用笔记本，则由该 Agent 服务连接并获准使用笔记本节点。关闭客户端窗口应当只释放界面观察。节点进程能否在无人登录时运行依平台和能力而定，控制已登录桌面沿用原平台的会话与授权。用户只分享 Chrome／Edge 标签页时可以直接用现有扩展；独立 CDP 浏览器也能单独部署。[连接管理](../../packages/web/application-host/lib/connections/README.md) · [桌面分配](../../packages/web/application-host/lib/computer/DOCUMENTATION.md) · [浏览器扩展](../../packages/browser-connector/README.md)

### 桌面安装与更新

下载页把完整桌面版作为常规入口，连接已有服务的人可选轻客户端，服务器或工作设备的部署入口提供对应角色。完整与轻量共用渲染代码及桌面壳；构建时按角色组装依赖。轻客户端的连接与恢复界面要能在本地 Host 从未安装过的机器上启动。远端连接使用现有客户端传输，只有随完整 Host 提供的 SSH 管理等服务操作明确归到所连接的服务。需要本机提供文件时安装节点，避免在首次连接远端时隐式下载整套本地服务。

桌面更新按平台、架构和已安装角色选产物。完整桌面版继续沿当前渠道升级，轻客户端的更新清单只能匹配轻客户端。桌面组件、OS 驱动和内核仍使用现有签名与版本核验。由完整安装改成客户端，或加装同机节点，应由用户选择；保留已有会话数据和资源状态，切换前先处理仍在运行的本地工作。完整 Host 与独立节点若接管同一资源身份，必须依次停启，不能同时写同一个数据根。不同实例各自拥有身份和目录。[桌面构建](../../packages/electron/package.json) · [更新来源](../../packages/electron/updater-feed.ts) · [桌面发行流程](../../.github/workflows/desktop-release.yml)

### Docker 与无界面部署

保留 `ghcr.io/astrmira/varin` 的标准应用含义和现有 Compose，已有 `varin-toolbelt` 用户可继续使用带工具链的完整环境。新增的节点镜像只发布资源节点所需的程序和依赖。slim、toolbelt 描述环境中装了哪些工具；服务端、节点描述进程承担什么责任。已有 runtime 基础镜像继续作为构建材料。需要 Java、GPU SDK 或团队内部命令的测试机可从节点镜像派生，工具装在实际执行命令的地方。

提供两种部署示例即可覆盖主要选择。

- **单机使用。** 原标准 Compose 启动一个服务，用户从浏览器访问，服务可以直接使用已挂载的工作目录。静态前端已能独立构建；另行托管时，使用原有认证与观察连接访问所选服务。
- **云端 Agent 加开发／测试节点。** Agent 服务保管会话和模型，测试机启动节点容器，分别挂载节点状态卷和要提供的目录。节点对外报告容器内的目录、Shell 与工具链。需要操作宿主机现用桌面或使用未经容器映射的开发环境时，在该机安装原生节点。Compose 示例标明哪个路径属于宿主机、哪个属于容器以及谁发起连接，便于用户或 Agent 自行部署。

服务端与节点可独立更新。继续用原 managed 协议版本和能力发现决定能执行哪些请求。新 Agent 服务应优先利用老完整 Host 已有的单次来源能力，在协调端把同一轮的不同操作分别发给对应 Host。遇到确实需要新端支持的能力，向调用方返回具体不支持项；协议不兼容时显示需要升级哪一端。Host 与自己私有的内核继续成套构建发布。

节点可走现有可达的 HTTP(S) 地址或由 Agent 服务建立 SSH 转发；自建 HTTPS／FRP 可沿同一资源协议使用。仅有客户端 relay 配对不建立 Agent 到节点的资源通路。“添加工作位置”不负责在远端安装软件。替换镜像时复用节点状态卷、原资源登记及配对授权。在同一机器将完整 Host 转成纯节点前，显式核对它还承担哪些会话与工作；相同设备名或路径不足以认领旧资源。现有连接若因端点或身份变化需要重连、重配对，继续走原连接流程。[标准 Compose](../../docker-compose.yml) · [镜像构建与发布](../../.github/workflows/docker.yml) · [自建节点接入](self-hosted-external-access.md)

### 工程拆分的着力点

构建产品已有 `prepareFrontend`、`prepareHost`、`prepareKernel`。优先拆 Application Host 的装配入口：从现有资源实现明确列出节点启动、停机排空、重启恢复所依赖的服务，再让完整 Host 和节点调用同一套装配。文件版本、进程监管、能力授权需要的原生代码应当随节点交付。仅关闭页面或路由，无法省去会话服务启动、依赖体积和后台开销。

内核当前随 Host 交付，部分资源实现依赖同一二进制中的 Storage 和工具执行。首版节点可继续携带匹配的内核，只启动需要的服务。是否进一步拆原生二进制，应根据实际依赖、安装体积和空闲资源占用决定。轻客户端则可以直接省去整套 Host 和内核。桌面签名、Linux 架构、Docker 镜像清单与前端产物继续复用现有流水线；在有独立用户用途时才发布新的组合。

## 实施顺序与验收

1. **先用现有完整 Host 打通原生 Agent。** 在设置中保存常用位置与普通新会话起点，补齐分支默认、位置发现、按操作准备目标，以及读写、搜索、命令和文件交接。沿工作台与 Bot 的真实发送路径验收，避免功能只有设置页或测试适配器能使用。
2. **接通跨设备工作的后半程。** 让进程观察、停止、文件历史、隔离副本整合、恢复与导出都回到原 owner。把位置选择接入输入框和必要的过程信息。项目配置在下一请求边界更新，外部 Harness 按实际支持范围接入。
3. **推出独立发行物。** 轻客户端可独立推进。先验证完整 Host 与节点共用资源实现，再交付原生节点与节点镜像、按角色更新的资产和两种部署示例。已有完整安装继续服务老工作；独立发行物的正式名称、平台首发范围和实测体积在拆包验证后确定。

验收围绕同一个真实任务展开，不要求穷举所有角色组合。

| 场景 | 可观察结果 |
| --- | --- |
| 开发机和测试机都有同名目录；并行读测试日志、改开发文件，同时用户更改会话默认值 | 两次操作各自到受理时确定的目标，下一次模型请求看到已确认的新位置；过程行和文件恢复记录能区分机器。用户和 Agent 并发切换按同一分支修订处理。 |
| 传构建产物并在测试机启动测试，执行已启动但回复丢失；重启协调端后读输出、点停止 | 能找到原目标与原进程，复用原操作回执。离线时显示未确认状态；恢复连接后协调原执行，测试只启动一次。 |
| Bot 从家目录临时读另一台机器，或只读／隔离子任务请求修改 live 原件 | Bot 的家目录和原项目配置可区分。只读／隔离操作按原任务授权处理；旧文件引用仍指向原版本和视图。 |
| 轻客户端连云端服务，同时使用笔记本节点；只关客户端，再替换节点版本 | 安装清单能核对客户端未携带本地 Host／内核。关窗口后已受理的工作继续；原节点身份和配对随状态保留。节点暂不可用的工作得到真实状态。 |
| 从现有标准应用镜像按原 Compose 升级，并用另一台机器的节点容器运行测试 | 原数据卷、会话、项目和已登记 Host 可继续使用。测试命令看到节点镜像自己的路径和工具。发布清单区分角色、平台、架构，桌面自动更新选择同角色产物。 |
