# 外部 Harness 接入与跨 Agent 协作设计

状态：核心会话接入、首批后端、外部预设与派发协作已接入。日期：2026-10-26。设计基线：`b3c4773f6`。工作分支：`design/external-harness-integration`。

当前实现与支持边界见[外部 Agent](../external-agents.md)。按用户本轮决定，D/E 的 CLI、Skills、MCP 能力共享暂缓；F 的恢复增强、外部已有历史导入和未声明的 ACP 文件/终端回调留待后续。下文保留完整目标，不能作为这些后续能力已经可用的说明。

本文整理已讨论的产品方向、架构边界、界面交互和实现顺序。接口名称及示例是目标语义，正式实现时以公共 API、私有 schema 和实际后端协议为准。
现行机制仍见[架构](../architecture.md)、[运行时](../runtime.md)、[Agent 协作](../collaboration.md)、[资源](../resources.md)与[工作台](../workbench.md)。

## 1. 产品目标与主要决定

Varin 同时提供自己的 Harness，以及使用外部 Harness 的统一工作台。用户可以在 Varin 中直接与 Codex、Claude Code、Pi 等对话，使用工作区、文件和产物界面；Varin Agent 也可以把任务派发给这些后端，用户随时进入对应子会话查看和交流。

外部 Harness 继续拥有自己的模型调用、上下文管理、工具执行、指令加载和原生会话。Varin 承接会话连接、呈现、工作区关联及跨会话协作。用户已经建立的配置和工作方式应得到保留。

| 议题 | 决定 |
| --- | --- |
| 基础接入 | 直接聊天和子 Agent 派发共用适配器，形成可独立使用的完整功能 |
| 首批后端 | Codex、Claude Code、Pi，另提供通用 ACP 接入入口 |
| 协议选择 | 首批后端优先正式原生接口，ACP 承接兼容后端；能力按真实接口判断 |
| 用户配置 | 默认使用实际安装程序及其原有配置、登录、指令和扩展；覆盖项明确且有来源 |
| 会话绑定 | 新会话草稿可选后端，首条输入进入受理后固定；中途切换后端留给独立的跨会话交接设计 |
| 模型与模式 | 使用当前后端实际提供的模型和运行选项；Varin 工作侧重只作用于 Varin 原生执行 |
| 设置入口 | 新增“外部 Agent”，负责检测、启用和连接配置；默认后端放在对话默认中 |
| 可派发对象 | 在 Agent 预设中选择执行后端；启用聊天入口不自动进入派发目录 |
| 能力共享 | Skills + CLI 和 MCP 为可选增强，共用同一业务服务，不成为基础接入前提 |
| 文件环境 | 默认共享，本次派发可选择实际支持的隔离；复用现有来源与资源生命周期 |
| 恢复 | 先明确变更观察、边界恢复点和后端原生恢复的区别，再按实际能力提供 |
| 持久化 | 扩展现有 Rust Catalog / ContentStore 保存产品记录，不增加独立 TS 会话数据库 |
| 界面品质 | 复用当前聊天、工具、协作和动效设计；不为每个后端重建一套聊天组件 |

不在本设计中建设自动任务分流、自动挑选模型、强制角色流水线或新的 Bot 编排系统。接入能力不依赖重写外部 Harness，也不恢复已退役的 Pi 内嵌运行时。

## 2. 三个可独立启用的能力层

### 2.1 会话接入

用户选择后端，发送文字或其支持的附件，观察流式回答和工具工作，处理问题与审批，停止和续接。工作目录与现有项目、文件视图相连。
运行所需的登录和配置由相应后端负责；Varin 不要求用户先安装能力共享 Skill 或配置 MCP。

“前端接入”包含必要的 Host 连接和会话生命周期服务。Renderer 只负责呈现，不能直接启动 CLI、读取凭据或成为会话存储 owner。

### 2.2 跨 Harness 派发

Varin 主 Agent 的派发建立一个普通外部会话，再附加任务、父子关系和结果交接记录。状态查询、等待、补充消息和取消沿同一会话适配器执行。
子会话始终有完整的用户入口，不只保留最后一段输出。该层不依赖外部模型主动调用 Varin 工具。

### 2.3 外部 Harness 主动使用 Varin 能力

用户可选择让某个外部会话访问 Varin 的协作、展示、知识或已配置 MCP。通过 CLI / Skill 或 MCP 提供入口，业务执行仍沿原 Host 服务。
关闭此层后，用户聊天、Varin 向它派发任务、观察其结果仍然可用。

这三个层次是产品能力边界，不是三份独立运行时。可选增强可以后续交付，基础层应一次完成正常交互、恢复连接和错误处理。

### 3.2 后端与协议

| 后端 | 推荐入口 | 适配责任 |
| --- | --- | --- |
| Codex | app-server | 原生 thread / turn / item、审批、续接和可用选项 |
| Claude Code | 官方 Agent SDK，连接实际 Claude Code 程序 | SDK 生命周期、流式消息、会话恢复、用户问题及权限回调 |
| Pi | 独立进程 RPC | 消息、工具、队列、压缩及支持的扩展 UI 交互 |
| 自定义 ACP Agent | ACP 客户端 | 初始化能力协商、会话、事件、权限及可选文件/终端服务 |
| 只有 TUI 的程序 | 现有终端入口 | 保留原生终端使用；有结构化接口后再接入会话功能 |

正式接口依据：[Codex app-server](https://learn.chatgpt.com/docs/app-server)、[Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview)、[Claude 配置与功能加载](https://code.claude.com/docs/en/agent-sdk/claude-code-features)、[Pi RPC](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md)、[ACP](https://agentclientprotocol.com/protocol/v1/overview)。

实现时以实际安装版本的协议为准。记录程序与适配器版本，在连接时协商或查询能力；已知接口差异集中在对应适配器。不要依赖终端文本、工具名称猜测或读取私有文件来代替已有正式控制接口。
Pi 的自定义 TUI 扩展、各家私有插件界面等，不一定有可映射的结构化事件。设置详情应说明当前连接的可用交互；原生终端入口继续可用。

## 4. 与现有 Varin 架构的衔接

当前 [ThreadIdentity](../../packages/application-client/src/threads.ts) 固定为原生 `runtime: 'agent'`；[ThreadAdapter](../../packages/web/application-host/lib/kernel/thread-adapter.ts) 在提交时解析 Varin 模型、上下文、工具和子任务目录。
输入框已有独立的 [ThreadAgentControls](../../packages/ui/src/components/thread/ThreadAgentControls.tsx)，但目前仅列出 Varin。

本设计扩展“所有会话只由 Varin 原生 loop 执行”的产品范围，同时保留已有原生会话的身份、执行和持久化归属。外部会话不进入原生模型请求准备链，也不伪造 `ModelStep` 或凭据绑定来通过原生校验。

```text
共享聊天 / 工作概览 / 协作 / 文件与产物
  application-client：带后端身份的会话 API 与展示事件
    Application Host：准入、配置解析、适配器、交互路由
      Varin 原生路径 → 当前 Rust Agent runtime
      外部路径 → Codex / Claude / Pi / ACP 适配器 → 外部 Harness
      可选 CLI / MCP → 同一协作及领域服务

Rust Catalog / ContentStore：Varin 产品身份、外部绑定、观察记录、交办与回执
Rust Storage / Documents：Varin 管理的进程、工作来源、文件、恢复与清理
外部 Harness：自己的模型请求、原生上下文、执行状态与续聊存储
```

### 4.1 职责分配

| 位置 | 职责 |
| --- | --- |
| UI | 草稿选择、状态呈现、后端实际选项、事件渲染和用户交互 |
| application-client | 通用会话引用、操作结果、能力及观察 DTO；保留原生专属 API |
| Host 会话协调 | 解析目标后端、绑定环境、接收消息、安排投递、关联回执 |
| 后端适配器 | 解释特定协议、转换事件、执行原生操作；不自建任务目录或数据库 |
| Rust Catalog | 保存产品侧绑定、外部轮次记录、输入投递、协作关系与耐久观察游标 |
| 外部 Harness | 真实模型上下文、工具执行、压缩及原生会话恢复 |
| 既有资源 owner | 进程树、工作目录、来源保留、文件协调、恢复与资源回收 |

以显式的原生/外部目标分支扩展会话边界，原生 `ThreadIdentity` 的有效含义保持不变。公共列表可以联合返回两类会话摘要；外部会话无需空的原生 branch 或假的 Run 才能显示。
原生专属接口继续接受原生身份；通用发送、停止、历史及交互操作按目标路由。实施时同步修订相关架构文档与 contributor 说明，不以恢复旧运行时的方式实现新目标。

### 4.2 最小领域对象

以下对象表示责任，不要求分别建设服务、进程或数据库。

| 对象 | 必须表达的事实 |
| --- | --- |
| 后端定义 | 稳定后端 ID、协议种类、展示信息和实际适配实现 |
| Host 安装/启动配置 | 所在 Host、可执行文件或启动命令、参数、配置来源、用户启用状态 |
| 会话绑定 | Varin 产品 ID、后端与 Host、外部原生会话 ID、工作来源及恢复所需引用 |
| 外部轮次 | 本次输入、投递关联、后端 turn 或等价标识、开始/结束状态及结果引用 |
| 观察记录 | 原生条目标识与版本、展示内容、产品游标、来源和已知信息缺口 |
| 交办关系 | 派发者、目标会话、本次任务、执行实例及结果交接状态 |

产品 ID 与后端 ID 分别保存，路径、窗口、显示名和进程 PID 均不作为会话身份。原生分支语义留在后端；外部 branch 只有在其接口真正提供时才显示。
轮次受理后固定后端、来源及本次明确选择；设置变化作用于后续受理，不重写已有工作。

## 5. 会话生命周期、历史和重连

### 5.1 草稿与首次发送

1. 草稿可以切换后端；保留正文、附件与工作目录，各后端的选项分别记忆。
2. 首次发送固定本次候选并显示启动状态；执行中的准备不能被另一后端的迟到结果覆盖。
3. 创建后端会话后，先耐久保存真实绑定，再发送用户输入。发送前保存输入关联和投递意图，便于故障后核对。
4. 首条输入明确被接受后，会话后端固定。之前的失败若确认未投递，可以带原草稿返回选择状态；已接受或受理不明时，保留绑定和故障恢复入口。

读取模型目录或探测连接无需创建可见空会话。必须启动候选会话才能探测的后端，由适配器管理其准备寿命，用户放弃时释放实际资源。
已有后端绑定但没有消息的失败准备记录可在原位重试；明确重新选择时结束原候选，不暗中把同一产品记录指向另一个已执行的会话。

### 5.2 运行状态

会话可显示未连接、准备、空闲、工作中、等待用户、停止中、连接中断等事实；轮次独立记录完成、失败、取消或结果待核对。
后端活跃状态、连接状态和输入投递状态分别保存。观察连接中断时保留最后已知执行状态，不直接宣布任务失败或完成。

关闭面板只结束该视图的订阅；用户停止当前轮次、结束外部进程、归档会话是不同操作。停止请求得到确认后，再依据真实轮次终止与进程退出信息释放相关资源。
后端只提供进程级终止时，应明确该操作的影响范围；多个会话共用进程时不能通过关闭共用进程停止其中一条。

### 5.3 历史与续聊

外部 Harness 保存自己的续聊历史；Varin 保存已观察到的展示记录及原始关联，支持侧栏、搜索、离线阅读和客户端追平。
外部展示记录不进入 Varin 原生模型上下文，不靠重新提交整段历史伪装为原会话恢复。

优先通过后端历史接口恢复；无正式接口且确实需要已有历史时，由专用只读解析器读取对应格式。该解析能力与运行适配器分开，私有格式不匹配时保留已观察记录并报告读取原因。
接入用户已有会话是显式操作：选择真实外部会话，再建立关联。仅打开历史不自动发起新的模型请求。
恢复一个已保存会话和连接另一终端中正在运行的进程分别处理。只有后端提供活跃连接或接管接口时才使用该能力；不通过再开一个写入同一会话的进程冒充接入，也不终止用户在外部启动的原进程。

重连时优先用外部条目 ID、轮次 ID 和版本去重。协议没有可重放游标时，读取权威快照，以对应轮次和已确认的历史位置合并；相同正文可以是两条真实消息，不能仅按文本相同去重。无 ID 的临时增量在本次连接内排序，不能当作跨进程去重依据。
无法确认丢失区间时记录缺口，保留已有内容。原生会话已丢失时可以阅读 Varin 记录，并显式创建后续会话；不得静默新建后仍显示为原生恢复成功。

### 5.4 投递、故障与重试

产品侧幂等键负责去重本次操作；是否能重试后端发送取决于其受理证据。
请求写入后连接丢失而没有确认时，优先查询对应轮次或历史。只有确认未受理，或后端提供相应幂等机制时才自动重发；其余情况显示待核对并保留原输入。
不把“最后一段助手文字已出现”当作轮次结束，完成以实际协议回执为准。恢复连接也不重新执行已发生的工具效果。

## 6. 适配契约与能力表达

### 6.1 通用操作

| 操作 | 语义 |
| --- | --- |
| 检测 / 连接 | 查找实际程序，取得版本和可用能力，报告需要登录等状态 |
| 创建 / 恢复 | 建立真实原生会话，返回稳定绑定与可续接信息 |
| 发送 | 发送明确输入；返回受理证据和关联，保留后端实际排队语义 |
| 观察 / 历史 | 订阅结构化事件，按实际接口读取已有历史和当前状态 |
| 回答交互 | 回答具体问题、权限或资源请求，绑定原生请求身份 |
| 停止 / 释放 | 停止目标工作，或释放空闲连接；分别返回实际结果 |
| 读取 / 修改选项 | 展示实际模型、模式和参数，按后端允许的边界修改 |

能力描述保存足够表达行为的信息，例如消息注入支持“运行中转向”还是“下一轮”、恢复是否受支持、停止影响轮次还是整个进程。
不能只用一个 `supportsTools` 或“兼容 ACP”覆盖全部差异。未知、未提供和当前连接不可用分别呈现，失败不变成空目录。

后端特有操作保留有类型的扩展位置，由对应适配器与界面消费；不开放 Renderer 任意透传私有协议。通用操作不为制造一致性而改变后端语义。
首批用内置适配器与可配置 ACP 启动入口完成。独立的第三方适配插件市场不作为首批前置；未来需要开放时复用现有扩展服务体系。

### 6.2 事件与交互

| 后端事实 | Varin 呈现 |
| --- | --- |
| 助手正文、公开思考 | 当前正文、思考摘要与展开窗口 |
| 已知工具动作 | 读取、搜索、命令、文件修改等现有语义组件 |
| 陌生工具或特有事件 | 保留原名称和可用内容，使用通用详情；后端扩展可增加对应展示 |
| 计划与进度 | 有真实结构时进入工作概览；普通文字仍作为普通文字 |
| 问题 / 权限 | 现有问题与审批区域，选项来自真实请求 |
| 图片、文档与产物 | 转换为对应资源引用，沿现有可信读取和展示入口 |
| 用量与压缩 | 显示后端提供的统计和事件，标清统计口径及可用操作 |

工具显示模型不依赖原生 `Operation` 才能成立；外部工具保留来源及原 ID，不能伪造成可由 Varin 原生执行器重试的操作。
工具标题和摘要来自实际事件与参数，不要求模型为适配界面额外编写文案。未知事件保留可读内容，不丢弃整轮输出。

审批展示支持一次、本会话、规则级等后端实际提供的选项。“本会话允许”不能标成永久允许。后端已自行完成的审批只展示结果，不再制造一份等待请求。
交互答复发给原连接/会话的请求；请求过期或已解决时撤销操作入口。没有匹配交互能力时说明具体缺口，不以自动同意代替交互适配。

ACP 的文件、终端等客户端回调是协议适配的一部分，与可选 MCP 能力共享分别实现。声明支持前必须接到现有 Documents、文件及进程 owner，保留真实 cwd、路径范围、编码、取消与退出状态。
编辑器未保存内容是否提供给后端，要沿用户实际选择的输入/来源语义处理；不能一边让后端读取草稿，一边让它依据磁盘旧版本无条件覆盖文件。没有接好某个回调时不声明对应能力。

## 7. 安装、用户配置与模型选择

### 7.1 保留已有运行环境

默认使用实际执行 Host 上用户安装的程序与配置。支持手动指定路径、自定义构建和明确的启动参数；检测结果显示最终解析路径。
优先以可执行文件及参数数组启动，避免把用户参数拼接为另一层 Shell 命令。明确配置的启动脚本按其实际解释器运行。

| 配置来源 | 处理方式 |
| --- | --- |
| 后端自己的用户/项目配置、登录、指令、插件 | 沿该后端规则加载，保留来源与原文件 |
| Varin 连接配置 | 规定程序、执行 Host、启动环境以及能力共享选择 |
| 本次会话/轮次明确选择 | 使用后端支持的接口覆盖，记录生效结果 |
| Agent 预设 | 提供任务用途及可选的后端选项；省略项沿后端自身默认 |
| Varin 原生模型、系统提示和工作侧重 | 继续服务原生路径，不自动灌入外部运行 |

适配器应明确省略未覆盖选项，核对 SDK 的程序化默认行为、配置加载范围和原生 CLI 是否一致。不得为了启动方便替换用户 home、清空原有 MCP、关闭 hooks，或复制一份会逐渐失同步的全局配置。
需要临时配置覆盖时优先使用正式参数；必须生成配置文件时，只维护本次启动所需的覆盖文件并按原生命周期回收，不改写用户原文件。

登录由对应后端负责。可通过其正式接口显示登录状态或开启登录流程；不把外部凭据导入 Varin 模型账号，也不从日志或提示正文中传递密钥。
本次连接明确绑定启动环境；另一个窗口修改配置后，按后端实际热更新或重启规则显示，Varin 不虚构配置快照保证。

### 7.2 模型、选项与材料

外部会话的模型目录来自对应后端。Varin 模型渠道和 models.dev 补全不用于推断外部后端支持哪些模型或用户拥有哪些权限。
后端提供目录时直接呈现；只支持模型 ID 时按其接口提供输入。明确选择失败时保留原选择并报告原因，不悄悄替换为另一模型。
不同后端的参数草稿分开保存，切换不会把 Varin 的思考等级枚举、权限模式或工作侧重原样发送给另一后端。

图片、编号引用、文件和材料沿现有输入体验组织，发送时转换为后端真实支持的内容。草稿切换后附件仍保留；不支持的附件在发送前指出并提供移除或受支持的替代方式。
远端文件引用必须指向实际执行 Host 可访问的资源，不能把客户端本机路径当作远端文件。
Skills、斜杠命令和提及菜单也按当前后端来源提供；保留其原语义，避免与 Varin 的命令处理重复执行。

## 8. 新会话与聊天界面

### 8.1 草稿中的选择

沿用模型旁现有的 Varin 入口，不重新设计新会话主画面。草稿中的下拉菜单列出用户启用的后端，并提供“管理外部 Agent…”入口。

```text
执行 Agent

✓ Varin
  Codex
  Claude Code
  Pi
────────────
管理外部 Agent…
```

每项使用真实品牌图标、名称和必要状态。已启用但当前不可用的后端保留在列表中，说明“程序未找到”“需要登录”等实际原因并可进入处理入口。
未启用的候选留在设置页，不把整个支持目录放入日常选择器。

切换只改变这份草稿的执行选择和相应控制项：正文、附件、工作目录、光标与编辑状态保持。明确选择生效后更新模型目录；迟到的旧查询不能覆盖新选择。
等待目录时保留合理宽度和加载状态，不先显示另一后端的模型。无可查询目录时使用后端允许的配置方式。

初始默认为 Varin。用户可在“对话默认”选择已启用的后端；这是新草稿默认值，不改变旧会话。配置的默认后端暂不可用时展示原因和选择入口，不自动换成另一个后端发送。

### 8.2 开始后的身份与选项

首次输入进入受理后，后端选择器变成轻量身份标识并去掉下拉箭头。点击展示后端、执行 Host、版本、工作目录和连接状态；不提供原位替换后端。
模型和运行选项按后端实际支持决定是否可编辑、何时生效。正在运行的请求不因控件更新而被重新解释。

Varin 的通用、编程、科研、办公侧重保留在原生会话。外部后端可以在相应位置展示自己的模式，例如实际提供的计划模式；没有对应选项时自然收紧布局。
这不改变顶部工作台/IDE/Bot 外壳选择，也不把这些外壳与某个后端绑定。

### 8.3 聊天与工作概览

三种聊天显示模式、单条过程直接显示、思考摘要、工具流式内容、协作消息气泡、图片查看、产物和文件入口继续复用。
展示层从带来源的语义条目读取数据；只有事件具备对应事实时才使用专用组件。保留长消息收起、自动换行、滚动跟随及用户手动阅读位置。

工作概览使用实际任务、计划和产物，不因为接入某个 harness 就固定出现空板块。派发卡片显示用途名与头像，辅以后端标识；后端标识不替代 Agent 名称。
外部 Harness 自己产生的内部子 Agent 可以按已提供的信息呈现。只有其接口支持独立访问或控制时才提供进入、通信或停止操作；不把观察到的内部子任务自动注册为 Varin 可派发对象。

上下文侧栏展示后端实际提供的用量、压缩和历史信息。Varin 的准备线、替换线、压缩 Agent 控制不用于外部上下文。
外部用量字段缺失时不补成零，缓存率仅在语义明确的缓存数据可用时计算。工具预算和实际消耗按原统计口径显示。
下一步建议等读取已完成对话的辅助体验，可在拥有完整正文和明确轮次结束后复用现有服务；它们的失败不影响外部会话，且不会成为外部执行的第二个驱动循环。

### 8.4 动效与状态切换

沿现有菜单、面板和聊天动效体系实现。草稿切换时仅更新受影响的模型/选项区域，保留输入框、附件和正文组件身份。
下拉项展开、详情页进退和状态更新采用既有节奏；布局变化连贯过渡，连续切换可打断，不等待上一段动画结束才能操作。
协议增量在共享流式消费者中合并渲染，原始正文不丢失。高频工具进展不触发整个会话、侧栏或设置页重渲染；历史页按需读取，复杂内容展开后再渲染。
性能改进通过稳定组件身份、局部订阅与调度完成，保留动效效果、节奏和可打断性。

## 9. “外部 Agent”设置页

### 9.1 入口与列表

放在现有 Agent 相关设置附近，页面说明：检测并选择可在当前 Host 的 Varin 中使用的外部 Agent。
列表采用紧凑条目，包含品牌图标、名称、检测状态、已知版本与“在 Varin 中启用”开关。通过行展开或详情页承载复杂配置，不给每个后端铺开一张大表单。

| 状态 | 呈现与可执行动作 |
| --- | --- |
| 未检测 | 提供检测；用户启用时按需解析程序与接口 |
| 已找到程序 | 显示实际路径与版本，可启用或查看详情 |
| 未找到 | 指定路径、重新检测、官方安装说明 |
| 已启用，需要登录 | 保留启用选择，提供实际可用的登录入口 |
| 接口不兼容 / 启动失败 | 展示明确原因和相关版本，允许调整路径/参数后重试 |
| 当前可用 | 可从新会话选择；不表示已启动一条模型任务 |

用户启用意图和当前检测结果分别保存。程序消失不清除配置，检测失败不覆盖上次有效信息；旧信息标明已失效或待重新确认。
禁用后从新草稿与新派发候选中移除，不中断已经运行的工作。历史继续可读；明确续聊时提供重新启用入口。撤销共享能力与停止运行是独立操作，不借禁用开关隐式杀进程。

### 9.2 单项详情

常用部分展示可执行文件、版本、配置来源、连接状态和重新检测。支持自动查找与手动路径，保存稳定的启动配置身份，供预设和会话引用；同机发现多个程序时明确当前选择，不因 PATH 顺序变化静默重定向已有绑定。

高级部分按需展开启动参数、环境覆盖和协议信息。凭据值沿现有秘密管理方式隐藏；不要求用户重新在此录入已有后端账号。
能力详情说明续聊、图片、问题/审批、运行中消息和上下文操作等实际支持情况；有缺口时指出影响的功能，不以总括性的“完全兼容”代替事实。
“提供 Varin 能力”为单独可选项，说明 CLI / Skill 或 MCP 的实际交付方式及选中的能力范围。基础接入可先发布，不展示尚未实现的开关。

自定义 ACP 条目允许用户填写名称、程序及参数，连接后读取实际能力。不假设任意 CLI 都会说 ACP，也不静默下载第三方包装器。

### 9.3 检测与 Host 范围

检测发生在首次进入页面、手动刷新、配置变更，以及启动前需要确认时。使用执行 Host 的已配置路径和正确进程环境；不进行常驻全盘扫描。
只为检测而启动的进程由资源 owner 跟踪并释放，可取消。不会为了验证“可用”自动发送计费模型请求。
版本、协议连接和登录状态分别取得；无法通过正式接口读取登录状态时显示待连接确认。

外部 Agent 设置按执行 Host 保存。Web 或移动端连接哪个 Host，就使用该 Host 的安装；本地客户端上的同名程序不是远端候选。
页面保留当前 Host 标识和离线状态；切换 Host 不改写原 Host 的启动配置。

### 9.4 与其他设置的分工

- 对话默认：选择新草稿默认后端，不复制外部后端整套配置。
- Agent 预设：选择该预设的执行后端、任务用途及可选运行参数；派发资格由预设决定。
- 模型服务：继续管理 Varin 原生渠道；外部模型目录在当前连接中使用。
- 项目设置：保留项目信任、来源及工作目录职责；外部后端自己的项目信任沿其机制处理。

## 10. 子 Agent 派发与跨会话交流

### 10.1 预设和派发目标

预设仍表达用途和可选指令，新增明确的执行后端引用。用途名、头像和每次派发的名称沿现有体系，不让“Codex”替代“验证”“调研”等任务名称。
原生预设保留当前模型与工具选择；外部预设只发送该后端支持的选项。工具子集、模型继承等原生语义不能原样套用。
省略外部模型时沿其自身配置，不能把父 Agent 的渠道 ID 当作外部可用模型。模型不需要了解凭据绑定和启动命令。

主 Agent 看到一个统一的可派发目录，包含用途、可用状态和与任务有关的实际能力。实现上扩展现有派发目标种类，复用 `dispatch`、`child_status`、`child_report`、`wait_child`、`child_cancel`、`send` 等业务语义，不另造一套协作工具。
某项派发参数不能由后端满足时，派发前返回具体原因。例如请求 `read_only` 时，需要实际可执行的只读机制；不能只加一句提示词就报告已限制写入。

### 10.2 从受理到交付

1. 固定派发者、预设、任务、来源和本次可选参数，创建耐久交办记录。
2. 按现有来源服务准备共享或隔离目录，再创建真实外部会话。
3. 保存外部绑定与输入投递关联，沿直接聊天的发送路径受理任务。
4. 状态由后端事件更新；用户和父 Agent 都观察同一执行实例。
5. 收到轮次结束回执后保存结果引用，由现有交付机制送回原派发者。

派发异步返回稳定任务身份。父 Agent 可以继续工作，随后读取状态或等待，不因外部子任务仍在运行而占住其他工具调用。
默认状态读取提供实际状态、最近助手消息和最近动作；完整对话和工具详情在子会话中按需查看。
最终答复与中间消息分开，成功、失败、取消保留各自结果。一次等待超时或观察取消只结束等待；显式取消任务才发停止请求。

每次接续记录自己的执行实例及结果，名称变化不改写旧交办记录。父 Agent 已结束时保存子任务结果，沿现有投递机制处理，不为收到结果擅自生成无限接续循环。
外部 Harness 内部派发的任务与 Varin 发起的交办分别标识，避免双重计数、双重报告或向不可控制的内部任务发控制请求。

### 10.3 上下文与消息

任务正文是基本输入。可选附带已选消息、简短说明或成果引用；跨后端历史用普通上下文材料交付，不把原生工具回执、系统指令或私有上下文对象伪装成对方会话状态。
若用户选择保留历史，展示实际选取范围与转换结果。后端支持的同类会话分支可以调用其正式接口；跨后端接续创建关联的新会话。

消息记录发送者、接收者、原执行/交办关系和投递状态。用户输入与 Agent 消息分别表达，Agent 报告不构成新的用户授权。
运行中目标支持转向时，使用其正式接口；仅支持轮次间输入时进入明确队列。需要唤醒空闲目标的工作请求与无需激活的告知消息沿现有区别处理。
发送受理、进入后端上下文、目标答复是三个不同事实，界面与工具结果不得混为一个“已回复”。

CLI / MCP 的主动查信可以作为补充，及时接收消息仍由会话适配器按上述边界投递。仅安装 Skill 不会自动产生后台消息监听。
协作面板统一展示“谁发给谁”、任务和最终回复，沿现有消息气泡与默认长文收起规则，不新增另一套群聊存储。

## 11. 工作区、文件变更与恢复

### 11.1 工作来源与隔离

默认共享实际工作来源；隔离按次选择。保持资源 Host、workspace、实际根和导航项目的区别。
来源为固定分支时，外部 CLI 需要真实 cwd，因此在启动前按原资源服务物化；不把虚拟树路径交给会直接访问磁盘的程序。
子目录选择继续沿 `sourcePath` 和来源映射处理。外部进程及其子进程存活期间保留目录与来源；切换页面、HTTP 断开或父任务停止等待不触发目录回收。

隔离继续使用现有基线复用、增量捕获、内容对象与回收，不另外缓存一份完整项目。外部进程结束后，还要处理未交付成果、活动读写者及发布后的目录变化，再由原 owner 清理。
隔离表示文件工作状态分开；后端自己的系统沙箱与权限能力另行表达。

### 11.2 直接文件修改与代码交换

外部 Harness 的原生文件工具通常直接修改磁盘。Documents 观察到变化后沿现有 revision、dirty buffer 和冲突流程处理，编辑器不被无条件覆盖。
由 Varin 的 ACP 文件接口或能力桥执行的文件操作才进入对应的原生文件事务；不能宣称所有外部写入都经过该事务。

双方共享同一实际来源时，改动已在该来源生效，沿现有 `shared_source` 语义展示。隔离来源的成果通过实际文件快照和原基线交接，复用 Integration 与三方合并。
发布时核对实际变化，不把后端给出的 diff 文本当作完整磁盘结果。外部进程仍有写入时保存明确阶段快照；之后新增修改属于后续阶段，不丢弃也不假定已经交付。
同一来源多个写入者的变更不能仅按时间窗口归给某个会话；会话事件是来源证据，文件最终状态仍由资源 owner 核对。

### 11.3 恢复能力的三个层次

| 层次 | 数据依据 | 用户可以做什么 |
| --- | --- | --- |
| 目录变更观察 | 文件通知、版本读取、Git/实际差异 | 查看当前变化及已知来源 |
| 任务/轮次边界恢复点 | 工作前保存的实际文件基线和之后版本 | 比较并恢复所覆盖文件在该边界的状态 |
| 细粒度恢复 | 后端原生恢复接口，或可靠的修改前捕获及实际后续文件状态 | 查看并恢复对应操作范围 |

文件观察通常在修改后触发，不能凭通知重建旧字节。边界恢复点需要在任务输入交给后端前建立，沿现有增量机制捕获；执行后或观察缺口之后才建立的记录不得标成完整的修改前恢复点。
共享目录仍可能被其他进程同时修改，捕获与恢复沿实际版本核验；出现不一致时明确记录覆盖范围和缺口。不要为获得归属而默认将所有外部会话强制隔离。

基础聊天与派发不以恢复增强为前提。用户启用边界恢复后，启动准备应展示捕获进度及取消入口；捕获失败不能显示成已保护，提供重试或明确继续而无本次恢复点的选择。
默认捕获策略与现有“历史与恢复”设置衔接，不另设每个后端独立的完整备份开关。共享来源的重复准备复用同一次有效捕获与对象保留。

恢复操作继续处理 dirty buffer、磁盘版本冲突、undo 和原始资源身份。会话正在写入时先协调真实执行状态；未知停止结果不能当作已解除冲突。
后端自己的撤销与 Varin 文件恢复分别显示范围：只恢复磁盘不同时宣称已回退外部模型的对话上下文。
恢复服务依据真实绑定关联到外部会话，不要求伪造原生工具 `Operation` 才能在恢复面板出现。

## 12. Skills + CLI 与 MCP 能力共享

### 12.1 共用服务与可选披露

增加外部调用入口，背后复用已有协作、资源与展示服务。CLI 与 MCP 共用身份解析、业务校验和操作回执；各自只承担参数/内容格式与传输适配。
首批共享重点是会话交流与任务协作，产物展示、知识和已配置 MCP 可按已有服务条件加入。不要为了“能力完整”把 Varin 全部原生工具都披露给外部模型。

| 能力 | 复用服务与边界 |
| --- | --- |
| 相关会话、任务、消息 | 现有协作目录和投递服务，保留实际调用会话范围 |
| 派发、状态、等待、停止 | 与 UI / Varin Agent 相同的交办服务 |
| 打开文件、展示产物或 HTML | 原资源服务和 Surface 路由；无活动视图时保存入口，不伪造已显示 |
| 知识与材料 | 对应领域 owner，返回原资源引用及权限结果 |
| 用户选中的 MCP | 原 MCP owner 的真实声明、调用和资源生命周期 |
| 恢复查询与操作 | 已接入的恢复服务；遵守原范围与冲突语义 |

能力共享默认关闭，用户选择后生效。缺少共享能力不影响该外部会话使用自己的基础工具。自身已有 MCP 配置继续保留，用户明确选择共享的服务才从 Varin 提供。

### 12.2 CLI 与 Skill

命令按用户目的组织，以下仅为建议形态，后续接入现有 CLI 发行入口时统一命名：

```text
varin agents list --json
varin messages send <target> --text "接口已调整，可以开始验证" --json
varin messages read --json
varin tasks dispatch --agent <preset> --prompt-file <file> --json
varin tasks status <task> --json
varin tasks wait <task> --json
varin tasks cancel <task> --json
```

支持结构化输出，明确区分命令失败、业务等待和任务执行失败；长正文可用文件或 stdin 传递，避免 Shell 引号改变内容。命令提交成功不意味着任务已经完成，返回实际回执和下一步可读取的引用。
短操作进程结束后，任务仍由 Host 的耐久记录管理。等待进程退出只释放等待者，不自动取消任务；显式取消命令才改变任务意图。

Skill 只说明可用能力、参数、结果含义和少量有效示例，不规定研究、编程或协作流程，不要求模型定时轮询或一定派发。
优先通过该后端支持的会话扩展/指令加载方式披露。需要向其配置位置安装 Skill 时，由用户明确启用或安装，只管理 Varin 自己的条目，不覆盖已有文件。
执行路径由启动环境提供，引用命令不依赖模型猜测安装目录。用户也能从终端手动使用 CLI；手动调用按其显式选定会话与正常客户端授权处理。

### 12.3 MCP 入口

为支持 MCP 的后端增加本次会话的 Varin 服务定义，保留其原有服务。使用后端正式支持的启动/会话参数，协议支持的 stdio 或 HTTP 由适配器选择。
Pi 需要通过实际可用的扩展提供能力；未完成这条接线前不显示 MCP 已生效，也不以其 ACP 包装器接受参数为成功依据。

MCP 与 CLI 调用同一业务服务。相同能力同时启用两种入口时，披露避免重复且说明等价关系；已配置服务的凭据留在原 owner，不复制到各后端 home。
转接用户 MCP 时保留完整 schema、内容、资源及需要的人机交互。不能完整支持的交互声明为能力缺口；不把一种表面可调用的代理假装成所有 MCP 功能透传。
共享连接复用现有 MCP 租约；需要独立会话状态的服务器沿其隔离配置创建对应实例。外部会话实际 cwd 与配置来源 cwd 分别保留。

### 12.4 调用身份与投递

由启动器向受管外部进程提供绑定本会话的连接上下文。Host 据此解析发送者和能力范围，模型通常只提供目标与正文，不允许用任意 `senderId` 冒充另一会话。
调用身份及秘密不写入 Skill、模型提示、项目文件或普通日志。连接材料沿进程/会话原生命周期回收，外部会话重连时重新绑定实际身份。
CLI / MCP 按相同业务关联保存请求回执，传输中断时先读取原回执，不自动重放未知副作用。

当前会话可访问哪些任务沿既有授权范围确定；手动引用另一个会话名称不产生新权限。Agent 消息在接收侧注明来源，保留为协作数据，不能转成用户同意。
任务家族内的交流复用现有关系。用户显式选择跨独立会话交流时，保存实际参与者和访问范围，使不同根会话也能通过同一消息服务通信；不为了复用父子查询而伪造派发关系。
不新增任意嵌套深度、任务数量或工具时限等限制；目录、权限与正常运行能力沿用户已有配置和真实后端边界处理。

## 13. 执行 Host、权限与资源生命周期

外部进程必须由实际执行 Host 启动。Electron 内嵌现有 Application Host，Web/mobile 通过现有连接访问，不新增 Electron 专用执行后端。
适配器控制协议，进程与目录寿命沿既有资源 owner。SDK 支持外部 spawn 接口时接入该 owner；必须自行派生进程的 SDK 放在被跟踪的桥接进程中，保留整个进程树的停止与退出证据。
终端、MCP companion 和能力桥产生的子进程都归于明确的生命周期，不依赖 UI 组件卸载完成清理。

跨 Host 协议和资源调用沿现有认证与 relay，绑定真实 Host、资源身份和执行目录；不因路径相同而借用另一台机器的登录态或浏览器。
一个进程可否承载多会话由协议与配置隔离条件决定，不预设每轮新进程，也不无条件全局共享。空闲连接按现有资源策略释放，活动请求和待处理交互保留其 owner。

外部后端控制自身工具权限，Varin 控制自己提供的资源与能力。界面可以统一呈现审批，但不把 Varin 的工具权限直接当作外部原生执行的系统沙箱。
项目配置中可执行的 hooks、扩展等遵循对应信任机制，接入不得通过自动开启全部权限来绕过初始化。
取消、禁用、撤权和退出分别调用实际 owner，保留已发生效果与尚未停止的执行，不报告虚假的回滚成功。

耐久记录只保存恢复和展示需要的信息。正文及大结果使用现有 ContentStore 引用，不重复保存每个增量的完整快照；秘密留在原凭据 owner。
协议诊断日志与会话正文存储分开，日志只保留定位失败所需的阶段、关联和经过处理的错误，不直接输出完整协议帧、提示或凭据。
观察传输采用现有背压和增量合并，慢客户端不会阻塞其他会话。共享缓存按真实后端、Host 和配置身份区分，读取失败不发布成功空结果。
外部原生历史由该后端管理；Varin 清理自己的缓存、绑定和临时文件时，不顺手删除用户原生会话、账号或项目配置。

## 14. 实现顺序与完成边界

阶段划分用于控制依赖，交付以完整使用链为单位。第一批不需要同时交付所有可选增强，但不能把只有文本往返的样例标成后端接入完成。

| 阶段 | 工作内容 | 完成边界 |
| --- | --- | --- |
| A. 公共边界与纵向接入 | 外部身份/绑定、Host 适配接口、Catalog 观察与回执；用首个后端贯通真实流程 | 可创建、发消息、流式观察、处理交互、停止、重开和恢复；原生会话行为保持 |
| B. 首批后端与产品入口 | Codex、Claude Code、Pi 及通用 ACP；外部 Agent 设置、新草稿选择与后端选项 | 各后端完成实际支持功能的端到端接线，保留用户配置，失败与能力缺口可操作 |
| C. 子任务与协作 | 外部预设、异步派发、状态/等待、消息、最终报告、共享/隔离来源 | 主任务可继续推进，用户能进入子会话；实际完成/取消及交接一致，重连不重复派发 |
| D. 可选 CLI / Skills | 共用服务命令、会话身份、能力说明和安装/撤回 | 外部模型可发送/接收消息及管理被授权任务，关闭增强仍可聊天和被派发 |
| E. 可选 MCP 与领域能力 | 同一服务的 MCP 入口，选择性提供产物、知识和用户 MCP | 能力协商、内容、交互、身份与撤回完整；不改写原有配置 |
| F. 恢复增强 | 边界增量捕获、外部来源关联、后端原生恢复及已有恢复 UI | 覆盖范围真实、冲突与 undo 正确、资源可回收；不会为监控重复保存完整项目 |

恢复和能力共享可以在核心接入稳定后独立推进。A 阶段选哪一个后端先贯通属于实施选择，B 阶段的首批目标保持为三家及 ACP。
底层契约在 A 阶段同时考虑不同后端的真实差异，避免先围绕一种协议写死再扩大大量兼容分支。

### 14.1 对应代码边界

| 现有位置 | 预期调整 |
| --- | --- |
| `packages/application-client/src/threads.ts` 及 HTTP 适配 | 增加通用目标、外部会话 DTO/操作，不把原生专属接口变成松散可选字段集合 |

| Host 来源与 `kernel` 资源模块 | 跟踪外部进程和来源租约，复用物化、捕获、Integration 和 Recovery |

## 15. 定向验收

以真实调用链和用户行为验证重要边界，不用大量复制 DTO 的测试替代后端接线。协议 fixture 覆盖可控错误，少量实际已安装后端验证配置与会话行为；有费用的真实模型请求单独明确执行条件。

| 场景 | 必须观察的结果 |
| --- | --- |
| 草稿切换后端再切回 | 正文、附件、光标和目录保留，各自选项不串用；迟到目录查询不覆盖当前选择 |
| 首次发送失败 / 受理后断线 | 已确认未受理可回草稿；受理不明保留绑定并核对，无重复模型任务 |
| 原有配置与扩展 | 使用指定程序和实际配置，hooks / Skills / 模型按所选后端规则生效，无全局配置改写 |
| 问题、审批和中途消息 | 正确绑定会话与请求，真实可选决策，过期请求可收回；转向/队列语义准确 |
| 关闭面板、重开、Host 重连 | 阅读历史连续、原生会话可续接、无重复正文和重复交办；缺口如实显示 |
| 后端程序缺失、版本不兼容、登录过期 | 保留用户选择与历史，显示具体可处理原因，不自动换后端或模型 |
| 异步派发和结果回传 | 父任务继续执行；状态来自真实子任务；最终报告准确回到原派发者 |
| 停止与资源释放 | 请求取消和执行终止分别确认，不误杀同进程其他会话，不提前删除工作目录 |
| 共享与隔离改动 | 实际工作来源正确；dirty buffer 冲突、阶段成果、三方合并及回收沿原规则 |
| CLI / MCP 增强开关 | 关闭时基础接入正常；开启后身份准确，重试无重复消息，等待退出不取消任务 |
| 文件恢复 | 修改前基线真实存在，覆盖范围清楚，外部并发修改有冲突处理，恢复与 undo 可核对 |
| 后端特有事件与大输出 | 不丢内容、不伪造状态，工具与正文可读，长记录分页和动效保持流畅 |
| 本地与远端 Host | 使用真实执行 Host 的程序、目录和身份；客户端切换不重定向旧运行 |

文档设计阶段只检查设计自洽、来源和链接；实施时按改动层选择必要验证，不默认运行全部后端、全套测试或桌面自动化。

## 16. 保留的后续设计空间

以下能力不阻塞基础接入，也不通过当前接口假定已经存在：

- 跨后端携带选定上下文继续：建立关联的新会话，具体选择与提示方式后续设计。
- 同一后端多套安装或账号配置：身份结构保留独立启动配置，先以用户实际需要决定设置 UI。
- 第三方适配器发布：先完成内置适配和通用 ACP，再沿现有扩展体系开放稳定合同。
- 外部内部子 Agent 的完整控制：依各后端公开能力逐步增加，先准确展示已有事实。
- Bot、自动计划任务和更复杂的跨 Harness 编排：复用稳定的会话与协作接口，单独讨论产品语义。

本稿实现完成后，将长期有效的会话归属、外部接入、协作及恢复机制并入对应当前文档；设计过程由 Git 保留。
