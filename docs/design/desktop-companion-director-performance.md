# 主管式桌宠：完整演员分工与动作表演矩阵

状态：2026-10-29，角色设计候选，待整套审阅后制作/接线；**不是把这张表当成已交付动画数量**。对应[主管式项目台](desktop-companion-director.md)。现有默认 Q 版身份、柔软俏皮程度、直颈、单播放器与真实手/电脑接触合同全部保留。

## 一句话表演方向

**她在替你照看一张有生命的项目台：接住新的安排，把工作交给真实负责人，认真听项目进展，把该由你决定的事递给你；忙的是项目和它们的 agent，不是让她不停敲键盘装忙。**

不是威严董事长：不双手抱胸俯视、不指人训话、不盖审批章宣布权限通过。也不是忙乱跑腿：不每个 token 抬手、不在三个工具之间飞快换装、不让失败演成自责哭泣。她的可爱来自认真和小反应——接到安排稍微坐正，发现用户在看就轻抬眼，接到好消息有一个克制的眼笑，忙时也能安静陪着。

## 1. 四个演员层，不能互相替代

| 演员 | 负责的戏 | 永远不能借用的事实 |
|---|---|---|
| Varin | 管理项目台、看简报、协调、递交待决事项、向用户指出已知状态 | 不能把项目工具执行变成她在亲自读文件/写代码；不能虚构已安排、已审核、已批准 |
| 项目主 agent | 该真实 thread/branch/currentRun 的执行负责人；接收项目、组织子任务、产出结果 | 不创造 child operation 冒充自己；不把主 agent 头像替换成第二个 Varin |
| 子 agent 精灵 | 各 exact delegated execution 的准备、执行、等待、结算、结束 | 不根据人数减少演成功；准备完成不等于开始执行；Run 结束不等于 delegated owner 已结算 |
| 项目卡/简报小页 | 标注实际状态、请求/结果身份、检查详情和范围 | 不是新文件产物，不是新业务 Project/计划数据库，不凭装饰线制造依赖关系 |

项目主 agent 使用已有头像主体与脸，加局部负责人角色外观；当前短肩领/披肩方案只是候选，不能在未选定前改变用户的全局头像。短披肩角色方向已获认可，但逐头像贴合仍由视觉 owner 修复，不能把通用套装穿模候选当成完成。主 agent 的明确性来自位置与肩领轮廓，不只靠颜色、大小或皇冠。子精灵不穿这套负责人外观。

## 2. 统一动作语法：入场有理由，保持自然，退出有接触

- **进入 E**：眼神先注意，手/肩再跟上；项目卡先有真实身份再入场。不能手已经伸出才猜一个任务补到手上。
- **保持 H**：进入动作不反复播。用作者真实稳定曝光配稀疏眨眼、小视线转移和卡内状态，不用呼吸缩放整个人制造电脑/凳子漂移。
- **退出 X**：先收项目语义，再由当前曝光真实收手；新的 urgent 信息立刻显示，不等身体收完。旧卡不能贴到新任务标题下面继续飞。
- **二级运动**：头像小浮动、卡角轻回弹、短细线追踪只跟已证实的管理边缘/实际曝光 cue。没有物理接触原画时，卡只能停靠到屏幕/虚拟项目台，不能声称被手抓住。
- **频率**：每个事实边缘最多一段，不排队补戏；稳定总览大部分时间是安静保持。可用可调整的视觉冷却抑制连续短动作，但不延迟请求/错误事实，不用固定秒数决定任务完成。
- **人格一致**：先保证默认小尺寸能看懂意图：迎接坐正、倾听转向、呈交开掌、汇拢内收有清楚剪影；眼睛和肩部的小反应负责丰富而不替代这些主体动作。她可以俏皮，但不靠不停歪头、挤眉弄眼、跳舞或过度亲密暗示制造存在感。

## 5. 身体、主 agent、子队如何合演

### 接新安排：四拍，不是四次任务状态切换

1. 当前事实中新一轮受理，项目卡先出现标题与真实主 agent 身份。
2. Varin 胸前轻回应，看向屏幕/项目台；这是“收到”，不是宣布执行成功。
3. 主 agent 在自己的卡上进入对应准备/执行。只有新 child execution 事实出现，才由主 agent 向该子精灵发出短分派线。
4. Varin 收回管理手势，回稳定监督；项目细节继续动，她不用持续忙。

### 检查进度：信息走向她，但没有假报告

负责人卡的状态点或简短信息条靠近屏幕边缘 → Varin 看/指向实际显示的内容 → 信息仍挂在该卡。没有报告 artifact 事实时只称“状态/本轮结果”，不出现一个带完成签章的文档文件。实际工具的纸页、文字带、检索候选若保留，缩在检查卡内，由对应主 agent 一侧承担。

### 请示：负责人明确来源，Varin帮用户看见

B 主 agent 卡有锁标记；C 卡有问号。Varin只做一次转呈姿态。用户实际审批发生在原主窗业务界面；动画不执行命令。某一项解除后，其卡只更新自己；有其他事项时不欢呼、不放下所有待办。多个请求的公平性由可访问清单保证，不靠一群精灵争着撞她的手。

### 收到结果：不把所有项目收场

A 的确认状态从 A 卡方向到达屏幕/结果位，Varin短眼神回应/指示，B 的负责人和实际执行状态继续存在。A 若还有独立工作，结果卡明确本轮与未结算区别；失败/取消结果以温和中性呈现，不套用成功动作。新的 urgent 项到来就直接转呈，A 的旧短回应不排队。

## 6. 自然节奏与边缘优先级

1. 真正提起/落座与手电脑接触始终由唯一播放器保证。
2. 新的观察未知、结果未知、需要用户的事项即时更新信息；身体从真实曝光用最近安全出口转呈。
3. 新工作/明确结果/分派等有限管理边缘只留一个最新相关目标。新 urgent、隐藏、拖动、Host 变化直接丢弃，不在之后补演。
4. 稳定跟进是默认底色；检查镜头不换“身体演员”。普通工具/输出进度最多更新项目卡，不进入身体队列。
5. 本地 hover/tap 与生活点缀优先级最低；忙时可短关注，但不能打断持续请求的可读性。

多个项目一分钟内不断更新，不意味着一分钟内 Varin 要表演几十次。理想观感是：你瞥一眼知道她在照看全局，只有真正值得用户注意的变化会把视线带到某个明确项目；等你认真看时，有稳定标题、角色和列表让你查清楚。

## 7. 新原画需求与复用闭包

### 已有资产真正保留的价值

- v2 `welcome/tap/permission/query/dispatch/reading/editing` 等保留人物身份和可用手位；主管模式重新分配演员职责，不删除资产或另起一套人物。
- v3 已制作 `arrival-chest`、`thought-rise/chin/blink`、`explain-rise/content`、`error-observe/locate` 很适合接待、审阅、简报、检查；当前是已制作候选，不把它们的旧“工具输出”触发直接带入主管模式。
- 闭盖 rest/hover/tap/wake 与现有机械抓放链继续有用；不能为了改角色定位无意义重造同像帧。

### 真正需要补画：倾听与汇拢，不是再做几十套状态

实看现有原画后，首轮建议 **5 个关键/承接源组成 2 个动作族**；这是解剖与动作意图推导的制作估算，不是数量上限。若正常速度揭露手/颈桥断裂，补必要真实中间画；不为了凑数新增无差别眨眼。

| 新原画组 / 暂定设计 ID（尚未绘制） | 为什么不是现画改名 | 真正的身体设计与 E/H/X |
|---|---|---|
| `D-LISTEN-TURN / LEAN`，2 源 | 现搜索 yaw 是朝向候选，不包含“停止自己的动作，把注意让给负责人”的颈肩与重心；托腮又像自己想事 | 先看侧台，手先停；TURN 肩略向负责人打开，LEAN 胸口前移少量、头与颈同向 yaw，嘴闭、眉稍提，另一手保住电脑。不是侧歪头，不捧脸。听完先胸肩回 TURN，再回原稳态。当前台位以 viewer-right 可读方向为首选，不镜像发饰 |
| `D-GATHER-OUT / IN / TURN-USER`，3 源 | dispatch 是把注意送出去，offer 是单项递出；缺少“把若干独立事项收拢后转交”的反向语句 | 单手从已有低开掌桥向台面打开 OUT，手掌沿短弧向自己屏幕一侧收拢 IN（肘先回，手后回），TURN-USER 眼和胸口转向用户，掌保持低位。虚拟卡沿台面收束到摘要位，不贴指尖。继而走已绘 offer-mid→offer 单次呈交；若肩/手接不上必须补桥，不能硬剪接。退场按实际最后源逆收至稳定支撑位 |

实图复审后不再预设新“舒服监督”画：`open-user` / `listen-rest` 已有直颈与放松手位，先用真实静段审片；只有实际显僵硬才追加落肩/支撑桥。原提出的“低位呈交”也可由已有 `offer-mid/offer` 完成，不另重复画。

不优先补：实体文件夹捏取（没有业务需要，虚拟台已能讲清）、整套左右扫视（已有真 yaw）、另造大笑/庆祝/挫败套装、每个等待类别一张脸。开盖 hover 先用同头位 open-user + 现温和社交源验证；若缺自然注意承接再局部补眼/肩，不让闭盖 hover 顶替。

每个新增普通曝光都必须补实际源 SHA 抓取入口、去凳、早放/再抓与相同几何安全出口；项目台装饰 cue 挂在真实曝光，不挂在尚未显示的目标动作。验收后才能选入生产，不以资产目录名或动作枚举数量代替实际完成。

## 8. 制作顺序与验收

先审阅这份演员/动作矩阵与五组分镜，再选主 agent 角色外观及项目台位置；随后复用现有源制作低频管理编排，补确实缺失的新原画，最后做原生多项目联动。纯投影、只读事实和资产资源可以并行准备，但**完整角色方案审阅前不推广旧工具→主体适配器，也不把候选负责人外观设为全局头像默认值**。

验收不仅看一张图：同屏至少三个真实项目、两个独立请求、一个结果到来另一个仍执行；初次加载/断线重连/拖动不补旧动作；主 agent 身份正确、孩子所属项目准确、主 Run 更新后旧孩子仍真实工作；自然速度下 Varin 大部分时间安静监督，不是一直挥手或无限输入。减少动态模式仍读得懂分工和请求；所有透明卡、精灵和连线继续不截桌面点击。

## 9. 演员的表演谱：身体能读懂，不靠卡片替她表演

以下时长是**审片起始节奏**，不是业务计时器。E 包含注意/蓄势，H 区分动作峰值与可持续稳态，X 必须经过实画支撑桥。新画为设计，不声称已有安全出口。动作方向用观众左右，不颠倒发饰或镜像角色。

| 身体语句 / 适用情境 | E：意图出现 | H：完整表演与停顿 | X：把动作做完而不锁住事实 | 轻俏皮的细节 / 禁止误读 |
|---|---|---|---|---|
| **“嗯，我收到这项了”** M02 | 100–180ms 由屏幕抬眼，肩稍坐正；先有项目身份 | attend→arrival-chest，手落在自己胸前，不立正敬礼；峰值 280–420ms，视线随后落到新卡 | 按真实 attend 桥 150–250ms 落手，再看台面；短事件不必硬播完整峰值 | 小眼笑是收到信息，不是“理解了全部需求”；初始快照不做这一拍 |
| **“让我理一理”** M03 | 160–240ms 先停手，视线由卡回屏；thought-rise 真抬手 | thought-chin 600–1100ms，一次缓慢眨眼可选；目光有一个固定落点，不乱转眼球；随后手放下进入舒服监督 | 用 thought-rise 回收 180–300ms，不从托腮硬切 dispatch | 指尖轻托下巴而非压脸变形；只是思量表情，不自动给项目新增“已规划”事实，也不永久托腮 |
| **“这项交到你那边”** M05–06 | 先看已知负责人，dispatch-rise 140–220ms，肘带手起 | 只用目标 A 或 B 一次开放掌心 280–450ms；不是食指指人。负责人自己的分派在卡内完成 | 按该方向实际 transit/rise 回手，回监督；不为了播完 A+B 编造第二个分派对象 | 袖口落后掌心 1 个真实曝光；发梢保持，绝不程序摇整人。负责人回应无需服从式鞠躬 |
| **“我照看着，你继续”** M07/21 | 现 open-user/listen-rest 从各自真实手桥回稳，约 250–400ms | 稳态可持续，8–20s 安静段仅作审片样本；目光偏项目台，偶尔正视用户。后台忙碌由负责人/卡内承担 | 当前实际稳态的手桥退出；urgent 信息即时出现 | 不整人呼吸缩放、不每秒点头；一次目光转换有明确落点，不把“低打扰”变成全程无表情 |
| **“我在听你这项的情况”** M09/11 | 新 TURN 120–180ms，眼先找到该负责人，双手停止自己输入 | 新 LEAN 500–900ms，稍前倾、开放肩线、嘴闭，保持视线；需要长听时退回 TURN 或舒适稳态，不一直伸颈 | LEAN→TURN→原稳态，约 250–400ms；不以点头宣布审阅通过 | 身体让出话语权，负责人侧短状态条出现。没有真实报告内容时只是状态沟通隐喻，不能循环张嘴假讲话 |
| **“这里有个地方值得看”** M10/16/17 | 80–140ms 小停顿，眼先定位异常卡/屏幕摘要 | error-observe→error-locate 或 explain-rise→content；指实际笔电区域 300–600ms，另手支撑不丢 | 先收食指/手，再回 listen-rest；异常卡持续，不随动作消失 | 不惊跳、不责备、不红脸；源指向笔电就让摘要停笔电，不把错误方向解释成跨屏指卡 |
| **“我把几件事理在一起了”** M12/14 | 新 GATHER-OUT 140–220ms，掌打开朝台面；每项卡保留身份 | OUT→IN 200–320ms，卡向固定摘要槽收束；IN 停 120–180ms，TURN-USER 150–220ms。收拢的是注意/展示，不是假造归档或合并请求 | 从 TURN-USER 接真实 offer 桥；中断则按实际源回手，未出现的卡动线取消 | 肘先内收、眼先看摘要后看用户，有“整理好再开口”的认真感。卡不进掌、不硬画实体纸 |
| **“这部分需要你拿主意”** M13–15 | offer-mid 130–180ms，眼看用户，掌心低位向前；身体微坐正而非逼近 | offer 400–650ms 后主动收回 listen-rest；卡留着，手不永久悬空。多项也只呈一次，之后稳定注视 | 单项回答只收该项；有剩余时继续 listen-rest，不演全局 nod-soft | 轻抬眉可读期待，无催促招手；授权锁属 B 卡、问题留白属 C 卡，不在她头顶套全局锁 |
| **“这一项结果给你看”** M11–12 | 先向来源负责人一瞥 150–250ms，然后面向用户 | 同 gather/屏幕指示的有限段，明确成功可用现温和眼笑；失败/取消用中性表情。峰值 300–500ms | 回监督，其他项目照常；有请求则直接退到呈交/倾听，结果短边缘不排队补播 | 不挥手撒花、不抛文档、不演“我完成了”；结果状态卡不等于正式报告 artifact |
| **“没关系，我在这儿”** M19–21、等待用户 | 由当前动作真实收手，抬眼一次 180–250ms | listen-rest 或 open-user：放松肩和嘴角，偶尔看卡再看用户；不凭等待时长加更焦虑表情 | 新事实直接启用下一意图；未知时不自行打开/合上项目台 | 安心来自稳定陪伴，不是空口承诺一定能恢复；不把每次 retry 演成希望→失望循环 |
| **“咦，你在看我？”** L02–04 | alpha 驻留后，眼先到用户；现闭盖 hover-middle 真上身回应 | hover-attend 400–650ms，不歪头摇摆；tap 的小笑再 150–250ms | 真实 middle 回位；忙时最多正视一下，保留待决信息 | 互动是局部社交，绝不能点人物就批准；不得为开盖 hover 强行合盖 |
| **“稍微歇一下……好，我在”** L05–07 | 保留 v3 支撑感：闭盖→单手离盖→手掩嘴小哈欠→真回手→另一手到自己裙侧 | 舒服停顿后才 drowsy→doze；新输入用 wake-middle→wake-alert，不拿普通 blink 当醒来 | wake→rest-settled→rest-middle→精确 closed，再走真实机械开盖（若最新事实需要） | 哈欠是罕见一次，不在每轮休息循环；doze 仅全局明确静默，本地输入重置资格 |

### 视线和次级动作的硬约束

- 听负责人时看**真实所在台位**；接用户时看镜头；核对信息时看左下笔电。三个注意目标不同，不能全部用同一歪头母版。
- 现有左右 yaw 已含头颅/头发真实运动，复用整组局部真实源，不只拽瞳孔；左右不自动成套播放。上一次看右侧，本次仍是右侧负责人就不为了丰富改看左侧。
- 所有手势只抬一只手，另一只维持笔电/膝部可靠支撑；新掌势不能盖掉现有另一只手。衣袖/发束跟随必须在原画里成立；工程只能给装饰卡角小回弹，不能给身体挂弹簧。
- 眉/眼/嘴的表情不承担业务编码。成功、失败、未知都由有身份的卡保留；人物是情感节奏，不是红绿灯。
- 画面可丰富：纸页状摘要、双行状态条、归拢短弧、几枚层叠便签；但页数不是项目数，光点不是 agent，线条不是未经证实的依赖边。

## 10. 五段正常速度导演分镜（内部构图板对应）

1. **接待→交接→退场观察（约 2.1s）**：用户正前方 attention 140ms → arrival-chest 360ms → 真落手 180ms → 看负责人 180ms → 单向 dispatch 400ms → 真回手 240ms → 稳定观察。若新项早已推进，卡立即更新，不继续显示“准备中”；胸前峰值可缩短，但不能瞬移手。
2. **负责人说、她听（约 1.6s + 安静保持）**：外侧卡露出真实状态摘要 → D-LISTEN-TURN 160ms → LEAN 650ms → TURN 180ms → 舒适监督。此段不点头盖章，不自动计时生成回应文字。两张倾听原画缺口在板上用空白占位明确标出。
3. **B/C 两项请示（约 2s + 等待）**：两个身份卡先在位 → D-GATHER-OUT/IN/TURN-USER → offer-mid/offer 一次 → listen-rest。B 被处理时 B 更新；C 留着，她不再举一次相同托盘、不全局笑着点头。需要切看 C 用卡焦点与一次 gaze，不重复整个进场。
4. **A 结果到达、B 继续（约 1.5–2.4s）**：A 状态沿短线进入屏幕摘要槽；负责人保留 A 身份 → Varin 侧看/听 → explain-content 指笔电摘要（或以后 gather 呈交）→ 回监督。B 的工作位置不迁移；不得整台收场。失败和取消同样有完整中性收尾，绝非丢弃不给看。
5. **安静共处→被叫醒（事件决定停留）**：只有组合确实静默才真实合盖；复用已审完整 yawn/rest/doze → 新工作卡/请求立即可读 → 真实 wake 链 → 机械开盖 → 新意图。不是每过五分钟强迫表演，也不在后台工作时打盹。

内部板使用现有实际 PNG；新 LISTEN/GATHER 格明确写“缺新原画”，不拿旧人物配一条箭头冒充已经完成的新动作。板是构图/演员分工，不是验收动画；现有原画来源和实际 SHA 见[归档复用索引](desktop-companion-assets/director-performance/reuse-audit.json)；可打开[设计板](desktop-companion-assets/director-performance/index.html)或[分镜图片](desktop-companion-assets/director-performance/director-performance-board.jpg)。板右侧蓝框是分镜说明标签，不是最终卡锚；真正指屏摘要应落在笔电/屏幕侧停靠位。

## 11. 复用分类、制作与艺术验收

复用维度与发布状态分开：**R0 原样同意图**（机械/共处）、**R1 原像素但重新导演**（收到/权衡/开放掌心/呈交）、**R2 局部真重绘才成立**（侧听颈肩、舒适手位）、**R3 缺整段关键姿态**（汇拢）。R1 绝不意味着把旧 trigger 改名就直接上线；必须重新确定目标、视线、外部卡位置、有限时长、退出。v3 候选源是否已进入当前默认包以父级集成选择为准，本文不替运行验收盖章。

- **保留不删**：阅读前倾/翻页、输入改字、检索左右/触控仍是有价值的原画。主管默认身体不再逐工具执行；其视线/审阅子段可以 R1 使用。原完整工具场景保留为历史资产/项目检查视效参考，不能把 Varin 的完整大人物缩进主 agent 卡冒充负责人。
- **不推广**：v2 `nod.png` 已拒绝的冷表情、未纠正 attend、旧斜头资源；这些即使审计联系表存在也不是可选来源。`nod-soft` 也不能作为任意管理确认的万能回执。
- **先编排后补画**：用现来源做接待/单向协调/单项呈交/屏幕简报的真实 E/H/X 试片；并行审批 2 组新动作的关键姿态。新画只从 upright-v2 几何出发，512 viewport、电脑骨盆凳锚不漂，不因角色升职换脸、制服或年龄。
- **验收看身体**：隐藏所有符号，至少能区分收到、自己权衡、把注意给负责人、汇拢后呈交、休息/醒来；恢复符号后能知道“哪一项/谁负责/是否需要我”，不是图标替角色表演。默认原生小尺寸检查，不以放大图上的指尖差异当可见动作。
- **验收看节奏**：10–20 秒真实多项目观看片段中既有可读完整动作，也有足够长的安静稳态；不能十几个动作峰值连播、没有意图与放松。短工具爆发不得重启身体，短管理事件必须不虚构持续事实。
- **验收看连续性**：新旧接点正常速度与半速都查头骨/蓝眼尺寸、颈肩、发饰、袖口/另一只手、电脑支撑。静区像素一致只是必要依据，不代替实际接触合理性。每个实际曝光都须有普通回收、抓取去凳/落座入口，新增 SHA 先告知搬移 owner 再谈全覆盖。
