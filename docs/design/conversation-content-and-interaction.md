日期：2026-11-04。适用于 Varin 长期助手与普通 Agent 对话，共用 Web、Electron 和移动端实现。

## 1. 目标与判断

让一次回答可以自然地包含文字、图片、选择、可调整的结果和真实任务入口。用户既能读，也能在有帮助的位置直接参与；操作结果能带回对话，或者交给已有的文件、任务等能力继续处理。

采用一套内容与交互底座：普通文字沿用 Markdown；简单选择、输入和操作直接嵌在正文流中；复杂布局与计算沿用 `render_ui` 的 HTML/JS；已有任务、文件等对象由平台按真实引用呈现。Varin 模式更主动地组织交流和参与，普通 Agent 模式保持日常的文字表达密度。

平台负责稳定的排版、主题、交互反馈、状态保存和宿主联动，模型负责内容与表达意图。能力按原子操作组织，不预制“旅行助手”“科研问卷”“办公审批”之类的行业模板，也不要求每次回答按固定版式输出。

用户提供的《ChatGPT 聊天内 Web 呈现与交互能力全景报告》（2026-11-05）带来的主要启发是：交互还包括本地探索、计算、对比和结果带走，不能只围绕“选完答案发给模型”设计。本文据此结合 Varin 已有实现制定方案；报告作为体验参考，其中的功能描述不作为已核实的平台 API 合同。

## 2. 设计起点与改造范围

下表记录设计起点；实施后的当前行为以[交互内容](../interactive-content.md)为准。

| 当前已有 | 本次补齐 |
| --- | --- |
| Markdown、公式、表格、图示、图片与内容引用 | 在正文准确位置穿插轻量交互与原生对象引用 |
| `render_ui` 流式预览，完整调用保存不可变修订 | 正文里的显式作品位置，与工具活动记录协调展示 |
| HTML 跟随主题、宽度与会话滚动 | 轻量控件和 HTML 共享视觉与交互基础，减少手写样式 |
| `varinUI.state`、`saveState`、控件和滚动位置保存 | 声明式片段沿用同一状态领域，形成可靠的草稿衔接 |
| `setContext`、实际画面观察、选区引用 | 把当前选择、计算结果放进可编辑消息；提交时固定来源 |
| 作品按 `ui:` 引用继续修订，视图与虚拟列表生命周期分离 | 新内容与用户状态协调更新，保持历史决策和当前探索的区别 |
| 任务、材料、文件、计划等有自己的 owner 与界面 | 在回答中引用它们，复用真实状态和现有操作入口 |

HTML 当前已能以内联样式出现在聊天中。具体位置主要来自 `render_ui` 的工具时间线，普通正文里的一组选择仍需要模型制作整段 HTML。`setContext` 也主要服务宿主“用当前参数继续讨论”的引用操作，没有通用的正文交互到可编辑草稿的联动。

本次沿用这些基础，不另建作品数据库、聊天执行循环或文件操作通道。

## 3. Varin 与普通 Agent 的体验

| 场景 | 默认倾向 |
| --- | --- |
| Varin 长期助手 | 可以更主动地把比较、选择、调整和工作进展组织进回答，让用户少做信息整理与转述 |
| 通用、编程、科研、办公 Agent | 通常保持正文与已有工具活动节奏；需要比较、解释、探索或交付时使用相同交互能力 |

倾向作用于实际回答者的表达指导，不跟随用户当前打开的外壳临时变化。用户从工作台查看 Bot 会话，或在 Varin 里查看派发任务，都不会因此更换该会话的表达约定。

总助手的交流节奏、持续工作入口、独立发送默认和设备空间由后续[Varin 聊天与工作空间方案](varin-conversation-and-workspaces.md)接续，待实施。本文继续定义正文内容、交互片段、作品和宿主动作的共享能力。

用户要求直接答复、只给代码、完整报告或特定格式时，按本次要求表达。交互数量、篇幅和视觉复杂度不设模式配额，也不增加每轮必选的呈现策略调用。

同一轮应有阅读节奏：解释和结论保持正文地位，操作放在相关内容附近，详细依据按需展开。模型可以连续写完一段话、给出一组选择，再继续解释，无须为了每组控件增加一次工具调用和模型续轮。

## 4. 内容组成与生成方式

### 4.1 普通正文

保留现有 Markdown 和媒体表现。标题、段落、列表、图注与图片组使用已有排版，不把每段内容包成卡片。

“✅”“值得注意”等表达含义仍由模型写出；平台负责字号、对齐、颜色和间距。实际任务是否完成则读取任务状态，不从模型的一句话或一个符号推断。

不扫描普通句子自动添加复选框、成功标记或操作按钮。普通 Markdown 任务列表继续表达文档内容，需要可操作状态时使用明确的交互片段或真实对象引用。

### 4.2 轻量交互片段

新增一个明确标记的 Markdown 围栏 `varin-ui`，内容使用简短 JSON。它出现在助手正文的准确位置，由共享解析器生成独立内容节点。围栏前后仍是普通 Markdown。

单选使用如下语法：

````markdown
我想先确定发型的长度与风格。

```varin-ui
{
  "type": "choice",
  "label": "发型",
  "options": [
    "偏短发：蓬松、清爽，发尾到脖颈",
    "中长发：及肩微束发，温柔中带点俏皮",
    "偏长发：到肩胛骨的低束发，更优雅飘逸"
  ],
  "action": "按这个发型继续设计"
}
```

服装可以沿用刚才的方向，之后再调整细节。
````

`action` 是用户表达的意图，默认生成输入框草稿。模型不必同时为同一选项填写显示文案、发送文案、摘要文案和每一端的布局参数。平台根据动作文字、字段名和实际选择组成可编辑文字，例如：

> 按这个发型继续设计。
>
> 发型：中长发：及肩微束发，温柔中带点俏皮

多选、补充文字和多个问题使用同一组输入原语；多问题在一个片段内按顺序排布，共用一次结果操作。必填等校验只用于内容本身确有要求的字段，不给所有问题统一施加必答约束。

片段可以包含以下基础能力：

| 基础能力 | 表达范围 |
| --- | --- |
| 选择 | 单选、多选、简短选项切换；长选项纵向排列 |
| 输入 | 文字、数字、范围、日期等浏览器基础输入；允许用户补充自己的表达 |
| 操作 | 填入草稿、引用结果、复制、打开实际对象；明确发送见第 6 节 |
| 折叠与视图切换 | 展开说明、切换已有内容的查看方式，不因此请求模型 |
| 内容引用 | 作品、图片和原生对象在正文中的位置 |

常用静态片段不要求模型生成 ID。平台从原消息和内容位置分配稳定身份；需要跨修订更新时才使用已有作品引用及稳定控件键。解析器保存原始文本，未知类型或无效片段有可读退路，保留选项和意图；不把失败片段变成空白，也不自动发起修复模型请求。

只解释助手正文中明确的专用围栏。用户输入、工具原文、引用段落和被更外层代码围栏包住的示例保留为普通内容。支持客户端对复制、导出和引用提供文字表示；未支持的客户端至少能看到原始内容。

### 4.3 HTML 与自定义计算

比较权重、预算分配、动态图表、分支故事等需要自定义逻辑时继续用 HTML/JS。滑块和表格之间的公式由页面执行，新增判断、检索或内容生成才进入 Agent 请求。

不在声明式片段里再开发公式语言、条件流程和通用数据绑定语言。普通控件覆盖直接表达，复杂计算由已有 JavaScript 环境承担。

为 HTML 提供随应用发布、按需加载的基础样式与控件辅助模块，复用主题变量、输入样式、焦点、状态反馈和宿主动作语义。模块通过现有作品模块解析入口加载；无需外部 CDN 才能绘制基本控件。自定义 HTML 可以采用这些基础，也可以自行设计，不强制套入固定容器。

### 4.4 正文中的作品位置

同一 `varin-ui` 语法支持引用作品，例如：

```json
{ "type": "embed", "ref": "ui:作品引用@3" }
```

模型使用真实工具回执中的引用。没有显式位置时保持当前工具时间线的内联展示；有位置时在该处展示作品，原调用保留为可展开的制作活动或来源入口。

同一轮、同一修订的完整视图只挂载一份。多个引用仍可出现，其余位置作为可定位入口；用户主动打开独立视图时才创建独立实例。

流式制作时先在调用位置预览。正文中的引用到达后，投影把原视图衔接到正文位置，保留状态和滚动锚点；若用户正在原视图输入或操作，先保留这个操作位置，新引用显示定位入口，待离开操作后再完成布局调整。历史重开时一次确定最终位置，避免先挂载工具卡、再闪移到正文。

历史回答默认绑定其固定修订，后来修改作品生成新修订。需要查看最新版本时提供明确入口，不悄悄把过去回答替换成今天的内容。制作阶段同一轮连续更新沿用现有聚合投影。

### 4.5 原生对象

模型可以在正文引用真实任务、Agent、计划、文件、材料、恢复点与用量对象。平台解析引用，采用对应领域已有的身份、头像、状态与操作。

默认呈现与用途匹配：文件是紧凑的文件入口，任务是带负责人和状态的行，计划可展示当前摘要，需要时进入已有面板。详情层级延续现有设计，不统一替换成大卡片，也不在回答里复制一整套工作概览。

正文描述是当时的叙述；对象行的状态可以显示现在的进展。用户引用进下一条消息时，捕获所引用时的状态与时间。固定版本的材料或恢复点继续绑定版本，实时任务的变化不会重写历史引用。

首次实现直接接入已有对象解析和导航能力；扩展的地图、天气等专业表现通过数据能力及渲染适配加入。组件呈现、真实数据来源和执行权限仍各自有明确归属。

## 5. 三种动作如何衔接

| 用户动作 | 实际处理 | 模型上下文变化 |
| --- | --- | --- |
| 勾选、调整参数、筛选、切换图表、展开说明 | 当前视图更新和本地计算，按既有状态路径保存 | 不新增模型消息 |
| 填入输入框、引用选择或区域 | 准备可编辑草稿与固定来源引用 | 发送后才成为本轮输入 |
| 明确发送、继续任务或实际修改对象 | 交给原聊天输入、任务或资源 owner 受理 | 沿原请求与操作记录回报 |

普通选择可以没有后续发送动作，例如查看不同方案、练习题或纯计算器。一个内容也可以既支持本地探索，又提供“用这组参数继续讨论”。

模型生成的选择不自动进入用户消息；拖动过程不产生逐步事件日志供模型阅读。操作结果以实际回执显示“已填入”“已发送”“已排队”“已保存”等对应状态，错误留在相关操作附近。

## 6. 与输入框的关系

### 6.1 填入与编辑

普通动作的默认行为是填入草稿，按钮旁使用轻量提示说明会进入输入框。选项切换本身不抢焦点。

输入框为空时写入动作意图和选择结果；已有草稿时，在该会话最近有效光标处插入独立文字段，没有光标则追加，保留原文字和附件。通过页面按钮插入不主动替换用户选中的文字。一次插入作为一个可撤销编辑处理。

草稿短暂记录这段文字与源交互的关联。同一交互再次点击填入时，若原段落未被用户改动，更新原段落；其他地方的用户编辑不受影响。用户改过关联段落后解除自动更新关系，再次填入生成新的插入操作，不猜测如何合并用户措辞。

不在用户已填入草稿后因普通选项变动自动改字。用户再次执行填入动作，才更新尚未修改的关联段落。用户删除该段后，仍能再次从交互中填入。

插入使用现有编辑器事务、撤销与输入法处理。中文组词期间不打断 composition；动作准备完的文本在组词结束后应用到同一草稿。下一步建议继续作为建议层显示，真实用户编辑和显式插入优先；`@`、`/` 菜单保持现有输入规则。

### 6.2 发送与正在进行的任务

用户在输入框确认后走现有发送路径，包含附件、引用、排队、补充当前任务和失败重试。交互不新建第二条消息队列。

确有一键继续需求时，可提供明确标为发送的宿主动作，附可查看的待发送内容。用户点击即按现有发送规则受理，不额外叠加一次常规确认。原输入框草稿保留；这个动作仅发送其自己的内容与引用。

自定义 HTML 可请求呈现这类宿主动作，真正的发送由平台渲染的按钮接受用户点击。页面脚本不能在加载、计时器或状态恢复时自行调用发送。其他已有实际操作继续经过原 owner 和已有权限机制，不因“来自交互页面”多叠一套审批，也不因此绕开原权限。

请求受理成功前保留待发送快照；双击和不确定重试复用原投递身份。用户后来调整页面内容不会改写已排队消息。该消息成功后，仅清理这次操作对应的草稿片段和附件，保留期间新输入的内容。

### 6.3 提交内容与引用

用户显式引用的后续交互由[聊天定点引用与可拖动输入标记](chat-quoting-and-draggable-markers.md)细化：段落／对象范围、输入框内标记、图片与引用拖动、结构化来源与模型可读内容分离。该方案尚未实施；本文以下原则继续适用，不表示现有发送链已完成该改造。

普通选择使用动作意图、字段名和用户实际选项在本地组成文字，不调用辅助模型。用户补充的自由文本原样进入草稿。结果过于复杂时，页面通过现有 `setContext` 给出讨论所需的数据，再由宿主固定来源快照。

用户提交或引用时保留：所见内容的修订、实际选择或结果、出处。正文带可读的选择和关键结果；较大的图表、数据或材料沿现有引用机制携带，按需读取原内容，不把完整 HTML、DOM、脚本和点击轨迹一起塞进请求。

模型产出的文字和计算规则仍有助手内容来源；用户点击确认的是这次选择与动作。保留来源关系，不能把隐藏的页面数据或全部页面文字重新包装成用户命令。

填入后被用户改写的文字是其最终表达。附带的原选择快照作为来源保留，不再把快照里的旧值另行标为用户最终确认值；模型可以据此看懂“从什么方案改成了什么”。

## 7. 状态、修订与长程对话

### 7.1 三类状态的归属

| 状态 | 保存与解释 |
| --- | --- |
| 页面正在探索的状态 | 选项、输入、筛选、展开和滚动位置，由交互视图领域保存；客户端切换与虚拟列表卸载后恢复 |
| 用户已提交的结果 | 固定来源与选择快照，进入原聊天输入记录；后续页面变化不修改它 |
| 真实任务、文件、计划等状态 | 继续由各自领域 owner 保存；交互只观察或提交操作 |

声明式片段的原始定义保留在助手消息中。为现有交互源身份增加“消息片段”来源，指向原消息、片段位置与内容版本；控件和引用状态沿现有 `ui.view`、`ui.snapshot`、`ui.selection` 存储路径扩展，不为了普通单选生成一份 HTML 再保存。

首次打开、引用或更新时，由 Host 按原消息登记可解析的 `ui:` 作品身份，初始修订引用原定义；相同来源重复登记返回同一身份。原消息无需因登记而改写，也无需前端常驻才能再次解析。片段引用通过会话资源元数据与用户操作回执提供给模型。

内联片段初始身份由运行时消息与流位置确定，完整历史提交时保留对应关系。不能用可视列表行号、标题、显示顺序或 React 挂载次数作为状态身份。

切 Host、换会话、建立分支时继承现有身份与作用域规则。新分支可以从分叉点的内容和状态开始独立探索，后续修改不串回原分支。不同客户端拥有独立视图实例，继续一个已有结果时从其快照恢复，不让两个窗口的草稿互相覆盖。

普通状态保存合并写入每个视图的当前状态，不为每次拖动建立历史快照。显式引用、发送和作品修订才保留对应固定结果。删除会话与回收未引用作品、预览和快照沿原存储生命周期处理，保留仍被消息引用的来源，不另留永久交互日志。

### 7.2 内容更新时如何保留选择

片段首次生成后，与该消息版本绑定。需要在之后的轮次继续调整同一内容时，沿作品引用提交新修订；为相同含义的字段与选项保留稳定键。

具体更新入口扩展现有 `render_ui`：HTML 仍使用 `changes`，声明式作品允许提交 `content` 定义，两种写入载荷由 Host 按实际参数校验。调用可写为 `render_ui({ ref: "ui:…@1", content: { /* 更新后的片段 */ } })`，返回原有作品引用与新修订。工具根 schema 保持 object，按目标 provider 的工具 schema 合同导出。普通第一次表达仍直接写正文围栏，只有需要继续编辑、独立制作或复用时才走工具。

`resource_read kind: ui` 读取声明式作品时返回原定义、固定修订和可用状态，继续共用作品冲突检查、快照和访问作用域。不会把更新后的片段拼回旧助手消息，也不要求模型重新生成一份视觉等价的 HTML。

新增一个选项、补充解释或调整布局时保留仍有效的用户输入。含义改变、已选项删除或字段类型改变时，局部说明需要重新选择的部分，其余值继续保留。不按相同数组下标把旧选择迁移到新的含义。

原始简单选项可以只写字符串；只有可持续编辑的内容才需要稳定键。平台不会靠语义猜测两个相似文案是否是同一选项。

对于正在跟随制作进展或已选择查看最新内容的视图，新修订在用户当前输入期间不替换焦点所在控件。先保留正在编辑的视图与草稿，提供已更新的轻量提示，在用户接纳新内容或离开当前编辑后对齐修订。历史固定视图保持原修订，已提交的选择也始终绑定原修订。

### 7.3 与压缩、记忆和任务的关系

选择结果作为真实用户输入进入当前上下文，之后由现有上下文整理处理。作品源码与引用已有按需读取机制，压缩不会销毁作品存储。保留当前问题所需的选择与结果属于上下文整理的职责，不增加一份随每次请求重复注入的“交互状态总表”。

一次勾选不自动写成长期记忆。需要长期沿用的信息仍由现有记忆写入、检索和维护机制决定；持续后台工作仍由任务与接续系统承担，页面关闭后也按它们本来的生命周期继续。

## 8. HTML 联动接口与原生操作

保留现有 `state`、`saveState`、`setContext`。新增的草稿联动建议收敛为 `varinUI.compose(...)`：页面提供可读文字，可选择携带当前讨论状态，宿主固定快照并写入所属会话的草稿。接口返回草稿准备结果，不能把返回成功解释为消息已经发送。

原生对象的打开、引用和可用动作通过统一的对象引用适配器解析。HTML 和声明式内容使用同一种动作描述，宿主渲染可信动作区域；任务状态与可用动作来自原 owner，页面不能自行声明“有停止权限”或伪造执行成功。

宿主动作区域可以直接排在内容末尾，与页面形成自然的视觉整体。导航、复制和填入等轻量动作可紧贴内容；会改变真实任务或资源的操作显示真实对象和动作名，复用产品现有反馈。

实现继续复用现有 iframe 通信通道、来源核验、视图身份与 lease，不把 `postMessage` 变成任意 Host API 透传。脚本在作品保存后运行的规则保持不变。原生发送按钮和资源操作的点击不会由页面加载或重连自动重放。

查看任务、文件和恢复点优先打开已有面板。作品本身仍可进入侧栏或全屏细看；移动端使用现有展开方式。页面不能为了跳转偷偷更改用户正在编辑的另一会话草稿。

## 9. 排版、主题与动效

### 9.1 正文层级

文字、图片和轻量控件共用正文宽度与基线。简单选项直接排在相关段落下面，长文案自动换行，选中态用控件和柔和强调表达。多问题逐项排下，组间用间距和标题区分，内容较多时允许展开详细说明。

主要操作靠近其作用范围。多个动作区分主次，避免每段都出现同等醒目的整行大按钮。需要较大操作面积的单一主要动作可以占满当前内容宽度；这取决于用途和容器，不按类型套同一种卡片。

图片沿用比例自适应预览、图注和分组，点击查看原图。图表和表格根据内容选择局部滚动或展开查看，外层正文跟随会话滚动。通用控件与长路径自然换行，不以文档级横向滚动解决排版。

### 9.2 亮色与暗色

颜色使用现有主题语义：正文、次要说明、边界、表面与重点色。选中态随用户重点色变化；成功、错误、警示等状态保留其语义，并有图形或文字辅助识别。

亮色下避免大片纯白与高饱和色块形成刺眼对比；暗色下用表面与文字层级区分信息，不给所有区域铺有色滤镜。HTML 明确采用自己的前景和背景时保留成套配色，通用控件采用对应容器的主题变量，避免浅底浅字。

### 9.3 连续性与性能

新内容流入、局部展开、选中反馈、版本切换与收起使用现有动效时长和缓动；允许中途反向操作，从当前进度继续。保留用户要求的动效效果，不通过关闭动画来换取性能。

解析只处理流式变化的部分，稳定片段不随每个 token 重建。控件的值和焦点不寄存在易被重新创建的 Markdown DOM 中。自定义计算只更新相关区域，原生对象按对象身份共享观察，避免每张任务行独立轮询完整会话。

HTML 高度测量、虚拟列表与会话滚动继续用现有所有者；更新时合并测量和布局工作，保持阅读锚点。用户主动上滚或操作内容时释放底部跟随，不让新控件、图片加载或版本替换把视图拖走。

基础控件支持键盘、读屏标签、合理焦点与输入法，尊重系统减少动态效果偏好。收起包含焦点的内容时先把焦点交还触发入口；恢复历史不会自动展开所有控件或抢焦点。

平台按钮、状态、错误与辅助说明沿现有 i18n 管理；模型生成的内容保持其原语言。日期和数字按客户端区域设置呈现，提交保留明确的值与单位。

## 10. 流式生成、失败与恢复

正文中的专用片段未完整时，不展示跳动的 JSON。可读标题与已经确定的内容可以逐步呈现；只有结构完整、动作含义确定后才启用对应交互，不猜测缺失的属性。

完整片段到达即可本地选择和准备草稿，不必等整个回答结束。若原助手消息尚未耐久提交，引用沿现有预览快照机制固定所见定义与选择，标明预览来源；历史提交后对齐来源身份。若生成中断，已固定的用户引用仍能重现当时内容，不伪装成成功保存的作品修订。

`render_ui` 继续保持“流式预览、提交后运行脚本”。纯声明式控件可以更早操作，是因为其结构完整后没有待执行的用户脚本，两者分别按自己的实际语义处理。

解析失败、脚本错误、引用不可用和状态保存失败只影响相关内容。保留可读正文、已经输入的值和原草稿；在相关位置提供实际错误及合适的重试入口。不会为了修一个控件重发整段助手回答。

从虚拟列表重新挂载、切换工作台页面、重连 Host 观察时恢复已有视图，不重放用户操作。保存失败可继续本地查看和编辑，并保留未保存状态提示；只有原 owner 确认后才显示已保存。

## 11. 提示词、披露与上下文成本

沿用当前开放的 `communication` 表达指导，只补足新能力的使用方式。共享常驻内容包含专用片段的基本语义和一个短示例，让模型能直接写普通选择；复杂输入、作品更新、HTML 辅助模块和原生对象动作通过现有按需能力说明获取。

Varin 的表达倾向可写成：

> 根据交流需要，自主组合文字、图片和交互。用户需要比较、选择或调整时，可以优先采用便于直接参与的呈现方式，同时保留自由表达的空间。具体形式和展开程度由你判断。

普通 Agent 沿用当前交流指导，知道这些能力可用即可。不建立“先判断任务类型、再选模板、每轮补固定问题”的流程，不额外配置一个呈现决策模型。

共享语法和能力版本保持稳定；动态选中值、任务进度和界面状态不回插系统提示词前部。客户端实际支持的能力在请求准备时固定，沿现有能力披露接线，切换页面不重写正在进行的请求。

成本主要通过少写重复内容来降低：轻量选择不生成 HTML/CSS/JS，不为每次点击续轮；复杂 HTML 仍返回现有小回执；同一选择不用再生成多份显示和发送文案；本地计算不调用模型。普通短片段保留在助手历史中，不再另附一份重复摘要；较大作品、数据与观察继续按引用读取。

不为这项功能增加机械 token 截断、固定控件数量或固定回复长度。上下文窗口与请求预算沿现有模型能力处理。

## 12. 与已有功能的衔接

| 已有功能 | 衔接方式 |
| --- | --- |
| `ask_user` 和等待中的问题 | 可共享选择、输入的视觉组件；回答仍交回原问题请求，保留阻塞/等待语义，普通正文选择不会创建待回答请求 |
| 权限请求 | 沿现有权限界面与 owner，普通交互文案不能代替权限受理 |
| 账号与凭据输入 | 继续用现有私密输入通道；普通片段状态和讨论引用不承载真实密钥 |
| 下一步建议 | 保持为输入框建议层；显式填入与用户输入优先，不吞掉 `@`、`/` 的操作提示 |
| 引用与附件 | 继续使用 `ContentReference` 和原附件受理，固定选择的来源；原文件传递按文件能力处理 |
| 任务、计划、协作与接续 | 对象组件打开已有面板、观察实际状态，发送或修改交给原 owner |
| 内容复制与导出 | 轻量交互导出问题、选项、选择和动作意图的文字表示；HTML 导出沿现有作品能力，外部页面不声称仍有宿主操作 |
| 外部 Harness | 支持其实际输出能提供的正文与引用；若适配器支持新格式再声明能力，不修改外部隐藏执行循环；普通输出继续可读 |
| 扩展能力 | 专业数据组件按需注册并披露，沿相同引用与动作路径接入，避免堆入常驻提示词 |

历史交互可以再次查看或引用。已经回答的问题不会因重开历史再次变为待回答；用户想改主意时产生新的消息或实际操作。

## 14. 交付顺序与验收

按依赖推进完整设计：先落共享来源与动作合同、正文片段解析和草稿事务；再接视图持久化、流式恢复及版本更新；随后接 HTML 正文位置、宿主桥接和原生对象；最后统一主题、动效、无障碍、模式指导与按需说明。这些是实施顺序，完成范围包括整条体验链。

围绕实际交互验收，按失败类型选择 UI、Host 或原 owner 的测试，不为每个层复制同一套断言：

| 场景 | 完成表现 |
| --- | --- |
| 发型选择穿插在两段正文之间 | 长选项竖排换行；选择不请求模型；按钮生成可编辑草稿，原有文字与附件保留 |
| 多问题与多选 | 可在同一区域完成、补充自由文字，一次填入；结果保留问题和选择的对应关系 |
| 填入后手工修改，再调整选择 | 用户修改的段落保持原样；未编辑段落仅在再次执行填入时更新；删除后可以再次填入 |
| 预算或权重计算器 | 调整后本地即时计算；继续讨论只发送实际选定参数、结果和来源，不发送每次拖动事件 |
| 连续制作与正文引用 HTML | 一个完整视图，制作记录可追溯；位置衔接不丢输入、不重跑脚本、不拖走阅读位置 |
| 同一内容追加选项或更新版本 | 不受影响的选择和焦点保留；改变含义的字段明确处理；旧消息里的已提交结果仍对应旧版本 |
| 真实任务与文件入口 | 任务显示实际状态、打开正确会话；文件与材料定位正确来源；操作回执来自原 owner |
| 发送时任务正在执行，或响应丢失 | 使用现有排队/补充规则与重试身份；不重复发送，不清除期间新输入 |
| 切会话、切 Host、分支、虚拟列表卸载 | 状态按身份恢复和隔离；不混用别的会话草稿，不重放操作 |
| 亮暗主题、窄屏、键盘和中文输入 | 可读、有层级、无意外横向滚动；焦点与组词连续；动效可打断 |
| 流中断、无效片段、脚本或保存失败 | 正文仍可读，用户输入保留，错误定位到对应内容；预览与保存结果区分清楚 |
| 用户只需要普通答复，或客户端不支持交互 | 普通内容自然呈现；可复制和读懂内容，不依赖隐藏界面才能继续交流 |

已实现合同维护在[交互内容](../interactive-content.md)、[工作台](../workbench.md)和[Bot](../bot.md)。上表继续作为目标验收依据，尚待完成的真实环境证据与功能边界分别以本文开头和[运行时验收](../runtime-acceptance.md#聊天交互内容)为准；定向测试不替代代表性布局、输入法、设备和真实存储验证。
