# 聊天交互内容与精确引用设计

状态：已讨论确定的目标方案，待实现。本文中的新工具参数、作品资源和引用点尚不是当前系统能力。

## 目标与体验

Agent 可以在聊天中生成图表、计算器、模拟器、交互解释和其他 HTML 内容。用户边生成边看，在卡片内操作，
也可以展开到工作区、查看源码、下载，或带着当前参数和选区继续讨论。

生成与交互是主要体验。模型自行决定使用哪些能力、怎样拆分工作、是否需要查看效果；产品不规定生成后的
检查流程，也不要求先获取指南或通过验收才能保存内容。

普通回答继续使用 Markdown、数学公式、表格与 Mermaid。生成交互内容由当前 Agent 选择，无需前置模型
为每个问题决定展示形式，也不替换现有聊天框架和原生运行时。

聊天卡片采用 Varin 的字体、主题、间距和操作样式：

```text
贷款方案比较                       预览 / 源码   展开   ⋯
──────────────────────────────────────────────────────
贷款金额    [ 500000              ]
贷款年限    ━━━━━●━━━━━━━━   20 年
年利率      ━━━●━━━━━━━━━━   3.2%

                    月供对比图
                        ……

                    [引用区域] [用当前参数继续讨论]
```

- 简单图表自然嵌入回答，复杂内容使用有标题的卡片。更多菜单承载下载、复制、重置等操作。
- 选择文字可引用；需要圈定视觉内容时，显式进入框选模式。普通点击、滑动和拖动控件保持原用途。
- 展开到侧栏或窄屏全屏时延续当前内容与交互状态。关闭展开视图后可以回到原聊天位置。
- 进度与错误简短显示在对应内容附近，不默认展开内部职责、调用阶段、完整栈和诊断表单。
- 生成期间固定卡片身份并保持阅读位置，内容增长接入已有聊天滚动机制。

## 一、内容、修订与画面

### 1. 作品与修订

作品有稳定身份，可以包含 HTML、CSS、JavaScript、数据及关联资源。每次完整修改成功后产生不可变修订。

```text
作品 A
  写入第一部分 HTML       → 修订 1
  追加其余 HTML           → 修订 2
  同批加入 CSS 和 JS      → 修订 3
  修改按钮文字            → 修订 4
```

一次调用中的多项修改整体提交，形成一个修订。没有实际内容或元数据变化时返回原修订。未改动的文件复用
原内容对象，不为每次编辑复制整个作品包。修订号用于定位内容，不要求用户管理，也不对应一张新的聊天卡片。

不设置 `draft`、`publish` 参数或独立发布步骤。成功写入即保存并更新呈现。一次完整调用可以提交尚未写完的
HTML 文件；内容能否完整运行与源码是否已成功保存分别报告，不能把预览成功作为保存前置条件。

### 2. 临时预览

工具参数尚在流式传输时，已收到的内容可以形成临时预览，但尚未成为已保存修订。
临时预览绑定原调用、基准修订和进度序列。模型参数片段、已经显示的画面与最终提交结果保持可区分。

### 3. 交互状态与快照

用户改变金额、筛选条件、当前标签页等，不产生源码修订。可恢复的交互状态由作品视图会话保存，并关联
对应作品和修订；它不依赖某个 React 节点或 iframe 一直存活。

画面快照记录一次实际观察：源码修订或临时预览身份、交互状态、视口、滚动位置、捕获时间，以及实际取得的
截图和结构信息。用户引用点绑定这个快照，后续页面变化不会改写引用内容。

同一个源码修订可以有多个不同参数、窗口尺寸和滚动位置的画面。不能只凭源码版本推断用户所见。

## 二、生成工具 `render_ui`

### 固定接口

`render_ui` 以一份稳定且紧凑的 schema 提供常用编辑操作。以下 TypeScript 用于表达目标契约：

```ts
type UiChange =
  | { file: string; op: "write"; text: string }
  | { file: string; op: "append"; text: string }
  | { file: string; op: "edit"; edits: { oldText: string; newText: string }[] }
  | { file: string; op: "delete" };

type RenderUiInput = {
  ref?: string;
  title?: string;
  entry?: string;
  changes: UiChange[];
};
```

- 新建时省略 `ref`，提供标题和内容；HTML 默认入口为 `index.html`，多文件作品可指定 `entry`。
- 继续制作时使用已有作品或修订引用。使用修订引用时，以该修订作为修改基准；已被其他写入推进时返回冲突，
  保留用户和其他调用的修改。作品引用在受理时解析并固定本次基准。
- `file` 是作品内部相对路径，不解释为宿主机器的文件路径。源码支持相对引用作品内的样式、脚本和数据。
- `changes` 按顺序作用于临时文件集合；一次 `edit` 内的多个替换匹配该步骤开始前的原文，沿用文件编辑的
  唯一匹配与不重叠语义。全部修改成功后一起保存，失败不留下半批修改。
- 空修改批次只返回已有作品当前结果，不制造修订。没有单独的“提交发布”动作。

一次生成：

```js
render_ui({
  title: "贷款方案比较",
  changes: [
    { file: "index.html", op: "write", text: "<!doctype html>…" }
  ]
})
```

分次追加与修改：

```js
render_ui({
  ref: "ui:calculator@2",
  changes: [
    { file: "index.html", op: "append", text: "…" },
    { file: "style.css", op: "write", text: "…" }
  ]
})
```

引用字符串为示例。真实引用由 owner 生成，调用者不需要构造存储路径。

### 简短回执与资源

成功回执包含作品身份、本次不可变修订引用、标题和简短结果。大段源码只保存为资源，不在回执中重复发送。
保存成功不表示页面已完成渲染；实际呈现状态由客户端观察提供。

已有 HTML 可以通过现有文件读取能力取得后写入作品。图片、字体等关联材料复用现有授权资源引用与内容对象，
由作品资源解析器处理；具体材料绑定沿用媒体与材料协议，不能把任意路径或 URL 当成读取权限。
外部网络资源按其真实来源加载，网络不可用时显示实际结果。

工具提供能力和必要接口语义，不附送操作教程，不规定模型要分几次写、先写什么、什么时候检查。

## 三、流式呈现与保存分别推进

```text
模型工具参数增量
   → 增量解码与调用内预览状态
   → 可展示的 HTML / 样式片段
   → 稳定卡片内的增量 DOM 更新

完整工具调用
   → 基准修订与修改批次解析
   → 原子保存新修订及原调用回执
   → 原预览与最终保存内容对齐
```

### 流式处理

1. 接到 `render_ui` 的调用进度时创建稳定卡片，绑定原调用身份。尚未取得目标引用或标题时先显示轻量占位。
2. 增量解码参数中的字符串与修改项；保留不完整的 JSON 转义、Unicode 序列和标签，不靠完整参数 JSON
   已经可解析才开始显示，也不要求模型按某个字段顺序输出。
3. 已形成可展示结构的文字、节点和样式逐步进入预览。追加在当前基准上展示；局部替换在目标和匹配内容明确后
   才应用。未明确的修改不猜测目标。
4. 按浏览器绘制节奏合并更新，尽量保留已有节点。大内容解码和解析避免每个 token 都重新处理全部累计正文。
5. 参数传输期间只呈现可展示的结构与样式。模型脚本、事件处理等行为在完整写入保存后启用，避免半截脚本
   执行与流式重复初始化。

每次传输更新都重设 `iframe.srcdoc` 会造成闪烁、滚动和输入丢失，不能作为流式实现。普通内容更新和从预览
转为已保存时保持原卡片与可复用节点。代码变化确实需要重建执行环境时，在同一作品视图内恢复显式保存的状态，
不能承诺任意 JavaScript 闭包和运行中资源都可原样保留。

### 完成、中断与恢复

一次调用成功保存才生成修订。客户端收到原回执后对齐最终内容，未收到持久确认时不把临时预览标为已保存。
断线后沿原历史和回执恢复，不凭客户端曾显示过的内容重放写入。

取消或失败时，已保存修订保持不变。当前可见的未保存预览可以保留并标注中断，用户仍可选择、复制或引用；
没有被引用的临时进度不必逐 token 持久化。再次制作使用明确的内容基准，不自动把半截参数当成成功提交。

流式期间的框选会固定当时的预览内容和图像，绑定调用与进度身份。它不提前宣称一个尚不存在的修订号。

## 四、读取工具与实际画面

### 扩展 `resource_read`

在现有资源读取工具中增加 `kind: "ui"` 分支，保持原有技能和指令读取语义：

```ts
type UiReadInput = {
  kind: "ui";
  ref: string;
  view?: "summary" | "source" | "state" | "screen" | "structure";
  file?: string;
  startLine?: number;
  endLine?: number;
};
```

| 视图 | 结果 |
| --- | --- |
| `summary`（默认） | 标题、实际修订、文件目录及可用视图/快照引用；引用点返回所选内容与简短来源 |
| `source` | 指定文件源码；未指定文件时返回目录，行范围用于局部读取 |
| `state` | 绑定视图会话的当前状态，或固定快照保存的状态 |
| `screen` | 实际画面截图，或引用点对应的选区截图 |
| `structure` | 可见文字、控件、当前值和位置等可读结构，支持沿资源续读 |

读取沿现有输出预算与续读机制工作，不为这项功能另定一套随意的大小限制。截图作为图像内容块输出，不把
base64 当作正文发送；模型不接收图像时保留资源引用和可用文字/结构，明确未向该模型提供视觉内容。

### 引用语义

| 示例引用 | 解析含义 |
| --- | --- |
| `ui:A` | 读取开始时解析作品最新修订，结果返回解析到的固定修订 |
| `ui:A@4` | 修订 4 的不可变源码与关联资源 |
| `ui-view:abc` | 由原客户端提供的一个真实页面实例，允许请求新的观察 |
| `ui-snapshot:s1` | 已保存的观察快照，固定其画面、状态及来源 |
| `ui-selection:p1` | 用户选取时的文字或区域，绑定对应源码/画面快照 |

作品引用本身不代表某个用户窗口。读取实时画面需要视图引用；已有固定截图通过快照读取。
同一作品存在多个交互会话时，不凭作品 ID 猜测其中哪个是用户当前状态；summary 返回相关引用供精确选择。

当前用户消息可以携带与该次输入关联的作品视图引用；选区附件携带固定引用点。只有明确绑定到该客户端、
会话和视图的读取才请求其实际画面，不搜索其他窗口充当“当前”。视图关闭、客户端断开或截图能力不可用时
返回相应结果；后台复现渲染若被使用，须标明为复现，不能冒充用户所见。

示例：

```js
// 读取之前输出的一个文件片段
resource_read({ kind: "ui", ref: "ui:calculator@3", view: "source",
  file: "index.html", startLine: 40, endLine: 100 })

// 观察用户正在看的真实实例；结果包含本次固定快照引用
resource_read({ kind: "ui", ref: "ui-view:abc", view: "screen" })

// 读取用户选取时的区域，不随实时页面变化
resource_read({ kind: "ui", ref: "ui-selection:p2", view: "screen" })
```

截图、结构和状态采用同次观察身份关联，记录各自实际取得的内容。无法确认关联一致性时不得拼成看似同步的
快照。结构读取不默认倾倒整页 DOM；只读观察不调整用户的参数，也不隐式点击、重置或滚动页面。

## 五、文字与区域引用点

### 用户操作

选中文字后，通过轻量浮动操作或右键“引用”加入输入框。对图表、图片、Canvas 或跨元素布局，点击卡片的
“框选引用”，在明确的选区模式中拖出矩形；Esc 退出，完成后恢复普通交互。

对于动态图像，选区在捕获的画面上定位。输入框显示可预览、可删除的引用项：

```text
[引用点 1 · “月供合计”]  [引用点 2 · 图表区域缩略图]

把引用点 1 改成更明确的名称，引用点 2 的两条曲线用不同线型区分。
```

添加引用只修改输入草稿，不自动发送。用户可添加来自不同消息或作品的多个引用，再组织问题。
编号是该条消息内易读的称呼，底层使用稳定 ID；删除某项不会使已经写下的“引用点 2”改指另一个对象。

点击引用项可以查看固定选区，并在来源仍可定位时回到原消息/视图高亮。来源已变化时仍能展示旧快照；
不能把旧坐标直接套到新布局上。映射到新版的位置只能作为另一个明确结果提供。

### 引用保存与模型输入

每个引用点保存：

- 原会话/消息或作品身份，以及已保存修订或临时预览身份。
- 选中文字及可确定的原文范围，或区域截图与其在原画面中的位置。
- 画面快照与必要交互状态引用。
- 能实际取得的元素标识、标签及局部结构；Canvas 等无对应元素时保留图像定位。

模型首次收到选中文字或选区图像及简短来源。完整源码、整页截图、全部状态和大结构保持按需读取。
用户已经提供了选区内容时，模型可以直接回答或修改，不需要再调用读取工具完成形式上的“激活”。

引用进入现有附件与输入受理链，发送固定选取内容；失败、重试和排队保留原引用及身份。
历史中的引用继续可读。普通消息、作品、图片和 PDF 共用引用表示，各自沿原 owner 获取证据。

## 六、作品视图与页面接口

### 视图生命周期

作品视图会话独立于聊天消息 DOM。虚拟列表卸载卡片时，源码、修订、必要参数和阅读位置仍然存在。
重新挂载时按显式状态重建，不要求保留所有历史 iframe。进入侧栏优先转移同一视图；必须重新挂载时恢复
同一交互会话。真正独立打开的多个视图拥有可区分的身份。

连续制作期间，同一作品在该轮的主卡片持续展示进展，追加调用仍保留各自原回执。结束后的历史展示绑定
该位置记录的修订；后续轮次更新作品不会悄悄改写之前消息的内容。侧栏可以明确选择跟随最新修订。

### 页面端契约

页面只需知道少量固定能力：读取初始状态、保存可序列化状态、提供继续讨论所需的上下文。
这些是短小接口契约，随生成能力的稳定定义说明，不引入先请求一本指南的工作流。

页面内筛选、计算、图表操作在本地执行。页面可以提供上下文数据，但普通输入变化、初始化和定时器不能
自动提交聊天消息。宿主“用当前参数继续讨论”把对应作品修订与状态带入输入框；明确标为发送的用户动作
复用现有发送与排队机制，不另建模型请求通道。

主题由 Varin 实际选择决定，包含字体、颜色、间距、焦点与减少动态效果偏好。常用图表依赖按需加载并固定版本，
避免每张作品随机请求漂移版本。模型自由编写内容，无需套固定布局模板。

### 执行与导出

生成 HTML 在独立沙盒中运行，无法访问 Varin 主页面 DOM、凭据和特权 API。宿主桥只提供本节声明的能力，
文件、网络和工具调用继续由现有 owner 处理。流式可见内容不构成额外执行授权。

下载 HTML 保留可在浏览器运行的本地交互，并说明仍需要网络的外部依赖。依赖 Varin 的聊天动作在导出页面中
明确不可用，不能用返回成功的空函数模拟发送。保存到工作区沿现有文件接口；生成作品不默认污染用户项目。

## 七、工具上下文与缓存

本功能的核心接口规模有限，采用稳定的 `render_ui` 定义和 `resource_read` 分支即可。
不为作品编辑另造发现、加载、指南或按阶段启用工具的机制；不因为创建作品而附送一组未来可能用到的操作说明。

工具名称、描述、schema 与顺序保持稳定，同一会话跨轮延续。作品引用、进度、观察和选区随原工具回执或新用户
消息追加，不插回系统提示前部，不改写已发送的历史。读取接口有能力不等于每次都必须读，生成成功也不自动
串联截图、检查和修复调用。

外部 MCP 的大量动态定义有独立的按需发现需求。当前默认 `codemode`，direct 暴露路径则会在声明变化时更新
模型工具列表。后续处理这条路径应保持稳定调用入口、将发现内容追加到对话，或使用渠道明确支持的原生延迟
工具机制；不能把追加普通 `tools` 数组误认为保留历史前缀。这项工作与本功能共用原则，不成为新增 UI
发现框架的理由。

提示缓存取决于实际提供商协议，不能用本地 JSON 复用或固定 cache key 代替前缀稳定性。
参考 [OpenAI 提示缓存](https://developers.openai.com/api/docs/guides/prompt-caching)与
[Claude 工具缓存](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-use-with-prompt-caching)。

## 八、接入现有系统

| 部分 | 责任与现有入口 |
| --- | --- |
| 工具声明与受理 | 固定工具声明进入原生工具目录；沿原 Run、Operation、权限和幂等回执执行，具体内置分发遵循现有扩展机制 |
| 作品存储 | Host 负责领域语义，Rust 所有的存储负责内容对象、修订元数据与提交；不另建 TS 文件数据库 |
| 资源读取 | 扩展现有 `resource_read` 的 UI 分支；源码、快照和材料按原会话及资源身份解析 |
| 客户端 API | `application-client` 提供作品读取、视图观察与引用 DTO；UI 不透传任意内核方法 |
| 聊天呈现 | 现有工具/消息渲染入口接入卡片，保留实时调用与已保存结果的关联 |
| 流式预览 | 消费原工具参数进度；临时展示不触发新的工具执行或持久写入 |
| 侧栏 | 沿工作区视图身份接入作品展示，聊天卡片和展开视图使用同一交互状态 owner |
| 引用与发送 | 扩展现有引用、附件、草稿和输入受理链；选区捕获后固定来源与内容 |
| 画面捕获 | 原客户端提供截图和结构；桌面可复用窗口区域截图，Web/mobile 按实际平台能力接入 |

提交只短暂串行化同一作品的修订更新。源码解码、资源传输、渲染、截图与其他工具并行，不能持有全局运行锁
等待客户端画面。关闭界面不取消已经受理的保存操作，观察中断也不重放写入。

作品修订、被引用的临时快照和交互状态分别使用现有内容对象及保留关系。历史引用到的内容必须仍可读取，
释放遵循已有资源生命周期，不自行增加按天数或数量删除作品的规则。

## 实现时需要落定的接线细节

核心产品与工具语义按本文实现。以下细节需结合实际 owner 确定，不应在未接线时宣称已具备：

- 现有原生流式事件到 UI 的参数片段投影，以及重连后临时预览的恢复方式。
- 作品记录、内容引用和引用点在原生存储中的具体类型及保留关系。
- 沙盒视图在桌面、Web、mobile 上的实际截图和可见结构读取能力。
- 页面状态接口的具体名称、资源 URL 解析和固定依赖的分发方式。

这些接线不得重新引入显式发布步骤、每次编辑发现工具、常驻长篇指南或自动检查流水线。
