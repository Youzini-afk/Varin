# 动效与交互：丝滑到底

状态：2026-10-24，设计已确认，正在按第 6 节分期实施。可交互原型：[motion-preview/index.html](motion-preview/index.html)（用浏览器直接打开，纯前端；数据与运行过程均为示例，不连接 Host）。

原型的界面结构以现有产品为准：`varin-light` / `varin-dark` 主题，44px 标题栏与「工作台 ▾」「通用 ▾」切换，按项目分组的会话侧栏，左上圆角的会话画布，右侧导轨与面板，居中的新会话首屏，对话优先的过程行，思考阅读窗口，派发成员行与任务回复气泡，左操作右用量的轮末，以及设置窗口与 IDE 工作台。本稿只改运动、交互与节奏，不改信息架构和阅读规则（见[工作台文档](../workbench.md#聊天阅读与用户介入)与 [UI 模块说明](../../packages/ui/DOCUMENTATION.md#conversation-and-resource-projections)）。

侧栏底部的「动效实验室」是评审工具，不属于产品。它提供版本（新设计 / 现状）、阅读模式（对话优先 / 按时间展开）、动效级别、主题、×4 慢放与重播。「现状」按下文审计复现，是近似表现。

## 设计判断

「丝滑」不是让东西多动，而是让每个变化都有来处和去处。五条可检验的标准：

1. **连续**：元素不瞬移、不重挂载。位置、尺寸、状态都从上一帧的样子出发。
2. **可打断**：过渡中途改主意时，运动从当前位置和当前速度接着走。
3. **同一拍子**：全产品只用四个弹簧和两个补间，同类变化在哪里手感都一样。
4. **有节奏**：流式输出、工具推进、子 Agent 汇报按阅读节拍呈现，而不是按网络到达的节拍。
5. **克制**：同一时刻只有一个主角动作。运行状态靠文字与原位换字表达，不加装饰线条和卡片。

## 2. Token

### 四个弹簧

参数沿用 motion 的 `bounce` + `visualDuration` 写法（mass 1）。CSS 侧用同一组参数采样生成 `linear()` 曲线，JS 与 CSS 手感一致；不支持 `linear()` 时回退到三次贝塞尔。

| 名称 | bounce | visualDuration | 完整收敛 | 用途 |
| --- | --- | --- | --- | --- |
| snap | 0 | .18s | 约 320ms | 悬停胶囊、菜单、提示、按压反馈 |
| glide | 0 | .32s | 约 545ms | 默认：进场、选中胶囊、尺寸变化、面板与侧栏宽度 |
| travel | .06 | .5s | 约 680ms | 跨区域移动：发送飞入、输入框停靠、锚定滚动 |
| settle | .3 | .42s | 约 650ms | 只用于「到达」时刻：新会话长出、成员加入、徽标、头像落位 |

「完整收敛」是 CSS 动画的实际时长，尾段肉眼不可见；感知时长以 visualDuration 为准。

### 补间与编排

- 淡入 160ms，曲线沿用 `--wb-ease`（`cubic-bezier(.22,1,.36,1)`）。
- 退场 110ms，`cubic-bezier(.4,0,1,1)`，约为进场的 0.6 倍：东西走得比来得快，界面显得轻。
- 交错 18–24ms 一项，最多 6 项。
- 退役：到处使用的 `--wb-ease-settle` 过冲、`transition-all`、裸 `ease`。过冲只属于 settle 的到达时刻。

### 落地形式

- `packages/ui/src/lib/motion/tokens.ts`：弹簧参数、采样器、`linear()` 生成；导出给 motion 的 transition 预设。
- `packages/ui/src/styles/motion.css`：`--ease-*`、`--dur-*`、`--t-exit`、`--t-fade`，构建时写死生成结果。
- 根部 `MotionConfig reducedMotion="user"`，默认 transition 为 glide。
- 基础件：`<Presence>`（统一进退场）、`<SlidingPill>`（选中 / 悬停胶囊、导轨指示条、标签页底色）、`<SwapText>`（同格换字）、`useSpringValue`（宽度、滚动）、`useTailFlip`（时间线内的高度变化）。

## 3. 编排

原型中除注明「原型未包含」的条目外都已实现，可以慢放观察。

### 3.1 新会话与发送

1. 新会话首屏沿用现有布局：标题「我们要在 {project} 中做什么？」、居中输入框、八个起始建议。整个产品只有一个输入框实例。
2. 按下 Enter：
   - 标题向上淡出，起始建议依次下沉淡出。
   - 输入框用 travel 从首屏位置下沉到底部停靠。布局一次提交，位移由 FLIP 完成。
   - 输入框里的文字变成飞行层，沿一道浅弧线落进用户气泡（x 用 glide、y 用 travel）。飞行中逐帧读取气泡的实时位置，到达后与真实气泡在同一帧交接。复用现有 `.conversation-message-handoff` 与 [messageHandoff.ts](../../packages/ui/src/components/conversation/messageHandoff.ts)。
3. 首次发送创建会话：新行以 settle 在所属项目顶部长出，其他行 FLIP 下移，选中胶囊在原地淡入；顶栏标题从「新会话」换字为会话名。
4. 发送按钮的箭头上移淡出，停止方块以 settle 落入。打字时输入框即时增长，发送与清空时高度用 glide 收回。

### 3.2 锚定与跟随滚动

- 新回合锚定到视口顶部：给进行中的回合预留最小高度，回复向下生长，读者的视线不被推走。锚定滚动用 travel。
- 只有内容越过舒适线（进行中回合底部 + 56px 超出可视区）才开始跟随。跟随是滚动位置上的临界阻尼弹簧（ω≈14），目标只增不减。
- 滚轮上滑、触摸立刻脱离跟随；离最新内容超过 120px 时「回到最新」以 snap 进场，点击后 travel 滚回并重新跟随。
- 生产实现（已完成）：LegendList 继续负责虚拟化；时间线只有一根滚动弹簧（`SpringDriver`），每帧直接写滚动位置，同一时刻只属于跟随、锚定或回到最新之一。
  - 舒适线沿用产品已有的阅读间距：`min(96px, 视口 × 16%)`。
  - 锚定的回合越过舒适线后，视图交给普通跟随；同一根弹簧接着走，不重置速度。
  - 「回到最新」跳过长历史，只 travel 最后 1.25 个视口；接近最新内容时交给跟随。按钮仍在离开跟随时出现，保持产品原有的判断。
  - 列表自己调整滚动位置时（例如保持可见内容），弹簧带着这段位移继续，不和列表抢。
  - 发送飞入的消息随目标一起滚动，只有目标离开视口时才提前结束。
  - 进入会话、视口尺寸变化，以及简化 / 关闭动效时，直接放到末尾。

### 3.3 流式正文：墨迹前沿

- 配速每帧计算：`rate = max(26 字/秒, 积压 / 0.24s)`。网络突发时 0.24s 内追上，停顿时平滑减速。
- 网络结束后，剩余积压在 0.16s 内匀速排空。
- 每帧新出现的字从次级灰、低不透明度在 300ms 内显影为正文色；超过 420ms 的节点合并回文本节点。
- 光标是一个小圆点，输出时常亮；等待超过 280ms 才开始呼吸。结束时缩小淡出。
- 生产实现：rAF 配速替换 `usePacedText` 的定时器；morphdom 只修补已稳定的块，正在写的尾块走追加路径。

### 3.4 对话优先的过程行

遵循现有规则：两段发言之间的普通动作和公开思考共用一条可展开的过程行。派发、问题与独立产出永远独立成行。

- **运行中**：标签是实际动作，例如「正在思考…」「正在搜索文件 · login」「正在读取文件 · src/auth/login.ts」。
  - 运行状态用一束很淡的光从左到右扫过文字表达，不用转圈，也不在行下加进度线。
  - 动作切换时标签在原位换字：旧字上移淡出，新字自下进入，不再按 key 重挂载重放入场。
  - 快速完成的动作至少停留 260ms，读得清楚。
- **思考**：思考期间，标签后跟单行实时预览。新行出现时整行用 glide 弹簧上滑；一次到达大段文字时只动最后一行，不重放累积内容。思考就是思考，展开后是原来的「思考过程」阅读窗口：左侧细线、有界高度、可以继续跟随。
- **收尾**：下一段发言开始写字的那一刻，过程行原位换成回执摘要，例如「检索了 1 次 · 读取文件 2 次」「修改了 2 个文件」。失败、待确认、已取消在摘要右侧保持可见。
- **展开 / 收起**：保留 DOM，高度走 3.8 的尾部 FLIP，子项交错淡入。
- 单个活动直接渲染它自己的工具行，不再套一层摘要。
- 「按时间展开」模式下，过程行不收起，每个活动按发生顺序直接出现。原型的「集中展示回答」未包含。

### 3.5 工具行

- 结构沿用原组件：动作（次级灰）、对象（正文色 85%）、右侧回执（「9 处命中」「L1–182」「+38 −52」），以及展开详情（文件链接、命中片段、差异预览）。层级只用细线和缩进，不加外框。
- 运行中，右侧显示「进行中」与一个 12px 的细圈。完成时状态向右淡出，回执自左滑入，数字滚动到位。普通成功不加完成徽标。
- 失败与已取消在原位换字，颜色只用于真实失败。

### 3.6 文件修改：流式差异

卡片沿用 `ChatFileChangePreview`：头部有文件名、+N −N、展开按钮；中间是差异视窗，收起 8 行、展开 24 行；底部有阶段文字、回到最新、上一处 / 下一处、工具详情。投影规则也不变：`file_edit` 的 `newText` 未到时是拟删除，`apply_patch` 的文件头整行到达前不打开文件，路径完整之前不是可导航的身份。要改的是参数流到达时的呈现方式。

- **配速**：参数增量和正文一样按帧配速，`rate = max(140 字/秒, 积压 / 0.22s)`，结束后 0.12s 内排空。代码的基础速度高于正文，读起来像在打字，而不是一块一块地落下。
- **行身份**：每一行按来源编号保留身份（旧文本第 i 行、新文本第 j 行），不再整体替换。
  - 拟删除的旧行被确认为上下文时，同一个 DOM 行只把底色从删除色过渡为无色。
  - 插入或移除行时，下方的行只用 snap 弹簧滑动。新行从顶边展开，移除的行向顶边收起，两者用同一条曲线，边缘始终贴合。
  - 顺序发生变化的行不滑动，原地淡入。滑动的行由最长递增子序列选出，行与行永远不会交叉穿过。原型逐帧检测，可见行之间的覆盖为 0。
- **写入游标**：
  - 正在写的行带一个细的块状光标。新字以墨迹显影，一行写完后约 90ms 才着色，模拟 worker 延迟；颜色从正文色晕开到语法色，不会整卡闪回无色。
  - 正在写的新行如果与游标后的旧行同前缀，就在旧行上「复写」：已写部分是正文色，光标后的旧内容保持淡色。避免先闪成一行新增、写完又变回上下文。
  - 游标之后尚未决定的旧行保持删除色，但变淡；整段写完后一次落定为最终差异。
- **高度与跟随**：外框高度由 glide 弹簧追到「内容高度与 8 行的较小值」，超过 8 行后只滚动内部，时间线保持稳定。内部跟随是弹簧（ω≈16），不是 `scrollToEnd()` 跳转。滚轮上滑、按下或方向键立刻暂停跟随，底部出现「回到最新」；只有内容确实超出视窗时才显示。
- **路径后到**：JSON 属性顺序不固定，内容可能先于路径到达。此时卡片以「文件路径待接收」先开始生长，标题带微光；路径完整后原位换字为文件名，不重置阅读位置。过程行标签同步为「准备修改文件」→「准备修改文件 · src/auth/login.ts」→「正在修改文件 · …」→「修改文件完成 · …」。
- **阶段**：正在生成修改 → 正在应用修改 → 已应用（或已应用到未保存的草稿、已应用到工作分支、未应用 · 查看详情），每一步都在原位换字。头部的细圈以 settle 换成文件图标，计数原位滚动。
- **导航**：上一处 / 下一处用 travel 弹簧把内部视窗滑到变更起点，并短暂提亮落点行。
- **对话优先下的就地预览托盘**（已确认）：原规则把两段发言之间的普通动作全部收进一条过程行，流式差异看不见。现在过程行下方增加一个托盘，正在写入的修改卡片就地出现在托盘里，跟着参数流生长。收回按「批」计算：
  - **一批**：托盘里出现第一张卡片时开始。同一批里的卡片按开始顺序向下排列。
  - **收回时机**：批内所有卡片都完成（已应用、未应用或停止），并且安静了约 700ms 的阅读时间，才把整批一起收回。批内任何一张还在写或应用，都不收。
  - **接续**：停留期间如果有新的修改开始，它加入当前批，接在下面，计时清零。收回之后才开始的修改开一个新批：托盘重新出现，卡片从头生长。
  - **同时写入**：多个文件重叠时，过程行标签显示最近开始、仍在进行的那一项，例如「准备写入文件 · tests/auth.refresh.test.ts」，右侧注明「另有 1 项进行中」。先开始的完成时不抢标签。
  - **用户在看时不收**：指针在托盘内、展开了某张卡片，或在卡片里向上滚动暂停了跟随时，推迟收回。离开、收起或回到最新后，重新计 700ms。
  - **段落结束**：下一段发言到达，或这一段结束（例如开始派发）时，已完成的批立即收回；用户正在看的批等离开后再收。
  - **收回方式**：整批一次完成，快照交叉淡出，尾部 FLIP，高度只提交一次。收回前把进行中回合的最小高度保持在当前高度，下方内容平滑上移，滚动位置不会被浏览器夹回。快照里各卡片的内部滚动位置与原卡片对齐。收回后摘要计入「应用了 N 次修改」；展开过程行，卡片仍在原位，保留 DOM 与阅读位置。
  - **其他模式**：「按时间展开」下没有托盘，卡片直接在时间线里。降低动效只去掉位移与裁切，停留时间保留，因为那是阅读时间而不是动画。现状模式没有托盘。
  - 原型演示两种情况：`login.ts` 单独一批，写完停留后收回；`session.ts` 还在应用时测试文件开始写入，两者同批，都完成后一起收回。
- **整文件写入**：`file_write` 没有修改前的内容，不显示 +/− 计数，底部注明「写入内容预览」。行按写入顺序生长。
- **代码块**：正文里的围栏代码块用同一套规则。围栏一到就出现代码框和语言标签，行随到随长，写完的行再着色；块写完后光标移出代码框。
- **现状对照**：实验室切到「现状」，可以看到参数增量原样落下、没有配速，未完成的新行直接参与差异，旧行一律显示为删除，外框高度用 280ms 补间，内部跳到底部。

### 3.7 派发与任务回复

- 「已分派 N 个任务」是一条带细线的小标题。第二个任务加入时，数字原位换字。
- 每个子任务是原来的成员行：原 Agent 头像（`agent-avatar-art.ts` 的造型）、名称、任务、状态、展开箭头。
  - 新成员以 settle 进场，头像轻微旋转落位。
  - 状态依次换字：启动中 → 运行中 → 已完成。完成时细圈缩小淡出。
  - 不使用大卡片，也不用扫光或彩色边框表示汇报。
- 任务回复是原来的子 Agent 消息气泡，带「发送者 → 接收者」路由，默认两行预览折叠。展开时预览与正文一起过渡：旧外观交叉淡出，高度只提交一次。
- 右侧协作面板同步：成员列表就地加入新行，消息流里出现「派发任务」（主 Agent 发出，靠右）与「任务回复」。面板未打开时，导轨上的协作按钮出现一个 settle 弹出的提示点。

### 3.8 时间线内的高度变化：测量一次 + 尾部 FLIP

过程行、思考窗口、工具详情、文件修改卡片的收回与「工具详情」、成员详情、任务回复、检索轨迹、交互卡片共用一个机制：

1. 记下旧高度，需要时克隆旧外观作为快照。
2. 一次提交新布局并测量新高度。
3. 变高时本行用 clip-path 从旧高度揭开；变矮时快照被裁切并淡出。
4. 下方的行用叠加的 `translateY(-Δ) → 0` 跟上（`composite: add`，连续变化可以叠加）。

布局只变一次，之后全是合成层动画；虚拟列表只需在提交时重测一行。实施前需要一次 LegendList 技术验证：确认行高提交后列表的位置更新与 transform 补偿在同一帧生效。

### 3.9 轮末

左侧操作（复制、重试、有帮助）依次淡入，间隔 24ms。右侧用量（输入、输出、tok/s）淡入后数字滚动到位。标题栏的上下文环随每次工具结果平滑增长。

### 3.10 外壳

- **侧栏**：
  - 会话按项目分组。选中胶囊是可打断弹簧，快速连点时带着速度改道；悬停胶囊用 snap 跟随，并向指针方向偏移几像素。
  - 收起项目时，下方分组 FLIP 上移；展开时会话依次进入。
  - 会话图标原位换出：运行中圆点、未读铃铛、默认对话图标，换出时以 settle 弹入。
  - 归档、删除时该行向左淡出，其余行 FLIP 让位；置顶时该行 FLIP 移到顶部。
  - 侧栏开关：宽度由 glide 弹簧驱动，内层内容固定宽度并淡出，避免逐帧重排。
- **切换会话**：旧内容向列表反方向 110ms 淡出，新内容按回合交错进入，顶栏标题按同一方向换字。
- **右侧导轨与面板**：
  - 导轨激活指示条用 glide 弹簧滑到当前按钮；Git 更改数以 settle 徽标出现。
  - 面板宽度由弹簧驱动。打开前把主列锁定到最终宽度，文字只重排一次。
  - 标签页底色滑动；切换界面时旧内容 110ms 退场，新内容交错进入。
  - 面板内的协作成员与 Git 文件就地增量进入，不重建面板。
- **弹层**：工作台、通用 / 科研、模型、思考等级、会话操作的下拉都从触发按钮生长（scale .96 + 位移 5px，snap），选项交错 16ms，内部有悬停胶囊，支持方向键。选中后触发按钮的文字同格换字，宽度以 glide 过渡。
- **提示**：首次 520ms 延迟；400ms 内移到下一个锚点时不再等待，提示框直接滑过去。导轨按钮的提示在左侧。修正 `tooltip.tsx` 中 `skipDelayDuration` 的映射。
- **设置窗口**：
  - 打开时遮罩淡入，窗口以 glide 从 .985 落位，导航分组依次进入。
  - 切换分页时，左侧导航胶囊滑动，面包屑按方向换字；详情 110ms 退场，新页章节交错进入，目录保持不动。
  - 外观页的主题卡触发 3.12 的墨晕，动效卡与实验室的动效级别同步。
  - 聊天页的阅读模式卡与实验室同步。

### 3.11 工作台切换：晶格波

用约 750ms 的晶格波取代全屏遮罩。从「工作台 ▾」的位置向外，44px 的格子按距离依次长满标题栏以下的整个内容区（侧栏与工作区），覆盖约 380ms。在覆盖完成的那一帧提交工作台，再由同一方向的第二道波揭开，约 400ms。标题栏不动，切换器文字原位换成「IDE」。

- 全屏启动遮罩只保留给冷启动，以及目标工作台未准备好或准备超过预算的情况。
- 生产实现优先用 View Transitions（Electron 是 Chromium）对内容区快照，晶格作为遮罩；不可用时回退到 DOM 晶格层。需要验证 Chromium update callback 约 4s 的超时：工作台提交必须在超时前完成，否则直接走回退路径。
- 拖放沿用同一语言：文件拖入窗口时内容区浮现淡晶格场，靠近指针的格子变亮。原型未包含。

### 3.12 主题：墨晕

View Transition 让新主题从点击点以圆形扩散到最远角（660ms，基础出场曲线）。过渡期间压掉 CSS 过渡，避免新视图里再动一次。简化级别为 160ms 交叉淡入，关闭级别为硬切。

### 3.13 启动

热启动退场从 1900ms 缩短到约 600ms，之后界面分段入场：侧栏、标题栏、首屏标题、输入框、导轨，每段间隔 40ms，起始建议随后交错。原型只包含分段入场，不含启动遮罩。

### 3.14 移动端

- 边缘滑动实时跟手：位移直接映射到 transform；松手时按速度（> 0.5px/ms）或位移（> 35%）决定提交，否则以 glide 回弹。
- 引入 `@capacitor/haptics`，只在提交点触发轻触感：切换会话、发送、任务完成。
- 原型未包含移动端。

## 4. 性能预算

- 同一时刻最多一个主角动作（飞入与停靠、晶格波、墨晕），其余变化退为淡入。
- 热路径只动 transform、opacity、clip-path；虚拟列表内不做逐帧布局。侧栏与面板宽度是例外：它们由一个弹簧驱动，主列宽度提前锁定。
- 循环动画（运行标签的微光、细圈、运行中圆点）在不可见时暂停：离屏用 IntersectionObserver，窗口隐藏用 `document.hidden`。
- 每帧 JS 只做弹簧积分和少量 DOM 写入；读取集中在帧首。
- 验收：中档 Windows 笔记本上长回复流式期间 p95 帧时间 ≤ 16.7ms，单次长任务 ≤ 50ms。

## 5. 降低动效

- 跟随系统 `prefers-reduced-motion`，并在「设置 / 外观」提供三档：完整 / 简化 / 关闭。
- 简化：去掉所有位移、缩放与裁切，只保留 ≤160ms 的透明度变化；弹簧直接到位；晶格波、墨晕、飞入改为交叉淡入；运行标签不再扫光。
- 关闭：所有过渡与循环动画停止，状态直接切换；流式仍按节拍配速，但不显影。

- 过程行、思考窗口与任务回复可以展开；协作与 Git 面板打开时宽度正确，标签页切换正常。
- 文件修改流式：
  - `file_edit` 路径后到时，卡片先以「文件路径待接收」生长，再原位换成 `login.ts`。

  - 最终计数 +3 −6、+7 −1 与 Git 徽标一致；没有残留快照。
  - 托盘按批收回，逐帧记录的托盘卡片数依次为 1 → 0 → 1 → 2（同时显示「另有 1 项进行中」）→ 0；同时写入的两张没有逐张收回。
  - 流式期间逐帧检测 189 帧，可见行之间的覆盖为 0。
  - 展开后上一处 / 下一处可用；「按时间展开」下卡片直接可见。

- 舒适线之前滚动保持锚定，之后弹簧跟随；滚轮上滑后脱离跟随并出现「回到最新」，点击后回到底部。
- 以下路径都能完整运行：
  - 模型菜单的键盘选择；
  - 设置窗口的分页与主题墨晕；
  - 晶格波往返 IDE；

已在产品组件上确认（动效实验室，Edge 无头 1280×820，`motion-lab/checks/follow.cjs`）：

- 跟随：160 字/秒的流式，每 2.4s 一次 420 字突发。全程保持跟随，最大单帧滚动 36px，没有回退。突发落到视口下方时，最多落后 132px，约 0.5s 内回到视口。
- 滚轮上滑后立即脱离，内容继续增长时阅读位置不动，按钮出现。点击后经 30 多帧回到最新，接着跟随，按钮离开。

- 简化动效下末尾直接放好；全程无页面错误。

尚未验证，需要在实现时完成：

- LegendList 与尾部 FLIP 的同帧配合（P1 前）。
- Electron 中 View Transitions 的表现与超时回退（P3 前）。
- 真实模型流与长会话下的帧时间；无头浏览器帧率被限制在 30fps，原型的帧时间读数不能作为性能结论。
- 读屏器在换字、折叠和停止时的播报内容。WCAG 层面的完整结论需要辅助技术实测和专业无障碍评审。
