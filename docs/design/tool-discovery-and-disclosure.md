# 工具发现与按需披露：保留组合自由，按实际接口展开

状态：2026-10-29 设计提案，尚未实施。源码依据为 `89b7a3656`。

本稿接续[通用模式设计](general-agent-harness.md)的全模式发现原则，具体替换当前“搜索默认展开全部命中 schema、整组 full 后交给输出裁剪”的行为。设计覆盖内置工具、扩展、MCP 的发现与说明呈现，不改变各自的执行与权限归属。此处讨论工具披露；本轮体检发现的运行长停顿、进程输出游标和租约冲突需分别修复。

## 1. 设计判断

平台应让模型认识当前能访问的对象、可以执行的操作、可用的执行机制和连接服务，由模型组合这些能力完成任务。

工具发现的职责是定位真实接口，工具说明的职责是帮助正确调用。它们不承担任务分类、工作流编排、自动选工具或对用户目标生成一份“支持事项清单”。任务空间会持续变化，平台只需准确表达当前能力与契约。

这里的原子性指可组合、具有明确输入输出的真实操作。终端执行、脚本执行和应用操作可以很通用，不需要拆成大量针对单一任务的小工具。已有工具内部的操作可以分别阅读，但不会因此新增另一套执行端点。

设计需同时满足四件事：

- 模型能认识基础能力与扩展入口，形成自己的实现路径。
- 已经知道目标时能够直接取得用法或直接调用，不必走目录层级。
- 探索阶段只付出选择所需的信息成本，使用阶段取得完整、正确的相关契约。
- 同一实际工具只有一个执行与验证依据，披露视图从这个依据生成。

“少返回内容”本身不算成功。若模型少看一段却必须再猜三轮参数，披露质量仍然下降。

## 2. 当前问题及保留的基础

本轮体检中，Office 分组 full 返回 39,810 字节。进入下一次模型请求时，通用输出投影保留了 4/5 个工具，附带 `read_thread` 续读入口。原记录仍完整，但能力查找被变成了长输出阅读。

当前实现还有两个放大因素：关键词查询默认展开所有命中工具；每个详情重复附带通用调用教程、脚本调用教程、关联工具的完整描述和内部 metadata。Office 写入的创建与替换分支又各自包含整套格式定义。

应保留的基础已经存在：

- 请求拥有冻结的完整执行目录和较小的直接声明集合，两者职责清楚。
- `tool_describe` 支持名称、批量名称、搜索和分组；无需新增一组发现工具。
- `tool_invoke` 校验原工具的版本与参数，执行仍进入原生命周期。
- MCP 具有自己的直接工具、发现与调用入口，deferred 服务按选定依赖准备。
- 分组浏览已经能返回摘要；有效引用可以复用，不要求每次使用前重新发现。

改造应集中在信息组织与查询行为，而不是再建立一个“能力规划 Agent”。

## 3. 目录表达基础能力，分组只是索引

初始披露提供当前请求实际拥有的简短发现入口。直接声明工具已有完整参数，入口不会再重复它们的 schema。可按需取得的领域只说明覆盖的对象与操作范围；MCP 提示沿已有入口访问配置服务。

分组便于浏览，不决定任务该用什么，也不成为跨域搜索的边界。办公、科研、编程是产品侧重，不能变成平台能力的封闭分类。例如，办公工作可以使用文件、程序、脚本、应用和连接服务，不只包含 Office 格式工具。

查询“办公能力”时，呈现相关的底层入口及其范围，不生成“写报告、做表格、制作演示”等任务清单。格式操作、程序执行、应用控制与外部服务分别描述自己的实际能力；哪些入口被检索命中与全部可发现目录要在呈现上区分。固定 namespace 查询则明确表示浏览该分组。

同理，“截图”是一个查询词。搜索可命中实际具有捕获、观察或导出相关操作的接口；这些命中项不是完成截图任务的所有可能办法。通用执行入口不必为了某个查询被人工宣称成“截图工具”，模型已知的执行能力继续可用。结果可以直接转向其它范围或完整目录，不需要先接受一个预设场景分类。

分组及工具数量来自实际目录。新的扩展即使没有补充导航描述，也能以原始名称和说明被发现；不会因缺少人工分类而消失。当前按名称前缀分类的 fallback 可以保留为默认导航，扩展作者的明确归属应随其原声明贡献，避免只凭名称误导用户和模型。

配置启用、已发现、实际就绪是不同事实。目录可说明已知的条件，例如某项渲染需要组件；没有探测结果时不声称已就绪。搜索不扫描整台电脑或连接所有远端服务来凑齐状态。被用户排除的工具仍沿原选择规则处理，暂时缺少某项组件也不应抹去同一工具其它可用操作。

## 4. 一个入口，几种独立的阅读方式

继续使用现有发现入口。浏览、搜索、读取详情、读取具体操作是可直接选择的阅读方式，没有规定的先后顺序。

### 4.1 浏览与搜索

分组浏览和普通关键词搜索默认返回完整的候选条目：真实名称、简短用途、对象范围，以及确实影响选择的条件。每个条目提供直接取得详情的方式；当前可直调与需经通用入口调用的区别保持可见。

候选摘要来自声明者提供的简短说明。现有扩展没有简短说明时使用其原描述，不按字符数截掉句尾，也不由另一个模型改写能力含义。逐步整理内置工具的摘要，以“操作与对象”描述能力，不罗列面向人的任务场景。

名称完全命中时可以直接取得那个接口的用法，返回中说明这是名称命中。关键词只有一个结果，也不会因此自动猜测它就是用户任务的唯一正确选择。搜索、详情由查询意图决定，不依靠模糊的“置信度足够高”自动换一种响应。

工具名称、实际操作名、对象类型、说明和作者提供的常见说法共同参与搜索。支持大小写、标点和中英文常见术语归一；保留精确标识符检索。多个词用于相关性排序，不再一律要求整句中的每个词都在英文描述里出现。

搜索使用本地、随目录版本生成的轻量索引，不新增向量库、远端检索模型或常驻规划循环。术语关联帮助跨语言找到接口，不维护“一个用户任务应该使用哪些工具”的固定方案库。匹配结果多时按实际相关性和稳定顺序展示，并说明仍有结果；零命中只表达本次查询没有匹配，保留浏览与换词入口。

### 4.2 简单工具详情

普通工具按名称读取，一次返回完整调用契约。用途、参数含义与依赖关系、必要的结果语义、调用引用共同组成可用说明。

公共网关规则放在 `tool_describe` / `tool_invoke` 的入口描述中；脚本环境的通用调用规则放在脚本环境说明中。每项详情只保留当前目标的调用入口与真实差异，不复制长教程。关联工具默认给名称与简短关系，例如“读取返回的对象可用于编辑”，不展开整组说明。

参数、版本和约束来自原声明。内部服务 ID、实现版本、调度 metadata 不进入通常的模型阅读视图；开发与诊断确有需要时仍由原契约检查入口提供。会影响正确使用的版本前提、对象身份、单位、状态和结果续读语义必须保留。

### 4.3 复杂工具详情

复合工具先展示自身真实的操作结构、共同参数与重要约束，模型可以直接选择具体操作，也可以主动取得整个契约。结构目录列出完整的顶层操作范围，不因当前任务而隐藏分支。

例如 `office_write` 本身已有创建、替换、编辑以及格式分支。第一次查看时能够认识这些真实操作；已知要查看哪一项时可在同一次查询直接指定，无需先取得菜单。展开后的说明包含该选择下全部需要的参数和约束，仍调用同一个 `office_write`。

这与“创建一份周报”“生成某种汇报”的任务模板不同：操作来自现有 schema，模型可自由组合内容、执行脚本或选择其它入口。工具没有离散操作分支时，不强行为它建立一套任务菜单。

公共结构应从同一份构造定义复用，避免创建和替换各复制一次所有格式细节。实现时先支持内置工具声明中已有的明确分支；说明视图与实际校验使用相同构造来源。选定分支的说明必须保留共同约束、相关引用定义、条件依赖和其它仍合法的选项。

第三方任意 JSON Schema 不能仅凭字段名被推断成可拆分的操作。能够准确保留语义时按结构阅读；没有可靠分解依据时保留原契约，并提供其真实结构定位。不会靠一个通用删字段算法生成看似完整、实际不正确的参数定义。

## 5. 输出应由披露层组织好

发现结果应该在进入通用长输出裁剪前完成组织。使用现有可见输出预算决定一次容纳多少内容，不新增任意工具个数、调用次数或并发上限。

组织单位按内容性质确定：

- 搜索与目录按完整候选条目分页。名称、用途和继续入口一起出现，不出现半个候选。
- 多个明确工具的详情按完整工具说明分批；已指定的目标及尚未展开的目标保持可见。
- 复合工具按真实操作或结构节点展开；完整的参数分支不被当成长字符串从中间截断。

实际序列化后的体积用于检查本次响应，给已有通用信封和必要导航留下空间。普通披露不应再次被通用投影剪成一份残缺 schema。输出预算极低或第三方单一结构本身过大时，明确返回结构索引及精确阅读入口，标明当前是概览，不能将它伪装成完整调用说明。

跨页按原冻结目录和查询排序继续。新请求中目录或版本已发生变化时，说明范围变化并允许重新查询，不把两代工具参数拼接在一起。可复用现有不可变内容与版本身份，不新增永久保存的披露账本。

显式请求整组完整说明仍可满足，但按完整说明组织，不一次构造大表再让 `read_thread` 补救。`read_thread` 保留历史原文阅读职责；查找工具参数沿发现入口本身继续。

正常路径的标准是：模型选定一个常规操作后，就获得足够调用的完整说明。目录规模大和外部契约极大可以需要继续阅读，继续单位应是有含义的接口内容。

## 6. 常驻声明、记忆与模型自由

各模式继续决定常用工具的直接声明，用户的显式选择继续生效。本次设计不通过把所有工具隐藏起来换取更短的前缀，也不向模式加入强制发现流程的提示词。

已有可调用工具不必先查目录；已有有效说明与版本引用可以继续使用。模型可以一次查询多个目标、直接指定操作、在脚本中组合工具，也可以选择通用执行能力。发现结果不要求额外撰写理由、声明计划或完成固定检查。

目录摘要与说明视图按声明版本生成，只有实际目录变化时更新。请求准备复用已冻结的目录、查找索引与说明，不逐请求重建大型字符串。短暂就绪状态通过当前查询结果表达，不作为持续变化的系统前缀。

披露结果仍是普通工具历史；不因读过某个工具就动态把它插入 provider 函数列表，不另建“已学会工具”的持久状态。历史被压缩后，模型可以利用保留的真实引用继续调用，或自行重新查询。过期引用由原执行 owner 给出针对该工具的修正入口，不触发整目录重新加载。

## 7. MCP 与扩展采用同一阅读原则，保留原入口

已经直接声明的 MCP 工具继续直接调用。原生完整目录中的 direct MCP 工具可按名字或搜索定位；目录需明确 MCP 发现入口的覆盖范围，避免让无 namespace 的 MCP 条目在顶层导航中失去出处。

deferred / codemode 服务沿 `mcp_discover` 和 `mcp_call` 工作，不增加必须先经过 `tool_describe` 的步骤，也不为它们建立第二套调用代理。

MCP 发现采用相同的信息粒度：服务浏览使用已配置元数据；选定服务后工具发现默认提供候选摘要；已知具体工具时可直接取得其契约。选定服务的协议枚举可以由 owner 获取完整目录，但不因此把所有 schema 一次灌进模型结果。

全局查找可索引当前已经持有的 MCP 描述及配置元数据，并给出原 MCP 入口。未连接服务的内容保持“尚未发现”，不会因为查询无命中被说成没有相关工具。搜索不为补全所有结果而启动所有服务。缓存描述可帮助定位；可执行的版本引用仍由实际 retained MCP owner 核验。

扩展可在原工具声明旁提供简短说明、搜索别名和原操作的阅读结构。缺少这些信息时仍保留原名称、描述和 schema 的发现路径。声明内容随原 generation 固定，索引不对远端说明赋予额外权限，也不将说明中的文字执行成动作。

这些规则作用于所有模式及可用同一目录的子任务。MCP 资源与 prompts 沿已有发现、分页和读取入口工作，资源正文不混进工具参数目录。

## 8. 实际体验示例

以下说明查询行为，不作为匹配模板或模型必须遵循的流程。

| 情况 | 披露行为 |
| --- | --- |
| 泛问办公能力 | 展示相关底层对象操作、执行机制与服务入口的简短范围；不输出一张办公任务支持清单 |
| 查询截图 | 返回当前索引中的相关真实接口，说明命中范围；不把少数场景包装为全部方法，也不替模型选择 |
| 已知一个普通工具 | 直接取得完整用法；若已在请求声明中且用法明确，可直接调用 |
| 已知复合工具和操作 | 一次读取该操作的完整参数及共同约束，不先走分类菜单 |
| 了解一个复合工具的整体能力 | 展示其真实操作结构，再由模型决定查看全部或某一部分 |
| 明确需要几个工具 | 一次请求这些工具，去除公共重复；体积过大时以完整条目继续 |
| 工具需要的组件当前缺失 | 准确显示该操作的条件；已具备条件的独立操作仍可使用 |
| 已配置但尚未连接的 MCP | 可发现服务元数据，选定后由原 MCP owner 获取工具；不在后台全量连接 |
| 外部工具没有优化过的说明 | 原契约仍可查询，名称与原描述仍参与搜索 |
| 没搜到匹配 | 表达当前范围的零命中，保留浏览与改词方式；不替整个任务下不可执行结论 |

## 9. 实现归属与交付完整性

设计实施应作为同一条披露链交付，不能只把搜索结果改短而让详情继续输出巨表。

| 责任 | 实现位置与工作 |
| --- | --- |
| 常驻发现入口、原目录身份与直接声明 | `tool_disclosure.rs`：精简通用说明、保持直接调用边界，索引来自实际选择 |
| 查询、摘要、详情与分页 | `capability_tools.rs`：搜索默认候选、明确名称直达、批量详情、完整条目输出与继续读取 |
| 真实工具阅读结构 | 原工具声明及共享构造：补齐简短说明和实际操作导航，复用公共结构，保持校验语义 |
| 扩展贡献 | extension contract / Host 装配：将可选披露描述随原 schema 和 generation 固定，不建立独立注册表 |
| MCP 发现 | 原 MCP owner 与协议声明：服务及工具级筛选、摘要/详情、版本与来源，复用原发现和调用 |
| 模型可见结果 | 现有输出投影与历史：验证披露响应未被二次裁坏，保留可核对的原内容与正常续读 |
| 文档与旧测试 | 更新 runtime、MCP 与相关模块说明；替换“搜索必带全部参数”的旧断言 |

先从一个冻结目录中的实际声明建立索引与阅读视图；再贯通查询结果、调用参数和原执行验证；最后用真实内置复合工具及 MCP 验证全链。复用已有目录和内容所有权，不引入工具推荐服务、任务知识图谱或新的数据库。

实施的必要验收集中在以下行为：

1. Office 目录和广义搜索返回可选择的完整条目，不重复出现整组 schema；明确读取操作后能实际调用成功。
2. 中英文、名称与操作词检索可定位同一真实工具；零命中、部分匹配和全部目录保持含义清晰。
3. 操作说明与原 schema 对同一选择接受和拒绝一致；公共必填项、条件约束和引用定义不会丢失。
4. 大量工具、小输出预算和批量读取按完整条目继续，不靠从历史中拼半份契约；版本变化可识别。
5. 直接调用、通用调用及脚本嵌套调用仍使用同一真实目标；已经有效的引用无需重新发现。
6. MCP 无服务浏览不连接服务器；选定服务可直接取得指定工具，未发现内容不产生虚假的完整性结论。

文档阶段核对设计与源码事实、相关链接即可。实现阶段沿现有行为测试验证上述风险，不建设新的评测平台，不以固定调用轮数或 token 配额替代可用性判断。
