# 设置设计稿（2026-11）

直接用浏览器打开 `index.html`。数据都是虚构示例，所有操作只停留在页面里：不连接 Host，不保存凭据，不发请求。底部的原型实验室用来切换浅色 / 深色、桌面 / 窄窗口 / 手机、本机服务 / 远程服务和动效，它不属于产品。地址栏加 `#页面名`（例如 `#model-roles`）可以直接打开某一页。

本稿接替 [设置体验](../chat-settings-experience.md) 和 `settings-redesign.html`。颜色只用应用现有的主题令牌，导入的主题可以直接套用。

## 已定的方向

1. **整窗设置。** 打开后接管主画布，标题栏保留，左边换成设置导航。「返回」或 Esc 回到原来的位置。不再是盖在对话上的弹窗。
2. **按要管的东西分组**，7 组共 36 页。宽窗保留设置导航、对象目录和详情。窄窗通过顶栏「设置」回到导航，给目录和表单留出宽度。再缩窄时，目录和详情分步打开，较长的编辑控件移到标签下方。
3. **只用四种页面骨架**，每种对应一种保存方式：

   | 骨架 | 用在 | 保存 |
   | --- | --- | --- |
   | 偏好表单 | 通用、聊天、上下文、浏览器 … | 改动立即保存，页头短暂显示「已保存」 |
   | 对象目录（左列表、右详情） | 模型服务、Agents、Varin、项目、技能、MCP、设备 | 普通字段立即保存；连接信息先测试再保存；长正文在编辑单元里显式保存 |
   | 正文编辑 | 指令、技能正文 | 底部悬浮保存条 |
   | 概览 | 用量、存储、设备 · 连接关系 | 只有展示和操作，没有表单 |

4. **分组浮层表单。** 内容列宽 780 px，相关的几行放在同一块浅色面板里，标签和控件离得近。层级靠面板和间距表达，不靠加粗、加大字号。
5. **作用范围明确标出。** 页头用一个标签说明设置保存在哪里：此设备 / Varin 服务 · 名称 / 项目 · 名称。在原型实验室里切到「远程服务」，可以看到标签跟着变。

## 这次新整理出来的两件事

- **模型分工集中查看，功能页就地修改。** 例如在「网络与文档」可直接换挑选搜索服务用的模型，改动同步到「模型分工」。两个入口保存同一项选择，按服务商和模型识别，同名模型会显示服务商。功能开关留在各自的功能页，「模型分工」显示开关状态并链接回去。「模型服务」里的「用于…」可跳到对应分工。
- **设备按机器组织。** 「设备」用三个角色说明一台机器在 Varin 里做什么，分别是「运行 Varin 服务」「用来打开 Varin」「供 Agent 使用」。「远程访问」和「网络代理」跟随所连接的服务，各有独立入口。

## 设备

- **列表**汇总每台设备的角色。置顶「连接关系」，中间是当前服务，两侧是客户端和 Agent 使用的设备。列表底部可从已发现的 SSH 主机添加设备。
- **详情**用角色卡片切换设置，手机宽度收成横排标签。可以点开尚未配置的角色查看接入方式。
  - 运行 Varin 服务：当前服务显示连接状态和远程访问、网络代理入口，其他服务提供切换和连接设置。示例中的 `home-server` 有两个实例，各用自己的地址和连接配置。桌面版「打开时在本机启动服务」也在这里。
  - 用来打开 Varin：这台设备正在用哪个客户端、连到哪台服务；其他设备显示连接方式（局域网 / 中继）、最近使用和撤销。
  - 供 Agent 使用：连接方式、文件与命令、电脑操作和浏览器。服务默认目录、命令行和隔离工作副本组件在提供文件的设备上配置。
- **添加设备**：先选想做什么：在它上面用 Varin（和「远程访问」共用同一个配对面板）、让 Agent 使用它（SSH 或运行 Varin 服务）、连接它上面的 Varin 服务。
- **关联**由用户确认。以 `home-server` 和同地址的 SSH 连接为例，两条记录可归在同一台设备下，也可拆开显示。工作位置始终引用原连接和目录。
- **工作区**按位置列出设备和目录，项目目录与单独保存的文件夹都可使用。普通新会话可选起始位置，默认沿用服务目录。「会话示例」可体验临时读取另一位置的日志，再把那里设为后续工作的起点。
- 会话输入框下方的文件夹入口显示工作位置。无项目且未指定位置时显示「默认」，从项目发起或显式切换位置时显示「设备名 - 项目名或目录名」。展开可以查看路径和切换位置。
- 「添加设备」分别呈现客户端配对、资源节点接入和连接其他 Varin 服务。轻客户端、资源节点发行方式及单轮跨位置操作为本稿设计场景。
- **浏览器、电脑操作移到「能力」组**，按设备分组列出，每组可以跳回设备详情。

## 远程访问与网络代理

- **远程访问**按访问方式组织：局域网、Varin 中继、临时隧道（测试版）、公网访问（测试版）各占一行，显示状态，点开就是它的设置，可以同时开启几种。
  - 局域网：允许同一网络的设备打开（桌面版，会重启）、访问地址、运行时保持电脑唤醒；没有界面密码时提示风险。
  - Varin 中继：启用 / 停用，说明端到端加密和「只走中继的设备不能给 Agent 当工作设备」。
  - 临时隧道：提供方（Cloudflare / ngrok）、隧道类型（快速 / 托管 · 远程 / 托管 · 本地）、已保存的托管隧道、配置文件、连接链接和远程会话的有效期；启动后显示一次性连接链接、二维码和已兑换的链接。
  - 公网访问：已有 HTTPS 反向代理或 FRP（服务器、token、frpc 组件），先保存配置、再单独开放。
  - 下面依次是已授权的设备（连接方式、上次使用、撤销、清除已撤销、全部登出）和登录保护（界面密码、Passkey）。页头「配对新设备」展开配对面板：先选这台设备在哪里用（仅这台电脑 / 仅家里的网络 / 任何地方），再生成一次性二维码。
- **网络代理**恢复为单独一页：自动 / 直连 / 指定代理，指定时填地址和例外，在服务上测试。

落地时后端需要补的：

- 跨角色的设备标识。现在三个来源互不相干：这台设备上的服务目录、服务上的已配对设备、服务发现的 Agent 资源（SSH、远程代理、浏览器扩展、桌面）。需要一个把它们归到同一台机器的标识，以及合并 / 拆分 / 「不是同一台」的持久记录。
- 合并建议的依据，例如地址、主机名、配对时上报的机器信息。
- 浏览器和桌面资源要能说明自己属于哪台设备，「能力」页才能按设备分组。
- 设备列表只覆盖当前连接的服务能看到的设备，加上这台设备服务目录里的其他服务；切到另一台服务时，原服务管理的设备不显示（原型里切到「远程服务」可以看到提示）。

## 第二轮修改（2026-11-18）

- **聊天、外观恢复实时示例。** 两页共用一个示例，分「对话 / 文件与图表 / 输入」三个场景，左边每项设置都会反映在示例里。桌面宽度时示例常驻右侧；窄窗口和手机放在表单上方，可以收起。示例内容沿用应用现有的 `validate.ts` 示例。
- **语音补齐控件，模型改成卡片。** 补回朗读的声音来源（浏览器 / Varin 服务本地 Kokoro / OpenAI / 自定义服务 / macOS 系统朗读）及各自字段、声音和试听、语速、音高、音量、朗读内容；识别分「Varin 服务本地识别」和「识别服务」，后者有地址、密钥、模型、静音阈值和停顿时长。上一版把本地识别写成「在本机识别」，实际是在 Varin 服务上转写，已更正。识别模型改为两列卡片：先选主要说的语言，不支持的模型排到后面并变淡；选中未下载的模型会直接下载并换上，不再分「下载」和「设为使用」两步。
- **「规划」改名为「执行循环的规划」。** 它对应 `harness.models.agentPlanning`，只在插件提供的执行循环声明需要规划时使用，和上下文无关。上一版把它放在「上下文 · 由谁整理」下面，容易误解，已移走：在「模型分工」里单独放进「插件」一组，并在「插件 · 执行循环」选了非默认循环时出现。「模型分工」里的「上下文整理」可以直接调整思考等级，和内置 Agent 共用一项配置。点模型名可以打开 Agent 详情。
- **权限加入「智能判断」。** 三种确认方式为先问我、智能判断、直接执行。选智能判断时显示权限判断模型，「模型分工」也会标出用途是否启用。已有规则优先，模型只评估未命中的普通工具调用。
- **MCP 改成目录。** 左边按配置来源（全局 / 项目）分组，置顶「配置文件」；右边是一台服务器的连接状态、连接方式（先测试再保存）、登录、工具调用方式和单个工具覆盖、服务描述。

## 文案

- 页面描述只用一句话，说明这页决定什么。
- 行说明只写会影响理解或有后果的内容，例如「保存配置不会立刻开放访问」。
- 实现细节不进正文，例如「保存到当前 Agent 主机的全局设置。已有项目覆盖仍优先生效」改成页头的范围标签，悬停时再说明。
- 用用户的说法：「Harness 工具」→「工具」，「执行 Host 的出站网络」→「网络代理」，「relay」那段说明改成「你的设备能连上 Varin 服务，不代表 Agent 能使用这台设备上的文件」。
- 原界面里没翻译的英文条目（快捷键名称、编辑器工具栏、`agents` 导航名）都补上了中文。

## 没有改的

所有控件和功能入口都保留，没有为了好看合并或藏起来。「上下文 · 回复卡住时」那组设置目前不生效，照样保留，并标出「暂未生效」。模型服务按 2026-11-03 已定的左右分栏、先测试后保存来做。外部 Agent 页沿用 `external-agents/` 设计稿的生命周期管理，这里只调整了外观，让它和其他页一致。
