# 浏览器独立资源设计

Varin 应能连接任意部署位置的浏览器，包括用户正在使用的浏览器。前端、Application Host、Harness、文件工作区和浏览器分别选择位置；浏览器连接沿现有设备与 managed-host 体系建立。浏览器操作、页面预览和用户接管共同指向同一真实页面。

本文描述目标设计。已落地能力与仍有限制的提供方见[浏览器资源](../resources.md#浏览器资源)；下文的实施顺序和跨设备场景仍作为验收依据。

## 现有实现与调整位置

模型浏览器工具由 `computer-service.ts` 的 `applicationBridge` 路由，当前身份依赖 `desktopId`。已有远端 Host 转发，Linux 驱动的 `browser_bridge.py` 实现 CDP 操作；Windows 和 macOS 驱动目前没有声明这项浏览器能力。工作台 `BrowserResourceView` 则承载本地 Electron 浏览器或网页预览，它与模型控制的页面尚未形成独立、跨设备的浏览器资源身份。

调整首先发生在资源发现、身份与路由。现有 Linux 桌面浏览器继续作为一个浏览器资源被发现；浏览器服务也可以由其他设备连接提供。Harness 请求资源时不再需要先选择整台桌面。

## 资源归属

设备连接提供浏览器能力。浏览器 owner 负责启动或连接实例、报告实际存活状态，并执行操作。Application Host 负责目录、任务绑定与跨连接路由；前端负责展示和操作入口。凭据、配对、转发和远端身份继续归现有连接 owner。

| 对象 | 含义 | 生命周期 |
| --- | --- | --- |
| 浏览器资源 | 某个连接提供的浏览器能力与展示名称 | 跟随资源登记；离线时保留登记 |
| 浏览器实例 | 实际连接的浏览器进程或服务端会话 | 由浏览器 owner 确认建立和结束 |
| 用户配置 | 浏览器自身保存的登录、扩展及偏好 | 留在运行浏览器的设备上 |
| 标签页 | 实例中的真实页面及其当前代际 | 关闭、重建或重新连接时核实身份 |
| 任务绑定 | 某项工作选用了哪个浏览器、实例和页面 | 归原工作与资源分配记录 |

内部连接 ID 用于路由；模型看到浏览器名称、设备名称、页面标题、网址和简短引用。界面显示“办公室电脑 · Chrome”“云端浏览器”等可读名称。

浏览器配置不能与工作区路径绑定。任务可以在云端 Harness 修改远端工作区，同时操作办公室电脑上已经登录的网页。

## 连接用户现用浏览器

提供两种明确的连接方式，它们进入同一浏览器目录，保留各自真实能力。

**连接现用浏览器。** 用户通过浏览器扩展或浏览器自身提供的受支持连接能力，将现有实例连接给 Varin。扩展通过现有设备连接传递操作与事件，页面身份来自实际标签页。登录状态保留在原浏览器中，Varin 无需复制配置或建立另一份网站凭据。

**启动或连接独立实例。** 浏览器 owner 可启动使用指定配置的实例，也可连接用户提供的 CDP 服务。浏览器运行时由该设备或服务提供；桌面安装包沿现有能力复用已安装浏览器。

不能把“连现用 Chrome”直接实现成给默认配置附加调试端口。Chrome 从 136 起不再对默认用户数据目录接受 `--remote-debugging-port` 和 `--remote-debugging-pipe`。因此现用浏览器优先考虑扩展连接，专用实例则可使用独立配置与 CDP。[Chrome 官方说明](https://developer.chrome.com/blog/remote-debugging-port?hl=en)

扩展的调试连接需要浏览器声明的权限，并可能被用户操作或开发者工具断开。owner 必须观察真实 detach 事件，向任务报告连接变化。[扩展调试 API](https://developer.chrome.com/docs/extensions/reference/api/debugger/)

## 工具与工作台的关系

浏览器工具沿现有 tools owner 暴露资源选择、标签页管理、观察、操作和文件传输能力。已有工具名称和参数需要一次完整调用链调整，避免同时长期维护桌面浏览器与独立浏览器两套执行语义。

观察返回页面标题、网址、页面结构和本次可用引用；操作使用同一页面及观察代际。用户导航后，旧元素引用按实际页面变化失效，模型重新观察。远端浏览器也执行同样的协议，前端所在设备不会改变页面身份。

现有工作台浏览器入口继续承载预览与交互。绑定远端浏览器时，工作台显示该实例的真实画面或明确的观察视图；仅有结构观察能力的连接直接展示其能力。用户选择“在浏览器中打开”时，打开的是所选资源上的页面。

下载保存在浏览器设备，随后经现有 Files、Documents 与附件交接能力进入所选工作区。上传从选定文件来源传输到浏览器 owner。跨设备操作显式经过原文件 owner，路径始终带来源。

## 操作与用户接管

资源卡显示当前页面、连接情况和正在使用它的任务，入口仍放在现有资源区和工作详情。连接现用浏览器时，用户可选择交给任务的标签页，也可主动扩大操作范围；浏览器级操作范围由这次连接的实际授权决定。

用户接管时，原浏览器 owner 暂停该任务的新操作准入，并结算已发出的调用。界面继续展示实际页面和任务，用户完成操作后可以让任务继续。任务重新观察页面，再根据当前内容决定下一步。用户在原浏览器中导航、关闭标签页或停止扩展连接，都会作为真实事件返回。

同一页面上的自动化操作经原资源分配 owner 协调；不同标签页可按连接能力并行。多个任务同时需要同一页面时，界面呈现实际占用和等待者，用户可切换。占用释放依据执行结束或 owner 确认，不以预览窗口关闭作为释放依据。

## 远程连接和恢复

远端连接复用 managed-host 的完整来源身份和既有转发通道。浏览器 owner 可以随设备 Host 部署，也可以作为现有连接可访问的独立能力提供方；资源协议不要求与 Harness 或工作区同进程。

连接状态区分：未连接、正在连接、在线、连接中断、实例结束和等待用户接管。离线保留原资源与任务绑定，向 Bot 返回明确的连接事件。连接恢复后，owner 核实实例、配置与标签页的真实身份，继续原任务或报告原实例已结束。

已经发出的提交、付款、发送消息等操作，断线时可能执行成功却未返回结果。原操作保留“结果未知”及已有观察，由任务检查实际页面或业务结果后继续；重连本身不重新发送该操作。这个执行语义沿用 Varin 原有调用回执与恢复机制。

## 实施顺序

1. 从 `desktopId` 路由中提取浏览器资源、实例和标签页身份，先让现有 Linux 浏览器走完整的新路由，并保留当前能力。
2. 接入用户现用浏览器的扩展连接，以及独立 CDP 实例连接。设备配对、跨 Host 路由、资源占用和文件传输沿已有 owner 接入。
3. 让现有浏览器预览、任务资源区和接管入口使用相同绑定；补齐连接中断、页面变化与任务恢复呈现。

验收覆盖“本机前端＋远端 Harness＋另一台设备的现用浏览器”、多个标签页分工、用户接管后继续、跨设备上传下载，以及动作发送后断线。每条链路都要确认展示的页面就是任务实际操作的页面。

## 需要在实现时确认的平台细节

扩展连接要验证 Chrome、Edge 等目标浏览器对调试、下载与后台生命周期的实际支持；开发者工具造成的 detach 必须进入原状态链路。仅支持部分操作的连接按能力声明提供工具，模型和界面都能看见具体缺项。

浏览器提供方能力接入点应与现有设备能力声明一致。实现前沿 `computer-service.ts`、设备连接、BrowserResourceView 和 tools owner 确定最终协议位置，再提交接口；独立部署能力不意味着每个浏览器必须单独启动一个服务。
