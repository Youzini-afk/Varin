# Web 与科研检索：连续探索、原文阅读与协作复用

Status: accepted design / implemented through L5 (D-315, Stage L); L0–L5 are wired, with L6 workbench/settings closure tracked in status

Last updated: 2026-09-23

本文记录 Web search 与科研搜索讨论的设计结论。实施顺序见
[阶段 L](../archive/agent-harness-plan-2026-10-06.md#阶段-lweb-与科研检索d-315)，实际交付只记入
[能力状态](../status.md)。复用 [Harness](agent-harness.md)、
[科研集群](research-cluster-design.md) 和 [快速决策模型](fast-decision-model-design.md) 的现有生产通路。

## 1. 产品目标

搜索应帮助 Agent 更快发现有价值的问题、理解已有工作、形成判断并推进实践。具体成果可能是一个准确答案、
一组可比较的机制、某个失败原因、可复用代码，或下一项实验需要的参数；输出长短由用户任务决定。
来源可回读用于支持这些工作，不能反过来要求所有任务先完成证据表、固定研究流程或长报告。

通用 Web 与科研搜索共用发现、读取、展开、保存和复用的基础设施。科研增加论文身份、引文关系、段落检索、
图表/附录与代码/数据材料，不把所有研究简化成“找几篇相关论文”。工作侧重可以影响工具指导与优先材料，
不决定用户是否有权使用搜索；Agent、IDE、Research Workbench 使用同一能力，不增加强制研究入口或界面切换。

重要使用场景：

- 已知事实或官方文档：尽快找到准确位置并读到相关内容。
- 开放问题：用不同表达、来源和视角发现相近机制，允许新材料改变原问题。
- 科研调查：沿论文前后关系找到奠基工作、后续改进、相反结果与适用条件。
- 实践推进：从论文继续追到附录、代码、数据集、issue 和运行说明，取得实际操作需要的信息。
- 持续工作：后续讨论、实验与写作能够复用先前读到的材料，并按需要检查新变化。

## 3. 调研结论及证据边界

本节来源于本地代码阅读和 2026-09-22 的官方资料核验，未对付费服务做质量、延迟或成本对比。
项目名称是机制参考，不代表引入整套依赖或将宣传指标作为验收条件。

### 3.1 smartsearch

参考 [konbakuyomu/smartsearch](https://github.com/konbakuyomu/smartsearch)，本地检出提交
`916743469d8abf8d6eae300170d2bfd61fae4949`。关键实现是 `src/smart_search/service.py`、
`jev_search.py`、`jev.py`，说明见该项目 `docs/guide/zh-CN/research.md`。

- 普通 search 执行主搜索与可选补充渠道；deep 是离线计划；普通 research 执行发现/读取/整理。
  普通 research 的 gap check 主要按是否取得正文及错误记录收口，没有真正的多轮补检。
- 只有显式选择 Jev 路径才进入候选动作选择、并行调用、材料评估的迭代循环；默认 hybrid 不等于默认 Jev。
- Jev 候选查询来自原问题、离线拆分与固定缺口后缀。判断器不能选择候选池中不存在的新表达，
  因而候选生成和可见材料构成上限，不能仅靠更强的判断器突破。
- 能力路由、来源与模型答案分离、CLI/Skill 渐进披露值得借鉴。其固定数量/轮数/URL 截断、
  最低配置组合和独占 CLI 策略不直接移入 Varin。

### 3.2 可借鉴的机制

| 参考 | 相关机制 | 采用边界 |
| --- | --- | --- |
| [Exa](https://exa.ai/docs/reference/search)、[Parallel](https://docs.parallel.ai/search/search-quickstart) | 面向目标检索、相关正文片段、不同查询深度 | 适配真实 API；已合成答案与原文摘录分开；供应商延迟不是 Varin 承诺 |
| [Jina DeepSearch](https://github.com/jina-ai/node-DeepResearch) | 搜索、阅读、推理交替，按发现调整动作 | 复用 Pi Agent loop，吸收探索方法，不植入第二个研究 runtime |
| [Open Deep Research](https://www.langchain.com/blog/open-deep-research)、[Anthropic Research](https://www.anthropic.com/engineering/multi-agent-research-system) | 独立问题并行、子上下文隔离、汇总后继续调查 | 委派按任务价值；不把所有搜索或章节写作固定拆成多个 Agent |
| [Sciverse](https://github.com/opendatalab/Sciverse-Agent-Tools) | 字段目录、元数据搜索、段落语义检索、引文、分段原文和图表 | 可配置学术适配器；全文权限/覆盖按实际返回，字段按需发现 |
| [Semantic Scholar](https://www.semanticscholar.org/product/api)、[OpenAlex](https://help.openalex.org/how-to/api-recipes/) | 论文身份、引用/参考文献、相关工作与开放材料位置 | 用于发现与元数据；不把每条记录当作已读全文 |
| [PaperQA2](https://github.com/Future-House/paper-qa) | 论文解析/索引、问题相关段落、可复用阅读结果 | 借鉴阅读和检索粒度；无需复制它的 Agent/配置/数据库 |
| [OpenScholar](https://www.nature.com/articles/s41586-025-10072-4) | 专用段落库、学术 API、Web 互补，重排和反馈补检 | 专门语料与多入口具有价值；论文数据集快照不等于实时全网，基准排名不外推到本产品 |
| [STORM / Co-STORM](https://github.com/stanford-oval/storm) | 从材料发现视角、持续追问 | 让提问受新发现影响，不强制模拟专家会议或生成百科文章 |
| [Search-R1](https://github.com/PeterGriffinJin/Search-R1)、[Tongyi DeepResearch](https://github.com/Alibaba-NLP/DeepResearch) | 可训练的多轮搜索策略 | 后续训练研究；生成式搜索策略与候选判别模型分别评价 |
| [Docling](https://github.com/docling-project/docling/blob/main/docs/concepts/docling_document.md) | 章节、阅读顺序、图表和位置结构 | 结构化解析候选，不要求所有页面经过重型模型 |

综合取舍：宽召回、可读原文、灵活补检与材料复用共同决定效果。不能把来源数量、完整报告、
引用存在或模型“足够了”的分数单独作为任务已解决的判断。

## 4. 共用搜索与工具披露

### 4.1 保留目标，直接表达需要

普通 `websearch(query)` 继续直接调用搜索，不强制多一次分类或启动子线程。复杂请求可以补充自然语言 objective，
说明想判断什么、已有信息和当前缺口。用户给出的明确日期、域名和材料范围属于约束；模型推测的偏好只是建议。
不要求模型逐次填写意图枚举、置信分数或研究计划表。

同一需求可产生不同 query：原话、术语/别名、机制描述、相近领域表述或从新材料中提取的名称。
主 Agent 或当前检索线程按需生成这些表达；快速决策模型选择/排序候选，不能冒充自由文本生成器。
精确查找、已知 URL 和资料已经足够的情况无需额外生成式改写。

### 4.2 渐进披露的工具面

保留容易理解的基础搜索与读取工具，学术能力按任务发现并装配。以下是操作职责，不锁定最终新增工具名：

| 操作 | 初次返回 | 后续按需展开 |
| --- | --- | --- |
| 搜索 | 标题、URL/材料引用、相关摘录、来源类型、可用日期、实际 provider | 分页、其他 query、原文阅读、相关来源 |
| 阅读 | 原文片段、文档/修订身份、位置、可见范围与未读部分 | 章节/页码/行段、相邻段落、全文、图表 |
| 学术查询 | 论文身份、题目、作者/年份等可得字段、摘要/全文可用情况 | DOI/版本、参考文献、引用者、相近论文、关联代码/数据 |
| 材料内检索 | 在明确集合中命中的段落与位置 | 固定来源的上下文、原文图表、重新检索该集合 |
| 能力查询 | 当前可用渠道及其支持的操作 | 支持字段/筛选/分页、配置说明与示例 |

简短稳定提示说明“何时搜索、怎样展开、已有检索线程可委派”；实时可用性、schema 和字段由查询工具返回。
组合方法可通过按需指南披露，不将服务商所有参数和论文检索教程灌入每个会话，也不以新建 Skill 文件作为交付要求。
一个查询工具存在，不意味着 Agent 已经知道它；提示发现入口、真实 tool schema 与可用状态须一起接线。

独立 query/URL 允许批量并行，每项保留自己的结果和错误。分页/读取入口是输出组织方式，不是材料总量硬限制。
部分渠道失败时先返回已有结果，避免整批重做；取消传递到真实网络/读取与模型调用。

### 4.3 能力与提供商

Host 适配器描述支持的操作、筛选精度、正文/摘要形态、分页、刷新与实际平台条件；工具表面不要求用户记住提供商名字。
学术查找和网页阅读可能由同一 provider 提供，不用互斥的硬分类阻止它发挥真实能力。
简单查询优先当前选定路径；按目标补充互补来源，显式查询也能直接选定可用渠道。

默认免密钥 Web 路径继续沿 D-289；用户配置、禁用与 provider 选择保持有效。新增多渠道配置复用设置目录和原凭据 owner，
不复用聊天密钥去探测搜索服务。失败切换是同类可用能力的执行策略，主动扩检是寻找新材料，两者分开记录。
空结果、未配置、访问不到全文、限流和失败分别返回；提示性日期/领域偏好不能假称严格过滤。

不要求配置主 LLM、文档搜索与读取三种付费服务才允许搜索。provider 自身返回的合成回答标为派生内容，
其 citations 可作为后续入口；若 provider 已返回带定位的原文，可直接使用，无须为了形式再 fetch 同一内容。

## 5. 材料身份、阅读与复用

### 5.1 一个内容基础，多种材料视图

沿现有 Host 来源、receipt/artifact、Rust 对象与记录 authority 关联材料。语义上区分：

- **来源**：网页、论文及版本、代码或数据入口。DOI/arXiv/provider ID 等是别名和关系，URL 不总是作品身份。
- **内容快照**：实际取得的字节/提取正文，保留获取时间、内容 hash、解析方式与修订身份。
- **可读位置**：快照内页码、章节、段落、行范围或图表引用。位置绑定快照，不能在刷新后指向另一段文字。
- **派生材料**：模型摘要、相关性判断、归纳和笔记，关联原文与产生它的任务；不覆盖原文。

这些是职责边界，不要求新建四套存储或数据库。`research_source` 继续表达持久材料登记，通用读取视图与来源核对共用内容对象。
登记不等于取得正文；只读到摘要要标清，不把元数据存在当成阅读全文。

可信标识符/元数据可帮助合并同一作品；题目相似只是候选。预印本版本、正式发表版、主文和补充材料保持可区分，
不凭模型相似分数永久合并。引文和“方法类似”等推断关系也应分开，不能把语义共现写成真实引用。

### 5.2 读取粒度与结构

HTML 和 PDF 都从固定来源读取。正文片段、搜索 snippet、出版摘要和模型总结标明各自的来源类型；
先展示相关原文及继续读取的位置，可选 reader 的回答保留能回到原文的引用。

PDF 使用 `document_read` 读取本地文件或已有快照；两种来源进入同一个 `materials.read` Host 服务。
本地路径先由 Host 授权，再把原始字节写入材料存储；网络 PDF 也先固定原始字节，再进行探测或解析。
原件固化成功与文字/结构解析是两个结果：解析失败不能抹掉原件、页图或 overview，也不能伪装成空内容。

### 5.2.1 PDF：原件与独立视图

读取请求选用彼此独立的视图：

| 视图 | 提供内容 | 继续读取 |
| --- | --- | --- |
| `overview` | 原件 `sourceHash`、原件引用、页数/页面几何（若已探测）和文字状态；不先抽取全文 | 选择页或读取文字 |
| `text` | PDF.js 提取的选定页或全文文字，可附页边界和字面查找命中 | 继续看原页图或按需解析结构 |
| `page-image` | PDF.js + Canvas 直接渲染的 PNG 页面或页面区域裁剪 | 调整页、缩放和裁剪区域 |
| `structure` | 按请求生成的布局/结构分析；支持 `native` 或显式 `docling`，并可显式请求 OCR | 用页图核对布局、表格、公式或图像候选 |

基础 PDF.js 文本与页面图像渲染随 Host 提供，使用包内的 PDF.js 和 Canvas renderer，不要求安装 Poppler。
页图读取独立于文字、结构和 OCR；没有可用解析器时，仍可读取原件页图。区域坐标以旋转后的页面为基准，
左上角为原点，`x/y/width/height` 均归一化到 `0..1`，因此缩放不会改变选区含义。

Docling 结构解析和 Tesseract OCR 是 Host 上的可选组件，不会自动安装。用户级 `harness.documentReading`
可配置 `doclingCommand`、`tesseractCommand` 和 `ocrLanguage`；空值恢复 `docling`、`tesseract`、`eng`。
配置项是 Host 直接启动的可执行文件名或路径，不作为 shell 命令拼接。Host 用受管进程运行它们并返回真实的
`unavailable`/失败状态；某个可选组件不可用不应使独立的文字和页图路径失效。

原件字节的 `sourceHash` 是稳定锚点；可读文本快照另有自己的 `contentHash` 和 `snapshotId`。派生分析带有
`analysis.id`、`sourceHash`、解析器、实际解析器版本、页范围、OCR 选择和状态。结构位置/元素记录其 `analysisId`，
而原始页和区域仍以 `sourceHash + page + normalized region` 定位。解析配置、页范围或 parser 版本改变时生成新的分析身份，
不重写原件页锚。Docling CLI 的 parser version 与它输出 JSON 的 `schemaVersion` 是不同字段，不能互相冒用；
没有结构分析的页图引用也不需要绑定一个 parser version。

因此跨读取只复用当前授权的 `snapshotId`；回跳链接使用该当前快照，并携带 `sourceHash`、页/区域以及可选的
`analysisId`。`sourceSnapshotId` 仅说明派生材料来自哪个原件，不能替代当前可读的快照身份。

### 5.2.2 按需解析与渐进式披露

Agent 不需要先把整篇论文解析完。`document_read`/`materials.read` 先核对当前材料权限，再依据视图请求探测、提取或渲染：

| 请求 | 返回 | 深入入口 |
| --- | --- | --- |
| `overview` | 页数、旋转后页面尺寸、原件 hash、文字状态 | 指定页的 `text` 或 `page-image` |
| `text` | 页码、原文、字面查找命中；文字不可用时给出状态 | 页图与选区 |
| `page-image` | 可供模型读取的实际 PNG、页码、尺寸、原件 hash 与可选 crop 坐标 | 更大缩放、邻页或其他 crop |
| `structure` | 实际返回的 heading/layout/table/cell/figure/formula 对象、页/区域引用和 analysis identity；未解析部分保留状态 | 对照原页或改请求目标页 |

结构和 OCR 按需在目标页执行；默认不是“所有页面必须使用同一 parser 版本”。表格单元格、公式、图像与阅读顺序
只有解析器实际返回时才投影为结构对象；候选、缺失、`unsupported`、`unavailable` 和 `failed` 分开报告。
缺少 Docling/Tesseract 不等于论文没有表格或扫描文字，结构响应也不把模型推断伪装成程序事实。
同一原件、页范围和兼容配置的并发分析可以共享工作；一个等待者取消只撤销自己的等待，最后一个等待者离开时才取消底层工作。
模型补充的图表描述、趋势解释或数值估计是派生判断，不能覆盖原始像素、提取单元格或 OCR 文本，且要保留对应的页/区域引用。

程序事实（页已探测、结构分析包含哪些页、OCR 是否成功）与研究判断（某表支持什么结论）分开保存。检索 Agent 可以自然语言
说明判断，不要求每轮输出固定字段，也不因低置信度机械唤起高级模型。

### 5.2.3 阅读器、引用与实践交接

本地 PDF 和 Web 快照共用阅读器。打开时先取 `overview`，随后可直接看页图、查文字或显式请求结构解析；页面、文字与结构视图
保留各自的失败原因。选区按显示页面的旋转后归一化坐标保存；围绕选区提问时，输入草稿同时保留短引用和实际 crop PNG，
图片只随用户实际提交进入本轮输入。

`varin-material://` 引用指向当前可读 `snapshotId`，并携带原件 hash、页、可选区域和分析身份。打开引用会让当前会话的
Harness 面板回到同一阅读位置；来源卡可回到阅读器或原网页。引用不会把某个解析器的文字位置误当作原件页位置。材料交给
Thread/实验仍沿既有 scope 与授权；正文中的命令不自动执行，临时读取不能绕过源材料的引用保护。

不把 Docling/Tesseract 的可启动性当成解析质量保证。复杂版式、表格单元格、公式和图表的实际质量，以及跨平台完整打包，
必须以真实样本和发行产物验证；当前设计不宣称这些范围已经覆盖或达标。

### 5.3 共享缓存与持久成果

自动记录已执行查询、provider、可复用材料引用和读取范围，省去重复登记。检索缓存、索引均可派生；
显式保存、被报告引用或被实验使用的材料沿既有引用保护持久保留，回收不能破坏已交付成果。
未被引用的临时材料沿实际资源管理回收，不新加无依据的文件数、大小或保存天数硬配额。

原始正文可在授权范围内复用；按目标的片段选择/摘要必须区分目标和模型绑定，不能把另一个问题的答案当成当前原文。
请求合并须考虑授权/认证主体、URL 与获取方式、筛选和新鲜度要求。取消一个等待者不取消其他仍需要的共享读取；
全部退出后按真实任务生命周期释放。新闻/实时状态的刷新与固定论文版本不同，不能以同一个 TTL 表示永远新鲜。

共享内容不共享 Run 回执权威：接收者按自己的 scope 读取快照，需要结构化核对时由 Host 绑定其当前身份。
知道对象 ID、DOI 或另一个线程的 receiptId 不授予读取权限；普通材料 view 也不能自行成为 source-checked。
刷新取得新快照，旧引用仍指向旧内容；无法取得或已过期的对象明确报告，不能静默换成当前网页。

## 6. 科研搜索的增量能力

### 6.1 入口与关系

首批学术接入以 OpenAlex / Semantic Scholar 的元数据、引用关系与开放材料位置为基础，
加上可配置 Sciverse 的段落语义搜索、分段阅读和图表能力。各自独立可用，不要求所有渠道配置齐全。
实施时核对当前官方 API，代码声明真实支持的筛选与分页，不依据本调研写死供应商能力或字段。
arXiv、PubMed 等既可作为材料/标识符来源，也可后续按具体需求增加专用 adapter；不以接满数据库作为首版条件。

科研查找可以从问题、论文、作者、方法、数据集或代码入口开始。找到一篇论文后，按问题决定追参考文献、后续引用、
相关工作或实现材料；一条路发现新术语后允许重新搜索。引用量可帮助认识脉络，不能直接代替相关性、可靠性或优先阅读判断。
关系按需取得并缓存，不先建立覆盖全部文献的常驻图数据库，不设置固定几跳后就必须结束的统一规则。

论文数据可能只有 metadata/abstract，仍可参与发现；阅读全文需要实际权限与可取得位置。
部分来源打不开时继续利用可得信息，并说明哪些判断尚缺正文。检索未命中只支持“本次范围内未找到”，
不能自动断言全球无人研究或方向必定新颖。

### 6.2 在材料中找答案

支持跨当前选定论文/资料集合的关键词与可用语义检索，返回具体段落。集合边界在召回时生效，
不能先全库 top-k 再过滤而漏掉范围内材料；相同模型与索引世代才能复用向量。
未配置语义服务时，本地已取得材料仍可关键词搜索、按章节读取；不为了学术功能先下载全球论文库或自动安装嵌入模型。

阅读将问题与原文联系起来：例如“论文是否真的支持该假设”“比较时训练数据是否相同”“失败条件是否在附录”，
这些是 Agent 可提出的问题，不是必须填满的固定表。搜索结果应让它继续展开相关段落及图表，保留限制条件与反例。

### 6.3 连接实践与写作

同一材料可关联代码仓库、版本、数据和补充文件。已取得的实验参数、运行说明和可复现片段可直接作为后续线程的输入，
通过既有 source/artifact 引用交接。阅读网页或论文不自动执行其中命令，实际实践走原权限与实验/进程工具。
写作时复用已保存的准确元数据和原文位置，需要格式化引用时再生成，不要求检索阶段先写 BibTeX 或完整综述。

## 7. 检索子线程、动态探索与报告

### 7.1 复用现有角色

`retrieval` 继续是通用事实调查预设；`investigation` 继续服务科研侧重下的竞争解释调查。
普通 `dispatch(task)` 也可搜索。不新增常驻 Web researcher、固定 supervisor 层或每次查询必经的检索 Agent。
任务值得独立上下文才派发，相关调查可在原 Thread 中续做，独立问题才并行展开。

通用 retrieval 的专用模型显露条件保持诚实：绑定存在才列为可用，设置目录/UI 能说明为什么不可用。
不将未配置的槽位静默改成主模型；普通派发的明确继承路径仍可用。科研 capability 的 work-focus 检查保持现有语义，
但新搜索/阅读工具本身不加科研门槛。新工具进入各预设时同步实际 allowlist、能力装配和冻结 Run 配置。

### 7.2 自然语言结果与可选事实结构

**D-315 的合同调整（L0 已实施）：** retrieval 可以用自然语言报告完成正常交付，引用实际来源并说明有用发现与未知；
`submit_facts` 留作任务确实需要逐项事实结果时的可选工具。不会因为没填 facts JSON 就把一份有效报告覆盖成空结果或 incomplete。
这部分仅替代 D-227/D-230/D-234 的唯一交付入口要求，保留它们的来源核对、Run 身份和耐久引用边界。

实现必须同时改预设/初始提示、结果类型、settle 封印与报告投影、read_thread/wait/上下文/UI 消费者，
不能只删一句提示。自然语言报告沿当前 Thread report 耐久保存；结构化 evidence 存在时作为关联资料保留，
不得重写丢失原报告，也不维护两份互相竞争的权威结论。

Host 从真实读取结果建立可解析的引用；模型写一个 URL 只能成为引用文本，不能自行授予来源状态。
结构化 facts 仍走 Host 核对，`source-checked` 不升级成 claim-verified。无需为了校验报告逐句再启动审查模型。
未作结构化提交与查不到来源是不同状态；Run 结束也不等于开放研究问题已解决。
失败/取消可保留已取得材料与部分报告，状态由真实执行与结果形成，不因自然语言里写了“完成”而覆盖失败。

retrieval 保持被分派的事实调查职责和无文件写入/shell 的边界，可以解释材料之间的联系、冲突和缺口；
不会自动接管产品设计、全局优先级或科研主线。任务要求更广的分析时使用现有普通线程或 investigation。

### 7.3 交流与程序生成的现状

现有 retrieval allowlist 未列入 send/read_thread 等协作工具；需要交流时沿现有关系授权补齐它们，
不能只在提示中要求“给兄弟发消息”。读取其他线程与材料仍分别过原 scope，不授予任意会话访问权。
主 Agent 保留完整目标，子线程按具体子问题探索；新发现可以通过自然语言消息改变其他分支的调查重点。
不要求消息具有假设/置信度/下一步等固定字段，也不强制每个结果都过高级 Agent。

已搜索的表达、取得的材料、读取范围、获取失败和在飞任务来自工具/执行记录。按需查询可看完整活动，
简短的新结果/完成事实复用 7G 请求前增量与现有团队现状，不新增 Zone 0 动态大表、额外状态总结请求或隐式唤醒。
“已读一页”是程序事实，“改变了研究方向”是模型判断；程序不把关键词命中推断成研究突破。

长调查沿 Thread/Run admission、send、wait 和 follow_up 续接；普通网络请求用现有工具取消/等待，
不能把内存中的网络调用宣称重启后仍继续执行。Host 重启可以重新读取持久材料，未完成操作由既有任务 owner 对账或重试，
不另造搜索专用 scheduler、会话库或永久后台 worker。

### 7.4 材料调查与研究判断分离

检索 Agent 的默认职责是扩大并整理材料：发现论文/入口、读取原文、定位相关段落、指出冲突和未知，并把这些内容交给主线。
它使用什么模型都不改变这个边界；中等模型可以高频执行召回、阅读和局部比较，但不需要在每轮工具调用或每次新增材料后形成
“当前判断”与“会改变判断的信息”。这两项不是检索结果的固定字段，也不进入持续更新的状态表。

主 Agent 或用户明确发起综合时，才由适合的模型把当前问题、已取得材料、冲突和运行结果放在一起形成暂时判断；需要时再把一批新
材料与该判断进行一次针对性比较。程序只保存材料身份、原文位置、运行/消息来源和取得状态，不把中等模型的解释自动提升为主线
结论，也不因新材料到达自动改写已有判断。

检索 Agent 可以在自然语言报告中主动提出可能的解释或下一步，但这是带来源的工作意见，不是 Host 状态。若判断确实改变，改变的
理由和可能反例随综合报告或普通消息保留；不为此增加固定 JSON、强制每轮摘要或自动唤起高级模型的流程。

## 8. 快速决策与探索策略

主 Agent 或检索线程负责提出新问题、生成查询、发现跨术语联系和暴露冲突；需要形成研究判断时由主 Agent 或明确发起的综合任务处理。
快速决策能力只按自然语言目标批量判断：
候选相关性、阅读价值、互补贡献、可能重复、值得继续追踪的关系或潜在反例。
程序负责网络、原文读取、精确身份、去重与执行，不把可确定的文件/权限/状态事实交给模型猜。

候选必须可继续生长：当前结果、论文关系、页面链接、章节、已发现术语和 Agent 新表达都可提供下一步。
判断器只选择本轮真实候选；返回价值与探索价值分开，某篇当前不适合引用仍可能提供关键新术语或入口。
低分先影响顺序，未读候选仍可查询/恢复，不因一次评分永久裁掉方向。若因输出容量没有呈现全部候选，应保留展开方式。

充分性判断限定于已见材料和当前任务需求，用于辅助下一步，不能将“有正文”或一个分数写成研究完备性证明。
结果缺口与相反解释可由生成式模型继续提出。判断接口的 missing/failed 不解释为 false/零分，也不拿阈值冒充可靠概率。

调查是否已经满足用户目标由当前 Agent 根据实际材料决定，遵守既有取消和用户预算。
查询内没有新动作/新材料时返回已有结果和缺口，不重复执行同一请求；这表示当前路线暂时耗尽，
不自动结束整个研究或宣称所有方向均已覆盖。需要换问题或继续其他路线时沿同一线程推进。

沿 D-312 注册实际 Web/学术用途（内部名称随实现确定），复用默认绑定、用途覆盖/关闭、configurationId、Pi 认证、
模型输入与结果容量处理、取消和用量记录。一次操作冻结绑定，下次操作可用新配置；已退役的迟到结果不覆盖现行选择。
Web 判断不借用代码 `models.explore` 槽位，更不因为支持 judge 就把模型当成能生成查询或看图片。

同目的选择由一个模型路径承担，不先串普通重排再串 LLM 选择最后串快速判断。
相互独立的候选尽量批处理，已知页面或简单检索无需先经模型路由；总延迟含网络往返、抓取与读取，不能只报模型推理时间。
未配置/关闭/不可用时保留来源排序和直接检索，当前 Agent 仍可判断与补搜；不临时借另一付费模型填空。
新能力随配置有效直接使用，不以外部跑分作为启用条件。

## 9. 所有权与 UIUX

| Owner | 本阶段职责 |
| --- | --- |
| Application Host | 搜索/学术/读取 adapters、材料解析与授权、共享获取、来源关联、工具服务 |
| Rust kernel / 既有存储 owner | 对象、记录、引用保护与文件 authority；派生索引沿既有检索 owner |
| Pi host / broker | 当前 Agent 和既有检索 Thread、模型/凭据调用、工具取消、结果与消息 |
| Protocol / application-client | 进程与 Surface 契约、来源/内容类型、能力描述和真实状态 |
| UI / 工作台扩展 | 搜索结果与来源展示、阅读/图表/集合视图、任务进度、原文定位与设置 |

普通对话先展示紧凑结果和可点击引用；用户可展开原文、加入工作材料或继续围绕该来源提问。
科研工作台提供更适合比较论文、并排阅读和关联实验的视图，但共用同一材料与授权服务。
引用应定位到当时读取的内容，旧快照和最新线上页面入口分别表达；复杂解析进行中可以先读已有文本。
UI 不复制搜索/正文获取后端，不强制用户先创建资料集合、选择研究模式或填写筛选表。

来源刷新/任务进度沿现有事件与缓存失效通路；正文通过获准读取取得，不塞入 SSE 或常驻上下文。
检索集合可以是临时工作集，也可由用户/Agent 显式保存为项目资料，保存动作复用原 source/knowledge owner。

## 10. 实施顺序与完成含义

分三层交付，每层都是可使用的生产通路。详细写入边界、依赖与判据见阶段 L：

1. **L0–L1：通用基础。** 整理既有 retrieval 交付与工具发现，完善目标/批量 Web 检索、固定阅读视图和复用。
2. **L2–L3：科研材料。** 接通学术身份/关系、集合内检索、结构阅读及代码/数据材料。
3. **L4–L6：探索与收口。** 共享材料和线程交流，接入快速决策，再闭合设置、各工作台和文档。

UI 的最小消费者随对应服务切片交付，不能把前面阶段完成定义为“已有 helper，最后再接线”。
一般检索的身份、设置、无模型路径和现有 Thread 生命周期保持可用；代码检索不并入一个新的万能 search 实现。

验收以真实错误风险选择证据：工具是否收到实际 provider 结果、片段能否回到同一快照、目标范围是否贯穿、
失败/取消是否保留已取得材料、跨线程复用是否保持授权、自然语言报告是否真实留存、科研信息是否能进入实际后续工作。
沿既有装配与 faux provider 验证协议和调用链，少量真实任务用于改进质量；不新增固定测试数量、全平台 smoke、
独立评测平台或“必须优于某产品”的门禁。真实付费效果、完整桌面路径未实测时如实记录。

适合观察的实际任务包括官方文档精确查找、跨术语相近方法、复现实验所需细节、失败条件调查及已有材料的二次利用。
关注能否发现会改变判断的信息、获取实践所需内容、首次有用结果时间和总模型/网络成本；
“返回很多来源”“生成很长报告”“引用链接存在”均不能独立证明效果。

## 11. 后续训练与明确暂缓

专项训练分两条研究路线：候选/段落的轻量判断器，以及学习生成查询、换入口和追关系的搜索策略模型。
二者可分别开展，不预设必须训练一个完整研究模型。后续研究应区分候选没召回、选材错误、原文读不出和综合错误，
不能只用最终短问答是否答对优化所有环节。

本阶段不包含训练工程、全球论文爬取/镜像、完整文献管理软件、出版商付费全文接管或全部领域专用数据库。
现有 trace/材料引用可为后续研究提供线索，不自动导出用户材料或上传训练数据；真实数据与训练方案另行设计。
不附带新研究流程 DSL、强制专家会议、常驻检索管理 Agent、机械语义事件触发高级模型或统一数值硬配额。

当前已接线的部分：retrieval 线程可以直接交付自然语言报告，`submit_facts` 作为可选的结构化来源核验；`research_search` 通过
Host 查询 OpenAlex/Semantic Scholar 的元数据、摘要、身份和开放获取入口，并支持论文详情与分页。
已追加接线：`action=relations` 的 references/citations/related 分页展开（保留 provider 身份、canonical/版本身份、
来源记录与缺失字段）；`materials.collections` 服务与 `materials` 工具实现临时/持久材料集合与集合内关键词检索
（范围先于召回）；`webfetch` 结构化位置读取（page/section/table/figure/appendix/lines，PDF 页码映射，
`structure-unsupported` 与 `position-not-found` 分态）。L3-P0 进一步保存 PDF 原始字节，快照记录页数/解析器/source hash，
并支持 `view=page-image` 按页或像素区域返回模型可见 PNG；文本、原件和视觉读取仍共用同一快照 authority。
L3-P1/P2 已补基础纵切：PDF.js 坐标布局与明显双栏顺序、表格/公式/图像候选、按页可取消的可选 Tesseract OCR、reader 模型图像提问、
固定快照页面路由和来源卡入口。复杂版式、表格单元格准确率、OCR/图表解析质量及真实 provider 质量/延迟仍未测，不作收益结论。
