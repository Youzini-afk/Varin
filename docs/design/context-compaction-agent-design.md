# 后台压缩 Agent 与语义续接设计

Status: implemented — D-314；实施顺序见 [阶段 C](../plan/agent-harness-plan.md#阶段-c后台压缩-agent-与语义续接d-314)，交付事实以 [status.md](../status.md) 为准

Last updated: 2026-09-28

## 1. 目标与当前实现

压缩的交付物是让主 Agent 能继续正确工作的上下文。它需要理解用户当前要做什么、哪些要求仍有效、工作推进到了哪里、
哪些证据支持已有判断，以及接下来还缺什么。缩短文本是手段；不能把摘要写成流水账或只留下“已完成”的结论。

D-284 交付了固定范围后台准备、近期原文保留、请求前容量检查和按需提交；D-314 把原单次总结替换为
有查询能力的独立后台子进程（实现入口 `packages/pi-host/src/compaction-worker.ts`、共用契约
`harness/compaction-agent.ts`、查询工具 `harness/compaction-tools.ts`）。现有容量、固定候选和安全提交机制
继续复用：

- `packages/pi-host/src/harness/context-preparation.ts` 冻结 `CompactionTaskSpec`（S0/A/B/边界/模型配置），
  经 `compaction.run` 桥接请求交给 broker 派生的专用 `compaction` worker；首次与后续压缩共用同一完整提示。
- 原文切点按 token 预算与 Pi 安全交互边界决定，不是固定最近几轮，也没有“最近 user 必须原文保留”的规则。
- S0 与待替换的 A 完整进入 worker；B 能放下时逐字下发，否则提供带 entryId/原角色的参考摘录与未读范围。
  A 本身过大时只选择更早的合法切点，其余历史继续保留在父会话；不能移走 A 后假设查询能扩充窗口。
- `context-request-boundary.ts` 在每次真实请求前检查容量；不足时采用或等待同一候选，再从最新 Pi 历史构造请求。
  自动压缩开启时，代码以 `inputTokens + max(reserveTokens, request.maxTokens) > contextWindow` 判断需要空间。
  这里的输入是估算并结合实际 usage 校正，不是服务端精确 token 计数。
- Pi SessionManager 仍保存原始历史；候选生成不改写会话，实际提交才改变下一请求使用的摘要与原文范围。
- worker 使用 Pi 的消息转换保留旧摘要与 custom 消息，每次模型请求重新核算查询结果与输出预留；成功任务累计各轮用量。

## 2. 产品行为

用户正常推进工作时，压缩 Agent 在后台理解固定历史范围，必要时查证，生成候选摘要。材料充分时可以直接完成，
不要求每次调用工具、不固定执行“检索—核验—审查”流程，也不让主 Agent 为压缩写日报或重复交接。

不机械保留最后一条 user：那条消息可能是长篇参考资料、他人的报告、局部补充或暂时讨论。是否保留及如何表达由压缩 Agent
结合对话语义判断；关键措辞可短引用，材料可归纳或留下来源，尚未解决的歧义如实留下。近期工具过程继续按合法切点保留原文。

沿用已有“后台准备／需要时等待／已完成／失败”的状态与压缩边界展示。正常不新增聊天会话、项目或业务子线程条目，
也不把压缩 Agent 的查询过程混入主对话；必要诊断能看到它处于准备、查询、完成或失败，以及真实原因。

## 3. 固定材料与原文接续

```text
P  = 主会话当前执行配置的系统提示与工具定义
S0 = 已有摘要，首次为空
A  = 本次将被摘要替代的历史
B  = 准备开始时将保留的近期原文，只读参考
N  = 准备开始后主会话追加的新消息、工具调用及结果

主 Agent 继续使用：P + S0 + A + B + N
压缩 Agent 理解：S0 + A + B，并按需查阅有来源的记录
产出 S1：替代 S0 + A；B 帮助理解任务位置，不重复复制 B
会话提交后使用：P + S1 + B + N
```

父会话在准备前确定 session、活动祖先路径、已有 compaction 边界、固定末端、A/B 分界、模型执行配置与输入世代。
这些是程序持有的任务身份，不要求模型填写。原始 role、消息顺序、entry 身份、工具调用与结果对应关系应保留；
不能把整段历史拍成一条没有来源区别的大字符串。

B 需要实际送入理解范围；模型必须知道哪些将被替换、哪些稍后还在。若容量装不下，程序选择更早的合法 A/B 切点，
或用明确标记的参考摘录及分页入口提供 B 的其余部分，披露实际未读范围。不能只传一个 marker 就声称模型看过 B，
也不能为了提供 B 而静默裁掉 A 中尚未处理的材料。

正常追加 N 不使候选失效，也不触发反复重新总结。尤其不能把 N 中的内容先写进摘要，再把相同消息作为原文重复投递。
N 中的新纠正作为后来的用户要求继续生效。另一次压缩、分支回退/切换、fresh、会话切换或压缩重点改变，需要复核来源；
不匹配的候选弃用，不能采用迟到结果。模型/工具配置变化重新核对 worker 请求和容量，不能挪用旧模型的 usage。

摘要 Agent 不自行移动切点、删除 B/N 或编辑主会话日志。若实际组合仍超窗，由会话 owner 发起下一段有明确来源的新准备，
而不是让旧候选在后台不断追逐最新 leaf。每次追加压缩必须实际减少旧内容；无进展则明确失败并保留历史。

## 4. 子进程与运行责任

复用现有 runtime-broker / pi-host 的进程启动、模型/provider、认证、取消和退出处理，新增明确的内部 compaction 用途。
Host/broker 管理子进程与受权查询，父 session worker 持有候选身份和提交权，子进程运行 Pi Agent loop 并返回摘要。
不重新实现 Agent loop、凭据栈、会话数据库或通用多 Agent 调度器。

压缩是所属会话的内部辅助任务，不通过业务 `spawn` 创建可无限延续的 Thread/Goal，不创建工作树、Integration 或自动 follow-up。
进程复用属于实现选择，但两次任务间必须清除旧运行状态、工具绑定与待处理结果。未提交候选与查询记录可丢弃；
Host/worker 重启后从 Pi 原历史重新准备，已提交摘要继续由原生 compaction entry 持久化。

压缩 worker 不再为自己启动压缩 Agent，也不加载主会话的业务自动接续、定时任务和团队广播。否则一次压缩可能递归派生进程，
或者为了整理历史启动新的业务工作。其上下文由本阶段的输入准备、按需查询与收口负责。

默认沿所属会话当前模型与已解析的运行配置，不自动换廉价模型或快速决策模型；生成式理解与摘要仍是本任务的核心能力。
凭据通过既有可信 runtime 获取，不放进 prompt 或产物。thinking/effort 与 provider 参数沿实际能力继承，不默认降为 minimal。
当前 worker 通过 Pi 原生 services 加载静态扩展 provider，使用父会话冻结的 project trust（包含单次授权）与
`streamSimple` 推理转换；不创建业务 AgentSession。父业务生命周期事件建立的私有状态/动态 hook 闭包不迁移，
依赖它们的扩展须提供可独立加载的 provider 注册；具体边界在 status 中单列。

业务线程的并发名额不能成为父会话等摘要时的循环依赖：即使普通工作线程名额已满，压缩任务也要有可推进的既有后台推理路径。
这不意味着无限旁路资源管理；复用现有 provider/机器准入并明确内部用途。可控制的调度中前台请求优先，单槽后端上的准备可以排队，
必要时明确等待；不能声称子进程会消除外部 provider 的限流。不给本阶段另加固定轮数、进程数或无依据的独立配额。

## 5. 查询工具与渐进披露

工具通过已有 Host authority 读取，绑定父 session、活动分支与本次任务来源。以下是能力职责，不规定新增一套同名 RPC：

| 能力 | 解决的问题 | 来源与行为 |
| --- | --- | --- |
| 历史搜索、按 entry 读取相邻消息 | 还原用户要求、纠正顺序、决定与理由 | 复用 `history` / Pi 会话读取，默认限定本次固定祖先路径与末端 |
| 工具输出、产物读取 | 从预览回到必要的错误、数据、结果正文 | 复用 `get_output` / 已有 artifact 路径，返回对应调用、修订及可用性 |
| 相关任务与线程记录 | 识别尚未完成的工作、运行身份和结果入口 | 复用已有关系授权，只读本任务相关记录；不因此获得其他根会话权限 |

简短工具说明放在 worker prompt；工具按需返回小段正文和后续定位/分页入口。没有可回读正文、临时句柄已过期、
任务未记录完成结果，都返回真实的缺失状态，不能伪装成空内容或成功。历史查询优先使用实际发生时的记录与版本化产物。

已发生的工具调用可以出现在输入历史里；它们是要理解的材料，不是待执行指令。压缩 worker 只安装完成上述查询所需的执行器，
不会因为输入里有 shell/write/spawn 记录而执行它们。该职责不需要修改文件、运行实验、发消息或改变设置，
也不额外开放这类业务操作。这避免后台整理与前台同时修改工作现场，而不是新增全局工具限制。

线程/任务状态若没有历史快照能力，要如实标注为实时观察，并在本次任务内固定读到的版本/时间。实时完成结果不能伪装成
A 中已经发生的事实，也不能使摘要提前宣称已经处理了 N。优先用固定范围内已有的任务记录，实时观察只作明确来源的参考。
当前磁盘文件不能代替当时的文件版本证明旧判断；既有原文足够时，不展开新的代码调查或互联网研究。

工具查询的日志属于压缩任务，不消费主 Agent 的增量观察游标、消息已读回执或 7G 送达收据。没有独立只读视图的接口，
先补齐该接口语义再复用，不能用主会话身份调用有读取副作用的观察路径。

## 6. 语义保留与提示词

实际提示词由 `packages/pi-host/src/harness/compaction-agent.ts` 的 `COMPACTION_SYSTEM_PROMPT`
维护；首次压缩和更新摘要使用同一个入口。这里记录输入与输出的关系，不再复制一份容易失步的完整模板。

- 输入依次包含已有摘要 S0、将被替代的历史 A、保留边界和近期内容 B。输出摘要替代 S0 和 A，B 继续由父会话保留。
- B 在 worker 中可以是原始消息，也可以是带 entry ID、原角色与截断标记的引用；程序给出实际遗漏范围。
- 摘要保留续接所需的当前目标、有效要求与授权、纠正、决定及理由、证据、未完成工作和精确续接标识。
  请求、引用材料、计划、观察和已验证结果在语义上保持区别。
- `history`、`output`、`records` 提供真实可用的只读查询；返回的实时状态与被替代历史分别标明。
- 结果是自由组织的摘要正文，供主会话继续使用。手动压缩重点仍通过现有任务参数附加。

Host 检查来源身份、完整结束与容量，并通过原生 compaction writer 提交。没有额外的摘要审查 Agent、
固定栏目或模型打分环节。

## 7. 容量、等待与提交

### 7.1 主会话

沿用 D-284 的准备/提交分离：默认约 75% 可用输入容量启动准备，以同配置实际准备耗时和增长速度调整提前量；
摘要 ready 先暂存，真正需要空间时才提交。界面的手动压缩与 `/compact` 也只启动准备；摘要状态条及详情中的“立即应用”可明确选择当前候选，跳过容量阈值。
空闲时直接校验并应用；模型请求或工具执行尚未结束时，在下一次模型请求发送前应用，若当前轮直接结束则在 settled 边界应用。
已发出的请求不重发、已执行的工具不重放。候选必须仍属于当前会话、模型和来源；重复提交同一候选是幂等的，取消或失效不再延期应用。
60% 是原文保留的规划目标，不能为凑比例删掉没有被摘要覆盖的内容。

每次模型请求前先计入系统、工具、原文、新输入与 7G 材料，再加输出预留。该预留是模型输出预算，不是等待时额外腾出的一块内存，
也不保证下一批工具结果不会突然变大。已完成的工具结果正常记录；下一请求装不下时先等待/压缩，再决定是否发送。
估算与 provider 实际容量可能有误差，保留现有明确错误处理，不宣称请求前检查能消除所有超窗响应。

当前候选在飞时，主会话等待它，不能再并行启动第二个总结。工具与外部进程继续自身生命周期，暂停的是新的主模型请求，
不是杀掉已启动的实验或 shell。用户取消等待/任务时沿既有取消链清理所属压缩调用和查询；原会话历史始终保留。

摘要完成后，由父会话在本步工具结果收齐、下一请求未发送的边界校验身份，使用最新 B/N 预构造请求并检查容量，
再通过 Pi compaction writer 发布。输出文本不完整、仅返回工具调用、来源过期或不能释放空间时，不提交半成品。
仍超窗时沿同一机制处理下一段旧历史或明确报告无法容纳的材料，不静默删新内容、不重放已执行的工具。

### 7.2 压缩 Agent 自身

独立进程不意味着独立的无限窗口。它的每次请求同样计算 system/tools、S0/A/B、查询结果与最终摘要输出预留。
准备输入时给按需查询留出合理余量，按当前模型、既有输出规格和实际材料决定，不把一个固定百分比或 token 数写成所有模型的硬限制。

初始材料装不下时，在启动前调整合法的摘要区间或采用有来源的分段读取；明确尚未读取的范围。查询结果使用已有分页与输出引用，
接近容量时先利用已读证据形成可用摘要，无法可靠覆盖 A 则返回失败/需要重新划定范围，而不是宣称已完整处理。
不递归调用自己的压缩机制，也不为每次查询重新总结全部工作记忆。

### 7.3 生命周期与缓存

准备关闭或自动压缩关闭时，后台行为沿已有用户选择；必要手动压缩沿同一任务实现，不保留两套长期摘要引擎。
仅因空闲、任务完成或时间流逝不新启动收费整理。候选 ready 后退出或释放 worker 的运行资源，由父会话暂存候选，
避免为一个待采用字符串常驻模型工作循环。普通模型错误不自动重试；若专用 worker 的模型响应停滞，
可按“上下文管理”中的设置中止该次尝试，并用同一份冻结材料启动新的 worker。流式输出按最后一个有效增量的空闲时长判断，
未输出或非流式响应按等待完整响应的时长判断；查询工具阶段重新使用等待响应时长。默认分别为 120 秒、300 秒，
默认最多重试一次，也可关闭或调整。重试前旧 worker 必须退出；取消、来源过期或普通 provider 错误不触发重试。
重试过程在压缩状态和转录视图中显示，失败后保留原始会话历史。

尽量复用原请求的角色、消息排列、运行配置和 provider 缓存路由；压缩专用指令与查询工具需要真实、稳定的执行合同。
不能为了声称 cache hit 而宣称具有原业务工具的执行能力，也不把查询工具改造说成完全不影响缓存。
前缀是否可复用由实际 provider 请求决定，新增工具定义或系统指令可能使缓存失效。旧前缀读取、查询调用与压缩后新前缀处理均是成本，
继续进入已有用量/错误记录，不建设独立费用面板、预热循环或质量评分平台。质量与速度收益待实际使用观察，不提前承诺。

## 8. 实施与验收边界

按 C0 → C1 → C2 → C3 → C4 推进：冻结材料与统一提示词、内部 worker 与查询、语义摘要接线、容量等待与提交整合、文档/UI 收口。
具体生产接缝与完成判据见实施计划；设计不是另一个需要执行 Agent 逐条填写的工作流。

重点验证真实行为：长篇补充与有效要求能同时呈现给模型；B 实际可见且保持原文；后台查询不消费主会话观察；
候选等待期间 N 与工具配对完整保留；取消/分支变化不提交迟到摘要；普通线程名额用满时压缩仍可推进。
复用现有 Pi/Host 集成覆盖和可控模型响应，按新行为补充必要反例，不新增全量重复 smoke。

不要求真实付费模型、跨平台桌面完整 E2E 或检索质量评测成为功能交付门槛。可控响应只能证明接线和行为，不能证明语义质量；
真实模型是否更准确、更快在后续使用中观察。交付时同步当前状态，移除被替代的单次摘要路径、弱化更新提示和过时说明，
保留 Pi 原始会话、已有压缩记录及当前正常恢复能力。
