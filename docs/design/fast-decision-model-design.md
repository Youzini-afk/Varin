## 1. 产品决定

产品统一名称为 **快速决策模型（Fast Decision Model）**。它根据给定目标和材料，完成候选选择、相关性判断、评分、
下一步动作选择等工作。名称体现产品用途，不承诺任何供应商或负载下的固定响应时间。

这是跨功能的模型能力类别，不是检索专用角色，也不叫 Jev 模型、重排模型或某供应商的 System One。
Jev 是首个适配器。Computer Use、工具/技能选择和上下文材料选择可以复用同一能力；
原阶段 F 交付通用调用、配置与 `explore`，阶段 L5 扩展 Web/学术消费者；记忆沿 BC 计划增加真实调用方。

目标是让原本昂贵的局部语义判断能参与日常执行：看到真实材料后决定读什么、追哪里、保留什么。
原有文字搜索、结构关系、向量召回继续提供候选；生成式模型继续负责需要产生新表达、复杂解释与开放推理的工作。
完整源码、文件修订和工具执行仍由原服务提供，不因为增加判断模型而迁移其 authority。

## 2. 当前实现与改变范围

当前 `explore` 是一次公开工具调用：Host 持有短生命周期 query，pi-host 可用 `models.explore` 生成搜索计划、
从当前原文中成组选段，并做一轮可选补查。词法、图和可用向量同时提供候选；LLM 选材状态为 skipped/unconfigured 时，
已配置的 `harness.rerank` 可以重排，失败/取消不触发另一模型。代码入口为：

- `packages/pi-host/src/harness/explore-tool.ts`、`explore-model.ts`：公开编排和生成式计划/选择。
- `packages/web/application-host/lib/harness/explore-query-services.ts`、`explore.ts`：query、召回、读取、选段、结束。
- 同目录 `explore-rerank.ts`：当前专用重排消费者。
- `packages/web/application-host/lib/knowledge/semantic/workspace-runtime.ts`：范围推理绑定与语义生产装配。
- `packages/pi-host/src/session-host.ts` 与后台推理 runtime：模型/provider/凭据所有权。

D-312 将候选语义判断抽成独立能力，并让同一个 query 可以根据判断迭代展开真实代码关系。
保留生成式搜索表达入口；不把 Jev 塞进要求返回自由文本的 `completeExplore`，也不把它的接口冒充 HTTP `/rerank`。
既有 `retrieval` Thread 仍负责更开放、更长的事实调查；一次快速查询不会隐式派生常驻子线程。

2026-10-01 已替换基线 `b7520322` 的 query 级全局排他分工：Explore按具体职责补位，详见 §4.4 与[检索专卷 §6.1](harness-retrieval.md)。沿用既有权重/provider，不要求训练新的决策模型。

## 3. 能力、配置与适配

### 3.1 能力合同

内部使用 `FastDecisionModel` / `fastDecision` 命名。公共请求表达消费者要判断的问题和实际材料，供应商 adapter
负责映射传输协议。能力按支持情况声明，不要求所有供应商具有相同输出形状：

| 能力 | 用途 | 必须保留的区别 |
| --- | --- | --- |
| 候选选择 | 在给定文件、范围或具体动作中选择 | 单选与多选；允许没有合适候选；ID 来自本次请求 |
| 条件判断 | 材料是否满足某个自然语言条件 | 模型判断不等于已经核实的事实；缺结果不当作 false |
| 评分 | 按说明评价候选的相关性或价值 | 相对顺序、分数标尺与绝对概率分别表达 |
| 输入模态 | 当前文本，未来可有图像等 | 不支持截图不能假称支持 Computer Use 视觉判断 |
| 批处理与容量 | 同批多问题、候选与材料复用 | 实际上下文/候选限制由 adapter 声明；可拆批或分层 |
| 不确定性 | 可选的概率、置信信息 | 未提供就缺省，不编造校准概率或给统一置信分数 |

初版实现真实消费者需要的能力；能力描述允许扩展，不先实现全套虚拟操作、图像代理或通用编排 DSL。
不同模型即使都输出 0–1，也不能当成同一标尺；Choice 的相对概率也不等于独立的相关性概率。
排名第一不证明材料有用。没有合适候选、材料不足或来源未完成必须能够明确表达。

一次请求至少绑定：用途、目标、实际输入材料、问题/候选 ID、模型配置世代、取消信号，以及消费者的来源修订引用。
结果按问题 ID 和候选 ID 关联，包含实际模型身份、支持的判断值及可用的用量/耗时；缺项、非法 ID、格式错误与
供应商不可用不能转换为有效的低分。原始供应商分布可以保留在内部详情，不强制各消费者依赖 Jev 专有字段。

### 3.2 用户配置

拟使用独立的 `harness.fastDecision` 配置种类，与 embedding/rerank 并列，不增加一个假装能聊天的普通模型槽位。
提供一个默认绑定，并允许已注册消费者按用途显式覆盖或关闭。解析顺序是用途覆盖、通用默认、未配置；
用户显式关闭不会被默认绑定重新启用。未知 provider 的模型名不构成能力证明。

设置页在模型分工附近显示“快速决策模型”，说明为“用于相关性判断、候选选择、评分和动作决策”。
沿已有模型配置 UI、i18n、共用设置目录和 `settings_search/read/update` 接线，用户不需要改 JSON 才能使用。
界面展示实际可用能力；未来加入一个用途时复用默认配置，不要求用户重新填写同一套凭据。

绑定与凭据沿用户/operator 所属 Pi 配置和 AuthStorage；按现有后台推理模式增加显式 adapter 注册与调用能力。
TypeSafe 凭据即使需要新增 provider 支持，也写回这套 authority，不在 Host、renderer 或检索模块复制密钥库。
Host 只持有去凭据绑定和已授权材料，通过 broker/Pi inference 请求模型；不借用第一个活动聊天的模型或身份。
具体字段可随现有设置合同整合，但默认/用途覆盖/关闭与 owner 语义必须一致。

未配置时现有检索照常工作。已配置且具备当前所需能力时，正式实现默认参与适用判断，不另设实验启用门。
不静默换用主模型或其他付费 provider；设置改变作用于下一次 query，当前 query 保持开始时解析的绑定，
凭据或访问能力撤销沿原有实时失效规则处理。

### 3.3 Jev 首个适配器

当前通过 Pi 1.0.0 原生 classifier API 调用 TypeSafe、Cloudflare System One 或 llama.cpp，
保留通用判断、选择、评分及部分回答语义。传输、认证、重试和供应商限制归原生 API；
不把某个 TypeSafe 模型的容量固化到通用协议。嵌入和 HTTP 重排继续使用现有独立请求协议。
由 adapter 处理版本、API 身份、真实输入约束、取消和返回映射；不从聊天模型列表猜测兼容。
合法的 typed 输出只保证结构与候选范围合法，不证明语义判断正确。

Jev 不生成自由文本。新关键词由主 Agent、已配置的生成式检索模型或当前源码中的实际符号/字面量提供；
模型可以选择这些真实候选。不能用连续字符选择模拟文本生成。
当前 Jev 的模态和容量由官方规格决定；未来 adapter 的能力变化不要求重命名产品或改写检索消费者。

## 4. 首个消费者：`explore` 渐进检索

### 4.1 同一查询内的循环

```text
问题、范围、来源与模型绑定固定
             ↓
文字 / 图 / 向量召回 + 按需生成新搜索表达
             ↓
候选到达 → 读取当前原文 → 形成材料和具体下一步候选
             ↓
快速决策：哪些材料适合返回？哪些动作值得继续执行？
             ↓                         ↓
更新已选材料                    并行读取 / 定位 / 关系展开
             ↑                         ↓
             └────────── 新材料与新候选 ┘
             ↓
结束判断 → 原文、范围、来源与实际缺口 → 主 Agent
```

已有精确路径/对象可以直达，不强制为每次查函数名增加模型请求。开放问题的文字、图、向量与必要的生成式计划
仍可并行启动；快速判断不成为所有来源开始前的前置分类关卡。候选到达与读取沿现有 query 调度整合，
独立材料成批判断，不逐个文件串行请求，也不每返回一条搜索结果就调用一次模型。

入口不足时，可以读取当前目录、文件大纲、签名、已有说明，再让模型选择值得展开的位置；不需要先生成全仓摘要。
这种结构浏览与词法/向量来源互补，目录名称仅作线索，不能凭低分永久排除整个子树。未知名字、跨语言表达或
需要新假设时，使用已配置的生成式计划能力；没有配置就继续可用路径或返回具体缺口。

### 4.2 材料价值和探索价值分开

同一片段可以“不是最终答案材料，但值得继续追”。例如三行转发函数可能不解释进程如何终止，却暴露了真正的
调用入口。分别询问返回价值与探索价值，不能把单一相关性分数同时用作材料淘汰、停止展开和充分性证明。

最终选材看新增贡献、互补关系和已有材料覆盖，避免返回一组重复的高分片段；问题不预先强制套成固定机制模板。
可以用候选范围 ID 选择支撑片段、用有限选项表达材料角色，不能要求 Jev 编造用途解释或自由文本缺口。
需要文字时，Host 按实际阶段事实组织简短说明；开放语义说明由生成式模型或主 Agent 负责。

### 4.3 下一步来自真实工作现场

Host 从已读正文、符号/关系服务和目录清单动态生成可执行候选，例如：

- 读取已发现文件中的具体函数、完整容器或相邻条件块。
- 查某个已发现符号的定义、引用、调用方或被调用实现。
- 沿当前语句的导入、事件、服务连接值定位另一端。
- 展开某个目录或文件大纲，或搜索已发现的确切符号/字面量。
- 返回已有材料，或请求已配置的生成式规划补充搜索方向。

每个候选绑定动作类型、真实目标、形成依据与来源修订。模型选择完整 action ID，Host 执行绑定的动作，
不把分别判断出来的函数名和不相容参数任意拼接。候选动作并非给 Agent 交流增加必填流程字段；它只是模型 adapter
与 query 执行器之间的内部合同，公开工具继续接受自然语言问题。

读新代码后更新下一步集合，支持多个方向并行和回到保留候选。模型输出影响待读/待执行顺序；不要求按目录层级
单线走到底，也不自动扫完所有出边。动作身份、来源修订和已执行参数用于去重；没有新材料不反复评价同一状态。
模型判定“无关”可以降低优先级，不能删除未读事实或形成仓库不存在某实现的结论。

### 4.4 与生成式模型、普通重排器的配合

**2026-10-01 已接入。** `query.start` 冻结动作/选材职责与模型配置。有LLM时由它联合选材，ready快速决策只选择动作；无LLM时决策模型可判断材料，之后才选择已配重排或来源排名。显式模式不改换付费路径，失败保留材料并报告。

| 职责 | 可选实现 | 缺少对应模型时 |
| --- | --- | --- |
| 新搜索表达 | `models.explore` 按需生成分组表达 | 使用问题、已读名称、字面量与已有召回 |
| 具体动作选择 | 支持本任务的快速决策；或 LLM 一次返回一批合法动作 | 确定性导航和初始调度 |
| 材料相关性 | 快速决策、HTTP rerank、LLM 中适合本次任务的一项 | 单元来源排名与精确去重 |
| 互补证据组合 | LLM 成组选段；或明确支持范围/组合选择的决策模型 | 按实际关系合并范围并装配输出，不编造语义解释 |
| 开放长程调查、试验与复杂综合 | 主 Agent 或显式 `retrieval` Thread | 不在快速工具内隐式创建另一条调查会话 |

嵌入是独立召回能力，是否配置不决定上述判断是否可用。四类模型全部未配时，搜索、读取、基础导航、去重和交付仍能执行。只有 LLM 时允许批量选动作/选材来补位，不机械模拟逐条 judge API；只有决策模型时使用它真实支持的任务，不用 typed 输出伪造自由文本规划或不存在的 Retain 能力。

同一职责不默认叠加多个判断者。快速决策负责动作时，LLM 仍可在需要时承担联合选材；LLM 已完成同批相关性与组合判断，则不再补一次同目的 rerank。确需先筛选大池再联合比较时，分别记录输入和职责，未进入后批的不记为已判无关，不混用分数标尺。

首先改进 `auto` 的本次职责分配。保留用户显式固定路径与关闭语义，配置变更作用于下次 query；不因为补位就启用被关闭的用途、借用聊天主模型或改换 provider。配置缺失/任务能力不支持时选择现成能力，与运行失败后追加付费调用分开：第一版继续在失败时保留已读材料并报告该阶段失败，不串行尝试所有模型。已计划的其他独立职责可以继续。

职责计划复用现有模型绑定和 UI，不要求用户为每种组合填写工作流。这一修订只改变 Explore 消费方式，不自动扩张 Web、scholarly 或 memory 的行为；通用能力字段确需变化时核对这些真实消费者。

### 4.5 结束、取消与呈现

一次快速查询继续使用原 queryId、授权范围、Documents/WorkingBranch 来源、输出存储与共享工作预算。
每次判断绑定本批材料和动作集合；新增候选保持未评估，必要时与已选材料一起增量判断。迟到的旧修订判断不能
覆盖新材料，结束/取消后的结果不重新发起搜索。查找范围、读取授权与访问撤销不由模型概率决定。

结束依据包括：明确目标已取得、没有值得继续且未执行的动作、无新增材料、用户取消或本次工作预算结束。
模型的“材料够了”只针对已读证据，是结束决策的一项输入；尚未完成的来源仍如实记录。
不复制其他产品的固定 4 轮/8 并发，也不新增统一文件数、深度、调用数或置信度硬门槛。
实际容量与请求限制由 provider 合同处理，工作预算沿既有可配置机制，调度并行度按执行能力选择。

结果仍以当前原文、路径、行范围为主体，保留选中依据所在的实际源码；大输出沿已有句柄渐进读取。
模型输入预算与最终展示预算分别处理，超容量时拆分真实单元或披露未评估项，不能截掉关键正文后声称评估完整。
决策详情进入已有 query provenance，不逐轮灌入主模型上下文，不增加独立辅助费用面板。

后续改造还须绑定实际被模型看见的正文范围和判断上下文。较长材料拆分时产生明确的范围身份，不能裁剪输入后把评价附在整段未见正文上；已有材料的新增贡献判断带入必要的已选依据。上下文变化可以重新考虑旧动作，精确执行缓存避免重复I/O。

交付按[检索专卷](harness-retrieval.md)中的 DeliveryPlan 一次决定：必需范围在实际展示预算内成组保留，renderer不再独立截去判断依据。现有可见计数修复保留，但不等于联合选材已经实现。

## 5. 通用复用和工程归属

protocol 定义供应商无关的请求/响应与能力；pi-host 的显式 inference adapter 负责 provider 与凭据；
Host 提供按用途解析绑定的快速决策服务。检索编排放在现有 explore query owner，快速决策服务不拥有文件、
查询循环、线程状态或动作执行权。UI/application-client 只消费配置、能力和实际状态。

首个纵切至少复用同一服务完成检索选材和探索动作选择，证明它不是只改名的 rerank wrapper。
未来 Computer Use 可传页面/截图材料和真实可操作对象；是否支持图像取决于所选 adapter。技能选择、知识相关性
等用途按真实需求另行接线，不在阶段 F 中顺手改写权限判断、Goal、scheduler 或研究集群调度。

适合替换的是脆弱的语义猜测，例如仅凭问句关键词猜材料角色、按文件名猜回答价值、硬凑相关性奖金。
精确匹配、计数、版本比较、动作去重、范围授权和真实进程生命周期继续由程序计算。
迁移时去掉被替代消费者的重复语义评分，不再叠一层旧权重覆盖模型选择；无模型路径保留必要的独立检索能力。

## 6. 交付与观察

交付需要真实公开 `explore` → 同一 query → 快速决策 adapter → 真实读取/关系展开 → 原文结果，而非只有 SDK helper。
沿现有会话/Host 装配做适量定向验证：配置解析、候选映射、多方向展开、转发桥接片段、取消/修订、失败保留材料。
选择能暴露实际问题的场景，不新增独立评测平台、固定测试数量或全平台/真实付费模型的前置门禁。

质量与速度按整次任务观察，包含网络、模型输入、串行轮次、搜索/读取、冷索引和最终材料质量。
少量代表性问题可比较是否找齐关键实现、是否减少无关正文和主 Agent 补搜；不据此宣称普遍优于其他产品。
真实 Jev provider、中文问题与英文代码、长输入的表现未观察时明确记录，不能用合法输出或接口连通替代效果证据。
