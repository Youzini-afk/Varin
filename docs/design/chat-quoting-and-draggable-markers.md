# 聊天定点引用与可拖动输入标记

状态：已实施。现行合同已归入[聊天交互内容与引用](../interactive-content.md#用户引用)、[工作台输入框](../workbench.md#输入框功能与对象引用)、[运行时](../runtime.md)及[输入框模块说明](../../packages/ui/src/components/chat/composer/editor/DOCUMENTATION.md)。原设计与讨论保存在 Git 历史，不再保留一份与现行实现并行的提案。

## 已确定的责任边界

- 捕获准确选区、实际正文块或用户明确选择的整轮；文件、图片、交互内容与工具调用使用自己的实际内容和原读取 owner。
- 对象身份、正文出现位置和显示编号分别保存。CodeMirror 事务共同管理原子编辑、长按移动、复制粘贴、编号、附件及撤销；草稿、剪贴板和可达撤销历史保留各自资源。
- 原生、外部 Harness、协作、新会话、队列和恢复沿原输入合同保存固定内容。模型的有序投影与历史紧凑显示分开，内部来源记录不作为提示正文发送。
- 原始图片或文件不凭同名标记获得权限。跨 Thread 复制引用由原读取器和目标已有上传 owner 转交；Host 切换、资源失效或能力不足明确反馈。图片标注只交付合成结果，不附带未遮挡的原文件。
- 不新增会话、回复路由、永久引用账本、辅助摘要模型或跨重启全量草稿保存。协作收件人和 replyTo 仍由原协作合同决定。

同一应用运行期的剪贴板保留结构化对象；跨进程的纯文本回退不恢复资源权限。现有队列编辑不能导入它尚未持有的新文件附件，相关粘贴会明确拒绝并保留原输入，而不是产生无法读取的标记。移动端手势与实际浏览器几何验收见输入框模块说明。
