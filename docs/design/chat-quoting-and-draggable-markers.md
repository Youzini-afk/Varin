# 聊天定点引用与可拖动输入标记

状态：设计提案，尚未实施。本文整合截至 2026-11-11 的讨论，并核对了当前聊天引用、图片标记、CodeMirror 输入框和发送链路。现行行为仍以源码及[交互内容](../interactive-content.md)为准。

## 1. 目标与产品判断

让用户准确表达“我在回应哪句话、哪张图、哪个结果”，并能把引用安排在自己句子里的合适位置。Varin 同时处理多个事项时，用户仍然是在与 Varin 对话；引用的起点是用户选中的内容，不按派发任务替用户划分话题。

保留现有开放的正文、Markdown、图片、工具呈现与交互作品。用户可以引用一小段，再写自己的话，也可以在同一条消息里讨论多个来源。发送后的消息清楚展示这些关系，不要求把整个聊天改成社交消息气泡。

确定采用以下交互：

- 选中哪段文字就引用哪段；未选择文字时，引用右键所在的正文块。
- 右键菜单另提供“引用本轮回答”，明确选择时才扩大到本轮助手正文。
- 图片、文件、交互内容、工具调用各自提供引用入口，携带对应的实际内容或可读取资源。
- 输入框正文显示 `[引用点1]`、`[图片1]` 这样的完整标记。上方保留预览，正文标记表达它与用户措辞的位置关系。
- 长按标记可在输入框内拖动；引用与图片共用拖动、键盘编辑和撤销机制。
- 内部来源身份由程序保存。模型收到用户的话、所引用的内容和必要的可读出处，不收到前端对象或来源记录的整段 JSON。

本轮只设计这条引用链路。其他功能向模型暴露冗余内部信息的问题，后续独立排查；不借此重做任务查询、压缩、记忆或权限系统。

## 3. 引用范围与右键菜单

### 3.1 文字选择优先

聊天中存在有效文字选区时，菜单主项为“引用选中文字”。保留实际选中的文字及其顺序，允许跨段、跨正文块和跨消息选择。选区内的代码、链接文字与换行应可读；来源映射在后台记录，不重复输出原文。

没有选区时，按右键所在的内容单元处理：

| 所在位置 | 默认范围 |
| --- | --- |
| 普通段落或标题 | 该段落或标题；视觉换行不拆成多个引用单元 |
| 列表 | 当前列表项正文；点击子项不隐式包含其他项 |
| 代码块 | 该代码块，包括可用的语言信息 |
| 表格 | 该表格；用户若选择了局部文字，则按选区引用 |
| 图片、文件、工具或交互组件 | 对应对象，按第 4 节处理 |

正文里的普通链接继续保留打开、复制等原动作，同时能够引用所在段落。不能因为点击了链接就退化成只附一个 URL。文件链接与图片链接按其实际对象类型处理。

引用范围取自渲染单元对应的源内容，不靠最近的 DOM 文本、屏幕坐标、卡片标题或整轮 `textContent` 猜测。菜单打开时固定目标，随后消息滚动、虚拟列表卸载或流式追加不会把目标换成别处。

### 3.2 明确的整轮引用

助手正文菜单额外提供“引用本轮回答”。它包含该轮各条助手正文，按原顺序组织，保留各段实际消息归属；不把全部来源统一挂在最后一条消息上。

整轮引用不隐式附上隐藏思考、原始工具回执、全部附件或 HTML 源码。需要这些内容时，用户从相应对象单独引用。正文中已有的图片或文件指向仍保留可读关系，不为了引用整轮而自动下载全部资源。

仍在生成的段落或回答，引用的是点击时已经产生的内容。引用预览可说明当时仍在生成，后续输出不继续灌入草稿；用户再次引用时才取得新内容。

### 3.3 菜单与触屏

主操作使用明确的名称：“引用这段正文”“引用代码”“引用图片”“引用文件”“引用此次调用”“引用当前内容”。只显示当前对象相关的项，不把所有引用类型放进每一个菜单。

图片预览、工具详情、交互内容外框的更多菜单也提供同一动作，供触屏和键盘访问。HTML iframe 内的右键不能被宿主随意读取，沿现有交互桥接提供入口；无法桥接时，作品外框仍可引用该作品或主动框选画面。

引用动作只准备草稿，不发送消息、不执行工具，也不抢占另一会话正在编辑的草稿。

## 4. 各类内容如何引用

| 类型 | 用户看到的预览 | 随消息携带的内容 |
| --- | --- | --- |
| 正文、选区、代码、表格 | 作者或来源名称、原文开头，可展开全文 | 固定原文，必要的作者或内容类型说明 |
| 图片 | 原有缩略图，角标与 `[图片N]` 一致 | 实际图片内容；沿现有附件链保留可读取原文件 |
| 文件 | 文件名、已有文件类型信息 | 原附件或文件选择，经原文件 owner 准备可读资源 |
| 交互片段 | 作品名称、当前选项或结果；适用时显示画面 | 引用当时的可读内容与已选状态，必要的画面或可读数据 |
| HTML、图表、画面选区 | 当前作品或区域的固定预览 | 原快照的可读上下文，或实际捕获的画面；不附整页 DOM 与脚本 |
| 工具调用 | 动作摘要、状态、结果预览 | 此次实际操作的必要参数和实际结果，保留理解错误与操作所需的信息 |

图片引用统一采用 `[图片N]`，不再同时生成一个额外的 `[引用点N]` 包住同一张图片。其他内容采用 `[引用点N]`，预览里明确它是正文、文件、交互还是工具结果。

普通文件不自动全文展开进提示词。系统负责复用已有附件、准备可读资源与跨来源交接，用户和模型无需先判断“是不是同一个工作区”再决定如何发。若路径只是界面中的文件指向，引用动作要交给已有文件选择／捕获能力，不拿文件名冒充附件。

交互内容沿现有 `setContext`、声明式控件状态和选区快照取得信息，不要求模型为了支持引用额外写一段摘要。已有选择和结果足以表达时就直接使用；图形内容需要画面时走实际捕获，捕获不可用时显示具体问题，不宣称附带了画面。

工具引用默认针对一个实际调用。组合工具视图的更多菜单提供选择具体调用的入口，不能悄悄引用全部折叠操作。正在运行的调用固定当前已经得到的结果并保留“仍在执行”的事实；其后续输出不改变这份引用。

已有分页或外置结果继续使用原结果与原读取能力。预览折叠不代表发送时截断，当前已加载部分也不能冒充完整结果。不为本功能增加新的字数上限或辅助摘要模型。

来源的机器 ID、内部哈希和导航坐标留在结构化记录里。用户引用的原文本身包含 ID、日志或 JSON 时仍原样保留；不能按外观批量删除这些可能正是讨论对象的内容。

## 5. 输入框中的标记与预览

### 5.1 正文位置

用户可以写：

```text
[引用点1] 这里我赞同，不过结合 [图片1] 来看，[引用点2] 这部分需要调整。
```

标记是可选中、可移动的完整编辑单元。显示文字仍然简单，保留方括号与编号，使用跟随主题的重点色和很轻的底色；不在句子里塞图片缩略图、大标签、来源路径或关闭按钮。标记与正文基线对齐，整块换行，周围文字正常排布。

从聊天引用时，在该草稿最近有效的光标位置插入标记；没有光标则追加到末尾。引用动作不替换输入框里原先选中的用户文字。跨会话或异步读取仍固定原草稿和插入锚点，不把稍后准备好的内容插进用户刚切换到的新会话。

### 5.2 上方预览

图片仍在输入框上方显示缩略图和较暗的编号角标。其他引用显示紧凑的类型图标、编号和可读预览，例如“引用点1 · Varin：可以把搜索拆成两步”。来源不能只叫“来源”或显示一串内部引用。

点击正文标记或上方预览可查看内容、定位原处，预览沿用各类型已有的图片、文件和内容查看能力。长引用在预览中折叠，需要时展开，不把全文固定铺在输入框上方。图片标注编辑继续使用现有编辑器及撤销逻辑。

附件区域可以折叠为紧凑总览，但不能隐藏错误或让用户失去管理入口。正常状态不新增“待准备”“下载源文件”等干扰；需要重新选择、资源读取失败等真实问题就近表达。

### 5.3 对象身份与编号

程序把“被引用的内容对象”“正文中某次出现的标记”“用户看到的编号”分开处理。一个对象可以在正文出现多次，每次出现可单独移动，预览和实际内容只保留一份。

- 图片和其他引用分别编号，形成 `[图片1]`、`[引用点1]` 两组。
- 拖动只改变正文位置，不改编号，也不排序上方附件。
- 增删实际附件时，沿现有图片体验整理当前未发送草稿的编号，并一次性同步对应标记和角标；清空后再添加从 1 开始。
- 显示编号改变不改变对象绑定。已发送或已排队消息保持原编号，当前草稿的操作不影响它们。
- 编号整理只修改有真实绑定的标记，不搜索替换用户自己写的“图片1”或代码示例。

手打 `[引用点1]` 或从外部粘贴同名文字，保持普通文字；只有明确引用、插入附件或内部带绑定的复制粘贴才生成真实标记。避免同名文字误指向现有附件。

### 5.4 删除、重新插入和复制

退格／Delete 命中标记时整块删除，不留下半个占位符。删除正文标记只移除该处位置，上方附件仍然存在，和现有图片的附件语义一致；用户可从预览再次插入标记。

点击上方附件的移除按钮，才移除对象及草稿里对应的全部标记。该动作与编号整理共同构成一次可撤销编辑。仍留在上方、没有正文标记的附件也会随消息发送，放在正文之后；这是明确保留的附件，不是已删除的隐藏引用。

内部复制／剪切使用编辑器支持的结构化剪贴板内容，保留标记与对象关系；同一对象重复粘贴不重复上传。剪贴板同时提供可读纯文本表示，粘到外部编辑器时至少保留编号、简短出处和文字摘录，不输出内部 JSON。

跨草稿粘贴在目标草稿重新分配显示编号，并沿原附件能力复用或转交资源。跨 Host 的材料准备交给原传输能力，缺失资源时就近显示问题，不能仅凭相同编号绑定到目标草稿的另一张图。

## 6. 长按拖动、连续性与可打断性

### 6.1 一次拖动的体验

1. **按下。** 普通点击仍用于查看标记内容。长按判定沿用平台手势约定；判定前发生文字选择或页面滚动时，让原操作继续。
2. **提起。** 长按成立后，标记轻微浮起并产生柔和阴影；原位置保留占位，不先删除文字。移动端可使用已有轻触反馈。
3. **移动。** 浮动标记跟随指针，输入框里显示清晰的插入光标。目标吸附到合法文字边界，不能落入另一个标记内部。
4. **落下。** 松手后一次性提交移动，标记从当前浮动位置落到目标处；光标位于标记之后，用户可继续输入。
5. **取消。** Esc、指针取消或退出当前编辑上下文时回到原位。拖出输入框不表示删除，也不触发发送。

拖动时根据输入框当前几何位置寻找字符落点，覆盖多行、长行、不同字号、缩放、中文、emoji 和不同书写方向。靠近上下边缘时平滑滚动输入框；离开边缘或结束拖动立即停止，不驱动整个聊天列表乱滚。

手指或鼠标未实际改变位置，或者放回原位置时，不产生空的撤销记录。完成长按拖动后不再额外触发一次预览点击。

### 6.2 渲染与性能

拖动中的位置属于短暂视图状态。每帧只更新浮动层的位置和插入提示，不反复修改草稿、不上传材料、不重新投影模型上下文，也不让整个聊天组件树随指针重绘。

保留源标记占位，避免拖动过程中整段正文不断重新排版。用编辑器坐标能力计算落点；滚动或布局变化时更新几何信息，读布局与写样式分开安排。浮动层只绘制小标记，不为每次拖动重新解码图片或捕获 HTML。

提起、落下、取消和预览开合沿用项目已有动效变量及主题。新操作从当前动画位置接续，不能等上一次动画播完才响应，也不能靠隐藏预览、取消动效来换性能。

### 6.3 键盘、触屏和辅助操作

方向键跨过整个标记，Shift 选择可包含完整标记，Ctrl/Cmd+X、C、V 可剪切、复制和重新插入。键盘用户不必模拟长按；用剪切粘贴移动即可。

Enter／Space 在显式聚焦的标记上可打开预览，普通输入位置的 Enter 保持现有发送／换行规则。屏幕阅读器读出标记类型、编号和简短来源，不朗读内部 ID。

拖动只接管已进入移动状态的标记手势。`@`、`/` 菜单、Tab 建议、普通文本选择、输入法组词、外部文件拖入和图片编辑的快捷键继续按各自原行为工作。

## 7. 编辑事务、撤销与草稿一致性

继续使用 CodeMirror 的事务和历史能力。一次“移动”由同一事务完成旧位置删除、新位置插入和引用范围更新，不模拟一串 Backspace，也不先把来源绑定删掉再猜回来。

引用插入、标记移动、附件移除及关联编号整理分别是完整的撤销步骤。Ctrl/Cmd+Z 撤销，Ctrl/Cmd+Shift+Z 或平台现有重做键重做。既恢复可见文字，也恢复对象绑定、附件预览和光标；不能出现文字回来了、图片已经被释放的状态。

引用对象与对应编辑历史共享草稿生命周期。仍能撤销恢复的材料保留必要的草稿持有关系；历史丢弃或草稿释放后沿原引用生命周期清理，不建立永久的拖动日志或额外数据库。

图片准备、引用捕获和交互填入使用映射到编辑器事务的插入锚点。中文组词期间，插入在组词完成后提交；之后的文字编辑不会让位置失效。若编辑器已经卸载，结果只进入原草稿，不修改新会话的输入。

在同一 Host 切换会话、模式或临时卸载输入框后，恢复原草稿的对象、标记位置和编号。草稿持久化范围继续服从现有产品设置；本功能不承诺应用重启后的新型全量草稿恢复。

## 8. 发送给模型的内容

### 8.1 用户表达、引用材料与内部来源分开

输入同时保留三种东西，但用途不同：

| 内容 | 用途 |
| --- | --- |
| 用户写的正文及标记位置 | 保留用户实际表达和引用顺序，供历史显示与模型输入使用 |
| 固定摘录、图片、文件或交互结果 | 让模型直接理解用户所指的内容，或通过原文件能力读取 |
| 原消息、片段范围、作品修订、资源 owner 等内部来源 | 支持准确定位、资源持有、排队重试和历史恢复；不默认输出给模型 |

模型输入只在必要处标明“引用 Varin”“引用用户消息”“引用工具结果”等可读出处。已有用户原文保持用户身份，助手和工具的引用内容保持材料身份；引用里的文字不提升为新的系统指令。

不再发送 `Reference: chat-selection:UUID`、完整 `Source` JSON、来源证明和无用途的定位坐标。不用另一种长字符串替换这些字段，也不要求模型先调用工具解开一个引用点才能知道用户引用了哪句话。

### 8.2 保留正文中的位置

原生输入沿正文顺序投影。遇到文字引用，展开固定原文；遇到图片，插入对应图片内容；遇到文件，给出文件名和实际可读附件。没有正文标记但仍明确保留在附件区域的材料，接在正文之后。

例如草稿：

```text
[引用点1] 我同意这里，但结合 [图片1] 看，后半段需要调整。
```

模型侧的可读含义为：

```text
[引用点1 · Varin]
> 可以把搜索拆成两步。

我同意这里，但结合 [图片1]
（此位置携带实际图片内容）
看，后半段需要调整。
```

括号中的说明仅解释设计，实际请求使用模型接口支持的图片内容。用户消息在聊天中仍显示紧凑标记，点开才展开引用，不把这份模型投影原样铺成用户发言。

同一对象在一条消息里引用多次，第一次提供内容，后续保留同号标记即可，不重复图片载荷或全文。跨消息再次引用时，沿该条输入固定对应材料；不通过扫描模型上下文猜测是否“已经看过”而省掉用户显式引用。

`[引用点N]` 是本条消息内的可读对应关系，不是模型需要操作的数据库编号。只有模型实际需要读取文件、长结果等资源时，才使用原工具可消费的路径或简短引用。与[模型操作引用方案](collaboration-context-and-model-references.md)保持方向一致，但本功能不依赖先完成所有领域的 ID 改造。

### 8.3 内容大小与不同模型接口

用户选择的文本原样提供，不为引用设置新的硬切字数或固定 token 预算。长引用在界面折叠，模型请求仍走原有上下文容量处理。明确引用整轮时，可在预览里看到实际范围，避免误带进大量内容。

文件和原本外置的长工具结果沿已有材料／输出读取链交付，不为了把它们变成“引用”而全部解码进提示词。工具结果的可读投影保留实际状态、有效数据、原错误与必要续读入口；内部收据和路由信息由 owner 保存，不在引用层另做任意字段黑名单。

各 provider 按实际协议编码有序内容。支持图文交错时保留对应位置；接口只能分开传文字与附件时，用同一编号建立对应，沿适配器现有附件顺序交付。不能只发一个图片文件名却表示模型已经看到了图。

当前模型不接收图片时，保留原文件可读能力并在发送前清楚显示当前模型的图片限制，允许用户换模型或按原有文件方式发送。既不静默丢图，也不为了这一项禁止文件交接。

### 8.4 不增加额外推理和提示词约束

范围选择、来源固定、编号分配、图片准备和输入投影均由程序完成，不调用辅助模型生成摘要，不要求主模型补写来源说明。

既有上下文压缩继续自主整理输入。程序保存引用与历史资源关系，不给压缩提示词追加“必须保留每个引用点”的清单，不在后续每轮请求末尾重发引用总表。

## 9. 历史中的呈现与显式回复关系

发送后的消息在正文原位置显示可交互标记，附件区保留对应预览。只有少量文字引用时可显示一行紧凑摘录，长内容默认折叠。引用不强制把消息改成气泡，也不把大段原文复制成第二份常驻正文。

点击标记展开被引用的固定内容；“定位原处”跳到真实来源并短暂突出目标段落、工具或作品。来源不在当前已加载历史里时，沿现有历史加载能力定位，不为了一个跳转预载整个会话。

一条用户消息可以引用同一条回复的几段，也可以同时引用不同消息、图片和工具。记录这些明确的来源关系即可，不强行归成一个父消息，不据此创建新的任务、会话分支或自动话题树。

原内容后来被修改、删除或不再能定位时，已经保存的引用仍显示其固定内容，并说明原处不可定位。不能因为跳转失败就让用户消息变空，也不能把旧引用自动跳到同名的新内容。

引用内容本身再包含引用标记时，只保存用户明确选中的正文和必要对象，不递归展开整个引用链。没有隐藏地把前面一串对话重新灌入本轮请求。

## 10. 受理、资源与生命周期

### 10.1 草稿与提交的同一份内容

点击引用时固定文字和对象的实际来源。图片或文件的准备可能异步进行，仍绑定当时选择的对象；文件在取得固定内容前已经变化时，显示实际变化并让用户重新选取，不能静默换成最新文件。

发送时把正文、标记范围、引用对象和准备好的附件作为同一份输入受理。新会话发送、普通续接、子任务续接、排队和立即发送都使用同一合同，不在某个入口退回拼接来源 JSON。

排队后引用保持原内容与顺序。继续拖动草稿、修改交互选项、编辑图片或重新排序附件，只影响之后的输入；“立即发送”提升原排队输入，不重新捕获来源。

不确定重试复用原输入身份及冻结内容。成功回执只清理原批次的标记和材料，保留提交期间新写的文字和新增引用；准备或投递失败时保留可继续编辑和重试的原草稿。

### 10.2 复用原资源归属

客户端负责捕获选区、编辑标记和管理未发送草稿。Application Host 协调材料准备与已有资源读取，Rust Catalog／ContentStore 保存已受理输入、历史关系及资源持有。没有新的“引用服务”或第二套会话历史库。

文字引用可把固定摘录与原来源作为输入的一部分保存；图片、文件、HTML 快照沿原附件和材料 owner 保留。短暂浏览、折叠、拖动和预览关闭都不生成新的耐久快照。

已有固定资源重复引用时共享原内容。新引用只新增必要的关系，不复制整轮历史、整个目录或整份工作区。跨设备交付走已有附件转交机制，显示名和路径不承担资源身份。

分支、回退、恢复和用户消息编辑沿原输入关系保留引用；不能按当前工作区重新解释老文件，也不能把引用恢复为来源作品的最新状态。源消息被删除后，仍被目标消息引用的固定摘录和资源由原引用关系保留。

草稿、撤销历史、排队输入和正式消息分别持有自己需要的材料。原持有者释放后由既有回收路径释放不再使用的内容，不增加永久引用账本、固定保留期限或全库扫描。

### 10.3 跨模式与外部 Harness

Varin、工作台、IDE 中的原生聊天共享这套行为。协作输入需要引用时复用同一标记与附件能力，消息收件人与原协作 `replyTo` 仍由协作发送合同处理。

外部 Harness 使用自己的实际输入与附件能力：文本引用可以投影为可读摘录，支持的文件／图片由对应适配器交付。Varin 保存自己的引用展示关系，但不伪造对方内部的消息回复 ID。能力不支持时在相应引用上给出可操作反馈，不另建外部执行循环。

## 11. 实现结构与改造顺序

### 11.1 复用现有三层，而不是扩写提示词

**捕获层。** `ChatTextSource` 和 Markdown 渲染建立正文块到真实源片段的关联；文字选区继续利用 `chatSelection` 的源位置映射。图片、文件、交互和工具组件各自交付可引用对象，由同一个引用动作写入草稿。显示摘要与来源捕获分开，不能从摘要反推完整结果。

**编辑层。** `useThreadDraftStore` 保存本草稿的内容对象及正文位置，CodeMirror 用引用范围与原子标记维护编辑。现有 `ContentReference` 扩展实际缺少的文件和工具来源；图片也绑定到真实草稿对象。保留内部稳定身份，编号只是显示属性。清理 `lib/agent-editor` 中这类聊天引用的第二份可变列表，编辑器上下文、未保存缓冲等其他职责继续保留。

**受理与投影层。** `application-client` 在现有输入合同上表达引用对象与范围，Host 使用原资源能力准备材料，原生受理路径把它们和输入一起存入 Catalog／ContentStore。模型投影读取冻结内容，按顺序构成可读文本与媒体；历史 UI 读取同一输入的正文和引用关系。不要仅在前端删掉 JSON，随后又让历史失去来源。

引用位置、`@` 与技能等其他范围都相对于用户原草稿文本解释。模型侧展开引用发生在对应范围解析之后，不让插入的长摘录把其他引用的坐标整体错开。输入仍可用现有文本和范围结构实现，无需把整个聊天编辑器换成新的 AST 或第三方富文本框架。

原生模型输入的引用投影应有明确的单一实现入口。Provider 只负责把该结果编码成自己支持的消息内容；Host 不再另拼一份来源文字，UI 不再生成另一套模型提示词。外部 Harness 适配同一可读含义，保留其原生附件交付边界。

2. 接正文块、文字选区与整轮引用，完成输入框标记、预览及已发送消息定位。

这些步骤构成同一项完整功能。不能把只加一个引用标签、只有鼠标能拖或只处理普通文本称为本方案已经完成。

## 12. 旧数据与已有行为

已有历史正文按原内容保留，不扫描旧消息删除类似 UUID 的文字，不把旧 `Source` JSON 猜成新的回复关系。新增输入从受理开始保存清晰的内容与内部来源；确需持久结构变化时，由原 Catalog 升级入口自动完成。

现有草稿中的引用附件转成同一内容对象，在其原有位置可知时保留位置，没有正文位置时沿附件语义保留，用户可主动插入标记。旧图片标记仅在其现有图片绑定明确时转换；历史消息仍按原编号显示。

已有技能、目录和会话 `@` 引用继续表达自己的含义。引用消息不等于选择智能体、派发任务、授权执行或写入记忆，不给用户的新消息自动加上“继续这个任务”之类的固定措辞。

已有交互“填入输入框”继续产生可编辑文字。附带的固定来源改为本方案的内容对象；用户修改后的措辞保持其最终表达，旧快照仅作为引用材料。轻量交互无需升级成一个新的发送流程。

## 13. 行为验收与交付范围

按真实失败边界复用和补充少量测试，不以 DOM 类名、完整快照或重复构造字段作为主要验收。

| 场景 | 应有结果 |
| --- | --- |
| 选中局部文字、右键段落、明确引用整轮 | 范围分别准确；整轮各段保持实际来源，不混入隐藏工具和思考 |
| 多个引用与图片夹在正文中 | 标记、上方预览和模型实际收到的内容一致，顺序正确；来源 JSON 与内部 UUID 不作为额外说明发出 |
| 拖动跨行、边缘滚动、放回原处或 Esc 取消 | 无跳字与半个标记，取消恢复原位；一次移动对应一次撤销，空移动没有历史噪声 |
| 删除标记、移除附件、重排编号及撤销 | 位置与附件语义清楚，对象不串号；文字、附件和来源绑定能一起恢复 |
| 同一来源多次引用与剪切粘贴 | 每处可独立移动，实际材料不重复上传；纯文本粘贴不会被误识别成另一个真实对象 |
| 中文组词、输入建议、异步图片准备期间换会话 | 不打断原编辑，不改错草稿；`@`、`/`、Tab 与发送快捷键继续正常工作 |
| 引用文件、交互状态、画面和正在运行的工具 | 固定真实内容与状态；不冒充完整结果或自动执行；文件可实际读取，图片可实际查看 |
| 排队后修改草稿或点击立即发送，网络结果不确定后重试 | 使用已冻结的原输入，来源不漂移；成功只清理原批次 |
| 重新打开历史、分支、回退与原来源被删除 | 引用内容仍可展示；原处可用时能准确定位，不可用时不跳到另一个对象 |
| 浅色／深色、窄屏、触屏和键盘操作 | 标记清楚但不抢正文，预览与拖动可打断；没有额外横向溢出和滚动抢占 |

优先用编辑器行为测试保护原子移动与撤销，用一条真实输入投递链检查模型内容和内部来源的分离；附件、队列和恢复复用已有测试设施，围绕新关系补关键场景。仅做设计文档时不运行应用全量构建、平台打包或 UI 自动化。

实施完成后，将当前合同归入[交互内容](../interactive-content.md)、[工作台](../workbench.md)、[运行时](../runtime.md)及输入框模块说明，并更新本文状态。最终用户看到的是能准确选取、移动、预览和回复的引用；模型看到的是足以理解这次讨论的内容。
