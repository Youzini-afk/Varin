# Varin 2.5D 围坐小队：三案设计说明

状态：仅构图原型，父级已看三案；等待用户选择。未修改当前运行舞台、native层、public399、Varin原画或64领队库。比较板已冻结，不再覆盖。

## 三案如何选

- **A 开口议事圈**：后侧两队，身前一队。默认候选最稳，三项目归属清楚，Varin位于讨论中心。
- **B 错层拥簇**：一队较远，两队近景。前后感最强，适合宽桌面与用户偏好的“被团子围住”；需要更多下沿空间。
- **C 贴身浅弧**：左右低位与前侧收拢，景深较浅，适合桌边空间不足时的同一构图语法。不是恢复单侧三行。

三案同一人物360px、同一组真实头像。书、镜头、笔是构图fixture，说明不同工作角色可放小道具，不代表此时真实Host正在读写检索；接线时只有真实detail才使用对应工具，无detail为通用专注/整理动作。每队fixture两名孩子，不宣称运行中真实人数。

## 空间而非3D化

保留全部原2D脸与衣服路径。只使用位置、整体大小、投影与有限遮挡，不把头像拉成透视梯形，也不重画脸。

| 要素 | 规则 |
|---|---|
| 远近尺度 | 后队lead48–56px，前队62–76px；每队child约lead的45%画布尺寸，保持明确主次 |
| 落点 | 局部扁椭圆软影，近影略宽/深，远影更小/淡；不是发光卫星轨道 |
| z顺序 | 后队/其孩子→Varin→前队/其孩子；同队内部再按地面落点排层 |
| 遮挡上限 | 只能少量触及椅脚、靴缘、衣摆边缘；主/子脸、真实管理手势、笔电始终可读 |
| 运动 | 先停在稳定home，短弧靠近/返回，重心有一次轻收束；不连续公转、不全队同频漂浮 |
| 工作 | 主agent自己的页/笔/镜头局部动作，孩子与自己的lead有短交流，不围Varin共用一圈 |

A/C最后把后侧B孩子移到外侧，避免其脸被人物头发藏掉；A前景队上移12px，让少量靴缘遮挡真正建立前后关系。人物和头像原资源本身无像素修改。

## 稳定归属与汇报路径

项目/主agent使用真实thread/branch身份，孩子使用真实direct execution关系。每队有自己的固定home扇区，选项目不把A/B/C换成一排、不交换工作位。

- **Bot**：Varin是真统筹。实际管理事件触发“负责人/其摘要从本队靠近→在真实视线/掌心接触点停稳→Varin已绘管理cue→沿不同的小弧回本队”。不能为了好看从没有关系的队拿孩子，不能把数量下降当完成。
- **Agent**：用户直连主agent。相同围坐舞台和工作位；Varin只面向用户提醒。不得借用Bot的分派/收报告动作暗示她指挥了这项工作。待授权/待回答绑定真实项目，提醒不是代用户批准。
- 负责人暂离home时，孩子可以继续留本队工作，home保留轻队标与来源联系；不能clone第二个负责人。若选用整小队靠近，则全组仅在本队通道内移动，不穿其他队。二者必须在选定分镜中择一，不混播。

当前左右LISTEN原画只支持固定侧向关注区域，不假装能准确仰望/俯看任意后排。应把实际负责人或有来源的小摘要送到既定报告槽，再衔接真实cue；需要新方向时才另画，不变形旧原画。

## 桌边 / 裁切 / 多队

比较图的600×520面板只是设计画布，不宣称符合当前native surface。近景队在人物canvas下沿之外还需要约55–70px（以人物360px计）的落点/标签空间；当前native下沿约止于人物canvas底，不能照搬后直接裁掉前队。

选定后按以下顺序收拢：
1. 保持项目扇区和身份，先压同队孩子fan、降低装饰与地面联系线。
2. 再压近远距离，采用C的浅弧；不缩到脸/短名不可读。
3. 空间仍不足则该队保留真实lead+已知队数角标，显式检查才展开。未知队数不造“+N”。
4. 屏幕边缘只在该队原扇区内找安全落点；不得镜像Varin，亦不得因检查某项目把所有队重排。

大面积渐变地面只用于设计稿解释空间，生产优先保留局部软影，不给真实桌面铺一块不透明背景。

## 被提起时的避让 / 回位

本稿不伪造新的“被提起”身体帧；实际提起仍沿用已绘grab/landing路由。

- 收到真实drag_start立刻让出人物拖拽/触摸区域：停止当前队间交流轨迹与交接，保留各队事实。
- 队伍在自己的扇区短距离后撤/压成lead+小队角标，必要时中性淡去装饰；这是空间避让，不是任务结束。不得为了等120ms装饰动画而阻塞拖动。
- 拖动中不让团子反复追逐人物，不让前景团子穿过腿/凳子；边界变化只重新解空间约束。
- drag_end之后等待真实落地/回稳姿态，再沿短弧恢复相同身份的home和孩子fan。无庆祝勾，无新派发边缘；未知scope先静态恢复。

## 透明窗口工程边界

当前scene窗在人物窗上方：SVG内部可以排团子之间的前后，但不能天然被另一个人物窗遮住。图中真正“身后”的遮挡是设计合成，不是当前运行能力。

可行选项由core评估：
- 第一阶段让大部分深度发生在团子之间，人物交叠区域严格避空；依靠尺度、落影、弧线建立空间。
- 要实现真实身后遮挡，按实际已绘drawing identity取人物alpha建立behind-mask，身体换绘图时同步，不以60Hz传图；或使用独立后景层。
- 不允许只把团子平移穿过人物，再称作2.5D。真实手、脸、电脑的保护区域随实际绘图校验。
