# Layout-guided whole-phrase rough probe

Status: **unselected; rejected as continuous animation rough**. One generation only; no same-method retry. Public assets, runtime and old source archives unchanged.

## Different controlled method

The approved identity was inspected and supplied as design reference only. A separately reviewed low-elbow, eight-phase motion layout was inspected and supplied as the pose/occlusion reference. The prompt specified each phase, stable picture-right support, thigh load, picture-left release and side-edge route, independent return, true contact, and whole-body rough linework rather than finished pictures. Inputs and exact prompt are preserved with SHA256 in manifest.json. Output was viewed unmodified. No pixel compositing, rigging, interpolation, or image editing was applied.

## Observed result

- Eight cells and rough linework format were followed; character appearance remains broadly recognizable.
- Cells 1–2 reuse keyboard-hand topology instead of the guide's base-edge support. Thus the phrase does not begin from the requested common rest.
- Cell 3 raises the picture-right hand; cells 4–5 instead raise the picture-left hand. The supposed continuous support hand changes.
- Cells 4–5 move the palm above the screen in a wave, not the reviewed low-elbow side-edge route.
- Cell 6 is already back at a keyboard-like rest. It omits the specified independent lowering, finger approach and base-edge contact. Cells 7–8 do not recover that missing chain.
- Torso, neck and hair remain nearly repeated poses; body anticipation and sleeve/hair settling are not established by these drawings. A polished face is not the relevant missing component.

These are route/contact/topology failures, not merely insufficient frame count. No playback was fabricated from this board. Layout feasibility does not establish drawing feasibility.

## Consequence

This tested built-in generation method, even with a complete viewed guide and explicit phase constraints, did not provide the needed continuous rough drawings. Do not proceed to cleanup or create more independent peaks from this output. The next required capability is controllable whole-sequence animation drawing/correction: an animator or a verified pose/occlusion-constrained process able to retain one support topology and correct every transition. That capability has not been demonstrated here. Keep the layout as a motion specification and this output as failed-method evidence, not usable animation sources.

No new tool or production pipeline is assumed available. Any further approach must first explain how it enforces the failed constraints rather than simply restating them in another prompt.
