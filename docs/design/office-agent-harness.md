# 办公模式与浏览器、电脑协作能力设计

状态：2026-10-23 已接入内置浏览器、Office 文件能力和办公模式组合。设计时审阅的 Varin 源码基线为 `25f52fdec`；具体格式能力和渲染条件见[Office 格式 owner](../../packages/web/application-host/lib/office/DOCUMENTATION.md)。外部浏览器继续由实际接入的 Computer 适配器提供。本机未安装 LibreOffice，真实页面转换与公式重算尚未实机验证。

办公模式的目标是接手用户真实的材料和工作环境，完成资料处理、分析、创作、修改与应用操作，并让用户能够顺畅地继续使用成果。重点建设文件与文档能力、Browser Use、Computer Use，以及它们之间的连续工作体验。

科研和办公均不注入专门的模式提示词。模式负责默认能力组合、工具披露和预制目录，任务方法由用户需求、模型判断和实际发现决定。共享协作机制见[科研模式与 Agent 协作设计](research-agent-harness.md)。

## 1. 已确定的方向与范围

| 议题 | 设计决定 |
| --- | --- |
| 模式指令 | 移除平台自动生成的模式提示词；保留通用指令、用户配置、预制用途与工具说明 |
| 核心能力 | 文件与文档处理、浏览器操作、电脑操作都是办公的一等能力 |
| Agent 分工 | 调研 Agent、快速检索、现有 Worker；主 Agent 可以亲自完成全部工作 |
| 临时派发 | 沿用科研稿中的继承主模型、任务命名和可选历史继承，不增加临时选模目录 |
| 工作方式 | 允许随时阅读、讨论、计算、制作、修改和操作应用，不设置统一流程 |
| 连续修改 | 接着当前文件、页面或应用对象工作，准确保留用户已有修改 |
| 默认浏览器 | 优先接通 Varin 现有内置浏览器，复用 Electron 和现有界面 |
| 文件交接 | 浏览器、执行环境、桌面应用和任务成果使用已有资源与传输机制 |
| 结果呈现 | 延续现有聊天、侧栏、编辑器和工具展示，按成果类型提供合适的预览与修改入口 |
| 外部集成 | 按实际已连接能力使用云文档和业务系统，不预先为每类业务复制工具 |

本稿包含主 Agent 与子 Agent 的办公能力，不扩展为 Bot 长期管理、企业工作流编排或新一轮设置页重设计。通用披露与全模式发现改进见[通用模式设计](general-agent-harness.md)。

不新增统一配额、固定标签页上限、固定 Agent 数量、强制审批阶段或验证轮数。需要约束时，沿真实平台能力、原有权限和具体资源冲突处理。

### 1.1 用户需求

| 工作情境 | 主要摩擦 | 目标体验 |
| --- | --- | --- |
| 查找和理解材料 | 文件分散、版本不清、查到的片段难以继续阅读 | 找到具体来源与位置，继续查看上下文并比较资料 |
| 修改已有文档 | 已有结构、格式、批注和用户修改容易丢失 | 按段落、表格或页面局部修改，保留其他内容 |
| 创建报告或方案 | 材料、分析、表达与文件制作之间需要手工搬运 | 从已有材料完成可继续编辑的成果，用户可随时指导 |
| 整理和分析数据 | 字段含义、单位、公式和关联关系影响判断 | 读取真实数据与计算关系，使用实际计算环境处理 |
| 制作演示和图表 | 内容组织、模板、视觉表达与可编辑性需要兼顾 | 查看真实页面，调整局部对象，交付适合后续使用的文件 |
| 操作业务系统 | 信息在网页、文件和客户端之间流转 | 在实际登录环境中操作，文件能够直接交给下一步 |
| 接着已有工作继续 | 用户已打开页面、改过文件，Agent 容易另起副本 | 明确当前对象，读取最新状态并继续工作 |

这些情境可以交错出现。例如“根据销售数据准备汇报”会同时用到数据理解、分析、写作和演示制作。是否提出大纲、先做样例、组织协作，取决于任务和用户偏好。

### 1.2 用连续工作判断是否做好

初次生成文件后，用户应能自然提出“换成本月数据”“第二部分缩短”“按地区拆开这张图”“我改了第三页，接着做”。平台需要让模型定位真实对象、取得当前内容、进行局部修改，并把结果接回原来的工作位置。

用户要求原生可编辑成果时，文字、公式、图表和演示对象按实际格式能力交付。图片、PDF、HTML 和原生文件各有用途，交付形态以本次任务为准。

| `webfetch` 的 Electron 渲染使用独立离屏窗口与 `persist:varin-web-agent` | 静态材料获取与用户当前浏览器页面分别保留准确来源 |

## 3. 模式、Agent 和上下文

### 3.1 模式只组合能力

办公 focus 决定默认披露、预制目录和相关界面入口。它不改变历史所有权、文件来源、当前桌面、浏览器账号或基础执行权限，也不注入“你是办公助手”一类指令。

实现时移除当前自动生成 `work_focus` 文本的路径；保留 `agent_profile`、用户系统指令、项目约定和技能。模式切换按已有请求准备边界生效，已受理的请求继续使用其固定配置。

预制目录提供简短用途说明；成员默认说明保留理解目标、自主判断、协作和成果质量等通用原则。Worker 的说明不列举工作类型或领域。工具说明讲清输入、输出与实际能力。格式处理知识、模板用法和辅助脚本按需取得，不把所有格式规则复制进每轮上下文。

### 3.2 共享分工

| 配置 | 主要用途 | 模型与执行方式 |
| --- | --- | --- |
| 快速检索 | 围绕明确问题定位文件、段落、数据位置或已知事实 | 复用内部快速检索与 `explore` 配置；无需为每次查找建立正式协作成员 |
| 调研 Agent | 查找、阅读、比较和整理网络、项目、业务及其他资料 | 复用 `retrieval` / `retrievalAgent` 的拟定调整，与科研和 Coding 共享 |
| Worker | 围绕整体目标自主推进派发任务，交付可继续使用的成果 | 沿用现有 `worker` 预制、模型配置与继承规则，供通用、Coding、科研和办公共享 |

快速检索的办公能力需要覆盖实际可读取的资料，不把所有文件当代码处理。沿现有检索和工具执行路径增加可用阅读入口，不引入办公向量索引或另一套固定检索循环。

主 Agent 负责与用户讨论、理解任务并推进结果，可以直接操作浏览器、电脑和文件。复杂分析、独立构思或另一种表达方案可使用继承主模型的临时 Agent。模型配置留在设置和运行时，主 Agent 不需要知道每个预制绑定了哪个提供商。

Worker 沿用现有默认说明中理解整体目标、协调相关工作、依据发现调整方法和交付可用成果的原则，移除仅面向编程的措辞。目录短描述与成员默认说明分别承担选择配置和指导工作的职责；成员默认说明统一见[科研协作稿的指令设计](research-agent-harness.md#7-模式与指令的边界)，办公模式不另外维护一份。

Worker 不枚举具体工作，不按阶段或模型速度定义职责，也不新增“实践 Agent”预制或模型槽。用户已有模型、指令与工具覆盖保留，是否派发由当前任务决定。

派发沿用已有 `task`、可选预制和实例名称。科研稿提出的 `inheritContext` 供需要背景的工作使用；继续已有成员时沿用其自身历史。材料通过已有引用及共享机制交接，浏览器控制和桌面分配仍由相应资源 owner 受理。

### 3.3 当前对象与用户引用

用户发送页面、文件、选区或应用引用时，输入绑定其真实来源和捕获时的内容。首次上下文提供足够理解所指对象的信息，完整文件、页面或应用状态按需读取。

当前浏览器地址、用户选中的元素、文档段落、表格区域和幻灯片应使用各自实际可取得的位置。模型不必从一张截图重新猜出平台已经知道的文件或页面身份。

只关联用户本次引用或明确交给任务的对象。打开的全部标签页、整份工作簿和整段应用历史不自动复制到每个请求。用户后来编辑了内容，执行前按对象实际状态重新读取；固定引用仍保留原选取内容。

## 4. 能力组织与模型端披露

### 4.1 默认容易找到的能力

| 能力组 | 披露目标 |
| --- | --- |
| 资料与阅读 | 网络搜索、网页读取、文档概览/定位/读取、材料与已有资源 |
| 文件与计算 | 浏览和查找文件、文本读写、进程和终端、脚本组合执行 |
| 浏览器 | 实例/页面发现、打开与接续、页面读取、常见操作、画面与文件交接 |
| 电脑 | 当前可用电脑与应用、观察、控制/交还、输入，以及子任务原有申请入口 |
| 成果 | 文档和表格等格式能力的用途入口、查看已有成果、继续修改 |
| 协作与交流 | 派发、通信、等待与结果，问答和已有工作状态工具 |
| 发现与扩展 | `tool_describe`、`tool_invoke`，用户实际配置的 MCP 与扩展能力 |

已有工具使用原声明和参数。浏览器与格式处理的新接口属于待实现能力，本稿中的能力名称不代表它们已经注册。具体工具拆分按执行对象、返回形式和常用操作确定，不以工具数量为目标。

Browser Use 与 Computer Use 的入口直接可见；核心操作涉及的前置能力也应能够顺畅取得。例如需要桌面控制时，相关发现、观察和原有子任务申请入口一起可达，不让模型只看到一个无法使用的点击函数。

低频网络诊断、站点存储管理、设备模拟、格式专用高级操作、文件恢复、环境安装和低频调度按需披露。模板、格式知识和脚本可作为现有技能/资源的一部分使用。公共网络搜索继续使用现有服务，登录后的网站内搜索由实际浏览器页面完成。

### 4.2 一个可执行目录

完整工具目录、用户显式选择、模式默认披露和本次模型函数列表分别有清晰含义。Host 准备真实能力，Rust 请求使用固定的声明与实现；工具执行校验与提供给模型的函数来自同一份准备结果。

没有直接声明的工具，经已注册的通用入口调用。读取工具说明不会使其名称自动变成模型可以直接调用的函数。发现结果给出完整调用方式，避免再次出现“看到了工具名称，却返回未注册工具调用”的错误。

格式、应用和平台能力应如实披露：可读取、可局部编辑、可渲染、可重算等分别来自实际后端。不可用组件给出原因和能继续使用的入口，不让一个可选组件失败阻断整个办公请求。

发现过程的分组、说明、相关能力查询和错误反馈采用[全模式共享的改进](general-agent-harness.md#6-全模式共享的发现与结果改进)。办公保留自身默认披露侧重，工具说明不增加固定工作步骤。

## 5. 文档、数据与演示能力

### 5.1 读取与修改的共同路径

文档能力围绕实际文件或应用对象提供概览、定位、局部读取、修改、预览和导出。新建文件与修改现有文件都需要覆盖。

| 对象 | 读取时保留的信息 | 修改与交付重点 |
| --- | --- | --- |
| 文本文档 / DOCX | 标题层级、段落、列表、表格、相关样式、页眉页脚和可取得的批注 | 修改指定对象，沿用现有模板与结构；按后端能力处理修订和批注 |
| 工作簿 / XLSX | 工作表、区域、表头、数值、公式、单位与数字格式、关联表和图表 | 正确区分公式与结果，保留工作簿结构，局部修改和真实重算 |
| 演示 / PPTX | 页面顺序、对象、文本层级、图表、图片、母版/主题和备注 | 修改指定页或对象，沿用模板，保留实际可编辑的文字与图表 |
| PDF 与扫描材料 | 原页、正文位置、表格、图片及解析/OCR 的实际结果 | 复用现有阅读能力；填表、批注、抽取或转换按具体可用能力处理 |
| CSV、JSON 等数据 | 字段、数据范围、编码、缺失项和原始值 | 在实际计算环境中处理，输出对应的数据或工作文件 |

阅读概览不自动展开整个文件。模型可以按结构、关键词、工作表区域或页码继续读取，返回实际范围和可继续操作的位置。格式解析不完整时，保留已读取内容，并指向原页、图像或实际应用。

定位信息绑定本次读取的对象版本。重新排序、插入行列或用户编辑后，旧的位置要重新核对；同一数字页码或单元格地址不能代替对象来源与当前状态。

### 5.2 保留已有工作的价值

已有文档里的字体、列表、表格布局、模板、图表和批注都是用户工作的一部分。局部修改应保留无关内容。所选引擎无法保留某种实际对象时，返回具体能力缺口，选择能处理该对象的应用路径或按用户要求进行转换。

用户提供参考文件时，从参考中取得实际样式与结构，再用于当前成果。无需为了复用模板新建模板平台；沿现有文件、技能和资源管理入口保存用户明确希望复用的内容。

同一成果继续修改时沿原资源和当前修订操作。另存为、生成对外版本或提供不同方案时再建立新文件，避免每次操作都留下完整副本。

### 5.3 工作簿计算

读取同时区分公式本身、当前显示值或缓存值，以及实际重算状态。不能把一个旧缓存值当作修改公式后的新结果。

公式计算交给支持相应能力的实际计算引擎或办公应用；通用数据处理可以使用 Python 等执行环境。二者结果保留来源，不自建覆盖全部工作簿语义的公式计算器。

字段清洗、统计与图表制作应保留数据位置和单位等必要信息。所做修改返回受影响区域、公式或数据变化，模型据此判断分析结果，不要求每次生成统一审计报告。

### 5.4 预览与文件格式

文字结构、公式结果和实际页面各自提供不同证据。排版变化看对应页面，计算变化看公式与结果，文字修改核对对应段落；验证强度随真实改动选择。

预览使用实际生成或编辑后的文件。HTML 预览、原应用画面和转换出的 PDF 标明各自来源；导出时仍返回用户要求的格式。

不同引擎的字体和版式可能有差异，预览应记录实际渲染后端。依赖特定应用版式的任务，通过该应用查看最终页面，不把另一个引擎的图片当作该应用的真实结果。

### 5.5 可用的执行环境

提供可复用的文档处理环境、辅助脚本和格式组件，避免模型在每次任务中从头寻找解释器、猜测库或重复安装。

组件按其实际用途准备，能力发现说明当前 Host 上可使用什么。基础材料读取、数据处理、Office 格式操作、OCR、渲染和应用桥接分别管理，不能为了读一份普通文件预热全部组件。

具体库与应用版本在实现时按读取、局部编辑、格式保留、渲染与平台支持选择。优先使用成熟库和原应用能力，终端保留处理未封装情况的自由。没有安装完整办公套件的环境，仍可使用已经准备好的文件处理能力。

## 6. Browser Use

### 6.1 目标与现有浏览器复用

内置浏览器成为真实、可接续的任务环境。用户可以打开网站、登录、查看执行中的页面，把当前页或元素交给 Agent；Agent 可以在后台处理页面，用户需要时进入同一页面查看和操作。

优先保留 `BrowserResourceView` 的地址栏、导航、外部打开、标注和侧栏/编辑器入口，接通其真实页面身份。已有 `persist:varin-browser` 登录态继续可用，不为了新的 Agent 接口另开一份看起来相同但需要重新登录的浏览器。

页面执行生命周期逐步归入浏览器 owner，UI 作为该页面的视图。切换聊天、折叠侧栏或 UI 暂时卸载，不能意外销毁仍被任务使用的页面。确实需要替换 webview 承载方式时，保留上述产品行为与实际会话数据。

当前 `webfetch` 离屏渲染继续负责获取网页材料。用户要求操作某个已打开页面时，使用该页面；普通抓取不会隐式使用用户所有浏览器账号。远端桌面上的 Chromium 仍由对应 Computer/浏览器适配器拥有。

### 6.2 浏览器、标签与观察身份

每个实际实例明确执行端、浏览器会话和页面身份。页面引用在导航后仍可指向同一标签，元素引用和观察则绑定相应页面状态。

| 身份 | 用途 |
| --- | --- |
| 浏览器实例 | 区分本地内置、已接入的外部浏览器或远端浏览器及其原执行端 |
| 会话 / profile | 保留实际登录态；不同会话的数据不因同一 URL 自动合并 |
| 页面 / 标签 | 所有读取、输入和文件操作的明确目标，独立于用户当前查看的页面 |
| 页面观察 | 保存这次读取的内容、范围与状态，供后续定位和解释 |
| 元素 / 区域引用 | 指向真实节点或观察中的区域，不能在重新编号后暗中指向另一个对象 |

模型可以选中页面后使用返回的引用；工具调用始终携带或在原调用绑定中固定该目标，不依赖跨任务共享的全局“当前页”。两个 Agent 操作不同页面可以独立推进；同一页面发生冲突时按实际目标协调。

元素身份优先使用浏览器节点、框架身份和可验证定位信息。导航、节点替换或引用失效时，返回真实状态和重新观察入口。不要用“第 N 个元素”在下一次快照里继续解释旧操作。

### 6.3 观察接口

页面观察可以取得正文、交互控件、表单状态、相关框架、局部结构和图像。读取范围由具体操作选择：概览、正文、指定区域、查找结果或实际画面。

模型看到控件的真实名称、角色、状态和必要关联。例如输入框的标签、值、是否禁用，表格的表头和当前显示范围，弹窗与其控件的关系。实际可访问性信息、DOM 信息和布局分别使用，不能把人为猜出的角色标为浏览器原生返回。

页面正文、操作对象和截图互相补充。无视觉能力的模型仍可使用可读内容与结构；需要视觉判断时返回实际图像媒体块，复用现有 provider 媒体处理。

iframe、Shadow DOM、滚动容器、虚拟列表和富文本区域纳入观察与操作设计。虚拟列表中尚未加载的数据按实际范围返回，允许继续滚动或查询；截图坐标与页面缩放、滚动和视口绑定。

动作后默认返回相关变化和可继续操作的状态。需要时再请求完整观察，避免一次操作重复返回全文、全部元素、语义副本和整张图。分页与截取应保留结构和续读方式，不以截断 JSON 代替页面结果设计。

### 6.4 操作能力

基础操作覆盖导航、点击、双击、悬停、滚动、输入/替换、键盘组合、选择、勾选、拖拽、弹窗和文件选择；结构定位、图像定位与页面脚本都可以参与。

浏览器输入应产生实际支持的事件与焦点行为。面向标准控件的结构化赋值可以保留，但结果要明确其操作方式；不能把脚本 `element.click()` 命名成可信原生点击，或把对 `value` 的赋值视为覆盖所有编辑器的输入。

遇到画布、自定义控件或缺少结构的页面，可以在当前页面内使用视觉和坐标操作。支持明确等待页面、元素或下载状态；等待条件来自本次任务和实际动作，不要求每步固定延迟。

页面脚本为模型提供灵活处理入口，沿原工具执行机制使用。浏览器协议适配负责目标选择、输入、等待与状态返回，不额外引入一个替模型决定站点工作流程的规划器。

实现优先复用 Electron 的 Chromium、CDP 和适用的成熟自动化库。驱动选型要确认能够连接现有受控页面、处理框架和输入，并维持同一用户视图；不要为使用一个库默认下载和启动另一套浏览器，也不从零重写通用定位与等待引擎。

### 6.5 用户查看、参与和交还

Agent 的执行目标独立于用户当前查看的标签，后台操作不反复切走用户视图。用户点击工具记录或页面入口时打开同一目标。

对同一页面需要协调输入时，只协调实际冲突的操作。只读观察、模型思考和其他页面不持有整张桌面的控制权。页面内用轻量状态指示当前操作者和停止/接手入口，避免用大遮罩长期挡住页面。

用户主动接手时结束后续自动输入，保留页面和已完成效果。Agent 继续前观察用户修改后的状态，不重放旧坐标。登录或验证码需要用户参与时，沿现有等待与用户交互能力展示实际页面；用户完成后继续原任务。

目标关闭、导航失败、渲染进程退出或客户端断开时，工具返回对应对象的状态。取消请求、输入已停止、网页异步操作完成分别记录；某次提交结果不明时，先读取当前状态或原操作回执，避免重复提交。

### 6.6 与 Computer Use 和外部浏览器的关系

内置浏览器的页面操作不要求先占用整个物理桌面。它仍复用原 Thread、Run、工具授权、取消和结果机制；需要原生窗口或文件选择器协作时，再进入对应 Computer 能力。

外部 Chrome/Edge 等浏览器是同一类接口的可扩展适配来源。接入时返回实际实例和用户选择的会话，不声称已经拥有系统浏览器登录态；当前第一条实现路径是内置浏览器。

没有本地浏览器的 Web/远端 Host，可以使用实际已连接的浏览器执行端。不能静默换到另一个环境继续使用不同账号；执行位置和资源交接在能力准备时明确。

### 6.7 infOS 研究的取舍

本轮研究了 infOS 的生产浏览器工具链。值得采用的机制包括 Electron 内置 Chromium、持久浏览器会话、用户与 Agent 共用页面、目标页与可见页分开、文字和截图配合，以及能力在线后再披露。

| 观察到的实现问题 | Varin 的对应设计 |
| --- | --- |
| 操作依赖全局活动目标，多任务可在切页与点击之间交错 | 每次操作明确绑定浏览器和页面 |
| 快照按当前排列重新编号，旧编号可能改指新元素 | 页面状态和元素身份可验证，失效后重新观察 |
| 原生点击、Shadow DOM 等描述超过当前驱动实际实现 | 工具声明与真实驱动能力一致，补齐复杂控件路径 |
| 原始结果和语义 scene 重复返回，每个动作多次完整观察 | 以相关内容和实际变化组织返回，需要时扩大范围 |
| 上传 token 缺少任务文件生成入口，下载尚未接入任务成果 | 文件从原资源 owner 交接，上传下载形成可继续工作的引用 |
| 以页面关键词阻断所有动作、以一般页面变化标记验证成功 | 页面内容按来源处理，回执描述实际效果，业务判断由任务承担 |
| 有表单规划与网页能力编译代码，但未接入当前生产工具链 | 不把这些模块当作已验证基础，也不为办公另建站点工作流引擎 |

这些取舍来自源码阅读，不是对真实网站完成率的测量。完整实现与实际网站行为仍需在对应阶段验证。

## 7. Computer Use 与应用内办公

Computer Use 延续现有 ComputerService、native driver、输入队列、控制权、子任务请求和远端路由。办公模式让这些能力更容易使用，不改变已受理操作的所有者。

主 Agent 和子 Agent 都可以按任务操作应用。子 Agent 沿原有分配机制取得目标；已经成立的授权继续有效，不因每次工具调用或切换办公模式重复询问。

### 7.1 观察与操作

观察返回当前应用、窗口、实际控件信息及必要截图。操作目标绑定原窗口与观察，键盘、鼠标、剪贴板、滚动或应用接口按实际平台能力执行。

Windows/macOS 当前没有完整 Office 结构桥。设计应同时推进可用的文件处理与原生应用操作，适合具体应用的结构接口可以按需接入；能读取应用中未保存内容的适配器应明确返回该状态。

通用电脑操作用于客户端、原生对话框、专用业务软件和需要实际应用呈现的工作。当前平台不支持某项应用结构读取时，使用实际可用的屏幕与控件观察，或回到相应文件处理路径。

物理输入占用与后台工作区分：真正需要桌面输入时协调控制权；文件处理、后台浏览器操作、模型推理不持有桌面输入锁。用户打断后按现有交还机制结束后续输入，再次接续取得新观察。

### 7.2 跨环境协作

文件/进程来源、浏览器执行端和 Computer 桌面可能在不同机器。沿现有 `computer_environment` 等状态入口说明它们各自在哪里；模型不能把同名路径当成同一个文件。

例如本地 Windows 下载的报表要交给远端环境分析，需经过原传输能力；远端产生的结果再回到本地应用时同样取得明确文件引用。UI 在需要用户判断时显示执行位置，常规操作无需用户理解内部 Host ID。

## 8. 文件流转、成果身份与生命周期

### 8.1 下载、处理、上传是一条连续路径

浏览器下载关联原页面、调用和实际文件状态，区分开始、进行中、完成、失败和取消。完成结果提供已接入资源体系的文件引用，后续文档/文件/终端工具能够直接使用。

上传接收现有文件、任务附件或成果引用，解析实际字节与目标执行端。必要的暂存和跨 Host 传输由原资源 owner 处理，模型不需要猜测私有目录或手工制造上传 token。

选择文件、浏览器开始发送、网站接受文件可能是不同阶段。回执返回已观察到的状态和后续查询方式，具体任务需要时继续核对目标页面。

典型使用路径：

```text
业务网站下载报表
  → 已关联当前任务的文件
  → 文档/数据工具读取与计算
  → 更新当前工作簿或汇报文件
  → 浏览器上传同一成果引用
```

每步可以暂停、由用户接手或改换方法，已有文件与页面继续可用。

### 8.2 当前成果与历史引用

预览、下载、外部打开和后续修改关联同一成果及其实际修订。用户查看的是最新成果时，继续修改基于当前状态；历史消息绑定的固定修订仍保留其原内容。

成果清单展示文件名、类型、位置和实际变化。派发交接沿现有来源、材料共享和文件机制进行；同一文件同时被多个成员或用户修改时，沿原 revision/外部变更语义处理。

用户不需要为每次导出建立新项目或 Git worktree。无项目任务需要文件时沿现有来源准备机制创建可用的工作位置，不在浏览器或文档组件中另外建立隐藏工作区。

### 8.3 回收与存储

浏览器 profile 和用户保留文件是可长期使用的资源；截图、渲染页、下载暂存和转换中间文件各自有执行与引用生命周期。

任务删除、成果删除和原有资源回收需要涵盖这些新增引用。仍被其他任务、用户成果或打开页面使用的资源保留；未引用的临时内容沿既有 owner 回收。

不要每次编辑、观察或派发都创建完整文件副本，也不新增一套永久浏览器操作大正文账本。已有 Catalog 保存调用和必要引用，原资源保存字节；缓存可以按需重建。

关闭侧栏不关闭仍在执行的页面。临时页面在没有任务使用后可以释放，用户明确保留的页面继续存在；不照搬固定五分钟回收、固定八标签之类产品限制。

## 9. 界面、交互与动画

### 9.1 沿用现有工作台

办公成果使用现有侧栏和编辑器组。浏览器沿用现有 BrowserResourceView；文档、工作簿和演示增加适合自身的预览适配，不重做新会话和整体聊天布局。

聊天继续支持三种阅读模式、独立子 Agent 行、已有思考摘要和轮末操作/用量。工具标题从真实页面、文件、应用和操作参数提取摘要，不要求 Agent 额外编写装饰性标题。

办公工具展开后按用途显示：表格看区域与变化，文档看段落或页面，演示看当前页，浏览器看目标页面和相关结果，Computer 看窗口与操作状态。完整参数和原回执保留在已有详情入口。

### 9.2 引用与连续修改

保留当前页面元素标注和截图附件，在其受理链中增加真实页面/观察身份。原生格式预览逐步支持段落、单元格区域和幻灯片引用，选中的内容进入当前输入草稿，由用户决定何时发送。

Agent 修改后的预览保留用户当前页、缩放、选区或滚动位置；仅在该对象确实失效时重新定位。后台更新不抢焦点、不覆盖输入框草稿。

用户从工具行进入成果时，打开已有的对应视图；必要时定位受影响区域。查看历史修订和当前成果有明确区别，不在不同入口生成互相脱节的副本。

### 9.3 执行状态与动态效果

短操作使用轻量行内状态；长下载、转换或计算显示后端实际进度，没有进度证据时只显示正在执行。等待用户、失败、部分完成和结果不明保持清楚区别。

展开/收起沿现有高度与透明度过渡，完成状态接替运行状态时保留行和页面位置，避免整个成果区域重新挂载闪烁。预览长内容在适合的视图中滚动；表格本身需要横向阅读时保留区域滚动，不让整个聊天被撑宽。

浏览器输入协调采用不遮挡主要内容的状态提示。切换到前台查看保持原页面，停止和接手动作及时反馈；减少动态效果偏好沿现有设置生效。

## 10. 实现归属与共用机制

| 责任 | 实现位置与原则 |
| --- | --- |
| 模式、预制和配置 | protocol 的 focus/presets/model slots；Host 原有准备；设置与 i18n |
| 工具发现与执行 | 原注册声明、扩展服务和 Rust ToolDirectory；复用科研披露调整 |
| Thread、历史和调用 | Rust Catalog 继续拥有 Run、Operation、状态与结果身份 |
| 文件与传输 | 原 Rust Storage、文件、物化与计算 owner，复用资源引用、恢复和回收 |
| 格式处理 | Host 通过已有执行/扩展机制准备引擎；外部程序写入与结果回执纳入原资源操作 |
| 浏览器协调 | 可信 Host 组合能力和真实任务；Electron/其他适配器拥有实际浏览器实例与页面 |
| 电脑操作 | 现有 ComputerService 与原 native driver、控制权及远端路由 |
| 用户界面 | application-client 的类型化接口，UI 视图、附件与预览；renderer 不拥有特权写入 |

Electron 只提供浏览器实例、原生页面和平台执行适配，仍由同一 Application Host 接入运行时。新浏览器服务不成为第二套 Agent 后端、文件存储或任务调度器。

二进制办公文件不强行进入仅面向文本的 DocumentsAPI；读取/变更通过正确的文件与格式适配路径。现有文本编辑仍使用 Document Registry 与 Documents 的缓冲、revision 和保存语义。应用内未保存文档由实际应用拥有，不能用磁盘上的旧内容覆盖它。

浏览器 profile、网页沙盒与应用主页面保持现有可信边界。通用网页不取得 Varin 的 Host 凭据或主页面 preload。浏览器接口返回实际能力和状态，权限继续来自用户授权及原有资源机制，不用页面文本关键词另造一套普遍审批流程。

## 11. 实现组织

以下按可交付能力组织，阶段用于开发依赖和审阅，不限制用户工作顺序。

| 实现单元 | 完整交付内容 | 主要依赖 |
| --- | --- | --- |
| 共享模式与协作 | 办公 focus、移除模式提示词；复用 Worker 并移除编程限定，不枚举其工作类型；共用调研及历史继承设计 | protocol、Host context、原生派发 |
| 能力目录与披露 | 真实可用工具、默认组合、按需说明、直接/通用调用一致 | 原工具目录与请求准备 |
| 文件和格式能力 | 文档、表格、演示的读取/局部修改/预览/导出；可复用处理环境 | 原资源与进程 owner、格式适配器 |
| 浏览器执行 | 接通现有页面；明确页面身份；结构与视觉观察；可靠输入和用户接手 | Electron 浏览器适配、Host、UI |
| 文件交接 | 上传下载接任务文件，跨执行端传输，成果修订和临时资源回收 | 原存储、传输和成果入口 |
| 电脑与应用衔接 | 现有 Computer 操作进入办公常用能力，准确处理窗口、未保存内容与交还 | ComputerService、平台驱动 |
| 成果交互 | 对应预览、引用、连续修改、实际进度、定位与动画 | 现有聊天、侧栏、编辑器和附件 |

文件能力与浏览器执行可以分别推进，但每项交付都包含调用、结果、继续使用和失败后的可恢复状态。不能只接一个工具名称或只能展示静态初稿就宣布该项完成。

实施前需要沿具体代码确定的局部事项：现有 webview 的后台生命周期与受控连接方式；格式引擎的对象保留和重算能力；浏览器下载如何进入原资源 owner；原生应用的未保存文档访问方式。它们影响适配选择，不改变本稿的产品目标。

## 12. 验收情境

验收检查实际行为，复用已有测试与最有价值的实机情境；不要求每行新增测试，也不建立新的强制评测系统。

| 情境 | 需要成立的结果 |
| --- | --- |
| 切换科研或办公模式 | 变化来自能力组合，没有额外模式提示词，用户配置继续有效 |
| 快速定位与深入调研 | 使用共享配置，任务深度不同但资料和执行能力可组合 |
| 同一预制派发两个不同工作 | 展示任务名称、稳定身份和各自结果；模型绑定按已保存配置 |
| Worker 在不同模式中使用 | 保留现有预制与配置，默认说明保持开放，不新增实践预制或模型槽 |
| 修改已有 DOCX 的一段和一张表 | 对应部分改变，无关结构和样式保留，能够继续修改 |
| 更新工作簿中的数据与公式 | 公式、结果和重算状态清楚，图表及关联区域按实际修改更新 |
| 修改已有演示的某一页 | 目标页和对象可定位，预览实际文件，交付可编辑格式 |
| 用户在原应用里继续编辑 | Agent 读取当前对象，不覆盖未保存或后来产生的修改 |
| 接手内置浏览器里已登录页面 | 使用同一页面和登录态，用户可随时查看与接手 |
| 两个 Agent 分别操作两张页面 | 每次操作目标明确，切换和点击不会串页 |
| 动态插入元素、导航或页面重建 | 旧引用失效或重新核对，不暗中改指其他控件 |
| 富文本、iframe、Shadow DOM、画布 | 实际支持路径与工具说明一致，可使用结构或视觉操作 |
| 网站下载、计算、文件修改后再上传 | 文件引用跨步骤连续，能定位实际文件和上传状态 |
| 用户接手、取消、断开或提交结果不明 | 停止状态与实际效果清楚，继续时取得当前状态，不盲目重复提交 |
| 本地文件与远端桌面配合 | 执行位置明确，必要传输完成后使用正确文件 |
| 关闭面板、切换聊天、删除任务 | 活跃工作不因视图卸载中断；资源按引用与所有者回收 |
| 缺少某个格式组件或视觉能力 | 已有文字、文件及其他操作继续可用，返回具体能力缺口 |

文档阶段只核对现状引用、设计一致性和本地链接。功能实施后按对应 owner 选择必要的协议、行为和实机验证，证据范围与结果一并说明。
