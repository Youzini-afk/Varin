# 外部 Agent 输入框：后续演进

状态：2026-11-05，连接准备、空闲回收、能力缓存、默认值、统一工具栏与协议上下文已接入实现。
当前行为与边界见[外部 Agent](../external-agents.md)。原设计来自 [#275](https://github.com/Youzini-afk/Varin/issues/275)，历史方案及 codeg `769610c6` 的源码比较保留在 Git 中。

## 保留的产品边界

- 外部 Harness 拥有其执行循环、原生会话和账号。Varin 不创建伪原生 Thread 或 Run，不读取其他 Harness 的私有会话文件来补统计。
- 控件选择固定在下一条耐久受理的输入中，不立即写入运行中的会话；后续改选不重新解释已排队消息。
- 新草稿使用 Host 中明确配置的默认值，否则沿用 Agent 自己的配置；不保存“上次使用”的选择。
- 观察、取消意图与实际进程退出是不同事实。空闲回收等待 Rust 进程所有者确认停止，保留原绑定和来源；恢复不重放已投递的副作用。
- 版本相关能力缓存只用于候选显示，不能作为实时就绪或发送凭据。未知上下文不估算，用量不替代窗口占用。

## 失败分类与配置变化提示

这些是后续交互，不属于本轮输入框实施范围：

- 按连接、登录、额度、请求拒绝、服务故障分类，提供相应的重试、登录或新会话动作。当前状态行保留真实错误及明确登录入口，不把所有失败自动归类。
- 在进程启动后检测启动配置或可执行文件变化，提示“重连以应用”。运行中的轮次禁止重连；配置改变不重写已受理输入。

需要验证的边界包括多客户端同时改配置、程序路径不变而版本更新、旧连接迟到事件、待答交互及后台子任务。配置变化提示与能力缓存的版本失效是两个合同，不能用缓存已经失效来宣称用户已看到变化提示。

## 适配层继续单独演进

输入框只展示实际适配器与协议提供的能力，不把预设或版本检测解释为逐后端兼容性认证。
以下仍需分别设计和验证：

- 各 Agent 的环境变量策略、版本固定安装与更新、非浏览器登录，以及 Grok 的专用问答与退出计划模式处理。
- Antigravity 当前通过自定义 ACP 接入；没有专用预设与逐后端验证时，只展示实际协商的数据。
- CLI、Skills、MCP 对外能力共享继续按此前决定暂缓。ACP 会话的 `mcpServers` 仍为空，不自动修改外部程序的全局配置。
- 首字延迟、输出速度与工具耗时需要可信时间来源，本轮不从界面计时推导这些指标。
