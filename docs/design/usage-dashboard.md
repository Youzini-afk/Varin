# 设置 · 用量

状态：2026-11-01 已实现。当前职责与入口见 [运行时](../runtime.md)和[工作台](../workbench.md)。[usage-preview](usage-preview/index.html)保留设计参考（示例数据；顶栏可切换桌面/手机、明暗和各种数据状态）。

## 1. 这一页回答什么

按用户打开这一页时最先想知道的顺序：

1. 这段时间大概花了多少钱，用了多少 Token。
2. 花在哪：哪个模型、哪个渠道、哪类工作、哪个对话或 Bot。
3. 哪天异常，趋势怎样。
4. 这个数字有多可信：哪些请求没报告用量，哪些模型没有价格，订阅和本地模型怎么算。

“后台工作”和“缓存省下多少”两项单独给出：Varin 会在用户没发消息时整理上下文、写标题、建索引，这些调用需要可见；缓存命中是 harness 节省的直接证据。

## 2. 当前实现

**价格目录。** Application Host 沿原 models.dev 刷新和离线快照读取价格，复用模型身份宽匹配；保留缓存、推理及多个上下文分档。`ChannelModel.pricing` 和 `billing` 可在模型详情编辑，目录价格与自定义覆盖有明确来源。价格进入真实请求绑定，并接到模型选择器的费用提示。

**用量记录。** 原生执行 owner 在原回执事务中写入不含内容的 `usage_records`，保留时间、来源、用途、计量方式和价格快照。ModelStep 和辅助推理都按实际请求计量，自动重试逐次记账，不能拿多个请求的累计输入选择单次长上下文价。同一次请求随回执细化更新，已确认未派发时撤回。删除原生对话后保留统计元数据。`runtime.usage.summary` 按时间索引读取，释放 Catalog 锁后计算；`runtime.thread.usage` 继续读取原分支回执。旧记录缺少可靠的完成日期，因此不会伪造日期导入新账本，界面标明有日期记录的起点。

**界面。** 设置已注册 `usage` 页，包括移动端入口；分支用量面板和轮末脚注保持原有语义。全局页使用真实统计、状态和账户配置，预览中的示例数值不进入应用。外部 Harness 的单轮、最后请求及累计口径独立于原生合计。

## 3. 位置

设置导航 Agent 组，紧跟「模型服务」之后：slug `usage`，标题「用量」，图标 `bar-chart-2`。桌面、网页和移动端都提供。单栏页面，宽度用 1200px 的宽页（含图表和表格）。

对话里的用量面板保持分支级，不改。设置页是 Host 级，两者互相链接：设置页「对话」明细的每一行可以打开该对话的用量面板。

## 4. 页面结构

沿用设置的版式和存储页的数字呈现（大号合计 + 构成条 + 两栏图例）。从上到下：

1. **标题与操作。** 「用量」+ 一句说明；右侧「导出 CSV」。
2. **范围控制。** 统计当前实际选中的 Agent Host，显示其 API origin，并可进入工作连接页；Host 切换复用现有连接机制。时间范围：7 天、30 天、本月、上月、90 天；右侧度量切换：费用 / Token。度量切换作用于合计、构成、趋势和明细。日期边界由实际客户端提供，处理夏令时和非整小时时差。
3. **合计。**
   - 大号数字：估算费用（或 Token），后面是日期范围和“较前一段 ±x%”。
   - 一行事实：Token、请求数、缓存命中率、缓存省下的钱、后台工作占比。
   - 构成条和两栏图例：前 6 个模型，其余合为“其他”；费用口径下标明「未计价」，不为未知费用编造占比。
   - 可信度说明，只在出现时显示：未报告的请求数；未计价模型及其 Token；订阅和本地模型的 Token（及订阅按 API 标价折算的参考值）。合计不完整时数字旁加“+”。
4. **每日趋势。** 按天堆叠柱，颜色与构成条一致；右侧给日均和最高日。悬停显示当天构成、请求数、未报告数和未计价模型；点击一天，明细只看这一天（出现可清除的日期标签）。今天用虚线框标“仍在累计”；有未报告请求的日子在柱顶标“?”。按本机时区切分日期并写明。
5. **明细。** 标签页：模型、渠道、用途、对话。排序：费用、Token、请求数。
   - 模型：一行是“渠道上的一个模型”，与对话用量面板的分组一致。列：请求、输入、缓存读取、输出、费用（带占比细条）。展开后显示未缓存输入、缓存读写、输出、推理、缓存省下的钱，所用单价及来源，以及实测 / 估算 / 未报告的请求数。
   - 渠道：按渠道汇总，副标题列出模型。
   - 用途：对话（含队友）、上下文整理、代码检索、规划、标题与摘要、记忆与知识嵌入、图像、MCP 采样；后台类标「后台」，并提示可在对应设置页为它们换更便宜的模型。
   - 对话：按对话（含 Bot 和定时任务）汇总，队友的请求计入派出它的对话；每行可打开该对话的用量面板。
6. **价格。** 价格目录来源和更新时间（可刷新）；没有价格的模型及原因，入口跳到模型服务填写价格；订阅与本地的计法说明。
7. **外部 Agent。** Codex、Claude Code、Pi 各一行：自报 Token 和轮数，由各自账号计费，不进入上面的合计。累计口径单独说明。
8. **统计范围说明。** 页面底部一句：覆盖哪些工作、外部 Agent 另列、未报告不按 0 计。

## 5. 状态与诚实性规则

- 这一页按已结算请求统计，进行中的原始回执仍在分支用量面板中查看。实测、估算和未报告保持区分，确认未派发的调用不计为付费请求。未报告不当作 0，合计不完整时显示“+”并说明原因；全部未知时显示「—」。
- 费用永远叫“估算费用”：按请求当时的标价计算，不含折扣、批量价、中转加价和税费，以服务商账单为准。
- 没有价格显示「未计价」，不显示 $0；订阅显示「订阅」，本地显示「本地」。三者的 Token 照常计入 Token 口径。
- 读取中：状态文字“正在统计这段时间的用量…”（设置里没有骨架屏，沿用现有写法）。读取失败：错误说明 + 重试，并说明已有记录不受影响。没有用量：空状态提示换范围或开始一次对话。
- 页面打开时跟随新的请求更新（沿用对话用量面板的观察游标），不轮询。
- 颜色只区分系列，含义都有文字；颜色沿用存储页那组低饱和色，明暗主题各一套。

## 6. 移动端

单栏：分段控件可横向滚动；合计、构成条，图例改单列；趋势图保留全部天数，点按一天查看构成；明细标签可横滑，每行只留名称和费用，下面一行写 Token 和请求数，展开后显示完整明细。导出 CSV 只在桌面和网页提供。

## 7. 费用怎么算

**价格来源**，优先级从高到低：

1. 用户在模型服务里为某个模型填写的价格（和其他目录字段一样，作为覆盖保存）。
2. models.dev 目录中匹配到的价格（沿用现有的模型匹配规则，匹配不唯一时不取价格）。
3. 都没有：未计价。

**计费方式**按渠道类型确定：按 Token 计费；订阅（OAuth 和各类编程套餐）；本地（Ollama、LM Studio、本地组件）。只有第一种计算费用。

**单次请求费用**（单价为美元每百万 Token）：

```
未缓存输入 = 输入是否包含缓存 ? 输入 − 缓存读取 − 缓存写入 : 输入
费用 = 未缓存输入 × 输入价 + 缓存读取 × 缓存读取价 + 缓存写入 × 缓存写入价 + 输出 × 输出价
```

- “输入是否包含缓存”按协议族确定，沿用 `providers/mod.rs` 里已有的口径（Anthropic 分开报告，OpenAI Chat/Responses、Google 等包含在内）。
- 缓存读取或写入价缺失时按输入价计，并在明细里标注。
- 推理已包含在输出时，单列推理价替换该已知子集的普通输出价，不重复相加；缺少该子计数或包含关系不明时保持费用未知。
- 长上下文分档价：目录给出分档且请求输入超过阈值时使用该档。
- 缓存省下的钱 = 缓存读取 × (输入价 − 缓存读取价)。

**价格冻结。** 每次请求的原绑定和账本保留价格快照及其内容摘要，目录变价不改写已定价记录。用户为尚未计价的账本记录补填价格后，可按现价估算并标注，原回执仍不改写；多个别名对应不同现价时保持未知。没有可靠时间的旧回执保留在分支用量中。

## 8. 实施取舍

- Rust Catalog 拥有按请求保留的统计元数据；对话删除后仍可读取这些不含内容、标题的记录。
- 使用价格来源的 USD 单位，不内置特定用户的货币、汇率、渠道价格或时区。
- 订阅 API 标价折算显示在对应明细中，不进入按 Token 计费的费用合计；本地模型另列。
- 桌面和网页提供 CSV；移动端复用读取与页面，隐藏导出操作。
- 预算、额度和提醒不在本轮范围，不新增请求、日期范围或并发配额。

## 10. 不做的事

- 不读取服务商的账单接口，不声称与账单一致。
- 不在页面里轮询，不在后台为统计发起任何模型请求。
- 不把未知、未报告或未计价当作 0，不按模型名称猜测渠道或价格。
