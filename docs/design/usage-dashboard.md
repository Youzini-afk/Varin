# 设置 · 用量

状态：2026-10-30 设计提案，尚未实施。交互预览见 [usage-preview](usage-preview/index.html)（示例数据；顶栏可切换桌面/手机、明暗和各种数据状态）。

## 1. 这一页回答什么

按用户打开这一页时最先想知道的顺序：

1. 这段时间大概花了多少钱，用了多少 Token。
2. 花在哪：哪个模型、哪个渠道、哪类工作、哪个对话或 Bot。
3. 哪天异常，趋势怎样。
4. 这个数字有多可信：哪些请求没报告用量，哪些模型没有价格，订阅和本地模型怎么算。

“后台工作”和“缓存省下多少”两项单独给出：Varin 会在用户没发消息时整理上下文、写标题、建索引，这些调用需要可见；缓存命中是 harness 节省的直接证据。

## 2. 现状（已核对源码）

**models.dev。** Application Host 每 6 小时拉取 `https://models.dev/api.json`（`packages/web/application-host/lib/models/directory.ts`），失败时保留上一份，离线用内置快照。解析（`directory-models.ts`）只保留上下文和输出上限、输入模态、推理与思考选项、tokenizer 和兼容字段；`cost.*` 在解析时丢弃，内置快照 `directory-snapshot.ts` 也删掉了 `cost`。models.dev 的 v1 API 提供 `cost.input`、`cost.output`、`cost.cache_read`、`cost.cache_write`、`cost.reasoning` 等字段，单位是美元每百万 Token。模型选择器里有一个“每百万 Token 费用”提示（`ModelPickerList.tsx`），但传入的数据恒为空，从不显示。

**用量记录。** Rust Catalog 在原始执行记录里保存 `UsageReceipt`（`kernel/crates/varin-runtime/src/execution.rs`）：输入、输出、缓存读取、缓存写入、推理 Token，以及实测 / 估算 / 缺失。`pricing_version` 字段已预留，生产代码里恒为 `None`。读取只有分支级的 `runtime.thread.usage`（`catalog_usage.rs`），按种类、渠道、模型和计量方式分组；没有时间戳、没有时间范围、没有跨对话查询。辅助推理的用途（标题、嵌入等）在汇总时统一归为 `auxiliary`。重试的各次尝试合并成一条回执。外部 Agent 的用量作为不透明 JSON 存在 `external_turns`，不进入上述查询；Codex 有时只报告整个会话的累计值，ACP 不报告用量。

**界面。** 对话的用量面板（工作台服务 → 用量，`ThreadTokenUsage` / `ThreadUsageView`）和每轮用量脚注已有；设置里没有用量页，全局用量和费用都不存在。

## 3. 位置

设置导航 Agent 组，紧跟「模型服务」之后：slug `usage`，标题「用量」，图标 `bar-chart-2`。桌面、网页和移动端都提供（移动端需加入 `MOBILE_SETTINGS_PAGES`）。单栏页面，宽度用 1200px 的宽页（含图表和表格）。

对话里的用量面板保持分支级，不改。设置页是 Host 级，两者互相链接：设置页「对话」明细的每一行可以打开该对话的用量面板。

## 4. 页面结构

沿用设置的版式和存储页的数字呈现（大号合计 + 构成条 + 两栏图例）。从上到下：

1. **标题与操作。** 「用量」+ 一句说明；右侧「导出 CSV」。
2. **范围控制。** Host 选择（与存储页相同）；时间范围分段控件：7 天、30 天、本月、上月、90 天；右侧度量切换：费用 / Token。度量切换同时作用于合计、构成条、趋势图和明细。
3. **合计。**
   - 大号数字：估算费用（或 Token），后面是日期范围和“较前一段 ±x%”。
   - 一行事实：Token、请求数、缓存命中率、缓存省下的钱、后台工作占比。
   - 构成条和两栏图例：前 6 个模型，其余合为“其他”；费用口径下未计价模型用斜纹，标「未计价」。
   - 可信度说明，只在出现时显示：未报告的请求数；未计价模型及其 Token；订阅和本地模型的 Token（及订阅按 API 标价折算的参考值）。合计不完整时数字旁加“+”。
4. **每日趋势。** 按天堆叠柱，颜色与构成条一致；右侧给日均和最高日。悬停显示当天构成、请求数、未报告数和未计价模型；点击一天，明细只看这一天（出现可清除的日期标签）。今天用虚线框标“仍在累计”；有未报告请求的日子在柱顶标“?”。按本机时区切分日期并写明。
5. **明细。** 标签页：模型、渠道、用途、对话。排序：费用、Token、请求数。
   - 模型：一行是“渠道上的一个模型”，与对话用量面板的分组一致。列：请求、输入、缓存读取、输出、费用（带占比细条）。展开后显示未缓存输入、缓存读写、输出、推理、缓存省下的钱，所用单价及来源，以及实测 / 估算 / 未报告的请求数。
   - 渠道：按渠道汇总，副标题列出模型。
   - 用途：对话（含队友）、上下文整理、代码检索、规划、标题与摘要、记忆与知识嵌入、图像、MCP 采样；后台类标「后台」，并提示可在对应设置页为它们换更便宜的模型。
   - 对话：按对话（含 Bot 和定时任务）汇总，队友的请求计入派出它的对话；每行可打开该对话的用量面板。
6. **价格。** 价格目录来源和更新时间（可刷新）；没有价格的模型及原因，入口跳到模型服务填写价格；订阅与本地的计法说明。
7. **外部 Agent。** Codex、Claude Code、Pi 各一行：自报 Token 和轮数，由各自账号计费，不进入上面的合计。累计口径单独说明。
8. **统计范围说明。** 页面底部一句：覆盖哪些工作、外部 Agent 另列、未报告不按 0 计。

## 5. 状态与诚实性规则

- 实测、估算、未报告、进行中、未派发分开计数；未报告不当作 0。合计不完整时显示“+”并说明原因。
- 费用永远叫“估算费用”：按请求当时的标价计算，不含折扣、批量价、中转加价和税费，以服务商账单为准。
- 没有价格显示「未计价」，不显示 $0；订阅显示「订阅」，本地显示「本地」。三者的 Token 照常计入 Token 口径。
- 读取中：状态文字“正在统计这段时间的用量…”（设置里没有骨架屏，沿用现有写法）。读取失败：错误说明 + 重试，并说明已有记录不受影响。没有用量：空状态提示换范围或开始一次对话。
- 页面打开时跟随新的请求更新（沿用对话用量面板的观察游标），不轮询。
- 颜色只区分系列，含义都有文字；颜色沿用存储页那组低饱和色，明暗主题各一套。

## 6. 移动端

单栏：分段控件可横向滚动；合计、构成条，图例改单列；趋势图保留全部天数，点按一天查看构成；明细标签可横滑，每行只留名称和费用，下面一行写 Token 和请求数，展开后显示完整明细。导出 CSV 只在桌面和网页提供。

## 7. 费用怎么算

**价格来源**，优先级从高到低：

1. 用户在模型服务里为某个模型填写的价格（和其他目录字段一样，作为覆盖保存）。
2. models.dev 目录中匹配到的价格（沿用现有的模型匹配规则，匹配不唯一时不取价格）。
3. 都没有：未计价。

**计费方式**按渠道类型确定：按 Token 计费；订阅（OAuth 和各类编程套餐）；本地（Ollama、LM Studio、本地组件）。只有第一种计算费用。

**单次请求费用**（单价为美元每百万 Token）：

```
未缓存输入 = 输入是否包含缓存 ? 输入 − 缓存读取 − 缓存写入 : 输入
费用 = 未缓存输入 × 输入价 + 缓存读取 × 缓存读取价 + 缓存写入 × 缓存写入价 + 输出 × 输出价
```

- “输入是否包含缓存”按协议族确定，沿用 `providers/mod.rs` 里已有的口径（Anthropic 分开报告，OpenAI Chat/Responses、Google 等包含在内）。
- 缓存读取或写入价缺失时按输入价计，并在明细里标注。
- 推理 Token 计入输出；只有目录单列推理价、且该协议不把推理计入输出时才单独计价。
- 长上下文分档价：目录给出分档且请求输入超过阈值时使用该档。
- 缓存省下的钱 = 缓存读取 × (输入价 − 缓存读取价)。

**价格冻结。** 每次请求在派发时绑定当时的价格快照（目录版本或自定义价格的摘要 + 各项单价），写进回执的 `pricing_version` 和新增的价格字段，之后目录变价不改写历史。早于本功能、没有价格快照的记录按当前价格估算，并标注“按现价估算”。用户为未计价模型补填价格后，过去的请求按新价格补算并同样标注。

## 8. 需要的工作

**阶段 1：价格进入模型目录。** 解析 `cost.*`，重新生成带价格的内置快照；`ChannelModel` 增加价格和计费方式字段及覆盖语义；模型服务的模型详情显示并可编辑价格；模型选择器的费用提示接上真实数据。

**阶段 2：记录补全。** 用量回执写入完成时间和价格快照；辅助推理保留具体用途，不再统一成 `auxiliary`；记录对话、项目、Bot、预设（Agent）等归属。按存储所有者的升级规则处理旧记录，旧记录缺的字段保持“未知”，不推断。

**阶段 3：读取与页面。** Rust 读模型（例如 `runtime.usage.summary`）：时间范围、时区、按天分桶、按维度分组，返回已知值和未知计数；合并外部 Agent 用量；Host 与 `application-client` API；设置页 UI、CSV 导出、多语言文案和用户指南。全量扫描过慢时再加可随时重建的缓存，它不是权威记录。

**之后：** 预算与提醒（月度预算、80% / 100% 通知），先不做。
