## 设计判断

设置需要让用户辨认对象、理解当前值、顺畅地完成修改。已有页面中，主题与聊天预览、模型品牌和完整模型详情、Agent 头像、项目分栏、Skills 原文编辑、存储分类及清理预览都有可以延续的基础。本次先保留这些基础，再重做页面内的信息层次和操作路径。

视觉上延续 Varin 的深色中性色、细线图标、克制边框与紧凑控件。页面的设计感来自内容关系：正文编辑器获得阅读空间，服务列表突出品牌和模型，存储突出数据构成，连接页突出位置和状态。普通开关不需要独立容器；多个字段也不必为了对齐强行挤进相同的两列表格。

每页先回答用户眼前的问题，再展开需要配置的内容。例如「模型服务」先列自己已经接入的服务，「外部隧道」先显示当前入口，「记忆」先展示已经记下的内容，「对话默认」先说明下一次对话会用哪个模型。

## 1. 外壳、目录与阅读节奏

### 外壳

正式产品保留现有设置模态外壳。桌面左侧目录约 220px；右侧上方显示当前位置和作用域，内容自行滚动。当前编辑单元的保存区固定在内容底部，只有需要显式提交时出现。

HTML 顶部的「桌面 / 窄窗 / 移动」「明 / 暗」「设计与覆盖」属于评审工具，不进入产品。图稿将设置单独铺开，便于评审；不要求生产界面切换为另一个全屏工作台。

普通表单阅读区约 1,040px；带效果预览、对象列表或正文的页面可以使用约 1,200px。短值控件采用局部对齐；路径、规则和正文上方放标签，输入空间随内容展开。页面变窄时允许说明换行，避免长注册名和路径撑破布局。

页面标题只出现一次。标题说明管理对象，副标题简述用途；章节之间用留白与细线区分。章节内的相关控件靠近，弱化重复说明，防止每一行都成为视觉重点。

### 目录与搜索

保留当前四组导航：使用偏好、AGENT、开发与项目、连接与扩展。组可以折叠；选中页在导航滚动后仍有清晰位置。重做布局不改变字段 ID、权限或后端配置名称。

搜索覆盖页面名、能力名和已有别名，例如「OCR」「Tokenizer」「重试」「保留期限」。正式实现沿已有设置搜索注册，结果应定位字段并展开所属章节。对象内字段还需选中所属对象；不能为了展示结果而修改当前服务或模型。

设计稿提供目录搜索与代表字段定位。真实目录的数据驱动搜索和跨对象定位仍需接入产品注册表；稿内静态别名表不进入生产。

### 三层信息

1. **当前选择与动作**：模型、来源、开关、对象名称、资源大小、当前连接、待处理错误。
2. **帮助完成决定的信息**：继承来源、保存和生效时机、必要依赖、清理影响、某状态的观察时间。
3. **配置与排障细节**：原始 JSON、Tokenizer、协议兼容参数、连接日志、资源标识、诊断详情。

层级由用户任务决定。模型提供商需要路径配置时，路径就是当前任务的重要字段；不能因为它含有技术术语就一律藏深。未配置的辅助模型、不可用的动态网页渲染、阻止全部域名的空白允许列表也必须直接解释。

## 3. 关键操作流程

### 模型服务：保留品牌与完整编辑

服务列表每行显示品牌标识、服务名称、地址摘要、模型数量和启用状态。启用开关只表达配置意图，不能变成未经观测的「连接正常」。

点击服务后先看到模型集合；连接与认证、请求参数在同层入口。模型详情继续提供名称/实际 ID、操作类型、上下文与输出容量、图片/思考能力、Tokenizer、协议与兼容参数。目录跟随值和用户覆盖值可区分，恢复目录值说明会恢复什么。

详情侧边保留模型预览与测试区；测试使用当前草稿，展示这次请求的结果、耗时与错误。测试失败保留输入；测试成功不额外制造持续健康状态。窄屏时测试区成为详情后的一个完整区域。

服务是保存单元。模型详情返回服务目录仍保留草稿；离开服务或切换主机时处理未保存内容。认证继续使用该服务类型支持的方式和凭据引用，已有密钥不回显。增加服务的选择器应由现有类型目录生成，不能按图稿中的六个示例硬编码支持范围。

「默认对话模型」「Agent 与辅助任务」提供用途导航；正式实现沿原用途配置写入。本次不引入新的账号管理实体、第二份用途映射或反向绑定数据库。

### 偏好与预览：改变能看见的结果

主题、聊天、通知、编辑器和终端适合在编辑时立即看到效果。预览使用静态示例数据与正式组件，不发送模型请求、不生成隐藏会话。

聊天三种模式使用同一段内容，便于比较信息如何排列。继续保留独立子 Agent 行、可展开的过程、思考阅读窗口、左操作右用量的轮末行。缓存数据只在存在时显示。新会话首屏不在此改版。

### 上下文比例条：压缩准备与替换是两个位置

预留比例确定切换压缩结果的边界。`readContextPolicy` 先按模型窗口计算预留 token；原生 `native_mode` 将可用输入预算定义为窗口容量减去预留量。估算输入超过该预算时进入阻塞压缩流程，需要发布可用的压缩结果后继续；结果尚未准备好则等待。

图稿使用与代码一致的默认值：预留 10%，替换边界约为整个窗口的 90%。页面保留“准备水位 75%”这一配置值，旁边直接注明“按可用输入预算计算”；条上显示换算后的全窗口位置 67.5%，并标注为准备基准。图稿调整不修改产品默认值或用户配置。

后台准备基准由 `harness.context.preparationWaterline` 决定，当前默认 0.75，分母是**可用输入预算**。以整个窗口为横轴时：

- 替换位置 = 100% − 预留比例。
- 后台压缩基准位置 = 替换位置 × 准备水位。
- 默认预留 10%，替换位置 90%；准备水位仍为 75%，其全窗口位置为 90% × 75% = 67.5%。

运行时 `PreparationTiming::waterline` 根据压缩耗时、上下文增长速度与已知待处理量，可能把后台准备提前。设置比例条必须写“基准”，不能把一个静态点冒充当前会话的精确触发位置；有真实运行观测时再显示额外的实际位置。这里只展示配置，不显示虚构的实时上下文用量。

条内依次显示继续使用当前上下文、后台准备区、预留区。两个标记均可鼠标或触摸拖动，放大命中区域，悬停、焦点和拖动时显示明确反馈。下方提供精确数值输入：准备水位以可用输入预算为分母，替换位置以整个模型窗口为分母；配置值与换算位置同时可见。

拖动准备标记时换算并更新准备水位；拖动替换标记时更新预留比例，准备水位保持不变，因此准备标记随之按比例移动。拖动过程中只更新预览，松手确认一次修改；Esc、触摸取消、失去捕获或窗口焦点时恢复拖动前的值，避免中间值反复保存。方向键按 1 个百分点微调，Shift 配合方向键按 0.1 个百分点微调。拖动采用 0.1 个百分点的操作步长，精确输入仍接受协议允许的小数；这不是新的配置精度限制。展开说明提供内部比例关系。

当前协议要求预留比例在 [0,1)，准备水位在 (0,1)。界面据此提示非法数值，不另加固定百分比间隔。关闭后台准备时，隐藏其标记、禁用其数值，保留替换边界；需要替换时仍走原有压缩流程。模型级覆盖、项目继承、token 取整和扩展预算策略继续由原配置及运行时处理，界面不能直接覆盖有效策略。

实现依据：`packages/web/application-host/lib/kernel/context-settings.ts`、`kernel/crates/varin-runtime/src/context_capacity.rs` 的 `native_mode / PreparationTiming`，以及 `packages/protocol/src/compaction-settings.ts` 与 `harness-settings.ts`。这里扩展的是设计稿；产品上下文设置和运行行为未修改。

### 记忆与 Skills：给内容完整的编辑位置

记忆以正文为主，来源信息次之。点击编辑后，该条目原位置切换为编辑器；原只读副本不重复保留。其他条目保持当前位置；编辑区随文字增长，在合理高度后内部滚动。保存成功恢复阅读，失败保留草稿。新增记忆明确当前作用域。

Skills 继续保留目录与原始文件编辑。内置、用户和项目资源显示真实来源及可写性；只读项提供复制到可写范围的入口。资源刷新冲突应显示文件版本变化，提供重新加载与保留当前草稿的选择，不能静默覆盖。

系统提示词的自定义内容与组合预览分开。用户可以编辑自己的指令；系统身份、工具声明和组合来源明确只读。各层之间可以导航，不把完整系统提示词误当成一个可写大文本框。

### 规则与请求策略：顺序必须可见

权限保留模式、工具、决定、可选参数名与匹配表达式，以及从上到下的规则顺序。图稿将规则压成可读列表，单条进入编辑器，支持上下移动。项目约束在规则下说明，文件/进程的资源准入范围保持原语义。

当前权限页逐条校验后即时提交；本稿提议将规则列表改为一个可审阅的本地草稿，保存时仍提交同一份 rules。默认模式与规则应明确分属各自提交单元，不能因重排规则暂存而拖延模式反馈。这个保存体验调整需要在产品实现时明确完成，不能仅隐藏现有自动保存提示。

对话重试保持现有 enabled、maxRetries、initialDelayMs、maxDelayMs、rules。规则继续使用 field、match、pattern、action 和真实匹配顺序；错误样例检查应调用现有检查能力。高级区只隐藏少用的匹配细节，启用状态、次数和等待仍可直接看到。

### 存储：从构成到可清理对象，再到真实结果

保留六类实际 inventory：恢复与工作状态对象、独立工作副本、会话与附件、记忆与知识向量、共享模型资源、其他应用数据。当前设备、工作区与共享范围始终明确。

清理预览先列出具体对象、预计释放量和保留原因。正在占用、共享引用、待发布的副本等必须使用存储领域提供的判断。没有统计就显示「尚未统计」，不填 0 B。

执行期间留在当前清理流程，显示仍在进行的阶段；完成回执区分已释放、保留、失败与待重试。失败项使用原清理身份重试。页面刷新和切换范围不重复提交清理。实际释放量与预览值分别标明。

会话删除与关联资源回收仍由同一领域生命周期串联；设置 UI 展示结果，不能自己新增删除路径、定时器或垃圾回收器。

### 连接、MCP 与扩展：围绕具体对象

工作连接关系图只表达已有位置事实：此界面、Agent 主机、文件来源与桌面。切换工作连接不改写已经受理会话的固定来源。

SSH、直接 Host、配对设备和隧道各自保留真实流程。配置保存、连接、认证完成、安装成功和实际运行是不同事件，反馈靠近触发的对象。等待与失败时不要整页清空；显示最近可用内容及其观察状态。

MCP 的工具目录说明来自当前连接还是缓存。授权按钮绑定所选服务；保存 JSONC 不显示为授权成功。结构化编辑和原始 JSONC 必须共享同一文档草稿，切换视图不能产生两份待保存数据。

扩展管理保留期望启用状态与实际运行状态。候选审阅、权限决定、应用候选、重启与恢复沿原生命周期。服务路由和工作台扩展集有各自明确的应用动作。工作台 Shell、服务替代与 Agent 执行身份继续独立。

## 4. 范围、草稿和状态

### 范围按字段实际归属呈现

导航分组不是配置作用域。页头只给整体定位；混合页在具体编辑单元说明它保存在哪里。

- 此设备的外观/聊天偏好不随 Host 选择迁移。
- 主机全局的 Harness 配置显示当前主机；项目只读有效覆盖不自动变成项目可编辑页。
- 项目、提示词、记忆和资源文档只在实际支持的范围提供选择。
- 项目覆盖可查看来源并「使用继承值」；不能把复制当前默认值叫作恢复继承。
- 远端实例、凭据、配对和文档各自沿原持有者保存。

HTML 中的 Host 选择用于演示上下文，不代表新增全局范围选择器。生产实现不得把所有页面无条件绑定同一个 Host 状态桶。

### 保存与切换

| 操作 | 用户反馈 |
| --- | --- |
| 单一即时偏好 | 控件就地更新，收到确认后短暂提示已保存；失败保留并说明 |
| 服务/文档编辑 | 固定保存区显示当前编辑单元；可以保存、取消 |
| 独立配置组 | 保存按钮在该组结尾，名称包含所保存的对象 |
| 离开未保存编辑 | 保存后离开 / 放弃更改 / 继续编辑；草稿仍属于原对象 |
| 保存失败 | 错误留在保存区，草稿保持可编辑，重试使用同一对象 |
| 主机不可达 | 保留上次内容并说明；恢复后确认版本再提交 |
| 远端文档变更 | 展示冲突来源，允许比较新版本并保留草稿 |
| 重启或下一轮生效 | 生效条件紧邻保存单元，确认后继续显示必要提示 |

异步回执必须按 Host、对象与版本归属处理。切换对象后的迟到响应不能覆盖当前页面；相同原则适用于探测、模型测试、下载与清理回执。

### 状态的视觉表达

正文色用于用户当前要读的内容；次级灰用于来源、时间与解释。绿色只用于已有成功事实，橙色用于待处理，红色用于真实失败。显示文字，不只靠颜色。

「已配置」「已启用」「等待授权」「已连接」「最近使用」「未探测」「连接失败」「版本冲突」保持不同含义。对象行上的状态负责概括，详情负责说明原因与下一步。原始错误位于可展开的技术详情里，直接影响处理的原因留在外层。

HTML 的「设计与覆盖」提供保存失败、主机不可达、清理部分完成、快捷键冲突、MCP 等待授权的代表场景。下载、系统通知、原生目录选择、真实 OAuth 和配对二维码等平台动作在稿中仅展示入口及流程说明；正式交互复用现有实现。

## 5. 动态、键盘与窄窗

动效围绕正在变化的内容，减少整页跳动：

| 场景 | 动作 |
| --- | --- |
| 展开依赖或高级区 | 高度与轻淡入一起变化，约 180–220ms；附近内容自然让位 |
| 对象切换 | 更新详情，保留目录和浏览位置；不让整页滑走 |
| 原位编辑 | 原正文区域切换，焦点落到正文；保存后回到同一条目 |
| 保存区出现 | 内容区域预留位置，底部轻出现；按钮不覆盖最后一行 |
| 状态更新 | 状态文字在原位置变化；无需重复播放整页进入动画 |
| 减少动态效果 | 尊重系统设置，停止位移动画，保留状态说明 |

以上时间是视觉起点，不是协议约束。内容高度变化需要照顾滚动锚点；用户正在编辑时不要把焦点抢到后台状态。

目录、分组、Tab、对象行、展开区和操作都可由键盘到达。焦点有明确轮廓，开关有完整名称，冲突和错误可被辅助技术读到。关闭局部对话框后返回触发按钮。长工具名、路径、模型 ID 支持换行或局部省略后查看完整值。

正式移动端沿现有「目录 → 子目录/对象 → 内容」导航。HTML 的移动预览用可展开目录压缩呈现这个关系，仅展示空间适配方向。生产页面需要保留返回路径、当前对象、保存区和草稿，避免直接把桌面分栏缩小塞进去。快捷键等平台不适用页面沿已有条件隐藏。

## 6. 与现有代码的连接

### 现状依据

- 导航与搜索：`packages/ui/src/lib/settings/builtin-page-metadata.ts`、`SettingsView.tsx`、`surface-registry.ts`，以及内置扩展注册。
- 配置字段和作用域：`packages/application-client/src/settings-catalog.ts`；Harness 页沿 `useHarnessSettings` 读取有效值并写入规定范围。
- 模型服务：`providers/ModelConnectionsPage.tsx`、`ModelConfiguration.tsx` 和 `application-client/src/model-connections.ts`。
- 资源与生命周期：`AgentMemoryPage`、`AgentPromptPage`、`NativeResourcePage`、`StorageSettings`、`McpConnectionsPage`、`RemoteInstancesPage`、`ExtensionsPage`。
- HTML 的「设计与覆盖」逐页列出当前组件位置，供进入实施阶段定位；组件路径属于开发说明，不显示在产品页。

### 工具目录必须先解决的真实问题

当前 `ToolsSettings.tsx` 硬编码了 `bash / grep / get_output / write_to_process / kill_shell / diagnostics / apply_patch` 等旧键。现行原生目录使用 `file_read / file_search / file_write / process_spawn / process_read` 等名字。

`extension-tool-owner.ts` 按扩展实际注册名读取 `harness.tools`；原生目录由 Rust `ToolKind`、运行组装与 Agent 的 `allowed_tools` 管理。因此这些旧键没有形成对应原生工具的有效开关。

新页面需要来自真实注册目录的能力投影，并明确全局可用性、Agent 工具选择和权限策略各自的持有者。具体配置控制必须完成运行时接线后才能显示为有效开关。只替换 UI 标签无法修复这个问题。本稿仅记录并设计入口，尚未修改这条产品调用链。

### 实施时的边界

共享组件负责排版、焦点、展开、草稿和错误展示；领域页面负责依赖、来源与操作含义。避免把所有页面塞进不断增加布尔参数的万能设置行。

保留原 Provider/auth、Host/trust、resource revision、扩展生命周期及平台能力。新增视觉状态必须有实际数据来源。设计不要求加入后台健康轮询、自动测试模型、第二份配置、独立回收服务或新索引。

进入实现阶段时，首先完成外壳与公共阅读规则，再按领域迁移完整页面和状态。每次迁移要同时保留搜索、范围、可用条件、保存、生效和返回路径；不能为了统一样式删掉原来能力。聊天和已认可的新会话不在这一轮重做。
