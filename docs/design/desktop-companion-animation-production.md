# Varin Q 版桌宠：完整动画与制作方案

状态：整体设计提案。角色、默认配色、坐姿电脑工作与提起换位沿用已确认设计；下述动作资源、制作工程和运行时接口尚未完成。现有试样证明部分图层可连续驱动，不代表最终动作质量通过。完整体验覆盖已整理；选择全帧原画与有意义中间画的连续制作路线，实际美术质量仍需逐组验证，不能用工具选择冒充质量已通过。

本稿接续[状态与产品蓝图](desktop-companion.md)、[默认色分镜](desktop-companion-assets/SHOT_PLAN.md)及[桌宠制作调研](desktop-companion-animation-research.md)。目标是先设计完整体验、资源依赖和制作方法，再按明确的整体方案分批生产。**分批提交是保存进度，不是把目标缩为一个示范动作，也不是做完一段再临时决定余下内容。**用户已授权自主推进，完整体验与制作路线经内部评审后即可实施，不再把每个制作阶段变成等待用户确认的关卡；新付费工具、额外许可等仍单独处理。

## 1. 完整体验与全帧原画制作路线

采用**全帧关键原画 + 有意义的中间画 + 人工编排连续时间轴**的制作路线，保留已选精细日系 Q 版画风。撤回“大动作专门做，小动作默认交给拆件骨骼”的分工：此前微动试样的表现没有通过，不作为生产底座。

- 工作、等待、陪伴与移动均设计完整的视线—头肩—手—身体—附属物运动。停留不是静态角色加呼吸滤镜，也不是两段大动作之间由旧 rig 填空。
- 每一种持续状态有完整的关注、停顿、姿势调整和回稳过程。关键姿势、衔接姿势及中间运动一起制作，不能把不相关的独立短片串成播放清单。
- 生图/改图提供姿态、细节修正与缺失区域候选；一致的轮廓、遮挡、运动路径和节奏需要继续制作。小动作同样需要相邻原画和运动设计，不因幅度小而降低制作标准。
- 帧序列、网格、骨骼和 shape keys 都只是实现已经设计好的表演的手段。只有实际观看证明能保持角色质感、透视和自然连续性时，才采用某段的变形或参数输出；不默认“小动作骨骼一定够用”。
- 现有 Canvas 实验只保留可用的交互和接触经验；它的切片与局部摇摆方案不继续充当最终美术基础。Blender 也不会自动修复同样的原画和动作缺陷。
- 当前可用生成能力为生图/改图，没有已确认可用的视频生成工具。视频生成不是本路线的阻塞依赖；若以后采用候选，也仍需清理身份漂移、遮挡、透明边缘与可中断性。

完整设计包括下面的 32 类表现、共用姿态、过渡网络、位置交互、素材清单、制作合同和验收。局部试做只能验证这份整体设计的制作手段，不能替代任何一项覆盖。

## 2. 角色表演语言

### 2.1 固定身份与镜头

以已选[Q 版母版](desktop-companion-assets/masters/Varin-chibi-original-reference.png)锁定身份，以[第一版工作分镜](desktop-companion-assets/storyboards/01-work-cycle.png)锁定坐姿和表演强度；其他稿不是混合参考。银白长发、蓝眼、人物自身左侧唯一圈丸与发饰、黑蝴蝶结、奶白外衫、炭灰外裙、浅蓝内裙、菱形吊坠及腰牌保持一致。禁止整图镜像来伪造另一方向。

镜头保持三分之四视角与一致透视。工作时电脑背壳面向用户，不能为显示手指或屏幕内容任意翻转电脑。角色较大动作仍在这一镜头下重新绘制透视，不靠把平面图旋转来冒充俯仰。

### 2.2 有主次，而非全部一起动

一次表演只有一个主意图：读屏、输入、询问、回应、查看异常或移动。各部位配合主意图：

| 通道 | 表演职责 | 禁止的替代做法 |
|---|---|---|
| 眼神 | 找到关注点，短暂确认，再停留；屏幕、用户和落点有明确区别 | 眼睛永远看用户，只让整颗头摇晃 |
| 头与颈 | 随视线转向，轻点头、真实低头/抬头；有回稳过程 | 固定图的平面 roll 冒充 pitch |
| 胸肩与骨盆 | 表达专注、放松、疑问和承重；骨盆依座面承托 | 全身同频上下漂浮，脚、凳、电脑也一起呼吸 |
| 手臂与手 | 操作键盘/触控板、稳住道具、托腮、摊手、挥手 | 为显得忙而持续打字；手穿过电脑或袖口 |
| 头发、袖口、裙摆、吊坠 | 对主动作产生延迟与回稳，按材质与连接点区别响应 | 所有附件用一个正弦函数；每次状态切换重置摆动 |
| 脸部表情 | 柔和可爱但清楚，眼眉口共同表达不同意图 | 强鼓腮、强 wink、夸张哭泣，或所有状态都一张微笑 |

目光通常先于头部，肩膀跟随更缓，附件最后收住；这是一种动作关系，不是所有场景都套固定延迟。受惊可以眼眉与肩一起快速反应，放松可以呼气先带动肩。节奏包含准备、动作、停留、恢复，不能所有曲线都用相同缓入缓出。

轻点、完成和欢迎的友好表演有区别：轻点是短暂关注，完成是轻松释放，欢迎是主动建立联系。等待授权保持认真，不能用撒娇迫使用户允许；拒绝后的反应自然接受，不责怪用户。

### 2.3 持续状态本身是一段完整表演

动作卡不只登记进入/退出，还必须写出停留期间的意图与时间关系：关注哪里、多久保持、什么变化引出下一次动作、身体如何重获舒适。自然静止允许存在，不能为“持续动画”强制各部位永远运动。

- **待命/陪伴**：视线停在环境或用户附近，短暂注意后回到舒适点；肩背随呼吸变化，手轻调整搭放位置、身体小幅重新坐稳，再形成有重量的停留。开盖与闭盖分别制作，电脑和凳子不随整人漂移。
- **阅读/输入**：眼神沿当前关注区停看，输入短串，手停在可信位置；抬眼核看、肩背调整、手重新归位有连续因果。输入不是两只手反复翻转，休止也不是冻结整张身体。
- **等待/思考**：停手、后靠或托腮形成新的支撑，眼神保持关注；解除托腮或换重心时，手、头和袖口同时遵守接触关系。不同等候的情绪与姿势节奏区别保留，但不凭空表达进度。
- **用户关注**：抬眼、转头、摊手、保持、收掌连续编排，保持时依然有自然的小表情与身体回稳；不能只有挥手短片，其他时间回到无关的呼吸循环。
- **悬空**：抱握持续、身体和头有稳定方向；移动速度变化时衣发响应，停止后按各自惯性回稳。它是可响应的持续表演，不是摆动两根腿的静态挂件。

上述过程与相邻状态共用匹配姿势和进出速度；需要实时改向的眼神或位置响应也必须有制作依据。整套评审包含长时间停留和反复转移，不能只挑大动作看起来最好的几秒。

## 3. 共用姿态与资产结构

共用的是相容的身体与接触关系，不是强行复用整张图。以下姿态族服务全部状态，编号仅用于制作，不新增业务状态。

| 姿态族 | 主要基准与必要变化 | 共用范围 |
|---|---|---|
| SEATED_CLOSED 合盖坐姿 | 双手轻搭电脑、单手稳机、准备开盖；正视与轻抬眼 | 闭盖待命、出场后待命、移动后尚未打开电脑 |
| SEATED_WORK 开盖工作 | 双手键入、触控板、掌托休息、前倾核查；头部看屏幕的俯仰变化 | 受理、准备、输出和八类工具活动 |
| USER_ATTENTION 面向用户 | 保持开盖，一手稳机，另一手摊开/挥手；点头和疑问侧倾 | 授权、提问、回应、完成、轻点 |
| OBSERVE_DIAGNOSE 观察与诊断 | 托腮、稍后靠、停手、轻扶额、收手核查；避免同形同意 | 思考、等待、失败、取消收尾、未知结果 |
| REST 休息与伸展 | 舒适坐姿、揉眼、一手伸展另一手稳机、软坐回 | 安静陪伴、困倦、恢复休息 |
| CARRY_AIRBORNE 抱机与悬空 | 电脑合盖竖抱、双手抓握前后层、悬空腿裙、方向性跟随 | 提起、持续移动、准备下降 |
| LAND_SETTLE 落座与整理 | 抱机坐下、骨盆/裙摆受座面承托、电脑从胸前移到膝上、整理衣摆 | 放下、再拖动、恢复开盖或闭盖姿态 |

SEATED_WORK–REST 的相近姿态可以复用已验证一致的头部原画与运动段，但不预设统一头部参数模型。前倾导致颈肩遮挡变化时必须有相应修形或替换画。CARRY_AIRBORNE/LAND_SETTLE 使用独立身体与衣裙资产；不能把 SEATED_WORK 下半身拉长成为悬空，也不能删掉外裙露出腿。

每个动作按 **进入 E / 可保持或循环 H / 退出 X** 设计，另有需要时的紧急收束 R。它们可以是同一工程内的片段，不要求每个编号都复制一个全身图集。循环变化有确定语义，例如输入短串、停手审阅再继续，而非无意义随机换图。

## 4. 全部 32 类表现的制作覆盖

表内“独立资源”是必须制作的视觉差异；复用制作工程不等于可以省略这些差异。具体业务事实仍以产品蓝图为准，动画不能产生执行结果。

| 编号 | 姿态与主要表演 | E / H / X | 必需的独立资源或修形 |
|---|---|---|---|
| C01 待命 | SEATED_CLOSED 合盖舒适坐姿；刚完成后可 SEATED_WORK 开盖休息 | 安坐 / 自然关注与休息 / 转开盖或直接工作 | 开盖、闭盖两个待命终态与相互连接，不强制每次合盖 |
| C02 接任务 | SEATED_CLOSED/SEATED_WORK → USER_ATTENTION 短确认 → SEATED_WORK | 察觉、抬眼 / 不设假等待循环 / 回屏幕 | 有无开盖两种接续；开盖手、稳底座手 |
| C03 准备 | SEATED_WORK 调整电脑、袖口与手位 | 手到掌托 / 短观察 / 键入、触控板或停手 | 双手归位、袖口让位、准备完成的接触姿态 |
| C04 思考 | OBSERVE_DIAGNOSE 停手托腮，关注屏幕 | 收手、托腮 / 目光停留与轻换焦 / 收回手 | 托腮接触手、脸部轻压与袖口折叠；不能用键入帧顶替 |
| C05 输出交流 | SEATED_WORK 输入与 USER_ATTENTION 轻回应 | 点头或短抬眼 / 键入与交流停顿 / 休手 | 用户→屏幕目光、回应口形与手归位；无需凭空配音口型 |
| C06 完成 | USER_ATTENTION 闭眼小笑、轻挥手 | 停手、松肩 / 短友好停留 / 回开盖待命 | 挥手弧线、笑眼、手臂回收；不是合盖或夸张庆祝 |
| T01 阅读 | SEATED_WORK/OBSERVE_DIAGNOSE 读屏，触控板滚动后停看 | 前倾 / 扫读、滚动、停顿 / 眼神与身体回正 | 触控板手、阅读目光、前倾颈肩与发束修形 |
| T02 编辑 | SEATED_WORK 较放松的短串输入、审阅 | 手归键区 / 输入与看稿交替 / 停手 | 可见键区指尖抬起、触键、释放；轻松肩形 |
| T03 编程执行 | SEATED_WORK 专注输入，一次确认后观察 | 集中、键入 / 输入段与执行观察段分开 / 按事实转后续 | 确认键手势、抿嘴专注；不能整个运行期敲键 |
| T04 浏览搜索 | SEATED_WORK 一手触控板，歪头查找 | 看屏幕 / 滚动、点击、停看 / 手休息 | 点触与滑动手形、短疑问眼神；不加实体放大镜 |
| T05 计算实验 | OBSERVE_DIAGNOSE 稍后靠看进展 | 结束输入 / 观察与小幅换重心 / 结果到达后前倾 | 后靠身体、稳定电脑接触；不虚构进度数字 |
| T06 整理归档 | SEATED_WORK 有序的触控板操作 | 轻整理袖口 / 操作、确认选择 / 休手 | 归类节奏和短满意表情，不搬实体纸堆 |
| T07 检查验证 | SEATED_WORK 前倾核看，动作更慢 | 凑近 / 分段检查与停顿 / 退回观察或异常 | 核查眉眼、近屏姿势、短选择手势；不以笑脸代表通过 |
| T08 协作调度 | SEATED_WORK 坐直，短输入后看进展 | 明确交办时短操作 / 观察 / 转收到的新活动 | 坐直胸肩、关注点切换；不循环发出假任务 |
| W01 排队 | 当前活动上的短侧眼；无活动则 OBSERVE_DIAGNOSE 等候 | 短注意 / 安静保持 / 队列消失自然退去 | 侧眼差分；并行工作时不新增双手抱臂遮掉原活动 |
| W02 等授权 | USER_ATTENTION 看用户、单手开放掌心 | 收手、抬眼、摊掌 / 温和认真 / 收掌后按决定进入实际后续 | 开放掌心、允许与拒绝后的不同但不施压的短反应 |
| W03 等回答 | USER_ATTENTION/OBSERVE_DIAGNOSE 轻歪头、询问、托腮 | 停手、询问 / 保持关注但不连续催促 / 理解点头、手归位 | 疑问眉口、托腮与摊手的相容组合；与权限姿势不同 |
| W04 等外部 | OBSERVE_DIAGNOSE 稍后靠或托腮看屏幕 | 手休息 / 观察、间歇关注 / 返回最新活动 | 后靠与托腮两个舒适变体；不做成功动作 |
| W05 等重试 | OBSERVE_DIAGNOSE 托腮看进展 | 休手 / 耐心停留、偶尔轻叩掌托 / 实际重试时坐直 | 掌托轻叩，不误当触键；重试开始的恢复片段 |
| E01 失败 | OBSERVE_DIAGNOSE 短惊讶后认真看屏幕 | 快停手 / 皱眉观察 / 真实后续才恢复 | 轻惊讶→认真连接，轻扶额变体；不循环摔电脑 |
| E02 取消收尾 | OBSERVE_DIAGNOSE 双手离键、持续关注 | 立即停止装饰输入 / 观察收尾 / 等真实停止或未知结果 | 离键与保持关注的手肩状态，不能先松懈庆祝 |
| E03 已停 | OBSERVE_DIAGNOSE → SEATED_WORK 释然松肩，向用户轻点头 | 确认停止后释然 / 短保持 / 开盖待命 | 呼气松肩与确认点头，和 C06 完成挥手区分 |
| E04 断联未知 | OBSERVE_DIAGNOSE 一愣、疑惑看用户 | 停止假操作 / 稳定未知姿态 / 同步或保持 | 困惑眼眉；连接标记独立显示 |
| E05 重连同步 | OBSERVE_DIAGNOSE 重新注意屏幕 | 抬眼、前倾 / 等快照 / 按最新事实返回 | 期待但不庆祝的眼神；不补播历史完成 |
| E06 结果核查 | OBSERVE_DIAGNOSE 收手、一手托腮认真核对 | 避开执行键 / 关注、只读核看 / 明确后续才退出 | 收手位置、狐疑眉眼，与确定失败不同 |
| L01 出场欢迎 | SEATED_CLOSED/SEATED_WORK 坐稳后短挥手 | 完整显现、建立承托 / 一次招呼 / 回当前状态 | 初次欢迎与隐藏后恢复的短版本；无任务不创建会话 |
| L02 呼吸眨眼 | 当前姿态内微动 | 接续当前相位 / 不均匀间隔 / 不重置全身姿态 | 各头角对应眼睑、眼白虹膜遮罩；胸肩微动与承托分离 |
| L03 轻点回应 | USER_ATTENTION 短抬眼、歪头笑 | 察觉 / 很短关注 / 回原关注点或最新重要状态 | 轻点反应与回程，不借机确认权限或发送消息 |
| L04 提起拖动 | SEATED_CLOSED/SEATED_WORK/USER_ATTENTION/OBSERVE_DIAGNOSE/REST → CARRY_AIRBORNE | 收手、合盖、抱稳、提起 / 悬空跟随 / 接下降或继续拖动 | 闭盖抓握、抱机、悬空骨盆腿裙、方向性发丝与裙摆 |
| L05 落位整理 | CARRY_AIRBORNE → LAND_SETTLE → SEATED_CLOSED/SEATED_WORK | 新凳承托、落座 / 坐稳短保持 / 放电脑、整理、恢复 | 座面压裙、抱机至膝上转移、整理衣摆、必要开盖 |
| L06 困倦伸展 | REST 单手揉眼/伸展 | 休手、困倦 / 一次伸展后舒适保持 / 收手、重新专注 | 揉眼接触、半闭眼、伸展肩袖与躯干；另一手稳电脑 |
| L07 安静陪伴 | REST 舒适坐姿或托腮 | 放松 / 长保持与稀疏微动 / 接关注或工作 | 放松终态与柔和回程；不压掉重要状态标记 |

独立变体应在动作卡上说明用途：例如“输入中审阅”和“等待外部结果”都可能停手，但前者目光仍沿内容扫读、手悬在可继续输入的位置，后者手已休息、重心稍后移。不能只改文件名或气泡当作两种完成资源。

## 5. 过渡网络与连续性

无需制作 32×32 条全身过渡，但要设计所有接触关系之间的连接。姿态族内部按当前手势和关注点退至相容中间位；跨族使用下表桥接。中间位是连续动作的一部分，不要求每次回到僵硬的正面站姿。

| 连接 | 必需动作 | 可改向的位置 |
|---|---|---|
| 闭盖 → 开盖工作 | 一手稳底座、一手提盖；开到工作角度，扶盖手移向掌托 | 盖未打开可回闭盖；开盖途中保留支撑，按当前位置接合盖而非闪回 |
| 工作 → 用户关注 | 输入结束/立即停手，眼神先移，头肩跟随；手离键后才摊掌 | 眼神、头部可随最新意图改向；持物与接触保持 |
| 用户关注 → 工作 | 收掌/收挥手，眼神回屏幕，手回掌托，再选择输入或观察 | 手未归键时的新等待可以接停手，不强播一次输入 |
| 工作 → 托腮/后靠 | 手离键，前臂抬至下巴或身体后移；另一手或膝稳机 | 托腮前可转摊掌；脸部接触解除后再转大幅头动 |
| 托腮/伸展 → 工作 | 手脱离脸，肩袖回收，身体恢复承托，再归键 | 不能直接把头从仍托住下巴的手里拉开 |
| 任意坐姿 → 抱机 | 结束与脸/用户的手势，稳电脑，合盖，换握点，抱到胸前 | 根据当前盖角与握持继续，不每次从零重播 |
| 抱机悬空 → 落座 | 稳机、腿准备落位、新凳可承托、下降与压裙、坐稳 | 触座前可转回悬空；触座后先保持承托，再重新提起 |
| 坐稳抱机 → 恢复 | 将电脑平放膝上，释放抓握，整理裙摆，再按最新事实开盖/休息 | 新拖动可从仍抱机时直接提起；不先放平又抱回 |

### 5.1 打断分为语义和身体两层

语义层及时更新真实状态、徽标和可操作入口；身体层按接触约束收束，不能为了把完整短片播完而延迟授权、取消或断联提示。

- **普通活动变化**：合并过快的工具变化，以最新主要活动为目标；当前短手势到最近相容退出点后转场，不排队补播所有历史工具。
- **需用户处理/取消/断联**：立即停止装饰性输入和庆祝，目光表情开始回应；如果正开盖、抱机或落座，保留支撑并通过该动作的收束段过渡。不是让电脑凭空合上或消失。
- **新的任务或范围变化**：旧庆祝和等待不继续补播；作用域更换丢弃旧一次性动作，只按新快照呈现。
- **重复事件**：同一事实不重复开盖/招手。晚到事件不能覆盖更新状态；最新目标与当前物理姿势分开保存。
- **输入反复发生**：轻点不无限叠加反应；拖动优先控制位置，放下后按最新语义恢复。角色反应不成为批准、发送或取消命令。
- **隐藏/恢复**：停止可见动画计时和物理工作。恢复时用当前事实选稳定姿态与短自然进入，不快进回放隐藏时的所有动作。主窗和角色观察生命周期仍按产品蓝图。

### 5.2 过渡何时能混合

共享网格与相容接触的局部参数可插值；已经制作好的匹配姿势可经桥接片段连接。不同身体构图、不同手部数量或不同电脑前后遮挡，禁止全身透明叠化制造双脸、双手和重影。完整动作片段播放时，只允许它导出的局部层继续活动，不能再叠一个不匹配的自由头部 rig。

动作退出的身体速度和附件余摆应接续；视觉上已静止的关键接触不必强求数学高阶连续。C2 参数连续只是技术手段，不等于表演自然或脸部一致。

## 6. 提起、移动与落座的完整设计

沿用[第08组](desktop-companion-assets/storyboards/08-reposition-lift-and-sit.png)，不复活整套凳子跟着飞的旧方案。

1. **拖动成立**：轻点和有效拖动先区分。位置反馈不能等合盖动画完毕才响应；抓取点与指针保持连续，角色身体的准备动作并行展开。短点击不触发抱机。
2. **收手稳机**：从键盘、触控板、摊掌、挥手、托腮、揉眼分别有收手路径；已有闭盖直接进入握持，已有抱机不重复放回膝上。盖未合时底座由膝/稳机手承托。
3. **合盖与换握**：合盖手与底座手分开，机盖关闭后再换到抱机抓握点。拇指在前、其余手指在后等前后关系随姿态绘制；电脑由平放转为竖抱时，手必须随各自握点走。
4. **提起**：骨盆离座，膝腿自然收拢，外裙与内裙展开但保持结构。原凳固定原世界位置，在失去承托后淡出。旧凳绝不挂在角色局部坐标上。
5. **持续悬空**：人物和电脑为稳定抱持整体；长发、裙摆对方向变化有有限滞后，脸部可看移动方向或用户。快速反向时先保住身体形状，不把裙摆拉成橡皮带。
6. **准备放下**：落点凳先在目标世界坐标形成可见承托；角色仍抱电脑，腿和裙摆准备就座。不是脚先踩住凳面再把整张坐姿图淡入。
7. **接触落座**：骨盆触座、裙摆受压、上身有轻缓缓冲与回稳；膝腿恢复坐姿。凳子不跟着骨盆弹跳，电脑仍由双手抱稳。
8. **电脑回膝与整理**：坐稳后电脑从胸前转平并落到膝上，接触建立后放手；整理衣摆或袖口，再按当前事实恢复。忙碌则开盖工作，等用户则进入关注姿态，真实停止则休息。

必须覆盖的分支：刚抓起即松手；原地松手；拖动时反向；悬空中快速再抓；凳子刚出现又拖走；触座前再抓；触座后电脑尚未放平时再抓；窗口失焦/取消拖动；跨屏与缩放变化；落点因工作区变化不可用。每条分支沿当前盖角、握持和接触继续，不能强行跑完一整套退场再重来。

窗口层决定有效落点、DIP 坐标与可见区域；动画层只负责表达，不通过人物动作修改执行位置或任务状态。移动中真实任务继续，电脑合盖不意味着暂停、取消或重启 Agent。

## 7. 素材制作包：按动作需要充分准备

素材数量由动作覆盖决定，不预设“16 层”“三张图”之类上限，也不以堆图数量衡量完成度。每项保留来源、修改历史、可编辑文件和批准用途；未选稿与待修稿不进入发行包。

| 制作包 | 需要交付的内容 | 依赖与检查重点 |

| 身份/尺寸基准 | 正面和固定三分之四参考、必要侧后结构、脸/手/服装比例、座面与电脑尺度 | 认可母版为身份基准；方向和 Logo 不镜像 |
| 头部角度 | 看屏幕的轻低头、中性、看用户的轻抬头、左右关注；必要组合角度 | 真实眼鼻口/耳/颈透视；前额、下巴、颈后、领内隐藏面；不仅做平面旋转 |

| 完整动作片段 | 各族进入/保持/退出/收束，前述32覆盖和所有跨族连接 | 关键姿势、过渡姿势、节奏和中间运动齐备；完整片段不只是几张关键帧 |
| 运行时元数据 | 稳定姿态、有效片段、循环范围、可退出点、接触与层级、必要的局部参数范围 | 供播放控制，不把软件事实硬写进图片 |
| 默认色与后续换色 | 默认色完整校准；发饰/毛衣/裙内里/吊坠遮罩随动作同步 | 瞳色和固定衣装不变。当前不批量制作其他色系，不能为后续换色全图 hue-rotate |

### 7.1 生图、改图与视频模型的具体职责

生图用于提出真正不同的姿态和视角；改图用于保留身份与构图的局部修正、隐藏面和手部差分。两者输出都要经过同机位、同比例、同服装结构的人工视觉比对，不将配准误差交给播放时的拉伸掩盖。

连续动作在动画工程中确定关键姿势、运动路径、节奏曲线和接触，再生成或绘制必要中间帧。相邻姿态对应关系明确的部分可以变形插值，轮廓、遮挡和透视改变的部分应补画。不能先随意生成许多图，再期待自动插值把它们变成一致角色。

视频模型可提供完整动作候选，但需要逐段检查脸、手、裙片、发饰和道具是否漂移，拆出稳定的进/循环/退段并修复透明背景。无法稳定重复或无法中断的片段不直接承担交互。现有桌宠源码证明的是它们消费的素材格式和播放方式，不证明作者上游从未使用过生成工具。

## 8. 制作工具、输出与播放分开决策

### 8.1 主制作合同

所有动作先落实同一套角色与动作卡，再用合适的工具生产。可编辑分层文件（如 PSD/ORA）、关键姿势及中间画、动画工程原件和输出资源一起交付。制作工程必须能重导，不能只保存最终 MP4。

默认以完整透明连续表演为运行交付；局部参数资产是有条件的补充，不是预先分配给全部小动作的任务：

1. **透明全身/主体片段**：PNG 序列为可审计母输出，运行包可图集化；独立帧时长或时间轴保留真实节奏，不为缩小包强制稀疏帧率。
2. **经视觉验证的可选局部动态层**：只有已制作并实际验证自然的部位，才输出遮罩、绑定点、层级和合法变形范围，并说明适用的主体表演。不能以实时响应为理由将未验证的眼神、表情、呼吸或发梢重新交回旧 rig；不满足条件就保留完整已制作的表演及相容响应过渡。

用户要求自然顺滑，没有要求固定帧率。完整动作的生产密度依据实际显示效果确定，不把此前试样编码设置升级为用户要求或生产质量合同。渲染目标为连续、稳定的运动；高帧率显示、帧数多或数学插值都不单独构成验收。快速手指和小幅眼睑尤其不能靠长时间持帧产生卡顿，大姿态的中间轮廓必须可信。允许成熟编辑器辅助网格、权重、曲线和导出，但不承诺自动 rig 达到角色质量。

### 8.2 候选工具的定位

| 工具路线 | 适合承担的工作 | 当前决策与边界 |
|---|---|---|
| 专业逐帧/合成或骨骼工具烘焙 | 全部尺度的持续表演、复杂遮挡、循环与过渡 | 是主交付方式之一；保留工程原件与透明输出，编辑器授权单独确认 |
| Live2D Cubism | 精细头部、五官、注视、呼吸与发丝参数模型 | 借鉴成熟制作规范；不默认引入专有 runtime。可导入不定模型的产品可能涉及特殊发布条款 |
| Spine | 全身骨骼、网格、附件替换、动作曲线与烘焙 | 可用于合法授权的制作；不把源码可见误当作自由嵌入产品许可 |
| Rive | 位图网格、骨骼、状态与局部交互 | runtime MIT，但编辑器导出规则独立；当前免费导出 splash 等需按具体使用核验，不自动选为最终引擎 |
| Inochi2D | 开放的位图 puppet、参数变形与物理 | SDK BSD-2；Electron/WASM 路径和工具版本尚需集成验证，不宣称即插即用 |
| 现有 Canvas 实验 | 交互、接触、打断和素材诊断 | 可复用有价值的逻辑；不能作为要求所有动作迁就同一图层布局的依据 |

已选择全帧原画序列作为本轮实际生产路线，不等待商业完整模型或视频工具。专业模型与视频仍是后续可研究的独立方法，不作为本轮缺画或动作不足时的默认回退。现有免费工具承担原画整理、时间轴与导出，不购买新许可。

### 8.3 本轮实际生产链：完整原画序列

整套32类覆盖和持续体验不变。与旧切片路线的区别是：人物的关键姿势、微动作、轮廓、透视与手衣关系在完整画面中实际改变；不靠旋转平面部件、整体平移或全身交叉淡化伪造动作。中间画承担清楚的运动阶段，不是把少数不连续图平均分配时间。

1. **完整表演动作卡**：先写每个动作族的准备、关注、动作、保持内变化、退出与打断位置；明确共同起止姿态、座面、电脑和手的接触。
2. **定向生图/改图**：依据认可母版与对应分镜制作全帧关键原画，再补有意义的中间姿势。保持相邻图的镜头、尺寸、身份和道具一致；脸、手、衣裙与隐藏区域实际看图修正。小动作同样制作，不交回旧微动模型。
3. **局部清理与登记**：用已授权的程序/手工局部修整做透明边缘清理、裁切、统一画布登记与必要修复。仅允许保持比例的整体登记；不以非均匀拉伸、局部骨骼或颜色填充掩盖错误透视和缺失身体。
4. **可编辑原画时间轴**：每张画拥有明确持续时间和动作阶段，重复保持仅在身体已自然停稳时使用。接续以匹配姿势、中间画和退出点完成，不生成全身重影淡化。循环末尾必须实际接回开头，不将ping-pong当自然动作的通用解法。
5. **导出与记录**：保留完整原画、修改来源、原画编号、每帧持续时间、接触点及输入/输出姿态。透明PNG为源，运行包以PNG图集与JSON时间轴输出；普通图片打包工具只整理资产，不合成未经制作的动作。
6. **连续审阅与产品播放**：用可变帧时长的序列预览检查正常速度表现，FFmpeg仅生成方便审阅的MP4；无固定帧率质量合同。运行端沿Electron展示层消费图集时间轴，不需要专有角色SDK，不创建后台Agent。

当前已有Python/OpenCV、FFmpeg和Node足以完成整理、时间轴与导出。Blender若用于时间轴合成也只是可选编辑工具，不引入默认拆件骨骼。没有视频生成依赖。某个动作缺自然的中间运动就补画并改编排，不自动回退至旧rig、全身淡化或强制插帧。

### 8.4 目录、所有权与可恢复交付

生产目录在实施时建立，现有历史试样不改写。`docs/design/desktop-companion-assets/animation-source/production/` 保存可编辑源与经批准的资源清单；`tools/desktop-companion-animation/` 保存离线工程生成、导出、配准/图集工具与可重现预览入口。生产播放资源待角色窗消费者落实后放入其相邻资源目录，不能把文档实验目录当正式加载 API。

生产源按 `shared`（角色比例、脸部、道具、颜色槽）、`seated-work`（SEATED_CLOSED/SEATED_WORK）、`attention-observe`（USER_ATTENTION/OBSERVE_DIAGNOSE）、`rest`（REST）、`relocation`（CARRY_AIRBORNE/LAND_SETTLE）分工，每组有原始来源、有效图层、工程、导出清单与代表预览。每个图层集和工程同一时刻只有一个写入负责人；公共锚点/道具变更由公共资源负责人发布版本，其他组主动对齐，禁止各组静默制造不同电脑或不同头部尺度。

中间逐帧渲染可在工作区复现，不把每轮数百张重复PNG永久塞入 Git。提交可重导源、实际采用的素材、匹配清单与代表预览；完整发行图集按真实消费者需求保存。每次阶段提交记录哪些资源已可用、哪些只是参考，不用不断复制整套 stage 目录代替版本管理。

## 9. 播放与 Varin 集成合同

保留简单明确的职责：真实事实投影 → 表现意图选择 → 动作播放与局部通道 → 角色窗口。无需引入第二套业务状态机或后台 Agent。

- 事实投影沿已有 Host/Thread/branch 身份、Run/Operation、等待请求、取消意图和执行停止语义。32 类是美术表现目录，不是32个新的协议枚举。
- 表现选择保留最新意图与优先事项，处理普通活动合并、一次性反馈去重和需要用户处理的覆盖。新事实更新不等于立刻跳到另一张图。
- 播放器仅维护当前姿态族、片段时间、接触状态、道具状态和合法局部参数。片段缺失时使用相容稳定姿态并显示真实状态，不用错误动作伪装覆盖，也不把永久降级当成最终交付。
- 拖动拥有位置控制权，业务状态持续更新；完成落位后选最新意图。权限、问题和需要处理事项通过原界面操作，不由摸头、点角色或表情自动批准。
- 凳子、电脑、身体与附件的层级由姿态定义；全身片段和局部模型只在已声明的相容接口组合。不要让多个控制器同时写同一眼睑/头角并相互覆盖。
- 减少动态模式提供各姿态的静态表达和必要短过渡；隐藏停止渲染和装饰循环。性能目标最终在支持平台和实际尺寸测量，离屏 MP4 不证明 Electron 常驻性能。

最小必要的动作资源记录应能表达：标识与版本、姿态输入/输出、片段时长与循环范围、退出/收束点、身体与道具接触、图层/局部参数兼容性、重导来源和校验值。此处不是提前创建复杂通用动画 DSL；具体结构随实际资产和消费者实现，不单为32类列表生成冗余代码。

## 10. 完整制作组织与验收

### 10.1 先完成整套设计材料

开工蓝图需同时具备：本稿的全目录、所有姿态族关键构图、全过渡关系图、手与道具接触表、隐藏面缺口清单、表演节奏卡、素材依赖和制作工具输出合同。现有8板是重要参考，但不自动代表这些材料全部完成。

制作按共享资产依赖成组推进：身份与身体/道具基准；工作/关注/观察姿态群；异常/等待/取消表演群；休息与互动群；悬空/落座完整动作群；全网过渡与运行时集成。各组从开始就按全体验清单设计，不在前一组交付后才决定后一组要有什么。能够并行的眼态、手态、身体与道具资源并行制作，避免一个局部缺图拖住全部工作。

| 生产单元 | 范围与交付 | 前置依赖 |
|---|---|---|
| U0 公共资产与制作工程 | 全姿态构图卡、脸部角度/眼态、电脑/凳尺寸与锚点、默认色槽、全帧原画登记与可编辑时间轴模板、导出合同 | 本整体方案、已选参考与已选全帧原画路线；不以单段样片代替 |
| U1 坐姿与屏幕操作 | SEATED_CLOSED/SEATED_WORK全部闭盖/开盖、准备、键入、触控板、前倾/后靠连接；C01–C03/C05及T01–T08的活动资源 | U0；手部与身体可以并行，集成时共用实际电脑投影 |
| U2 面向用户与观察诊断 | USER_ATTENTION/OBSERVE_DIAGNOSE完整询问、理解、挥手、托腮、收手、异常与恢复；C04/C06、W01–W05、E01–E06、L01/L03 | U0；与U1共享进出接口，而非等U1全部结束才设计 |
| U3 持续陪伴与休息 | 全姿态的连续关注、眨眼、呼吸、手部小调整、重心调整与回稳表演（含L02），REST的L06/L07、减少动态差分及回到工作/注意的连接；不是静态模型补微动 | U0和各姿态完整原画；与U1/U2同步设计，不等大动作完成后填空；不强制所有等待都困倦 |
| U4 搬移完整资产 | 所有坐姿收手入口、闭盖抱机、CARRY_AIRBORNE悬空与方向性响应、LAND_SETTLE落座压裙/回机/整理及早放再抓分支；L04/L05 | U0的道具与完整衣裙；U1/U2/U3提供不同手势出口 |
| U5 全图编排与集成 | 全32映射、姿态连接图、最新事实恢复、打断/混合、窗口交互、资源预取与释放、所有减少动态入口 | U1–U4按接口持续集成；不得用临时几种mode替代覆盖 |
| U6 整体视觉与产品验收 | 所有姿态与合法连接的完整观看、身份/边缘/手/衣裙修正，实际目标平台交互与常驻成本 | 各单元持续验收后集中贯通；不是新增一套庞大的重复测试体系 |

U0的公共源、各组动作卡及连接关系完整登记后，U1/U2/U4可并行生产，U3随各姿态接入，U5持续组装。内部评审和已有授权允许自主修稿、提交、推送；用户暂时不查看不阻断推进。制作中确有无法绕开的新增许可、付款或关键设计冲突才单独提出，不把普通美术修正退回给用户处理。

阶段提交保存可恢复的源、清单与匹配预览，不堆到最后才提交；未完成项清楚保留，不能以阶段保存冒称整套已完成。单个试片的用途是验证制作参数或局部质量，而不是把完整范围缩成“先做一段看看”。

### 10.2 质量关卡按交付性质区分

| 层面 | 必须看到的证据 | 不能充当通过证据 |
|---|---|---|
| 身份与美术 | 默认尺寸和放大图均保持脸、手、衣裙、发饰与道具；黑白灰/彩背景边缘干净 | 自动分层重建差0、素材张数多 |
| 表演 | 全32类的动作卡和实际片段各有可读意图；主次、停顿、重心、接触自然 | 只换气泡、只改文件名、全身同频摇摆 |
| 连续动作 | 正常速度检查所有进/循环/退、快速改向和提放分支；无穿插、断层、重影和硬切 | 高帧率编码、邻帧差统计、只看少数静帧 |
| 资源可制作性 | 可编辑源、明确隐藏面、局部变形范围、统一锚点与可重导工程 | 一张母版或几张独立生成图就称完整 rig |
| 业务呈现 | 授权/提问、取消意图/实际停止、未知/失败、重连与多任务对应真实事实 | 让动作自然结束去替代业务完成事实 |
| 平台与运行 | 实际窗口穿透/焦点/拖动、多屏DPI、隐藏恢复、常驻CPU/GPU/内存 | 离屏录像、其他项目的宣传性能 |

先按完整清单验收资源覆盖，再按完整交互路径验收组合；图像、动作、状态映射与原生窗口分别报告，不互相顶替。发现缺资源应补资源，发现动作编排问题应改表演，发现工具限制应调整制作方式，不能统一用缩小动作掩盖。
