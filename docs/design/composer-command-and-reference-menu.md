# Chat 输入框：斜杠功能菜单、技能与对象引用

状态：设计提案，2026-11-03。本文是 `/` 与 `@` 后续实现的设计依据，尚未代表已实现行为。当前代码事实见第 2 节。文件引用的交付合同与 [Agent 文件与附件交接](agent-file-handoff.md) 配套。

## 1. 目标与范围

输入框除了承载自然语言，也应让用户在当前交流中找到功能、使用技能、准确指定涉及的对象。入口需要易发现、可搜索，选择后的行为与界面表达一致。

确定以下组织方式：

- `/` 打开会话功能菜单。功能按用途分组，技能是同一菜单中的独立「技能」分组，共用搜索。
- 技能采用紧凑列表：图标、名称、一句说明，右侧轻量来源。不另建技能页、详情面板或复杂分类导航。
- `@` 引用文件、目录、附件和已有任务／Agent。引用对象与选择收件人分别表达。
- 功能执行、技能激活、对象引用分别使用真实 owner；菜单不是仅往输入框写入名称的装饰。
- 选择只修改当前片段，保留草稿其他内容、附件、光标和撤销关系。
- Bot、工作台、子任务、外部 Harness、Web 和移动端共用交互基础，候选取自各自实际会话和能力。

本设计覆盖功能目录、菜单、搜索、编辑语义、发送接线和实施顺序。新能力包含整理交接、对话导出和明确记忆写入入口；全局命令面板、设置页和技能管理页继续承担各自职责。

## 3. `/` 的信息结构

### 3.1 一个菜单，清楚分组

输入 `/` 后，默认按稳定顺序展示功能分组和独立技能分组。常用项可以提供快捷区域，但同一项目不在同一视图重复出现；打开期间不因异步使用统计改变位置。初次使用没有“常用”记录时，直接显示完整分组。

功能分组是便于扫读的小标题，不要求用户先进入分类才能搜索。技能不与功能逐项交错排序，不提供「功能／技能」双页签。搜索结果仍保留分组边界，无结果的分组不占位；名称、调用名、描述和明确别名都可检索。

功能需要继续选择时，在原菜单区域进入下一层，顶部显示返回与当前标题。返回时恢复上一层查询、选中项和滚动位置，不在旁边堆叠二级弹窗。技能本身不进入下一层。

### 3.2 功能目录与行为

下表是目标目录。已有功能复用其 owner；“新增流程”需要完整接线后才成为可用命令。面向用户的中文名称和英文别名都支持搜索，既有 `/compact`、`/tree` 保留。

| --- | --- | --- |

| 会话 | 重命名 | 就地输入名称，调用原 Thread 元数据更新 |

| 模型与执行 | 模型 | 进入当前会话的模型选择，展示渠道及当前模型，不修改全局默认 |

| 任务与协作 | 整理交接 | 新增流程，见第 6 节 |

| 任务与协作 | 交给 Varin 跟进 | 沿现有普通会话关联 Bot 的入口；已经关联时显示关系与管理操作 |

不把 IDE 的全部编辑命令、模型可调用工具列表或设置的每个字段都倒进 `/`。全局命令面板继续提供全应用发现；这里优先服务聊天现场的操作。

### 3.3 状态与适用性

功能行可以显示实际值，例如“思考强度 · 高”“上下文 · 已使用 38%”“任务 · 2 项进行中”。只订阅菜单可见范围内所需的已有投影，不为显示菜单另起高频轮询。

区分三类情况：与当前场景无关的功能不出现；临时不可操作的功能保留并说明原因；读取失败显示失败及重试，不冒充不可用或默认状态。平台本来就没有桌宠时不提供该项；当前模型没有可调思考档位时显示其真实情况。

权限的现有设置可能影响 Host 全局；模型选择只影响当前会话，运行中的切换在原安全边界生效；桌宠属于本机。确认前的子视图应表达这些真实范围。

## 4. 技能：独立的紧凑列表

技能行保持用户提供的参考形式：左侧小图标、名称、同一行的简短说明，右侧淡色来源“个人／项目／扩展”。不再叠加 `skill`、`project` 等重复徽标，不新增技能专属页面和常驻详情区。

宽度足够时名称与说明同行；窄屏时允许说明自然进入第二行。说明过长截断，可通过悬停、焦点或明确的展开说明查看全文；移动端不因缺少 hover 就删除说明。来源使用当前语言，必要时显示真实项目／扩展名消除同名歧义。

搜索支持名称、调用名和用途说明，包括中文。来源 owner 已裁定的覆盖关系仍按原规则：被覆盖的同一技能不能通过菜单绕过生效选择；有效目录中不同身份但同名的技能应分别展示来源，不再由前端按小写名称自行吞掉。

选择技能只把它加入当前草稿，不立即发消息。用户可以在任意正文位置使用、选择多个技能、继续写要求或删除引用。选中的技能携带稳定身份和来源选择，Host 在受理时按本次有效资源准备真实激活资料，不能只靠显示名猜测。

管理入口放在技能分组末尾，跳转现有管理页；菜单只负责发现和选择。显式用户调用与模型自主调用资格仍由原资源合同区分，不能因为技能禁止自动调用就直接推断用户也不能选择。

## 5. 功能确认与草稿行为

菜单项有明确的交互类型，但不要求用户理解内部字段：

| 类型 | 例子 | 确认后的行为 |
| --- | --- | --- |
| 直接操作 | 置顶、查看上下文、整理上下文 | 执行或打开已有面板；有副作用的操作沿原合同结算 |
| 继续选择 | 模型、思考强度、重命名、联系 Agent | 在原菜单进入子视图，明确确认后提交 |
| 插入能力 | 技能 | 加入草稿，发送时激活 |
| 准备新工作 | 整理交接、记住这件事 | 进入具体流程；需要模型处理时明确展示，而非伪装成本地瞬时操作 |

只有用户确认才执行操作。Tab 补全名称不执行；完整命令后的 Enter 按同一已注册行为处理，不再只给 `/compact` 写特例。带破坏性后果的删除沿现有确认；普通可逆操作不额外加入审批。

命令选择和执行只消费当前 `/…` 片段。打开设置、整理上下文等操作不发送其他草稿；未选中的正文、图片、文件和编辑器引用保持原样。取消子视图时不修改配置和草稿；失败后保留选择并展示原错误。

用户直接键入命令时，只有整个输入确为已注册的命令调用才进入命令执行路径。普通文字中提到 `/compact`、引用代码里的命令或未知 `/name` 不会被扫描成应用操作。菜单内明确选中功能可以在正文中执行，之后回到原编辑位置。

新会话、分支和导航保留原会话草稿，遵循原导航 guard。不存在“执行一个命令先清空整个输入框”的公共逻辑。

## 6. 三项新增流程

### 6.1 整理交接

用户可把当前工作交给已有 Agent 或新任务。入口提供接收对象、交办说明，以及可选择的消息／文件背景，允许直接调整后交办。

有选中文本或明确消息引用时先采用该范围；没有时提供当前会话背景的选择入口，不自动抓取所有历史、工具结果和文件。附件复用统一交接，既有历史选取沿 `dispatch.background` 等原引用机制。

需要模型协助整理交办说明时，由用户明确启动一次正常工作，结果成为可编辑草稿。模型可以自由组织说明，不固定科研、编程或审查流程。资料已经明确时可直接交办，不强制先调用摘要模型。

交给已有 Agent 沿 `send` / 原接续机制，保留队列与当前任务补充的真实选择；交给新任务沿原派发与模型选择能力。取消整理不创建空任务，重复确认沿原受理键避免重复派发。

### 6.2 导出对话

提供当前分支或明确选定消息范围；格式支持适合阅读的 Markdown 和保留结构的 JSON。默认导出公开消息，可选择工具详情和文件附件。

选择范围后固定历史位置，读取沿原历史与媒体 owner 分页完成。长对话和附件使用流式导出，不一次性把全部内容塞入 renderer 内存。包含附件时保留文件名与对应消息关系，由原 owner 准备下载产物。

导出沿当前用户的可读内容，不包含 provider 私有续接对象、凭据或不属于公开历史的内部状态。此功能生成本地下载，不默认创建公开分享链接或上传到新的外部服务。

### 6.3 记住这件事

优先使用用户选中的交流或当前草稿作为待记内容，打开轻量编辑与保存流程，清楚显示保存到哪个 Bot 或现有记忆作用域。用户可以直接保存自己的原文，也可以明确让模型整理。

实际写入沿已有 MemoryService / KnowledgeStore 的版本与回执，失败保留编辑内容，成功显示可打开的记录。不新建命令专用记忆库，不自动把整份聊天和所有附件加入记忆。

## 7. `@` 的候选与引用

### 7.1 围绕当前交流选对象

空查询优先显示本会话附件、当前实际来源里打开或最近使用的文件，以及当前任务家族中的成员。键入查询后搜索相关来源，结果按文件、目录、附件、任务分组；必要时提供轻量类型筛选，不要求先选分类才能搜索。

| 对象 | 行内信息 | 选中后的语义 |
| --- | --- | --- |
| 文件 | 真实文件图标、文件名、辅助目录／项目 | 保存明确文件选择；发送时按附件交接规则解析和固定版本 |
| 目录 | 目录图标、名称、所属来源 | 引用一个工作范围；不自动展开整个目录，不因此改变已有访问授权 |
| 聊天附件／产物 | 图片小缩略图或格式图标、名称、必要来源 | 引用已保存原件，直接复用其稳定身份 |
| 已有任务／Agent | 原头像、用途名、状态、必要父任务关系 | 引用真实 Thread/branch 或明确执行，供当前接收者定位与按权限读取 |

任务列表来自真实目录，不再用预制角色冒充已存在的成员。预设角色留在原任务创建或角色设置入口，本轮不向默认 `@` 列表新增一组角色模板。

同名文件、同名任务仍分别存在。主标题便于阅读，辅助信息足以区分；选中对象的身份不由名字或相对路径重新猜测。Agent 改名后引用仍指向原任务。

### 7.2 文件引用与附件交接衔接

文件候选选择时不读取全文或捕获整个目录；先保存原 Host、来源和文件身份／路径选择。发消息时由统一附件 owner 完成实际读取准入和版本固定。

已经固定的附件引用保留其原版本。图片继续用输入框上方的缩略图和正文中的文字引用；不把原图缩略图塞进段落。普通文件可以在正文显示轻量 `@文件名`，附件区与该引用指向同一对象，不重复上传。

在附件交接能力尚未接通前，现有路径提示只能如实作为路径引用，不能通过新图标宣称已经交付文件。正式完成本设计时，选中文件到原生消息附件的链路必须一起可用。

### 7.3 任务引用提供定位，不转移接收者

`@某任务` 将这个任务的准确身份作为本条消息的引用。它不隐式派发、唤醒、群发或改成给该任务发消息，也不直接把该任务全部历史放进当前上下文。

模型可以沿现有 `read_thread`、状态与报告工具按需读取。读取仍核验实际任务家族或已授权跟进关系，引用一个对象本身不扩张权限。

## 8. 联系 Agent 与明确收件人

`/联系 Agent` 进入实际成员选择，也可从任务候选的明确“发消息”操作进入。完成选择后，输入框显示独立的“发送给：任务名称”及原头像，可撤销或切换。正文中的 `@任务` 与该收件状态分别保存。

直接发送使用 User 身份及原协作输入入口，不伪造为 Bot 或主 Agent 的话。已有草稿和附件可继续编辑；点击发送前清楚显示目标，不能只通过正文里一个名字暗中改变投递位置。

原输入框负责的聊天草稿与定向消息草稿分别保留；取消定向发送恢复原草稿，不把两份文字互相覆盖。多人发送如从原协作入口使用，沿每位接收者的独立回执处理，保留部分成功后的重试身份。

用户切换聊天、Host 或目标失效时，不把定向草稿自动发给当前新选中的对象；提示原目标情况并保留尚未发送的内容。

## 9. 触发、编辑与键盘

### 9.1 光标附近的一套规则

触发器返回当前片段的起止范围、查询和适用候选，而非仅一个字符串。词首、行首和正文中的显式 `/`、`@` 使用同一编辑规则，识别名称、路径中的空格与重名情况。

电子邮件、URL、包名、普通路径中间的符号、代码块里的字面内容不自动弹出菜单。粘贴整段文字不触发操作；在已经打开的查询里粘贴关键词继续搜索。必要的语法判断复用输入框语言层，不在高亮、菜单和发送时各写一份解析。

### 9.2 轻量显示，保存准确身份

技能和对象在正文中显示为轻量文字引用，使用可辨认的颜色或细微底色，不做一排厚重胶囊。底层在草稿中保存引用身份和跟随 CodeMirror 事务移动的文本范围。

光标前后编辑、插入、删除和撤销同时更新引用位置。直接改写引用文字时解除旧绑定，按普通文本继续编辑或重新选择，不能保留一个显示为 A、实际指向 B 的隐藏对象。删除技能或任务标记会移除相应激活／任务引用。删除文件的正文标记不删除仍在附件条中的附件，也不删除用户已上传的原件；附件条的移除按原附件规则处理，仍将发送的文件必须保持可见。

带空格的文件名通过结构化选择和明确文本边界保留，不再依赖 `@` 后连续非空白字符。重名技能保留来源身份。复制为纯文本时提供可理解的文字；跨聊天粘贴的引用需要重新经过实际 owner 解析，不能携带隐藏授权。

### 9.3 键盘优先级

| 操作 | 行为 |
| --- | --- |
| 中文输入法候选确认 | 优先由输入法处理，不选菜单项、不发送 |
| 上／下 | 菜单打开时移动候选；菜单关闭后沿既有编辑与消息历史规则 |
| Enter | 确认当前候选：执行功能、进入子视图或插入技能／对象；不同时发送普通消息 |
| Tab | 有可选候选时补全该项，不执行应用操作；技能和对象完成结构化插入 |
| Shift+Enter | 正常换行，必要时结束当前查询；不确认候选 |
| Shift+Tab | 保留正常的反向焦点导航，不套用下一步建议或候选补全 |
| Escape | 有子层先返回；根层关闭菜单；该次按键不再丢弃下一步建议 |
| 点击外部 | 关闭菜单并保留输入，目标控件照常接收点击 |

菜单没有可选项时明确显示“输入文字／没有匹配项”等实际状态，Enter 沿原发送快捷键处理普通文字；未知 `/…` 不被自动解释为功能。Tab 不趁机插入下一步建议，可用于正常焦点导航。

已经精确识别为本地命令、但当前不可执行的输入，保留草稿并说明原因，不自动改成发送给模型的普通消息。用户仍可关闭菜单、编辑为正常文字后发送。

菜单关闭且有下一步建议时，Tab 才沿原建议规则插入。空草稿的 Enter 建议发送保持原逻辑。菜单打开期间，底部帮助显示当前候选操作，不同时提示会抢键的 Tab 建议动作；关闭后恢复建议入口。

Escape 主动关闭后，在同一未编辑触发片段里移动光标或迟到查询返回，不重新弹开。再次编辑查询、重新输入触发符或显式打开时才恢复。选中一项后保持输入焦点和合理的光标位置，点击行不能先失焦导致插入位置变化。

## 10. 搜索、范围与异步连续性

候选身份至少区分实际 Host、会话／分支、资源来源与目录代。切换 Host、会话或执行来源时撤销旧查询的发布权；旧结果不能成为新环境中可确认的候选。

文件从当前任务实际来源搜索，编辑器最近文件只在与该来源匹配时参与。Bot 从自身会话、附件和可读任务取候选；跨项目文件通过明确项目来源进入，不借工作台刚刚选择的目录作为默认。

技能取自当前执行或待创建会话的有效资源目录。管理列表可作为发现入口，但最终可选择的身份和提交解析必须由同一个实际资源 owner 裁定，不能仅靠 cwd 与项目路径恰好相等来决定。

搜索排序优先准确名称和前缀，再考虑路径、用途说明和适度的最近使用。各类型保留分组。用户已开始上下移动选择后，后台刷新不随意把列表重排到另一项；同一候选仍存在就保留它，否则选择相邻的有效项。

每个分组独立表示加载、结果和错误：

- 相同来源的已有结果可保持显示；新查询等待中不能把旧查询结果伪装成已匹配的新结果。
- 加载指示占用稳定位置，文件加载不遮掉已经可用的任务或技能。
- 返回结果按稳定身份合并，尽量保留选中与滚动位置，不每次回到第一行。
- 失败显示该来源的错误和重试，其他分组继续可用。
- 展示窗口可以有合适高度和虚拟化，但不能把前 15 个结果当成全部。使用已有分页能力或明确的继续搜索入口。

菜单浏览仅查询必要元数据，不读取每个文件正文、不展开全部任务历史、不逐项请求完整工具结果。目录与会话状态复用现有缓存和观察，在菜单关闭后停止仅为菜单服务的订阅。

## 11. 视觉、动效与无障碍

菜单贴近输入框上方，与输入内容区域对齐；宽度按内容和可用空间适配，窄屏占输入区域可用宽度。高度依据可见区域约束，长列表在内部滚动，不推着聊天内容反复跳动，也不覆盖正在输入的行。

功能行以图标、名称、可选当前值和继续选择箭头构成。说明只在确实帮助理解时出现。技能保留紧凑单列；文件突出文件名和辅助路径；任务使用现有头像。低饱和主题色辅助区分，选中状态主要依靠清楚的底色和对比，亮暗主题都能读清。

去掉重复厚边框与徽标堆叠，长路径优先通过辅助行和选中后的完整说明查看。常驻信息不依赖文字来回滚动才能读完。来源和状态不能仅靠颜色表达。

打开与关闭使用共享 motion token 的轻微位移和透明度；子视图切换在同一容器里连续过渡。关闭时保留退出内容到动画结束，快速重开或返回从当前动画状态衔接，避免重播整段。结果追加不逐行延迟入场，不让加载动画改变列表锚点。

共享一个焦点和候选控制器，输入框与候选使用可访问的 combobox/listbox 关系及 active descendant。子视图里真实的输入、按钮和选择器按各自语义处理焦点；不能为了共享样式把所有控件伪装成选项。

功能标题、说明、来源、状态和键盘提示统一使用 i18n；技能自带名称与描述保留原文。新增语言键沿 application-client 的设置／聊天词典提供中英文，其他语言按现有回退机制处理；UI 消费其 dist，修改词典后需构建对应客户端包。

触屏滑动列表不误选，点按确认后回到输入位置；移动键盘的可见区域变化沿现有 viewport 机制调整。减少动态效果偏好使用应用已有设置，正常模式保留完整的开合、切层和可打断性。

## 12. 与实际执行链路连接

### 12.1 复用命令注册与领域 owner

已有 Workbench command registry 管理应用命令。扩充聊天展示所需的分组、别名、当前值和交互形态，并为支持聊天的命令提供明确的 Host / Thread / branch / 执行来源上下文。无需新建一套与全局命令注册竞争的命令数据库。

只有明确声明适合聊天现场的命令进入 `/`。普通编辑器命令和扩展全局命令不会因为已注册就全部出现。扩展可以提供真实的聊天命令贡献，使用现有扩展身份与激活路径；外部命令名称与内置冲突时保留来源和可区分别名。

执行目标在用户确认时核验。迟到异步回调不能用当前全局选中会话替换原命令目标；用户在子视图期间切换 Host 或会话，关闭该旧目标的执行入口并保留原草稿。

### 12.2 草稿与输入合同

`useThreadDraftStore` 保存当前文本、选中技能、对象引用、附件和必要的文本范围；输入框只编辑，提交仍由 `ThreadConversation` 负责。定向协作草稿使用原协作身份和回执入口。

Host 将选择映射到本次已核验的技能资源、文件引用与任务引用，再随原生输入提交。运行中 enqueue、空闲 submit、已结束子任务 continueChild 都支持同样的内容，失败与不确定重试保留原输入身份。

技能支持多项显式激活：保存各自资源身份和原始用户文字，按消息中的选择顺序准备，重复的同一有效技能不重复加载。同名不同身份不自行合并。技能指令的组合仍交给原模型上下文机制，不新增流程编排或要求模型逐个执行。

手动输入 `/skill:name` 继续可用，沿同一解析和资源准备入口；菜单选择有准确身份，文本输入按当前有效目录解析。歧义或资源变化明确返回实际问题，不静默选另一来源。已受理输入继续使用冻结资源，不能因设置后来改变而改写一次重试的行为。

`@` 的任务引用只提供明确定位资料，文件引用沿附件合同交付，目录引用沿原 Source 读取准入处理。不要让 renderer 直接读取私有数据库、擅自生成授权或扩张工作目录。

### 12.3 外部 Harness

会话管理、设置和本地呈现等 Varin 功能按实际产品能力继续可用，不因使用外部 Harness 就关闭整个菜单。

模型、思考、技能和后端命令使用该 Harness 的真实协商能力与会话身份。不能把 Varin 技能或模型选择假装成外部后端原生支持，也不能因两边命令同名就投递到错误的执行者。

后端支持原生命令或技能目录时，作为明确来源的候选提供，仍与本地功能、技能保持分组。支持的附件和任务背景沿既有适配器交付；不支持的输入给出具体原因并保留草稿。外部会话的历史、运行与停止仍由其原执行 owner 管理。

## 13. 实施与验收

实施沿以下依赖推进，最终交付应覆盖选择到实际行为，不能以新的菜单外观代替输入合同接线：

1. 统一触发片段、草稿引用映射、键盘优先级与候选控制器，修复整框覆盖和异步选中跳动。
2. 连接原命令 registry 与真实会话上下文，接入已有功能目录及同容器子视图。
3. 技能独立分组，接通任意正文位置、多技能、来源身份和 Host 激活。
4. 以真实任务、文件来源和附件实现 `@`；与文件交接设计共同完成发送、保留和回读。
5. 接入明确收件人的协作输入，完成整理交接、导出和记忆快捷流程。
6. 完成 Bot、子任务、外部 Harness 和移动端的适用性、动效、i18n 与文档收敛。

验证按实际风险选择少量行为场景；主要依据如下：

| 场景 | 验收结果 |
| --- | --- |
| 已写长草稿，在中间选择功能／技能／文件 | 只修改当前片段，附件、其他引用与撤销保持正确 |
| 中文输入、Shift+Enter、Tab 建议与菜单同时存在 | 优先级准确，无误选、误发和键盘被空菜单吞掉 |
| 搜索进行中上下移动或切换查询 | 选中项稳定；旧结果不会执行成新查询的对象 |
| Escape 后异步返回、重新聚焦、快速开关 | 菜单不擅自重开，退出和重新打开连续可打断 |
| 同名技能、正文内多技能、资源修改后重试 | 激活准确资源，原已受理请求不换版本、不重复执行 |
| 带空格路径、同名文件、改名任务 | 引用仍准确；直接改写文字不会残留错误隐藏绑定 |
| Bot 与工作台来回切换、独立子工作区、远端 Host | 候选与执行对象始终对应当前真实来源 |
| `@任务` 与 `/联系 Agent` | 前者引用对象，后者明确改变收件目标，用户身份不变 |
| 新会话、导航、模型和权限操作 | 草稿保留，配置作用范围与生效边界表达准确 |
| 大目录、技能多、长会话导出 | 元数据按需加载，结果可继续查看，不扫描或读入无关正文 |
| 发送文件和外部后端不支持某项输入 | 原件实际可读，失败原因清楚，不悄悄删附件或降为描述 |
| 亮暗主题、触屏、键盘与读屏 | 说明可读、选择可达、滚动不误选，无厚重套层与焦点丢失 |

完成后将现行行为并入 [工作台](../workbench.md)、[协作](../collaboration.md)、[输入框模块说明](../../packages/ui/src/components/chat/composer/DOCUMENTATION.md) 与相关 Host 文档。本文在设计实施期间保留明确状态，后续按仓库约定收敛。
