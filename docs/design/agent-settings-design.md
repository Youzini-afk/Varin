## 1. 产品目标

设置页与对话是管理同一套设置的两个入口。用户可以通过自然语言查看、理解和修改 Varin 的大部分设置，
也可以继续在原设置页浏览、比较和微调。明确的请求沿已有授权直接执行、自动保存，结果简短说明改了什么、
作用于哪里以及何时生效；仅在作用范围等歧义确实改变结果时澄清。

范围覆盖整个产品，不只开放少量 Harness 开关。Agent 能发现当前可操作项、读出真实生效状态、完成修改、
恢复默认，并在需要时管理相关 Skill、提示词和扩展。持续运行的自我调参、额外设置规划模型、固定审批流程不属于本目标。

典型请求包括：

- “终端字体稍微大一点，通知声音关掉。”
- “现在检索用了哪些模型，为什么这个项目的行为和默认值不同？”
- “把网页搜索改用我已配置的服务。”
- “把刚才的文献筛选办法保存为这个项目的 Skill。”
- “帮我调整科研工作环境。”后者可以按需读取组合指南，再查询实际配置并操作。

## 2. 现有基础与需要补齐的部分

源码核对入口如下。它们是实现起点，不是已完成的统一 Agent 管理通路。

| 现有责任 | 入口 | 本阶段的处理 |
| --- | --- | --- |
| 应用设置保存与副作用 | [settings-runtime.ts](../../packages/web/application-host/lib/platform/settings-runtime.ts) | 复用保存 authority，补齐语义化操作、并发条件与变更通知 |
| 应用设置客户端 | [settings.ts](../../packages/web/src/api/settings.ts) | UI 与 Agent 汇入同一操作服务 |
| UI 偏好应用与同步 | [persistence.ts](../../packages/ui/src/lib/persistence.ts) | 复用界面应用逻辑，避免收到远端更新后又写回旧值 |
| 设置搜索目录 | [search.ts](../../packages/ui/src/lib/settings/search.ts) | 拆出界面无关的共用定义，替换独立手写搜索表 |
| Pi/Harness 设置协议 | [methods.ts](../../packages/protocol/src/methods.ts) | 复用 settings.get/update 与 revision，保留字段所有权 |
| Pi 设置、Skill、提示词资源 | [session-host.ts](../../packages/pi-host/src/session-host.ts) | 复用资源所有权和配置写入，协调运行中的 reload |
| 原生工具装配 | [select-tools.ts](../../packages/pi-host/src/harness/select-tools.ts) | 注册稳定的设置工具及实际可用的管理动作入口 |
| Varin 扩展生命周期 | [routes.ts](../../packages/web/application-host/lib/extensions/routes.ts) | 调用既有扩展服务，不创建第二份扩展状态 |

应用设置、Pi 原生配置、扩展配置以及客户端呈现状态的 owner 不同。统一的是发现、描述和操作合同，
不把它们搬进新数据库，也不让 Agent 直接修改内部 SQLite、浏览器缓存或发行安装目录来代替正常操作。

## 3. 覆盖范围

实施时从实际设置页面、字段定义和管理动作整理覆盖映射，逐项说明 owner、真实作用范围与接线状态。
以现有产品功能为依据，不设覆盖百分比，也不能只做几个示例开关便宣称阶段完成。

| 范围 | 应提供的能力 |
| --- | --- |
| 外观、语言、聊天、通知、快捷键、语音 | 查询当前配置与可选值，修改和恢复默认；平台专有项显示真实可用性 |
| 编辑器、终端、工作台偏好 | 修改原有偏好并应用到正确客户端；工作台布局与 Agent 执行配置仍分离 |
| 项目、会话默认、模型与 provider | 解释来源和覆盖关系，修改实际支持的范围；登录与凭据操作沿原服务 |
| Harness 工具、权限、上下文、模型分工 | 读取实际配置与运行世代，按字段所有权修改并准确报告生效时机 |
| 代码检索、网页访问、知识与语言支持 | 管理配置，发现已有准备、安装、取消、重试等动作及其状态 |
| Skill、提示词、Pi 包、MCP、Varin 扩展 | 通过原 owner 查看和管理；不能把插件私有任意字段推断成可安全修改的设置 |
| 远程连接、机器与执行偏好 | 绑定正确 Host/设备/工作区，复用连接与资源服务；操作状态如实返回 |

有些设置页项目属于只读诊断或实际操作，而不是持久配置。目录需区分可读、可修改、需用户交互、
当前不可用与尚未接线。需要系统登录、原生文件选择等步骤时提供准确入口与状态，不把它们从目录隐藏，
也不把“已打开入口”描述成“操作已完成”。第三方未提供结构化配置合同的部分可以保留原生编辑入口并说明边界。

## 4. 共用定义，原 owner 执行

```text
设置界面                    Agent 设置工具 / 管理工具
    \                              /
       共用设置目录、目标解析与操作服务
                     |
        应用设置 / Pi 配置 / 扩展 / 原生客户端
                     |
           保存与实际应用 → 结果、变更通知
```

界面无关的描述和 DTO 放入现有共享契约边界；Host 负责身份、目标解析、操作路由和结果，
各 owner 负责其数据校验、持久化与实际应用。共享定义不导入 React 或 UI store，私有 Rust kernel 不新增公开设置后门。
原生客户端动作通过既有 Surface/Runtime API 交付到指定客户端，不由远程 Host 假装已经操作了本地窗口。

设置描述至少表达：

- 稳定 ID、分类、标题/说明的 i18n 引用、搜索关键词与设置页位置；ID 不随显示语言变化。
- 类型、单位、校验来源、静态选项或动态选项的查询入口；动态模型、主题、设备列表来自实际服务。
- owner、可操作种类、支持的作用范围、平台/插件依赖与当前可用性。
- 值来源、覆盖规则和默认值的解析方式；规则复用实际 resolver，目录不维护另一套合并逻辑。
- 生效策略及相关管理动作引用；复杂说明、示例和组合指南的按需入口。

定义与校验共用可执行来源。必须通过专用服务验证的字段引用其 validator/adapter，不能再手抄一份约束。
目录和生成说明可以派生、缓存；配置值、授权结论、登录状态和实际生效状态仍在使用时向 owner 读取。
扩展按已有激活/停用世代注册和撤回描述，真实执行仍再次核对可用性与权限。

## 5. 渐进式披露

### 5.1 常驻能力入口

system/tools 中保留稳定、简短的管理说明，告知 Agent 可以查询并修改外观、通知、模型、Harness、检索、扩展等设置，
以及设置工具的用途。不放完整字段表、所有可选模型、完整指南或当前配置快照。
模型可见说明沿项目约定使用英文，UI 使用 i18n；中文等用户表达由当前 Agent 理解并转为查询，不增设设置专用 LLM。

### 5.2 查找时就返回简单操作所需信息

`settings_search` 支持关键词、分类浏览与已知 ID 定位。结果含 ID、简短用途、当前值摘要、
真实作用范围、可用性和生效方式；简单开关/枚举同时给可选值及执行需要的版本信息。
因此“关闭通知声音”可以在查到当前状态后直接更新，不强制再调用详情工具或先读 Skill。

搜索基于共用名称、说明、别名与关键词，不新建持久向量库。分类浏览保证不知道关键词时仍能遍历完整目录。
结果较多时沿既有输出分页/正文引用机制提供继续入口，不用无依据的固定条目截断隐藏设置。
没有匹配、目录不可用、设置存在但当前平台不支持分别表达。

### 5.3 复杂设置按所需细节展开

`settings_read` 查询指定项或相关组，返回当前配置、实际生效值、来源、默认/覆盖关系、支持范围与生效状态。
复杂规则的参数格式、操作示例、关联项、动态选项和指南正文可选择展开。
例如模型设置先给当前模型和用途，需要更换时再查实际可选模型，必要时按 provider 继续筛选。
普通布尔值不附一篇操作手册，也不因查询一个模型就读取所有 provider 和凭据配置。

每一层的返回都给明确的下一步入口；已取得足够信息可以直接操作。工具合同保持稳定，
发现新设置不逐项新增模型工具定义，也不动态重写历史前缀。已知 ID 的操作不强制重走 search → read 全流程。

### 5.4 Skill 的职责

查询/操作工具提供实时事实和可执行能力；Skill 解释组合方法、使用理由和复杂任务示例。
例如“准备科研工作环境”可以读取一个组合 Skill，再检查模型分工、通知、资源和检索的实际情况。
Skill 使用稳定设置 ID 或能力入口，不复制当前值、可选模型列表、凭据或独立参数校验表。

可提供精简的 Varin 管理指南及确有复用价值的专题 Skill。它们使用产品已有的 Skill 加载与用户/项目资源体系，
不新增仓库贡献者工作流 Skill，也不要求每个设置对应一个 Skill。单项设置无需先读指南才能修改。
Agent 创建或修改 Skill/提示词时走既有资源 API，变更与用户在界面管理的是同一份文件与 revision；
是否立即加载遵循实际运行时生效合同。

### 5.5 上下文与变更

按需取回的说明作为普通工具结果进入历史，之后遵循已有输出与压缩机制，不在每次请求重新注入。
已订阅/实际使用的配置变化可通过 D-301/7G 环境增量告知相关会话；只交付简短变化与详情入口，
不把完整设置快照加入团队现状表。工具已交付的同一变化不重复追加，送达收据复用现有机制。
配置保存或目录变更本身不唤醒空闲模型、不触发额外总结，也不主动重新配置其他 Agent。

## 6. 工具与操作合同

工具名为参考形状，实施时可按现有注册约定调整；语义与真实消费者必须一致。

| 入口 | 输入意图 | 返回内容 |
| --- | --- | --- |
| `settings_search` | 关键词、分类或 ID；必要时继续浏览 | 相关设置摘要、当前值摘要、范围、可用性、简单参数与详情入口 |
| `settings_read` | 设置 ID/相关组、目标、需展开的细节 | 当前值、effective/source、revision、选项/格式、应用状态、按需示例 |
| `settings_update` | 目标、一个或多个 set/reset 变更、已读取的条件版本 | 逐项实际结果、保存后/生效中状态、范围、失败或所需后续动作 |

工具调用传稳定 ID 和类型化值，Host 按登记的定义及 owner 校验。工具不接受任意 Host RPC 方法、
任意文件路径或可执行脚本充当设置更新。不要把 `JsonValue` 的传输能力误当作省略逐项类型与语义验证的理由。
省略项保持原样，`reset` 撤销对应范围的显式覆盖，再由原 resolver 计算有效值；`null` 仅在该设置本身允许时作为值。
非法值、未知字段与不支持的范围必须明确返回，不能复用旧归一化器的静默丢字段行为后宣称成功。

安装、登录、启停、连接、准备模型/语言服务等操作由目录引用原领域动作，复用或补齐该服务的 Agent 工具适配，
不伪装成布尔值更新。缺少 Agent 适配时记为未接线，只有 UI 链接不能算对话管理已完成。
涉及系统交互的步骤可以返回可打开的入口；涉及长任务的步骤只有在 owner 返回真实稳定身份、
并提供可查询/可取消 authority 时才返回 operation。Host 将 operation 元数据写入现有 Rust
`settings.operation` typed record，记录 caller session、entry 和 owner identity；重启后按
同一记录对账。Owner 只有异步启动而没有状态 authority 时返回 `unavailable`，不伪造 handle，
也不保留永远 `running` 的影子任务。

设置读取默认没有副作用，不能因查看可选 provider/组件便登录、下载、安装或唤起模型。
改变到需要尚未安装组件的配置时，明确给出依赖与准备动作，沿用户请求和既有授权处理，不隐式视为安装成功。

## 7. 身份、范围和权限

身份来自 Host/broker 的真实 session、Thread、owning workspace 和运行配置绑定。
临时 execution worktree 不自动成为项目默认的保存位置；目标中的 ID 是引用，不能覆盖服务端解析出的 authority。
当前设备/Surface 与计算 Host 是两个维度：连接远程 Host 时，桌面字号仍操作所选本地客户端，
远端执行设置操作相应 Host。存在多个客户端且无法确定目标时明确选择，不能广播修改所有窗口的设备私有设置。
没有客户端时可保存的偏好与必须有客户端才能执行的动作分别报告。

作用范围取决于实际字段定义，不为所有设置虚构全局、项目、会话覆盖。D-031/5.10 的 user-only、
可信项目与只能收紧的规则继续有效；若后续要扩大某字段范围，必须连真实 owner/resolver 和消费者一起实现并记录该语义变化。
“这次使用”与“修改以后默认”分别路由，不能为满足一句临时要求悄悄改动其他会话的默认值。

客户端 Surface 绑定由已认证 UI 先向 Host 登记当前 session，再由 Host 校验该 session
仍在 broker 中存活并绑定 SSE 连接；Harness caller 的 `sessionId` 是唯一选择依据。
Surface id 只作为 Host 返回的事实，不接受模型传入的 Surface 选择器。零个绑定 Surface
返回 `unavailable`，同一 session 的多个窗口返回 `ambiguous`，连接重建或 session 删除后
必须重新登记，不能把临时连接推断成跨设备永久绑定。

所有修改经过 Varin 原生 `tool_call` 权限门和 Host 能力检查，沿实际设置资源描述授权，
不因使用统一 update 入口便给予对整个应用配置的无限写入。已有授权可直接执行，不为每次改字体、通知重复审批。
权限策略修改按修改前的有效授权判断，不能让 Agent 用本次提交给自己放行；既有撤销仍即时生效。
普通子线程沿已授权的管理能力工作，不新设按角色名一律禁止管理的政策。

凭据字段可显示是否已配置、由哪个 provider 使用及登录/替换入口；查询、日志、广播和 Skill 不返回密钥正文。
敏感输入走原有凭据通道，目录只引用凭据身份。工具来源、第三方说明和 Skill 内容不会因此取得系统指令或额外权限。

## 8. 保存、并发与实际生效

### 8.1 按 owner 提交，避免覆盖用户修改

Agent 和 UI 都提交局部语义变更，不持有一整份旧配置再覆盖写回。复用已有 revision/CAS；尚无条件写入的 owner
在本阶段补齐必要检查。不同字段的变更可在 owner 的原子更新中合并；同一字段在读后被用户或另一 Agent 修改，
返回冲突及当前状态，由调用者重新判断，不能重试旧快照直到覆盖成功。

调度资源键按真实 owner、目标和修改范围解析，接入 D-302/7H。两个线程修改同一全局配置时不能因工作区不同而绕过协调。
能力检查后的读写关系参与调度，底层 owner 的原子性继续保留；设置管理不建立整套产品的全局执行锁。

一个请求可表达多个设置变更。同 owner 支持原子提交时使用其事务；跨 owner 先完成可做的校验，
再返回各项真实结果，不承诺不存在的跨进程全局事务。部分成功时明确列出已完成和未完成项，
后续仅继续未完成部分，不盲目重放安装、登录或全部变更。
若提供“撤销本次修改”，只逆转仍匹配本次写入值的项目，不恢复整份旧快照覆盖后续用户编辑。

### 8.2 生效时机由真实消费者决定

| 情况 | 合同 |
| --- | --- |
| UI 即时偏好 | 保存后发到正确客户端并应用；未收到实际应用结果时不谎称界面已改变 |
| 支持热更新的服务配置 | owner 确认新状态后报告 applied；候选准备失败保留原活动状态并报告错误 |
| 模型、工具和运行提示配置 | 遵守当前 Run/执行配置世代的冻结规则，在明确的新 Run/下一合法配置边界应用 |
| 需重新启动的组件 | 报告已保存、仍待哪个组件重启；通过既有生命周期动作继续 |
| 安装、连接、登录 | 返回实际动作状态，不用 saved 替代 installed/connected/authenticated |

Agent 正在执行设置工具时，不能同步 reload 自己正在等待该工具返回的会话，也不能让工具调用走回同一被占用的控制队列形成死锁。
持久配置更新与会话切换由原 owner/broker 协调；先准确返回保存或待应用状态，再在合法边界提交新世代。
原有 UI 写入路径也使用这一合同，不保留“UI 直接 reload、Agent 另外排队”的双轨。
取消一次等待不撤销已保存事实，响应丢失不等于操作未执行；通过 revision、当前状态或既有操作身份核实后继续。

### 8.3 同一份状态在界面与对话可见

变更成功后以 owner/target/revision 关联的事件刷新相关 UI 与缓存，不在广播里携带秘密或完整配置正文。
客户端重新连接时读取权威快照，旧事件和旧 runtime 的迟到响应不能覆盖新目标的状态。
界面应用权威状态时不触发一次反向保存，保留现有的防回写机制；未保存的用户编辑按字段冲突处理。
Agent 再次读取应看到用户刚修改的值，设置页也应看到 Agent 的修改及其待生效状态。

## 9. 扩展性与实现取舍

新增正式设置时，在所属模块登记同一份描述、校验/选项来源、读写 adapter 与生效合同；
UI 搜索、Agent 目录与按需说明从这里派生。自定义 React 控件可以保留，设计不要求全部页面改成自动生成表单。
随着该领域接入，删除重复设置搜索表、独立 Agent 配置副本与过期写入分支，不保留内部兼容 facade。

Pi 包、Varin 扩展和原生 UI 能力仍保留各自权威；第三方设置由真实声明和可调用服务接入，
不根据 DOM、字段名字或手写 Skill 推断执行能力。配置服务之外的文件/Git/线程/实验操作复用已有工具，
本阶段不复制它们，也不引入任意自修改应用源码或发布更新的后台循环。

## 10. 验收与交付边界

实施与验证按 [阶段 S](../plan/agent-harness-plan.md#阶段-s对话式设置与-agent-管理d-306) 推进。
核心判断是设置能否被找到、正确理解、写回原 owner 并实际应用，以及界面和 Agent 能否读到同一结果。
以下是应核对的行为，不是要求每项建立独立测试或重新跑完整平台矩阵：

- 现有主要设置类别和管理动作均有覆盖映射；未接线、平台不可用、只读和需用户交互没有混为“已完成”。
- 简单项 search 后可直接改；复杂项可继续获取真实选项和示例；分类可遍历目录，字段 ID 不依赖界面语言。
- 修改、reset 与来源解释经过真实 resolver；临时选择不污染全局，用户级规则不被项目配置越权放宽。
- UI/Agent 双向可见；并发编辑不丢用户值；远程 Host 和本地界面不会被混为同一目标。
- 正在运行的 Agent 修改设置不会死锁或中途更换冻结配置；保存、应用、重启、安装和失败分别表达。
- 跨 owner 的部分成功、动作响应丢失、客户端重连均按已发生事实继续，不重复副作用。
- 目录查询不启动下载/模型，凭据不进入可见结果；Skill 与工具说明不形成第二份参数与实时状态 authority。
- 原生权限、真实 Pi 工具装配、Host 操作服务、owner 与 UI 的生产调用链已接通，不能以 helper 测试或说明文档替代。

使用代码与直接消费者核对广度，针对真实风险选择定向行为证据。不以固定设置数量、源码字符串扫描、
测试数量、独立付费模型评测或全平台手工点击清单作为阶段门槛。尚未进行的外部服务/平台/真实模型实测在 status 如实记录。
