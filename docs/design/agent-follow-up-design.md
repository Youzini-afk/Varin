## 1. 用户需求

常见需求是当前工作遇到长任务或外部依赖时先等待，条件满足后在原工作上下文继续。
用户可以直接说“训练结束分析结果，失败就处理”“半小时后再看看”“产物准备好后继续整理”，
Agent 自然使用工具登记后续意图，用户不必另开调度器、填写流程表或选择触发器类型。

等待和明确条件检查由程序完成；确实需要理解、判断或执行时才恢复模型。
减少的是没有变化时反复调用模型询问进度的成本。轮询可能仍消耗远端 API/网络，恢复后的请求仍有输入费用，
不把程序监听描述为所有资源零成本，也不承诺跨长时间等待仍命中模型缓存。

原有每日/每周新建任务继续有用。时间、事件和条件检查共用触发与结果管理，
但“新建一次工作”和“续接已有会话/线程”的目标必须显式区分，不能互相替换。

## 3. 触发方式

| 场景 | 首选来源 | 程序负责的工作 |
| --- | --- | --- |
| 训练、构建或长执行结束/失败 | 耐久 experiment attempt；普通 shell 可按 executionId 登记退出/状态/输出命中 | 识别退出/成功/失败，给结果和原文入口；普通 shell 重启不可重附着时转 unavailable |
| 文件或产物就绪 | Documents/文件观察或产物收集服务 | 区分文件出现、发生变更与完整产物 ready，不能把开始写入当作完整可读 |
| 指标达到条件 | 已声明的结构化指标来源 | 读取值、单位、修订/时间并判断明确谓词 |
| 出现指定日志内容 | 指定执行的原始日志增量 | 沿游标匹配，保留命中范围和来源；不能把任意 ERROR 文本自动当作作业失败 |
| 半小时后检查、某时续做 | 时间触发 | 记录绝对到期时间和用户时区语义，到期产生一次触发事实 |
| 外部服务没有事件接口 | 已授权服务的状态查询 | 定期做确定性读取，条件成立才交付；沿服务限流与真实查询能力调度 |

已有可靠事件源优先使用，远端没有推送能力时才选择程序查询。条件字段由来源类型决定，
例如状态、退出码、数值比较、指定文本，不提供任意脚本求值作为默认条件接口。
协议只描述程序能实际核实的条件；“结果有价值”“方向不太对”这类理解任务进入后续指令，
在一批结果完成或用户选择的检查时间交给模型判断，不为每段日志调用判断模型。

支持明确需要的事件加时间后备，例如“结束就分析，两小时后还未结束则检查”。
这是两个带不同理由的触发入口：终态出现时消费完成续接，仍在运行时的时间检查可以保留终态订阅。
后备检查不必取消后续完成意图；同一时刻两者都成立则合并为一次可理解的续接输入。
无需引入通用工作流 DSL、参数矩阵或固定研究阶段才能表达这一需求。

一次性后续是普通“到时候继续”的自然语义。重复检查、每次新结果触发或定期新建任务须有明确的重复意图。
条件持续为真不应每个采样都唤醒模型；按来源事件/修订/阈值跨越产生 occurrence，重新武装规则在定义中可见。
查询频率来自具体需要和服务能力，不预设所有来源一律每分钟检查；同来源相容订阅可共享查询结果。
暂时离线、无权限和未知状态不能当成“实验失败”或“条件已满足”，应报告观察不可用并按实际连接/重试机制继续。

## 4. Agent 的自然使用与渐进披露

### 4.1 常驻短说明和操作建议

在稳定工具/提示说明中告知：工作需要等待时，可让后台执行继续，并登记条件和后续工作；
有其他工作可以先做，需要完全等待时可显式让出模型执行。常用长任务工具返回 execution/attempt 身份时，
附简短的可观察终态和后续入口，避免模型必须记得另一本自动化手册。

简单的“实验结束后继续”直接引用 experiment 返回的 attemptId 和自然语言后续指令，
无需先调用查询工具、读 Skill 或填写进展/优先级/理由等汇报字段。
复杂外部来源才按需查询支持的条件、状态字段和操作示例。Agent 可读取组合 Skill 学习用法，
但 Skill 不是执行事实或触发条件的权威，也不成为普通等待的强制前置。

### 4.2 稳定管理入口

参考入口 `follow_up` 提供登记、查看/列出、修改、取消、立即检查等操作；
参数与名称可结合现有工具族调整，保持少量稳定定义，不为每个条件生成新工具。
主要表达“等待哪个来源/时间”“触发后做什么”“是否现在暂停等待”。
session/Thread、owning workspace、运行目标、来源权限由 Host 从调用身份解析，模型不重复填写完整执行清单。
需要跨目标时使用已有授权的对象引用，不能信任请求里的任意 owner 字段。

登记结果返回稳定 followUpId、实际目标、可核实的触发摘要、后续指令、当前状态和详情入口。
更新/取消按 revision 处理，已取消或被替换的定义不能被迟到回调重新激活。
登记意图由用户要求或当前任务明确需要的后续行动支持；不因每次普通输出变化擅自建立长期监控。

### 4.3 登记与暂停是两个动作

登记可非阻塞返回，Agent 继续其他工作；它也可以在登记时或之后明确选择暂停当前推进，等待条件。
暂停是显式工具意图，由运行时记录，不通过猜测最后一句自然语言或额外模型审计推断。
短时间的立即观察仍可用现有 get_output/wait；不强制所有短命令创建持久后续。

明确暂停等待后结束当前模型回合并让出执行名额，不用长时间挂住一个工具 RPC。
运行中的训练、进程、GPU/目录 writer 等资源按真实生命周期继续持有；让出模型名额不等于释放实验资源。
Goal 保留目标及等待关系，不将等待标为完成/blocked，不在安静窗口后反复审计或自动续做。
非阻塞登记不停止仍有其他工作可做的 Goal。用户继续聊天可正常执行，已有等待仍按其有效定义观察。

## 5. 同一工作身份上的续接

默认恢复发起等待的 session/Thread，主线程和子线程均适用，不一律发给主 Agent，
不为每次触发创建隐藏会话。具体 Run 使用已有生命周期规则；旧 Run 已结束则在同一 Thread 上合法开始新 Run，
并保留成果与允许使用的当前配置。主动 fresh、分支导航和任务替换遵循原会话/线程合同。

触发时有两种交付：

- 目标正活跃：把事实和后续意图交到现有输入准备/消息接缝，在自然请求中处理，不并行开启同一目标的第二轮。
- 目标空闲且登记了继续意图：经过同一运行准入与耐久消息路径恢复；只登记通知的则通知用户或保存事实，不调用模型。

这两种是同一 occurrence 的交付选择，不能一边通过 7G 注入，一边再发送一条独立 prompt。
Host 在提交续接前重新检查目标是否活跃、是否被取消/归档/删除、权限是否仍有效，以及用户是否刚有新输入。
自然续接与自动续接竞争时合并到同一合法执行机会，保留触发事实，不覆盖用户的新指令。
明确取消等待或取代任务会撤销对应后续；无关的新聊天本身不自动取消等待。

通知用户、附加事实和恢复模型分别记录。前台关闭不代表 Host 不能运行；Host 真正停止后不承诺按时执行，
需要常在线时使用实际运行的远程 Host，目录与 UI 显示真正的协调位置。

## 6. 状态、持久化与恢复

### 6.1 轻量耐久意图与来源引用

Application Host 拥有触发与续接策略，沿现有 Rust durable storage 的类型化边界持久化必要记录：
定义及 revision、发起/目标身份、来源引用和观察位置、到期/检查时间、后续指令、等待/取消状态、
发生过的触发及其投递关联。Pi 保留会话和对话树，Thread/Run 保留工作身份，实验和进程仍由原 owner 管理。
不另建任务数据库、第二套 Agent loop 或复制原始日志/实验目录来实现续接。

只保护恢复工作需要的合法引用；等待不长期占有文件读写锁或模型执行槽。
自动回收不能先删掉仍被有效后续引用的目标/证据。用户明确删除或归档按生命周期取消/停用相应等待，
释放引用；保留一条等待记录不成为复活已删除线程的理由。

### 6.2 注册和消费不能丢事件

注册采用来源实际支持的快照加订阅/游标方式，处理“任务恰好在登记期间完成”。
登记前已经完成的来源应返回已满足事实并安排一次有效后续，不永远等待下一条不会出现的终态事件。
程序扫描和事件通知可能重叠，通过 definition revision 与来源事件/状态修订形成 occurrence 身份。

触发先耐久记录，再按该身份申请交付/续接。Thread 目标复用 `thread.send` 的 request ledger、目标串行区、held flush、
continuation admission 与同一 requestId；root session 没有 Thread ledger，继续复用 Pi 原生 notify/request receipt。
响应丢失后查投递/运行状态再继续，不盲目重复派发。观察、触发、消息接受、Agent 运行和结果完成分别表达，
不能把 accepted 当 completed，也不能仅凭去重键承诺任意远端副作用全局 exactly-once。
条件更新/取消与回调以相同 revision/状态边界协调，旧定义不能继续产生新动作。

### 6.3 重启、断连和错过时点

重启后重建有效订阅、重新核对来源与未完成交付。普通会话 shell 的进程不因等待记录持久化就获得跨 Host 重启存活保证；
原执行已丢失时报告 source unavailable。耐久实验/受管远端 attempt 按已有重附着接口读取真实状态，不重新启动作业。

一次性“稍后继续”在 Host 离线期间到期，恢复后对仍有效的意图产生一次到期事实，并说明延迟；
已取消/目标已删除则不执行。周期性条件检查恢复时检查当前状态，不逐个回放所有漏掉的采样点。
已有 recurring 新任务排程支持明确的错过时点策略；普通周期任务默认跳过历史时点并安排下次，
用户需要最近一次补跑时可明确选择合并补一次。不能把恢复后重放全部旧时点当默认行为。
绝对时间和时区来自注册时解析；重复日历排程继续使用原时区算法，系统睡眠和时钟跳变需核对到期身份防重复。

## 7. 事实交付、注意力与费用

触发材料采用明确的环境/工具来源，包含触发原因、相关来源身份、关键状态/退出码和日志/产物入口，
以及原先登记的后续指令；不冒充新的用户命令或 system 指令，不重播整段日志，也不引用隐藏推理。
7G 保留环境增量与送达收据；普通工具、线程消息和触发投递共享来源关联，已交付事实不重复注入。
会话压缩/重建按实际保留原文恢复必要事实；旧团队表继续是每请求临时状态，不承载完整等待目录。

同一执行的近邻终态/产物更新可以在一个可执行机会交付；不能为每个日志块、采样或 UI 刷新调用模型。
若用户选择按时间让 Agent 重新评估，则到时确实可以调用模型，即使没有机械状态变化。
语义判断发生在用户/任务选择的检查节点，不能偷偷增加一个循环判断模型或按事件类型升级到高价模型。

## 8. 界面与原有定时任务的统一

会话中显示轻量条目，例如“等待训练完成，随后分析结果”，可展开来源、条件、协调 Host、
后续指令和最近状态，提供取消、修改、立即检查和打开执行现场。
立即检查先读取来源；“现在让 Agent 接手”是明确的模型续做动作，不能把二者混为一键静默收费。
任务已完成但收集产物仍在进行时分别呈现，错误、断连和需要用户授权有可操作的状态。

原项目计划任务入口、CLI 和 Markdown 定义继续服务定期新工作，并接入同一触发/管理服务。
新会话排程与原会话续接使用不同目标类型，保留原生定义文件的所有权与 revision，不生成第二份可编辑副本。
Agent 获得查询、创建、修改、启停/取消和立即运行的原生能力；Markdown 变更有实际同步入口，
不能必须靠用户打开列表才能使 Agent 刚写的定义生效。

修复原 scheduler 的结果语义：启动接受后应显示 running/accepted，真实 agent_settled、错误、取消或 Goal 终态才更新完成结果。
每次触发与其会话/Run 有关联，可查看结果；排程并发和“同任务不重叠”按真实选定执行生命周期计算。
取消一次后续默认只取消等待/唤醒，停止训练/进程必须调用其真实取消动作；相关权限沿原生门执行。

## 9. 验收边界

实施分阶段见 plan W0–W4。关键证据应覆盖真实消费者和以下实际风险，按风险选定向检查，
不要求每项另建套件或重跑全仓/完整跨平台实测清单：

- Agent 从后台 execution/attempt 结果自然登记后续，简单场景无需额外指南或汇报字段。
- 等待和机械检查没有模型空转，显式暂停能抑制 Goal 续做；后台登记不妨碍其他工作。
- 事件、到时和程序条件可交付；语义判断按选择的节点发生，读取失败不误判业务失败。
- 注册前/注册中已完成、重复回调、时间后备与事件同时满足只产生正确交付；重复条件不会持续唤醒。
- 主/子目标正确，活跃/空闲竞争及用户新消息不导致重复运行，取消/归档/删除后旧事件不会复活任务。
- 接受、运行、完成、Goal 终态和产物收集各自真实；旧定时任务的 success 不能仍代表仅派发成功。
- 重启和断连按来源能力恢复，持久实验不会重新启动，普通 shell 丢失不会假装仍在运行；missed time 按所选语义处理。
- UI/CLI/文件定义/Agent 共用权威与实际生效通路；身份、权限、输出引用和数据保留边界保持。

不以工具数量、固定轮询间隔、预设并发/墙钟上限、独立付费模型质量评测作为完成门槛。
已完成代码通路与未实测平台/外部服务分别记录到 status，不能把尚未接线的核心能力改写成仅未实测。
