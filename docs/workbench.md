# 工作台、文档与呈现

Varin 的工作台是在共享状态之上的可替换界面。本文说明更换 Shell、编辑器或交互设计时仍须保留的职责边界。
具体类型、行为和失败结果以当前代码及定向测试为准；局部实现入口见 [UI 模块导航](../packages/ui/DOCUMENTATION.md)。
进程关系见[架构](architecture.md)，文件与执行资源见[资源](resources.md)，扩展生命周期见[扩展](extensions.md)，
聊天内的声明式片段、HTML 作品、原生对象入口、画面读取和引用见[交互内容](interactive-content.md)。
Shell 不改变实际回答者的表达约定；原生对象使用原身份、状态和导航，正文控件不新建执行或消息队列。

## 职责划分

| Owner | 职责 |
| --- | --- |
| Application Host | 工作区准入、磁盘文档、watch、恢复 journal、Profile、扩展目录及特权服务 |
| `@varin/application-client` | 与框架无关的 `RuntimeAPIs`、DTO 和类型化失败 |
| Document Registry | 实时 buffer、base/local revision、dirty/save/conflict 和草稿恢复 |
| Editor Workbench Kernel | 编辑组、tab、provider 选择、view identity、命令和恢复快照 |
| 编辑器 adapter | 引擎 model 投影、视图状态、渲染和语言结果投影 |
| Shell contribution | 布局、呈现和自身短期交互状态 |
| Runtime / 领域 owner | 对话、执行、终端、Git、语言、调试、测试和资源事实 |

Electron 在进程内承载同一套 Web Application Host；移动端连接 Varin server。
它们不另建文件系统或语言进程后端，renderer 也不能通过更换 Shell 或编辑器取得额外权限。

### 桌宠偏好与资源

桌面端在使用偏好下提供独立「桌宠」页，管理形象下载、进度、取消/继续、选择与删除，以及唤醒和沉睡。
沉睡只关闭人物与装饰窗口、停止动画，不改变 Bot 或任务的运行状态。所选形象保存在本机；陪伴哪个 Bot 仍由
原桌宠菜单独立选择。不同重点色复用同一份素材，实际人物继续跟随应用主题。

基础安装包保留播放器、轻量预览和下载目录，完整图集、轮廓页和审阅素材按需获取。Electron 按构建时固定的
源码提交和文件摘要校验下载，完整后才发布本机形象；取消、失败和重启后可复用已校验文件。已安装形象离线可用，
应用更新不重下载相同内容。删除当前形象会先沉睡，再回收素材和下载缓存。实现与打包入口见
[Electron 资源交付](../packages/electron/README.md#optional-desktop-companions)。

## Profile 与 Shell 切换

官方 Profile 的稳定 ID 是工作台的 `default`、IDE 的 `varin.ide` 和 Varin 的 `varin.bot`。
它们由普通内置扩展提供，可以停用或替换。工作台使用统一聊天界面，不再内置“通用／科研”布局切换。
旧科研布局的已保存选择由 Profile owner 自动转回工作台；实验记录和材料查看复用公共会话面板。
固定 Recovery Shell 在选中 Shell 无法运行时提供修复入口，不承担另一套日常工作区。

工作台选择属于 user/application，按用户选择、active profile 依次解析。工作区可以保存布局，
项目或会话导航不会自动选择另一 Shell。工作侧重、模型、权限和已受理 Run 的配置是独立执行事实：
切换工作台、IDE 或 Varin 不重配 Agent，也不改变当前任务的工作侧重。

模式选择器在进入 IDE 或 Bot 前按 Host 记住普通工作台，作为返回偏好，不另建当前 Profile 权威。
Bot 会话归属继续独立于普通会话导航。

Varin 的旁侧空间包含工作详情、电脑和文件页签。关闭详情不会停止任务，关闭或隐藏电脑只释放画面观察。
文件页签保留编辑缓冲及阅读位置，保存与冲突由 Document Registry 处理；服务切换前持久化恢复日志。
窄屏使用可返回的完整面板，当前聊天、输入草稿与原执行继续各自运行。

工作连接页以工作设备为默认入口：添加地址或 SSH 连接后，由当前服务实际检查资源能力。
添加设备保留现有执行来源与连接默认值；切换 Varin 服务和配对其他前端各有独立页签，避免混淆连接方向。

原生聊天输入框按“思考等级、模型、Agent、通用/科研”排列。这里的 Agent 指执行后端，新会话可选择 Varin 或当前 Host 已启用的
[外部 Agent](external-agents.md)；受理后沿原会话后端继续，不将 Shell 切换当作后端迁移。外部模型与运行选项来自实际连接，
不复用 Varin 模型渠道。执行智能体、多轮检索等内部子任务配置由 Agent 设置页管理。工作区由来源选择器决定。
工作侧重在创建草稿时采用项目默认值，随后按会话保留；它参与系统指令和可用子 Agent 目录的准备，与顶部工作台切换独立。
正在运行及已排队的输入保持原配置，输入框修改用于下一次手动启动的 Run。

Profile 的 `extensionIds` 是显式扩展集模板；编辑或选择 Profile 不会自动应用整套启停状态，
“Apply set”使用独立的 catalog mutation。当前模式选择器使用“启用并切换”路径时，可以先启用目标
Shell 扩展；Profile 提交失败则回退该次启用。未指定此选项的调用收到 disabled-shell 结果。

[WorkbenchProfileStore](../packages/extension-host/src/workbench-profile-store.ts) 通过 revisioned
extension storage 保存 Profile。读取失败或数据损坏时保留上次有效状态和诊断，不用默认值覆盖原文档。
暂时缺失的 contribution reference 留在布局中，重新启用后可以恢复用户选择。

[Shell 切换事务](../packages/ui/src/lib/extensions/workbench-shell-transition.ts) 捕获 Host、Runtime endpoint
generation 和 Profile revision，激活候选并验证 mount/render ready，之后才写入选择。目录监听的重启不改变
切换归属；真正的 Host 切换仍使旧候选失效。
revision 冲突、候选失败或 Host 改变时，旧选择保持权威。候选在稳定的 Shell slot 中准备；
选择提交后就地转为活动实例，保留组件状态，之后释放准备记录。失败时卸载候选。
内置工作台注册延迟加载入口，实际选中或准备时才加载该工作台模块。
启动时选中 Shell 失败，则显示 Recovery 与诊断，不伪造已经切回默认工作台。

### 视觉交接

`workbench.transition` 在 Shell 外选择 `transition-scene` contribution。
[过渡控制器](../packages/ui/src/lib/workbench/profile-transition.ts) 拥有 transition identity 与
cover/covered/reveal 阶段；scene 拥有画面和声明的时长。候选解析与 scene 准备可并行；
重组件渲染等到完全覆盖后进行，准备成功后才提交选择；揭示新界面还要等目标实际 mount 并跨过浏览器绘制边界。迟到的阶段或 mount 信号不能推进另一事务。
新选择立即取得事务归属并取消旧候选，尚未完成的隐藏 Shell 渲染也会释放；迟到的 scene 准备不会再启动旧过场。
切换入口不会将正常替代弹为失败；旧调用收到取消结果，停止后续会话导航。真正的准备或提交失败则揭示仍有效的旧 Shell 后报告错误。每次事务使用独立的动画宿主，
scene 的各订阅者分别记录已接收帧，外层读取状态不会吞掉内层动画的阶段通知。

scene 缺失、停用、失败或被撤回时使用 Core 不透明 fallback。事务捕获的 scene owner 保持到交接结束，
不会在 Profile 提交后中途重挂载。清理先保留终帧跨过 paint，再移除 canvas 和资源；减少动态效果偏好
传给 scene。公开合同不要求存在会话列表、页头或其他官方 Shell DOM 元素。

当前启动 splash 是产品实现。扩展派生的 pre-React bootstrap projection 和通用 shared-element/Motion
service 尚不是已实现的公共能力，不能从现有 Profile 动画推断这些接口已经存在。

## 聊天阅读与用户介入

开启「下一步选择」并指定模型后，Host 在用户会话一轮结束时独立起草一条可能的下一句。
输入使用本轮用户与主 Agent 正文、之前连续对话、已生效摘要及尚在进行的操作状态；模型从用户原话中参考
表达习惯。工具输出、其他 Agent 的消息和思考不作为普通对话输入。当前请求是文本请求，附件保留类型说明，
不携带图片字节；图片相关语义依赖对话中已有的说明。没有自然后续时允许返回空建议。
预算与生成复用同一份模型和分词器配置，包含提示词、输出格式说明和对话正文。历史按页批量计数，最终候选
再按完整文本核对；已知词表按分词结果取材，仅参考词表可用时沿用保守字节上界。准备、取消和完成都释放原计数租约。

建议绑定原 Thread、branch、Run 和历史 head，多窗口复用同一原生辅助请求。新一轮、分支或 Host 变化会使旧
候选失效。生成失败只在输入框提示建议不可用，正常聊天继续；已发送但结果不明的辅助请求不自动重复生成。
空输入框用比普通占位更淡的主题文字展示完整建议，整句淡入、自动换行。Tab 采纳为可编辑草稿；Enter 或
发送按钮将它通过正常消息通道发送。用户开始输入后隐藏灰字，仍可用 Tab 在当前选择处插入建议；命令、
技能和文件补全优先处理 Tab，输入法确认保持原行为。Esc 可收起建议。采纳不是自动发送，未采纳文字不进入草稿。

聊天提供按时间展开、对话优先、集中展示回答三种模式。未设置时默认对话优先；原有选择继续保留。
模型正文形成阅读边界，同一段后的普通动作和公开思考共用一条可展开过程行。当前段显示实际动作，
后续正文到达后保留确认过的工作摘要；手动展开状态保持。子 Agent、问题和独立作品保持可见，
脚本中已观测到的相同操作按原身份去重。思考、文件差异、终端仍采用原来的用途组件。
折叠过程行用动作图标和主要活动形成简短摘要，完整分类计数留在提示中；失败、待确认和后台进行状态独立可见。
搜索、网页和文档读取在对话优先与集中展示回答模式下先呈现动作、对象及结果数量，展开后按原内容展示；
按时间展开模式默认展示结果。结果标题、来源等只使用已有数据，短摘录直接可读，长正文按实际排版高度预览并可展开，
窗口宽度变化会重新测量。工具与摘录的手动展开选择随原会话保留，过渡沿用可打断的高度动画。
普通行内代码以等宽字体、中性文字和极淡中性底色标识；正文强调由字重与结构表达，链接继续跟随主题重点色。
自定义主题显式指定的 Markdown 配色保持优先。

普通成功调用不重复强调完成；修改草稿、分支变更和实际应用分别表达。摘要不足以确认唯一文件数时
统计调用次数。后续任务的当前状态和当时回执有明确区别，空列表不显示登记成功，取消条件不继续显示等待。
集中展示回答的过程收起保留高度过渡，沿用虚拟列表的测量与阅读位置；减少动态效果时直接切换。

问答区与输入框共用列宽，参与布局并独立滚动，不遮挡输入区或抢焦点。长选项纵向换行；一个请求可含
多题和多选，问题按顺序同时显示，题号导航定位原题，整组提交共用原 Operation。选项采用轻量纵向列表，
补充说明原位展开并保留输入，纯文本问题直接显示输入区。草稿按 Host、Thread、branch、Operation
隔离，收起保留内容和滚动位置；受理未知时查询原操作后重试原答案。回答不改变执行权限。

权限确认提供允许一次、一直允许和拒绝。持续规则由 Host 写入现有用户配置，界面先展示准确范围，
保存失败与本次决定失败分别反馈。目前该入口针对 extension/MCP 的具名能力，适用于所列工具的全部参数；
原生文件和进程继续由 Source grant 的资源范围控制。项目约束优先，后续调用读取最新策略，规则可在现有权限设置中撤销。

轮末左侧操作、右侧用量直接呈现，窄窗口自然换行。缓存读取和创建为正值时显示；缓存率使用完整输入量
作分母，仅在缓存读取存在且口径齐全时显示。不同渠道的缓存记账由 Rust provider owner 投影，原始回执保留。

## 上下文准备与替换

聊天中的上下文状态来自原生压缩任务和发布记录。达到准备条件后显示「上下文压缩正在准备」，消息、工具和输入框继续工作。
候选完成时显示等待替换；满足替换条件后直接应用。只有主 Run 实际进入对应的 `context-wait`，才在当前执行位置显示
「正在压缩上下文，请稍等」。完成提示按发布事务当时的历史位置呈现，原消息保留。后台失败、到线失败、停止和结果过期分别显示。

页头、工作概览和聊天状态行进入同一个上下文侧栏。比例条以完整模型窗口为分母，标出准备基准和替换／预留边界；
实际准备仍可能依据增长速度提前触发。系统指令、用户消息、助手消息、普通工具、MCP、已生效摘要和其他开销分色呈现，
点击可看组成。数值由 Rust 对持久化的原始请求和当时分词器计算，MCP 身份取当次冻结的工具来源。它是内容估算，
服务商上报用量、缓存读取与创建在独立用量区显示。未计量的媒体和模型不透明内容有明确提示；替换后新请求尚未计量时显示待计量。

侧栏保留当前摘要、历史结果、公开思考、原始消息分页和资源入口。压缩过程通过父会话持有的任务读取，不切换到内部辅助会话；
流式内容按帧更新，断线后重读，折叠保留阅读内容。停止只取消选中的准备任务，提前替换使用原生发布接口。
准备失败后可以重新生成候选；如果原任务已经失败结束，替换后需要发送消息继续。

## 唯一文本内容路径

`DocumentsAPI` 是文本读取和写入入口；`FilesAPI` 保留浏览、二进制与 CRUD，`WorkspaceAPI` 保留
项目、目录树、Git 和上传。它们不拥有第二套编辑 buffer 或文本保存路径。
[Host Documents](../packages/web/application-host/lib/documents/DOCUMENTATION.md) 管理准入、revision、
watch、journal 和认证后的 Surface 操作；生产磁盘变更使用绑定的 Rust file-resource owner，
没有 TypeScript 备用 writer。

Workspace ID 属于 Application Host。资源使用 workspace/resource identity，显示路径不是权限。
物理操作重新校验根身份和路径包含关系；离线或已删除目录保留注册，访问时报告 unavailable，
加载注册表不会逐个打开所有目录。另一 Host 上相同的路径不是同一资源。

同一客户端可依据 Host 的 coordination identity，让经过验证的父项目/嵌套项目别名共用一个文档。
不能凭字符串推断别名。不同窗口各有 buffer，通过磁盘 revision/watch 发现冲突，不暗中协同编辑。
Connection generation 用于拒绝迟到结果，不进入持久文件身份。

读取区分有效空文本、missing、binary、unsupported encoding 和 failure。Revision 是 opaque 值。
写入捕获 `expectedRevision` 和 operation ID，创建缺失文件是显式操作；move/delete 沿用同一校验。
冲突不能自动重试为无条件覆盖，普通文件系统的原子替换也不等于跨进程事务。

编辑 buffer 规范化为 LF，文档仍保留 encoding、BOM 和原换行格式，保存及固定输入 capture 据此还原字节。
不能可靠解码的文件返回明确结果，不以 replacement character 猜出可供保存的文本。

Watch 只携带元数据，source/generation/sequence 限定事件顺序。Reset、重连、overflow 或覆盖丢失
要求重新读取权威状态；不完整事件流中没有某文件不代表文件已删除。文件系统通知只使旧知识失效，
并不建立内容 revision。具体 OS 观察保证留在 Host 模块文档中。

## Buffer、保存与恢复

[Document Registry](../packages/ui/src/lib/documents/DOCUMENTATION.md) 是按文档订阅的 external store。
高频正文不进入 broad Zustand state 或 Local Storage。并发首次打开共用一个 Host read，
文档变更只通知相关订阅者，而不是让整个工作台更新。

Record 保留 base content/revision、当前 buffer、local edit revision、save identity、conflict candidate
及 recovery revision。所有编辑器共用以下竞态语义：

- 迟到 load 不覆盖新输入、另一 connection 或重新打开后的 document instance。
- Save 捕获正文和 local revision；保存期间继续输入，旧 save 成功后仍保持 dirty。
- Clean 文档遇外部变化可 reload；dirty 内容不同时保留 ancestor、buffer 和 disk candidate。
- Read failure 不清空 buffer/dirty；delete/move 不静默丢弃草稿。
- 增量编辑先校验捕获 revision 和互不重叠的 offset，再一次性更新状态。
- Shell、Profile、Settings 重挂载保留 record；endpoint 更换则隔离旧操作。

`prepareWorkspaceEdit` 保留文本、创建、重命名和删除的原始顺序，在内存中推演路径、覆盖选项、
中间文档版本与 change annotations；准备不写文件、不保存草稿。纯文本批次重新验证所有目标后，
先发布全部新 buffer 再通知监听器。含资源操作的批次由 Host Documents 在原租约、受影响缓冲 barrier
和 mutation writer 下执行，首次修改前将计划、磁盘原态与各实际窗口草稿写入 Rust Recovery。
创建后的文本仍未保存；重命名迁移 document instance、订阅、标签页与语言服务身份；删除草稿先审阅，
并保留恢复内容。多个窗口可以各自持有受影响文档，只有同一路径正文/版本分歧的文本修改需要解决冲突。

每批只有一个异步撤销入口，条件恢复避免覆盖后续输入或外部修改；无法确定的结果按文件进入恢复界面。
LSP 使用 `undo` failureHandling，不承诺文件系统与编辑器的绝对原子事务。丢失响应只查询原操作，
不会重新执行。code action 在编辑及后续 command 之间保留原语言 provider 身份；改名使用原实例的新路径，
删除后 workspace command 不伪造仍存在的文档版本。普通重构无需 Agent Run。

恢复 journal 位于 Host 的 document-recovery namespace，绑定 workspace、用户/recovery session 和资源。
它是带 revision 的未保存数据，不进入普通日志或对话历史。Restore 产生待审阅草稿，不覆盖项目文件；
旧 workspace epoch 和互相冲突的别名草稿保留区别。Save/discard 和 owner teardown 协调 journal 清理，
不以任意天数、数量或字节上限代替恢复语义。

### Agent 与编辑器协作

Selection、file、diff 和 diagnostic attachment 捕获真实 runtime/session/resource revision；
未保存正文作为显式输入快照。[Agent/editor bridge](../packages/ui/src/lib/agent-editor/DOCUMENTATION.md)
从可见 view owner 取得上下文，隐藏或已销毁的 view 不能成为兜底目标。

固定草稿来源与 Host-directed apply/undo 保留原 Registry owner、document instance、content hash、
base/local revision 和格式。Host 管理 dispatch 与 receipt，Registry 应用核验后的操作，不另开保存路径。
响应丢失保留 uncertain；已确认变更及条件补偿不能擦掉用户的后续编辑。

Agent patch review 使用同一 workspace-edit 事务，接受后仍是待显式保存的 dirty buffer。
磁盘操作走原 Host/Rust authority；来源不可用或过期时，不回退为 worker-local 写盘。
外部程序写入仍走普通 watch/conflict。Workspace recovery 自己拥有 affected-file log 和 restore，
编辑器不复制这份恢复状态。

## 编辑器 model 与 view

[Editor Workbench Kernel](../packages/ui/src/lib/workbench/editors/DOCUMENTATION.md) 拥有 split group、
preview/pinned tab、active editor、provider 和 workspace restore snapshot。Shell layout 与 editor state
分开：Agent 可以把编辑器放在聊天旁边，IDE 放在中央；关闭或隐藏面板不等于销毁共享文档或终端。

Desktop/Web 的 Agent 与 IDE 共用延迟加载的 [Monaco adapter](../packages/ui/src/lib/monaco/DOCUMENTATION.md)。
一个 document instance 投影为一个使用 opaque runtime/document URI 的 Monaco model，多 view 共享正文与
undo，分别保留 cursor/scroll/fold。Rename 保留 instance；tab/resource owner 在 Shell 重挂载期间保留
model，view 只拥有 DOM、observer、listener 和可见语言订阅。Model 从不成为 dirty/conflict/save 权威。

Mobile 与小型嵌入编辑器使用各自用途的 [CodeMirror adapter](../packages/ui/src/lib/codemirror/DOCUMENTATION.md)。
移动文件编辑保留同一文档语义；prompt/settings 编辑器不进入 workspace tab，也不启动文件语言服务。
Desktop Monaco 失败在局部保留 retry/recovery，移动 CodeMirror 不是自动桌面 fallback。

Monaco 只在可见文件编辑路径加载，worker 只负责编辑任务，内置 semantic worker 不复制 Host LSP。
语言请求和诊断携带真实 document/provider generation。Search、LSP、DAP、test 进程仍由 Host 管理，
renderer 不能启动不可信项目命令；provider 失败不使底层 buffer 消失。

Provider 解析使用已启用声明、显式 association、filename/language 匹配和 priority，再使用 text fallback。
同级匹配保留 ambiguous。显式 pinned provider，例如 browser 和 Git diff，不变成资源默认；
停用 pinned provider 返回 unavailable。Git diff 的工作区侧绑定 live buffer，staged/original 侧是不可变
快照；stage/unstage/discard 不与 dirty buffer 抢写。

Theme token、command ID、shortcut override 和有效编辑器设置仍由 Varin 管理。
Profile preset 只调整呈现选项。可选 `varin.editor.monaco` service 暴露 owner-scoped、可序列化的
action/decoration，不暴露可 dispose 的 raw handle，也不授予文件权限。第三方 `editor` contribution
仍可选用其他引擎。

## 输入框功能与对象引用

`/` 使用原 Workbench command registry，只展示显式声明适用于交流现场的贡献。会话操作、模型与思考、权限、上下文、任务、记忆和设置按用途分组；技能在同一列表单独分组，保留真实资源来源、用途说明与同名身份。扩展命令保留自己的贡献身份和命名空间，后端原生命令按实际 Harness/session 保存，不能因为同名改投另一执行者。

功能只消费当前斜杠片段，不发送剩余正文。Tab 补全不执行，整个输入恰为已注册功能时 Enter 才按该行为处理；正文、代码、未知命令不会被扫描成应用操作。模型、权限与其他选择在同一个菜单容器里展示当前值和实际作用范围，失败保留原选择与错误。新会话和导航沿原 guard，异步完成不覆盖用户后来补写的草稿。

`@` 的附件来自当前草稿和已读取历史的 typed holder，文件与目录来自本 Thread/branch 的实际 Source；cold draft 使用显式选定的来源，不创建空 Thread。目录与任务只提供定位，不展开全部文件或历史，也不改变收件人。任务候选来自真实家族目录，使用准确 Thread/branch，不用角色模板冒充成员。文件、目录和任务分别分页、加载与报错，查询代和 Host/source 切换撤销旧结果的确认资格。

引用身份与 UTF-16 范围随 CodeMirror 事务、撤销和重做移动；改写标记解除旧绑定。文件选择保存在独立可见附件条，删除正文标记不移除文件。发送时由统一附件 owner 读取并固定原件；稳定附件直接复用原版本。来源变化会拒绝旧路径选择，不能重新解释成另一项目里的同名文件。技能选择沿同一资源 owner 校验准确身份、版本和来源，多技能按选择顺序冻结，已受理重试不会切换版本。

聊天的 `[引用点N]` 与 `[图片N]` 绑定草稿中的实际对象；手打或从外部复制的同名文字仍是普通正文。对象身份、显示编号和正文中的每次出现分别保存，同一对象可重复插入，图片与内容引用分别编号。拖动只移动该处标记，不重排附件；移除附件及其全部标记、整理当前草稿编号为一次可撤销事务。已排队和已发送消息的编号不受之后草稿影响。

标记普通点击打开固定内容，显式键盘聚焦后的 Enter／Space 同样打开。长按后可在输入框中移动，源位置保留占位，边缘仅滚动输入框；Esc、拖出、取消和卸载恢复原位，不触发发送。移动期间仅更新浮层和落点，松手才提交一次编辑。触屏在长按成立前保留原生选择与滚动。剪切粘贴可完成键盘移动；同一应用运行期的结构化剪贴板保留原对象并为目标草稿分配编号，外部剪贴板保留可读摘录。跨进程／Host 不凭剪贴板编号恢复资源权限；当前无法交接的材料明确报错或保持普通文字，排队编辑拒绝引入原输入没有的文件附件。

正文范围、图片与文件 payload、选择位置和撤销历史由原草稿的 CodeMirror 状态共同持有；同 Host 切换会话再回来保留它们。接受发送或丢弃草稿清理旧撤销历史，不能撤销出已释放的材料。异步捕获使用原草稿中随编辑映射的锚点，IME 完成后再插入，不覆盖原来选中的用户文字。仅删除正文位置仍保留上方材料；无正文标记的明确附件也随消息发送。没有新增跨应用重启的全量草稿保存。

图片能力限制在发送前展示。原生聊天允许明确选择“将图片作为可读文件发送”：保留图片编号、来源与标注，转入原附件上传链，而不表示当前模型能够直接看图；也可直接更换有视觉能力的模型。转换与撤销共同恢复标记、附件类型和预览，不静默丢图。

明确收件人、整理交接、流式导出与记忆快捷写入见 [协作](./collaboration.md#输入框中的明确收件人与交接)。原聊天草稿和定向消息草稿分别保留；需要模型整理时由用户显式启动真实任务，审阅后再采用结果。外部 Harness 仍提供真实的本地会话管理与设置，不能接收的原生技能或对象选择会保留并提示，不悄悄降成文本。

菜单共享键盘控制和 combobox/listbox 关系。IME 优先，Shift+Enter 换行，Shift+Tab 保留反向导航；Escape 先退出子层，再关闭菜单且不会被迟到结果重新打开。子层控件不能提交外层聊天表单。退出内容保留动画但立即失去点击资格，窄屏沿原 viewport 机制约束高度，减少动态效果沿原偏好。

## 图片标注

输入框附件、正文图片、文件附件与工具截图共用图片预览器。标注提供箭头、矩形、椭圆、画笔、文字、编号和实心遮挡；标记可以选中、移动、缩放、改色或删除。图片支持适应窗口、原尺寸、指针位置缩放、空格拖动和双指缩放平移。

新标注默认使用纯色、不带描边。工具栏保留颜色与线宽，“样式”浮层提供实时预览、不透明度和无／浅色／深色／自动描边。选中标注后修改其样式，滑块拖动只在结束时计入一次撤销；预览与原分辨率导出使用一致的描边及整体透明度。遮挡始终完全不透明。

粘贴、拖放和文件选择中的图片使用带编号的缩略图，在光标处插入 `[图片N]`；移除图片同步移除引用，并按当前附件顺序重排剩余缩略图及正文编号；全部移除后重新从 1 编号。正文标号使用主题重点色，光标和退格/Delete 按完整标号处理，单独删除正文标号不删除图片。图片仍走统一附件上传和传递通路，预览直接编辑当前草稿，包括尚未创建会话的输入框。普通文件草稿只显示名称、大小、预览与移除；仅上传中或失败时显示状态，下载原件属于已发送附件的操作。

每张图片独立保存操作历史，一次绘制或拖动算一步。工具栏与 Ctrl/⌘ Z、Ctrl/⌘ Shift Z、Windows Ctrl Y 联动；正在输入标注文字时保留文本编辑器自己的撤销。清除全部标注同样可撤销，撤销后进行新操作会清除重做路径。

原图与矢量标注保存在当前会话的前端内存草稿中，切图和关闭预览再打开会保留。标注编辑保留图片身份和当前编号；历史图片使用“用于回复”加入输入框，不修改已发送消息，也不会自动发送。实际发送与下载基于原图分辨率合成，附件上传只传合成后的文件字节，编号随消息关联到固定附件；遮挡真实覆盖像素，不附带原图或编辑历史。中途卸载编辑器留下的标注也会在发送前合成。修改已准备的图片会使用新的上传身份，重试复用这次修改的固定内容。未发送的编辑记录沿草稿生命周期，不跨应用重启持久化。

远端图片的显式编辑读取通过已认证的 `/api/images/read`，使用 Host 既有出站策略和重定向处理，不转发浏览器的 Cookie 或账号凭据；图片查看与草稿导出不调用图像模型。

## 对话连续性

Thread 界面通过 `ThreadsAPI` 与 `ThreadProjection` 读取原生 Catalog 的快照、持久历史和临时进度，
不维护第二份执行状态。客户端用 Host、Thread 和 branch 身份隔离草稿，切换后迟到的响应不能写入新视图。

发送保存原 request key、正文、图片、PDF snapshot 和选定配置。明确未受理时可以恢复修改；受理结果未知时保留冻结输入，
重试使用原 key 并核对回执，不重新上传 PDF，也不自动生成另一个输入。成功晚回执只清理原草稿中已受理的内容。
已受理队列沿自身 revision 编辑、取消或交付，不靠清空重建模拟变更。

输入框复用 CodeMirror、模型选择器、语音和附件组件；文件补全使用选定来源的目录，技能补全读取 Host 资源目录。
明确选择的工作区在新会话首次发送时绑定；之后切换侧栏目录不会改变这项来源。PDF 原件由 Host 保存，附件打开同一作用域的
reader；页面选区使用真实图像。submit、三种 enqueue 和 child continuation 都保留相同的固定材料来源。

侧栏使用 Catalog 共享的项目／分组混合树，子任务关系仍直接来自执行 Catalog，分支选择使用实际 branch ID。工作概览承载任务、计划、后台操作和资源控制，
不把这些管理表单默认铺在消息正文中。工具调用与结果按 Run 和原调用关联；消息导航和右键引用只作用于当前视图。

会话树由右侧资源栏或输入框的历史入口打开，Bot 标题栏也提供入口。工作台和 Bot 分别保存面板布局，会话树跟随各自当前选中的会话。工作台的无项目会话使用空目录对应的布局状态。
树按当前 Thread 的共享历史展示对话轮次与分岔，长直线段可以展开和收起。结构查询只读取元数据，
可见轮次再读取简短预览，展开时沿固定历史位置分页呈现原消息、思考和工具。
搜索按需检查各路线的用户与助手正文，预览截取范围不会限制搜索范围。
点击节点切换到其原分支并定位消息；“从这里继续”显式创建分支，“回退到这里”沿原恢复流程执行。
路线、当前选中位置和后台执行状态分别呈现；子任务通过派发时的原历史位置关联，并提供独立聊天入口。
展开选择和面板滚动位置按 Host 与 Thread 保存，聊天草稿和阅读位置继续按 branch 隔离。
项目分组与会话子树的展开选择按当前 Host 保存在设备偏好中，切换视图和重启后恢复；子任务树默认收起。
搜索临时展开匹配的会话路径，退出搜索后恢复原有选择；归档列表沿用同一套会话子树偏好。
概览的完整和简要视图都采用悬浮卡片外观，在会话布局中实际占位，正文和输入框随之收窄；窄窗口改为上下排列。
卡片高度随内容变化，超出可用空间时内部滚动；完整视图支持调整宽度，展开与收起不重建消息列表。
大小概览共用一个连续变形的外框，内容交叉淡入淡出；关闭保留退场画面，结束后隐藏。
卡片尺寸与实际占位同步运动，连续操作沿当前速度反向；正文只在目标宽度换行一次，再随占位平移。
编辑草稿与各视图的滚动位置保留，窄窗口改为在聊天上方连续让出高度。
聊天、设置页和工作概览的离散滚轮输入使用连续的短缓动，连续输入保留速度，反向操作立即接管；
触控板与触屏沿用系统惯性，滚动条拖动直接跟随指针。聊天滚动条位于概览外侧，用户操作时显现、
停留后渐隐，流式输出只更新滑块位置。用户阅读历史、选择文字或展开详情后暂停自动跟随；
内容补载、工具折叠和宽度变化保留正在阅读的文字或操作标题。返回聊天保留阅读位置，
新文字回复通过返回按钮提示；短距离返回连续滚动，跨越长历史时仅聊天视口作有方向的退场与入场。
共享设置事件可以在客户端控制绑定尚未完成时订阅；向某会话发出客户端设置操作仍需原绑定成功。

新建多 Run 会为各候选记录实际 Thread/worktree 与受理状态。部分失败或结果未知保留已创建对象，供用户核对或继续；
不能为恢复空界面而自动删除可能已经执行的工作。来源选择、导航项目与执行 cwd 分开，切换项目不会隐式搬迁活跃 Run。

界面呈现实报的 usage、mutation receipt 和进度观察。文件 preview 不证明写入成功；工具完成、写入失败、
working branch 和 unsaved draft 分开显示。未知扩展 entry 仍可用 generic/raw detail，扩展 renderer
保持原注册优先级。

助手正文的图片在原解释位置呈现；相邻的图片段落合为自适应图片组，文字段落结束该组。小素材保持原尺寸，
普通图片按可用宽高展示，长图显示标明截取的上段预览；图注仅来自原 alt/title。句中图片链接保持文字形态，
点击进入同一查看器，支持组内切换、适应窗口、原始尺寸、缩放、拖动与下载。亮暗主题只改变周围界面，保留图片原色。
完整引用进入视口附近才读取；流式正文继续增长时保留已加载图片节点、解码状态和原读取。图片尺寸和加载完成
沿现有时间线内容变化路径通知布局，用户阅读历史时继续保持阅读锚点。移除内容、关闭查看器和切换 Host 释放其读取与对象 URL。
本地文件通过原 `/api/fs/raw` 权限和路径检查读取，普通大图在 Host 生成聊天尺寸的派生预览；长图预览不覆盖原文件，
SVG 在浏览器图像沙箱中显示，动画格式保留原帧。预览使用内容摘要验证浏览器缓存，不另建持久图片库。
远程图片直接使用原 URL，由浏览器缓存；原链接没有缩略图能力时仍需读取原图。已有工具“查看图片”记录继续使用其类型化媒体回执。

右键 quote 只追加当前 draft，不发送。记忆提取核验选中的原生 source，由 personalization/Bot memory
owner 保存。Thread PDF 和 typed media 使用当前 Thread 的 material/holder identity；任意 output JSON
不自动成为 media reference，也不授权访问其中的 URL。

### 按实际用途呈现工具

工具视图先回答用户需要检查的对象与结果。`ChatTimelineEntries` 保留扩展 renderer 的原注册优先级，
再将内置工具交给各自的呈现组件；未知工具保留完整输入、结果及错误。基础组件复用展开状态、调用身份和
主题变量，各工具按内容组织布局，不规定统一的外层卡片。

## 设置与呈现状态

桌面设置在中心轻微展开并淡入（220ms），关闭时原地淡出（160ms）。首次懒加载也有入场过渡，连续开关从当前画面接续；底下的对话保持挂载，关闭窗口不重建编辑器、草稿或滚动布局。
移动端设置占据整页时仍暂停被替换的会话视图。窗口首次出现不逐组播放导航入场，分类切换保留局部过渡。

共用控件按输入／按钮、列表项、菜单、对话框和聊天输入区使用语义圆角尺度。
`styles/shapes.css` 在支持的引擎上采用原生连续转角，普通圆角作为浏览器回退；圆形与胶囊控件保留原轮廓。
边框、阴影和裁切沿同一形状绘制，不为控件逐个添加尺寸观察或 SVG 遮罩。

共享[设置目录](../packages/application-client/src/settings-catalog.ts) 定义稳定 ID、字段、scope、发现和动作。
设置翻译静态数据位于 application-client 的 `settings-locales`；UI 按语言加载，Host 文本搜索按需复用同一份标题与描述，
支持中文及其他已有界面语言。无命中时返回空条目和空匹配分类；省略关键词可按原分类浏览，不把全分类伪装成搜索命中。
[Host settings service](../packages/web/application-host/lib/harness/settings-service.ts) 路由到 app settings、
原生 Agent settings、绑定客户端或原领域 action owner。查询目录不安装软件、不启动推理，也不证明能力已接线。
Owner/channel 缺失、平台不支持、只读和真实可执行动作分别表达。

目录同时提供字段约束和逐动作 inputSchema。读回区分保存层、合并后的下次使用配置与当前 Run 已受理的配置；
多字段条目逐字段给出来源，不把“保存成功”当作“本次推理已切换”。JSON set 替换声明路径的值；provider/MCP
语义 patch 由原 owner 保留省略的凭据。原生 context 调优按叶字段更新，避免开关覆盖其他预算或时间设置。

app 与 Agent 文件组分别使用原 owner 的 CAS；冲突返回明确失败，不自动以新 revision 反复重写。
跨 owner 返回带原输入序号、scope、revision、生效边界及 mutation 确定性的各自回执，不承诺全局回滚；
后一个 owner 不可用不会抹掉前一个已保存的结果。Saved、active、awaiting restart、authenticated 是不同事实。
长动作的查询临时失败不会将运行中操作改写为终态；后续仍查询同一 operation，而不是重执行作用。

设备本地变更一次绑定到当前认证 Thread/branch 的唯一 Surface，并等待实际应用 acknowledgment。
同步 UI store 在同一事件循环内提供真实 CAS；异步 Desktop owner 未提供原子条件写时明确声明 last-write-wins，
拒绝无法兑现的 expectedRevision。没有绑定返回 unavailable，多个返回 ambiguous，不能广播修改。

self.bot-profile 由受理 Thread 解析所属 Bot，使用 Bot 原记录 revision 修改名字、指令、模型；名字立即生效，
指令/模型在该 Bot 直接会话的安全请求边界传播，不改委派工作。self.conversation-model 仅为当前受理 Run
暂存模型选择，分别展示 desired/active，不修改 Bot、Agent preset 或未来会话默认值。保存后传播失败仍保留保存回执。

Host 扩展/MCP approval policy 与 Rust Source/Storage grants 是不同权限。普通设置授权、通配 allow 和 bypass
不隐含权限策略管理或凭据目的地授权；compound 每项先归一化为声明字段的真实语义目标。敏感字段的
Allow always 明确委托该字段后续值的管理；provider 路由授权则固定 base URL/挂载点、账号、传输及不透明
provider 参数。仅在既有挂载点下追加的合法 API 路径、普通模型/预算选择不扩大凭据目的地。项目策略只能收紧。
Smart/accept-edits 尚无实现：旧值保留可读并标明有效行为为 normal，新保存只支持 normal/bypass。
Allow always 自身保存规则造成的 revision 前进，仅能通过该次原调用的精确 before→after 回执衔接，不能忽略其他并发更新。

旧 compactionRecovery、dispatch/worktree、auto-worktree/后台 auto-accept 与 permissionJudge 等无现行执行
消费者的值保留可读，并明确标为 unsupported；这只是揭示既存缺口，不表示已实现对应恢复、调度或自动化能力。

Agent profile 用 `AgentProfilesAPI` 管理模型、指令和工具选择。Editor 保留 Host 和打开时 revision，
刷新不抹掉未保存草稿。省略 tools、显式空集合和 reset 含义不同；已受理 Run 保留冻结配置。

### 项目登记与跨设备来源

项目是原 Settings 配置，目录、附加目录、图标及默认工作侧重仍由原项目 owner 保存。
项目来源可显式绑定配置中的资源 Host；登记时由目标 Documents 解析路径并返回稳定 workspace ID。
已有项目没有绑定字段时保持本机含义。远端路径不会经协调 Host 的 realpath、目录校验或图标扫描解释；
已登记资源暂时离线时保留项目，读取失败不发布空项目列表。修改名称等已保存元数据不重新唤起资源设备。

新增项目先完成原登记，再提交 Catalog 分类；两步不是同一数据库事务。界面固定项目 ID、分类目标和
原受理键，分类失败显示“已登记、分类待完成”，不重复建项目，也不删除已成功的登记来伪造回滚。
移除同样先核对原登记操作，再解散分类入口并提升成员；它不删除目录、文件或会话历史。
已确认 revision 冲突后，新的显式重试读取当前关系；结果未知的重试保留原命令。

从分类新建工作时固定最近项目提供的默认来源，明确选择的来源优先。已准备来源保留完整 resource owner
和原 workspace 身份；物化执行目录不必等于项目根目录。分类位置与实际工作区分别显示，移动会话或祖先
不会改写已有来源、外部 cwd 或运行配置。项目名称、路径或同一 Host 的多个同源项目不足以消除歧义时不猜归属。

“打开项目文件工作区”是显式资源访问。远端项目在原 Files 主界面使用共享 ResourceFilesView，文件列表、
二进制、上传、重命名及复制/移动沿原资源 API；文本继续经过该 owner 的 Documents、Document Registry、
Monaco／移动端 CodeMirror、冲突与恢复记录。断连显示真实不可用错误，不回退到同名本机文件。
Bot 的文件页复用同一组件；打开文件页不替换会话执行来源。

远端项目的默认模型与 thinking 配置由协调 Host 的原 AgentSettingsService 按稳定项目 ID 保存，仍使用
revision 检查和全局继承；界面明确标识这是协调端配置。原本地项目继续使用受信任目录下的
`.varin/settings.json`。模型请求指定登记项目 ID，由 Host 核验原记录，不接收 renderer 自选的内部配置路径。
显式模型选择、Bot 模型及已有执行绑定仍由原优先级处理，不从分类树另建配置叠加规则。

目标设备的文件准入与信任仍由目标 owner 判断。项目管理请求携带登记项目与预期来源，协调 Host 先核验
真实登录用户的资源权限及原 Settings 绑定，再通过已有 managed-host 连接交给目标 Documents、Git 和
NativeWorkspaceOwner。来源绑定改变后，旧观察或重试拒绝重定向，不以同名本机目录、分支或配置替代。
Git worktree 的发现、创建、初始化观察与移除沿目标 Git service 及原 Documents writer；目标不可用与空列表不同。
删除 worktree 后若另选的远端分支删除失败，保留已完成的本地效果并报告剩余失败，不伪造回滚。

启用项目版本工作区先取得目标原身份规划，再由协调 Settings 保存 preparing 的 workspace、execution workspace、
branch 与 adoption operation，最后交给目标原 Storage 受理。未知结果重试继续同一操作，完成回执按原项目绑定核验后
更新 ready；导航、草稿与源准备引用该原身份，不把目标挂载路径写入协调端 DirectoryStore。
后端能力由目标报告；需要打开操作系统或扩展设置的交互仍在源设备完成，不由远端项目请求修改设备安全设置。
项目动作定义保留协调 Host 原项目配置，命令执行与终端观察、恢复、停止使用所选来源 Host 的原终端与进程 owner。
已采用的版本工作区动作携带冻结的逻辑 selection，目标用原 adoption 回执准备实际工作视图。该选择与原物理根
保存在原终端创建身份中；之后观察、输入和关闭核验原 session，不因项目重绑、切换标签或挂载路径变化重选来源。
远端外部 Harness 在显式选择或准备时读取目标 Host 的已配置 Agent 列表；不可用时不显示协调端同名配置作替代。
目标程序与环境在该设备解析、执行，产品会话与原生 session 续接回执仍留在协调 Host 原 Catalog。
仅浏览分类与历史不会探测程序、启动远端进程或切换来源。

### 设置与继承

设置按使用偏好、Agent、开发与项目、连接与扩展组织。目录中的 UI 路由只定位唯一管理页面，
不能改变字段 owner。对话默认保留全局/受信任项目继承；Harness 页面编辑当前 Host 的全局配置，
项目已有覆盖仍生效。模型服务管理连接与模型启用，各功能只选择已有模型；模型品牌与接入服务品牌分开。
模型服务的账号登录入口暂时只展示 OpenRouter；其他内置 OAuth/device 登录与重新登录按钮及账号登录推荐不出现在 UI。
API key、环境变量、云凭据配置及已有账号的查看、使用和主动移除仍保留；这不是后端认证禁用，也不会自动注销或删除凭据。
技能保留目录/正文编辑，命令目录来自有效技能，并不提供另一套命令编辑 authority。

草稿保存单元使用固定操作栏。切页、关闭、项目切换和 Host 切换先处理草稿；失败保存不能放行。
Host 切换先串行完成 guard 阶段，再运行旧 owner teardown，避免用户仍在确认时关闭原 MCP view。
即时设置的成功反馈只在实际 owner 确认后出现。聊天外观预览复用正式时间线、Markdown、工具和 diff
渲染组件，在只读预览上下文中禁用真实文件/终端动作与扩展渲染器。

对话默认可设置标题更新间隔，默认 5 轮，0 为仅首次命名；检查始终取最近三轮完整交流，间隔不会放大取材范围。
手动命名会持久停止自动更新，同名保存也按手动命名处理。普通会话的菜单提供「恢复自动标题」，
恢复后立即判断当前标题，随后按设置的间隔继续。子 Agent 名称和 Bot 的主要长期会话名称保留身份用途。

「模型服务」之后的「用量」页显示当前选中 Agent Host 的 Token、估算费用、缓存和后台工作。时间范围和日桶取实际客户端的日历与时区，
包含夏令时和非整小时时差；切 Host 后原请求和观察取消，迟到回复不覆盖新 Host。费用／Token 切换作用于合计、构成、趋势和明细，
点击日柱筛选明细，模型、渠道、用途及对话分别分组。对话行可打开原分支用量，再进入相应聊天。
未报告、未计价、按现价估算、订阅和本地分别呈现；缓存项只在有值时显示。价格在模型详情中编辑，支持缓存、推理和多个上下文分档。
CSV 导出保留空缺、计量与计费方式，桌面和网页提供；移动端沿同一设置入口使用紧凑布局。外部 Harness 仅显示自身上报的单轮或累计统计。

工作连接页是现有客户端连接、Thread source、Host 资源和具体 desktop 的组合视图，不保存第二套连接
profile。切换 Agent 只切换当前可见 Catalog；已受理 Run 的 source、execution 与 CU 选择不迁移。
资源连接编辑始终通过当前 Agent Host 的 HTTP owner；即使在 Electron 中，也不走本机 IPC。
SSH 配置、连接检测和 localhost 地址归该 Host，视图释放只停止观察，不断开后台 SSH。客户端默认 Agent
与资源 Host 的管理动作分开；资源页不提供切换 Catalog 或在客户端打开 Host 本地地址的操作。
远程资源仍要求 Agent Host 可达的 HTTP(S)/SSH 转发地址，客户端 relay 登录不自动提供资源路由。
桌面可保存下次启动是否运行本地 Host，并独立显示实际运行、环境覆盖和需重启状态；普通重启先走现有退出清理。
没有独立恢复页面的开发构建不能禁用唯一的本地入口。

存储页由 Application Host 统计实际数据根、共享恢复对象和缓存，并明确磁盘总量、Varin 占用与未知状态。
共享对象不按引用次数累加；不能可靠分摊的工作区容量不伪造为零。清理先生成绑定认证主体与作用域的
短期候选预览，再由原生 storage owner 重核对象引用及占用。客户端仅提交候选 ID，不提交删除路径。
设备切换复用当前 Agent 已配置的 managed 连接独立访问目标 Host，不切换 Agent Catalog。
远端预览绑定目标 Host/连接身份、原主体与目标清理回执；确认超时重试同一命令，不重算或改投新设备。
两端都核验权限，目标失联、仅中继、能力缺失和目录限制分别呈现。已接受清理不因观察连接断开而取消。
恢复记录删除/迁移仍由原恢复 owner 管理；空间清理统一进入存储预览。

## 能力降级与验证边界

Web/Electron 共享桌面文件能力；hosted/Capacitor mobile 使用兼容 contribution 与移动编辑器，官方 IDE
不声明 mobile 支持。Headless 可使用 Host 服务而没有任何界面。Provider 声明、module ready、实际可见
是三种不同证据。

隐藏 view 释放视觉 observer 和 demand-driven subscription，不能为保留布局重复扫描、轮询 Git、
准备语言服务或启动模型。大文件、多 model 和长历史需要测量与按功能降级，不能凭猜测设置妨碍基本读写的上限。

Profile transition、Registry、Monaco、client settings 和 Thread consumer 的局部测试描述中断与 stale-owner
行为；它们不证明完整 provider 集成、真机触屏/无障碍、打包 worker 加载或 UI 端到端验收。
平台验证应针对实际变更的 Surface。
## 共享会话导航

项目和分组可以任意混合嵌套，每个容器及会话只有一个正式分类位置。重复名称合法，所有修改以稳定身份为准。
项目节点引用原 Settings 项目，不复制名称、目录或模型配置；根成员呈现为“未分类”，空组可以保留。
分类不是磁盘层级，也不是执行派发层级。移动项目不移动文件，移动任务不改变派发者、取消树或原来源。
原生会话目录沿用原列表的可见性：可读取当前主体及未绑定主体的历史公开会话。公开会话在各主体的分类中
保留自己的位置，整理导航不改写会话身份；修改公开会话的元数据仍由 Host owner 执行，其他用户保留读取能力。
旧目录漏掉的公开会话在原 Catalog 升级后，由原 Settings 项目初始化补齐位置，已明确移动的位置与原回执保持不变。

归档／恢复／删除调用各自原会话 owner。归档不停止运行，外部活动 turn 删除保留原忙碌限制。

解散分组把直接子项按原相对顺序提升到父层，不删除会话、文件或任务；移除项目同样先完成原项目登记操作。
