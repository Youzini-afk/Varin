## 已修复

| 问题 | 根因与修复 | 验证 |
| --- | --- | --- |
| 网页/PDF 材料保存失败 | Host 写入 `web.snapshot`，Rust 内核未接受该类型；同组的 `material.collection`、`material.grant` 也遗漏。补齐现有记录契约，继续使用同一个内核存储。 | 真实 Rust 进程保存正文、原始字节、集合和分享授权；重启存储进程后重读；未授权线程仍不能读取。 |
| 用户级记忆句柄冲突 | 后台整理枚举 `.tdb` 文件时把 `user.tdb` 当成工作区源数据库，抢先建立另一个句柄。排除用户库的源发现和源整理调度，用户级入口继续拥有它。 | 整理启动、显式调度、工作区整理及用户库读取；已有记忆整理回归。未打开、删除或改写用户实际数据库。 |
| Responses 可选参数失真 | 本次会话使用 `openai-responses`。Pi 默认把 `supportsStrictMode` 设为 false，请求省略 `strict`；Codex Responses 另有 `strict: null` 路径。默认发出明确的 `strict: false`，保留工具的可选字段。用户显式提供的协议兼容选项和工具显式要求的严格采样继续生效。 | 检查真实 provider 构造的 HTTP 载荷；原生校验及执行最小 dispatch、document_read、webfetch、history 调用，省略的选择器未被补成空值。HTTP 使用本地响应替身，未请求付费模型。 |
| 诊断位置变成第 0 行 | 语言服务返回 `range.start`，适配器误读顶层 `line/character` 并补零。改为读取实际范围并转换成工具使用的一基行列号。 | 真实语言服务协议夹具在非首行、非首列报错，适配后的行列正确；修正文本后诊断清零。 |
| MCP 工具能用、设置却报告不可用 | 设置动作查询目录配置 worker；连接及配置观察属于当前原生会话。改为通过调用会话查询状态和读写同一配置来源，也支持未绑定项目的会话。 | 验证会话路由、配置读取及内容脱敏；目录 worker 不参与这些 MCP 动作。 |
| Windows 应用名称误匹配 | 同一过滤表达式混合精确进程名和标题包含匹配，资源管理器可能抢先命中。现在按 PID、精确进程名、精确标题、包含标题的顺序解析。 | PowerShell 执行实际选择函数，注入进程/窗口清单；覆盖同名文件夹、`.exe`、PID 和标题选择。没有启动或操作桌面应用。 |

OpenAI 的 [Function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)说明：Responses 省略 `strict` 时可能尝试把 schema 转为严格模式；显式 `strict: false` 保留非严格调用。这里修复的是发出的工具契约，未把每个工具里的空值统一转换为“未传”。

用户库打开失败会从环境观察组装的记忆读取路径向上传播，所以该故障能够造成 `varin-context unavailable`。本轮修复了这个已确认来源，未宣称所有观察超时都有同一个原因。
