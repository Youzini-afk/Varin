## 追加报告复核

新增的两项实验修复在当前 `7124288b` 上仍存在，回归先在未修改实现上失败，再迁移指定补丁的新增部分：

- 源截止计时器在读取等待中先中断 controller，会越过 pump 的 `deadlineStopped` 标记，整次 views 调用丢失已准备材料。现在按实际源截止判断，保留已有版本窗口并报告 partial/searchIncomplete；同时覆盖后续图关系补查中断。用户取消、提前中断与截止后主动取消仍不会变成成功结果。
- Pi 同一 worker 的请求队列等待 `harness.embed` 的完整网络请求，外层调度并发因此被串行化。现在按队列顺序接纳批次，再释放网络等待；批次预约、配置/会话顺序与取消隔离保留，不改变并发设置。

本地 41 项 query-run/服务检查、22 项 HostController/BackgroundInference 检查通过。实验的 112.10 秒候选阶段、3.51 秒 finish 和 9 个文件/16 片段收据已核对；收据只有完成材料，尚不足以确定 C# 文件是否进入候选、是否开始读取或哪一步未完成。没有增加文档过滤规则，也未执行真实付费请求或轮询 CI。

### 候选准备与结构等待

进一步直接核对当前源码，确认了两处可复现的接缝问题：同批读取要等全部文件完成后才串行准备窗口；LSP outline 的取消信号原先没有传进绑定/会话准备/符号请求。慢文档因此可以挡住本来可工作的读取槽位，源截止也不能及时结束该调用的 LSP 等待。

改为在现有读取槽位中立即接续候选，并在可选结构完成前保留已经读取、行号和版本核对过的文本窗口；结构返回后升级窗口。刷新中保留上一份有效窗口，截止时不会将已读源码丢掉。真正开始但未完成的准备显示明确原因，不再混进“未请求”候选。LSP 取消只结束本次等待与本次符号 RPC，共享的语言服务和其他调用继续可用。取消辅助函数移至 Host 公共模块，所有原消费者沿用同一实现。

控制用例在文档读取/outline 不释放时验证后面的 C# 代码已经进入 views 和最终片段，文档仍可返回；真实 LSP 进程用例验证取消共享准备后可继续使用，RPC 用例验证取消一个请求不会取消另一个、晚回复不会污染结果。相关 Host 检查 207 项、真实 release 内核计算 13 项通过，Host 类型检查和 Lint 通过；之后文本窗口提前保留的改动单独复验 Explore 的 133 项检查。
实际 `build:application-host` 成功，Pi Host 同时重新构建；生产图包含迁移后的公共取消模块（468 个可达模块）。

原实验缺少逐文件耗时和完整候选阶段记录，不能把这两个已复现机制宣称为其 112 秒的唯一原因，也不能宣称最新版已经在相同付费探针中返回关键实现。研究线可对最新提交重跑原参数，补留 views 原始返回、请求/完成路径和依赖计时。此次没有更改排序规则、排除文档、扩大截止时间或调整并发设置。
