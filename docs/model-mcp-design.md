# 模型渠道、认证与 MCP 服务设计

本文是待实施的设计，目标是让 Varin 独立管理模型接入、认证、配置和 MCP，移除这些能力对 Pi SDK 的依赖。
当前实现见[架构](architecture.md)与[运行时](runtime.md)；本文不表示默认运行时已经切换或 Pi 已经移除。
[能力补齐设计](capability-design.md)中的图像生成与编辑工具使用这里定义的模型服务。

## 1. 设计依据与现有基础

模型侧参考 `D:/project/new-api/newapi-gy-upstream-migration` 的**渠道类型、接入配置和模型管理**。
主要入口为 `model/channel.go`、`model/model_meta.go`、`dto/channel_settings.go` 和 `relay/channel/`。
Varin 直接按选定渠道的协议调用服务，不建设渠道间协议转换、请求转发网关或自动换渠道重试。
Varin 是 Agent 客户端，不引入 new-api 的账户余额、充值、预扣/结算、售卖倍率和网关计费体系。
客户端已有的用量统计、上下文容量计算和任务 token 预算继续保留，归属见下文。

参考项目解决的场景与 Varin 不完全相同。以下取舍基于具体代码，不能把“功能已有实现”当作整块移植的理由。

| new-api 的实现与取舍 | Varin 的处理 |
| --- | --- |
| 渠道类型、默认地址、前端类型表、表单条件和模型发现能力分散维护：`constant/channel.go`、`features/channels/constants.ts`、`channel-form.ts` 等 | 借鉴丰富的接入字段与操作流程；渠道定义统一提供字段、能力和发现入口，UI 与执行消费同一份定义 |
| `Channel` 混合连接、密钥、网关调度和计费字段，`setting/settings/other` 等内容分散为字符串 | 提炼连接与模型配置；使用有类型的配置对象和凭据引用，不移植整个渠道实体 |
| `GetSetting/GetOtherSettings` 遇存量配置解析失败时清空字段并尝试保存；保存入口另有有效性校验 | 读取保持无副作用，保留异常原文和当前有效配置，由明确的编辑修复；错误影响对应渠道 |
| 普通模型发现更新表单候选，自动同步和手动应用有独立入口：`controller/channel_upstream_update.go` | 保留发现与应用的区分，查询结果不直接改写用途绑定或删除用户模型 |

MCP 侧参考 `D:/project/opencr/extensions/pi-mcp-adapter`。它的离线目录、搜索、按需连接、OAuth 与内容处理
提供了可用基础，但其中一些实现依赖单个 Pi 会话的寿命和呈现方式：

| 参考实现的具体行为 | Varin 的处理 |
| --- | --- |
| `config.ts:mergeServerMaps` 逐字段合并同名定义，并用额外规则清理换 URL/transport 后的继承字段 | 连接定义完整替换；启停和暴露策略独立引用定义，避免跨来源拼接命令、地址和认证 |
| `server-manager.ts:connect/reconnect` 合并并发准备，但底层准备 signal 包含首个调用者的 signal；首次准备还等待 tools/resources/prompts 的 `Promise.all` | 实例拥有准备寿命，调用者只拥有自己的等待；连接和三类目录按实际依赖分别就绪 |
| `session-recovery.ts:withSessionRecovery` 对特定失效响应重连后再次执行回调，并读取实时配置 | 借鉴协议拒绝的识别；恢复与是否再派发由原 Operation 决定，绑定原定义和账号，不能转向同名新服务 |
| `metadata-cache.ts` 同步读写整份缓存，`computeServerHash` 包含解析后的 headers、env 和 bearer token | 目录由 Host 服务管理并异步持久化，使用非敏感配置版本和认证身份；凭据值不成为持久缓存键 |
| `utils.ts:normalizeDirectToolInputSchema` 为直接工具移除顶层 `$schema/additionalProperties` | 原声明保留并用于验证；模型协议需要的 schema 投影单独生成，不修改执行合同 |
| `tool-registrar.ts` 将二进制写到会话临时文件并修改原 resource；结构化结果追加为文本，另有插件输出限额 | 复用 Varin 的资源与结果投影，原结果不因展示而被改写，不移植第二套临时文件寿命、限额和说明文案 |

这些差异不都属于参考项目的缺陷。例如失效会话的重连具有协议依据，配置合并满足插件的覆盖需求；
它们进入 Varin 后必须服从已有的多线程共享、固定执行绑定和资源寿命。

按逻辑单元核对、提炼和改造可用实现，保留必要的许可与来源信息。Pi 的工具注册、会话事件、TUI 和配置目录约定
由 Varin 对应机制替换。通用 MCP 客户端、HTTP 和云认证库作为直接依赖使用；
客户端的取消、重连和请求重放行为也要与原执行合同对齐，不能仅凭 SDK 方法名推断实际语义。

已有基础与需要接管的部分如下：

| 当前基础 | 本次工作 |
| --- | --- |
| Rust Agent 的执行、历史、Operation、推理回执与恢复 | 继续作为执行事实来源 |
| Rust 协议适配器与 `ModelAdapterRegistry` | 扩展用途支持和产品注册入口 |
| `pi-host` 中调用 SDK 的模型目录、设置和凭据服务 | 替换为 Varin 服务与数据合同 |
| MCP authority 对 Pi 配置加载、客户端和 transport 的依赖 | 用 Varin 配置、生命周期和通用协议客户端替换 |
| 已有 MCP Tasks、资源订阅、反向交互和远端归属 | 接入新的 MCP 服务，保持原任务与资源身份 |
| 设置 UI 与部分变更通知仍经过 Pi broker | 改为直接访问和订阅 Application Host |

## 2. 服务边界

```text
工作台 / Agent / 后台功能
  Application Host
    配置服务：读取、校验、保存、发布变更
    模型服务：渠道、模型目录、用途选择与执行绑定
    认证服务：账号、凭据来源、登录与刷新
    MCP 服务：配置、目录、实例、协议调用与交互路由
  Rust 运行时与资源内核
    模型协议执行、Operation、用量与恢复
    文件、进程、媒体资源及实际执行环境
```

这些服务按 Application Host 共享，不为每个会话重复初始化。耗时计算和阻塞系统调用交给实际执行组件，
共享服务不意味着把全部工作压到 Host 的同一事件循环或队列。
Rust 继续拥有已转移的执行和资源状态；Host 负责产品配置、系统认证、MCP 客户端及工作台协调。
模型协议、公共 HTTP 与流式执行沿现有 Rust 实现扩展；Host 扩展或本地组件产生的推理也使用原 Operation 与回执合同。

公开 API 放在 `application-client`，UI 不接触凭据或内部 SDK 对象。配置、登录和目录查询可以在没有活跃会话时使用。
模块按职责命名为 models、credentials、mcp、settings，不增加 native 前缀或另一套迁移专用接口。

## 3. 模型渠道与配置

### 数据关系

| 对象 | 内容与身份 |
| --- | --- |
| 渠道类型 | 接入定义：配置字段、默认地址、认证方式、协议、模型发现方法及参数支持 |
| 渠道实例 | 用户创建的连接：稳定 ID、名称、类型、端点、账号引用、代理、启用状态及接入参数 |
| 渠道模型 | 渠道内的稳定身份、实际模型 ID 或部署名、能力、上下文容量及参数配置 |
| 用途绑定 | 某个功能选择的渠道模型与参数，如对话、标题、嵌入、重排、快速决策、生图、编辑 |

同一类型可以创建多个渠道实例；同一渠道可以提供多种用途的模型。修改显示名称不改变执行身份，
不同渠道中的同名模型不自动合并。用途绑定引用渠道模型，不复制端点和密钥。
渠道模型显式记录实际请求使用的模型 ID 或部署名，显示名称不承担路由职责。

渠道类型使用稳定的命名标识注册。每份定义提供配置 schema、展示元数据、支持的操作、协议绑定和发现入口，
不要求前后端另行同步整数编号、数组索引或“可获取模型类型”集合。类型专用的布局可扩展，校验仍来自同一合同。
渠道实例的类型专用参数是对应 schema 下的对象，不以多个含义模糊的 JSON 字符串字段堆放配置。

渠道类型与协议适配器分开。多家服务采用相同协议时复用适配器，各自声明地址、认证、参数和模型发现差异；
需要不同协议行为的服务注册对应实现。每种类型只声明实际支持的操作，不用一个包含所有空实现的大接口表达差异。

接入覆盖现有账号与模型能力，并逐步丰富渠道类型，例如 OpenAI、Anthropic、Gemini、Azure、Vertex、Bedrock、
DeepSeek、OpenRouter、国内托管平台、本地服务和自定义兼容端点。具体支持由接入定义和实现决定，不能凭类型名称宣称完整支持。

### 设置界面

用户流程是“选择渠道类型 → 配置连接与账号 → 获取或添加模型 → 为功能选择模型”。

- 渠道列表展示名称、类型、地址概要、启用状态和需要处理的连接问题，支持创建、编辑、复制非敏感配置、启停和删除。
- 配置表单按类型展示字段：例如 Azure 的部署信息、Vertex 的项目与区域、Bedrock 的区域与认证来源。
- 模型列表支持服务端发现、手动添加、启停与参数编辑。发现失败保留已配置模型，返回空列表不删除用户配置。
- 用途设置按能力筛选模型，生成图片与编辑图片分别选择；未配置的图像工具不进入 Agent 工具集合。
- 检查连接区分配置校验、认证、模型发现和实际推理。需要发起可能付费的试用请求时由用户显式触发。

同一份字段与能力描述用于 UI、配置校验和执行准备，避免三处各维护一套支持列表。
接入参数允许配置协议支持的路径、非敏感请求头和选项；敏感值通过认证服务引用。
参数区分未设置、显式清除、零值和 false，不能在合并时因真假判断丢掉用户输入。
支持匿名访问的本地或自建服务可明确选择无认证，无需填写伪造密钥。密钥格式提示不自动成为前缀或长度硬限制。

### 模型目录与能力

目录合并内置接入定义、扩展贡献、服务端发现和用户配置。用户显式配置优先于发现值；
缺少信息保持未知，不能通过模型名猜出完整能力。目录记录字段来源，供设置面板解释生效值。
发现列表是候选材料，选择、保存或明确配置的同步策略才改变用户配置；服务暂时不再列出某模型时，
保留其用途引用并显示发现状态，实际可调用性由对应请求确认。陈旧目录与成功空列表分别处理。

能力按操作和参数表达：文本生成、工具调用、结构化输出、图像输入、图像生成、参考图编辑、蒙版、嵌入、重排等。
推理选项、媒体格式、上下文容量和服务明确声明的参数范围属于具体模型与操作。
能理解图片不意味着能生成图片；支持一种编辑接口不意味着支持全部蒙版或多图选项。

扩展或用户可以补充服务未提供的元数据，最终有效能力还需有对应协议实现。
未知型号可通过显式兼容协议和配置接入，不要求先进入内置型号白名单。

### 执行与用途

执行准备解析用途、渠道、模型、适配器和认证引用，形成不含密钥的固定绑定；派发前由认证服务解析实际授权。
渠道编辑只影响后续准备，不能改写已受理的请求或把正在执行的调用转到另一个渠道。

各用途使用正确的输入输出类型：对话保留协议历史与工具调用，嵌入返回向量，重排返回排序，
图像返回媒体资源。它们共享身份、取消、用量和恢复机制，不各自建设请求数据库、重试循环或会话。
原始用量、缺失值和估算分别保留；图像等非文本操作保留其实际用量单位，不强行换算成 token。

协议适配器负责直接生成目标协议请求并解析结果，保留必要的签名、缓存和续接字段。
请求已发出但效果不明时查询原结果，不自动再次调用。类型定义中的可用渠道也不构成自动换渠道授权。

### 客户端用量与 token 计算

现有多处 token 计算承担不同职责，模型服务替换需要承接这些消费者，不将它们合并成一个无差别的计数器。

| 用途 | 数据来源与使用方式 |
| --- | --- |
| 调用与会话用量 | 提供方返回的 usage，归属原 ModelStep/推理 Operation，用于消息、会话、渠道模型及任务汇总 |
| 上下文容量与压缩 | 本次实际输入的计数或估算、模型容量、输出预留，以及符合条件的前次实际用量校准 |
| 检索切片与材料装配 | 对应模型的 tokenizer 或明确标注的估算，用于分块、批次和材料选择，不计作已消耗用量 |
| Goal 执行预算 | 原任务范围内的用量回执和用户明确设置的预算；继续使用现有输出 token 口径，不擅自换成总 token 或金额 |

调用用量只有原请求记录这一份事实，UI、Goal 和其他汇总是它的投影。同一请求在历史、恢复和父子任务视图中再次出现，
不产生第二份消耗。标题、压缩、记忆整理、检索中的模型调用和 MCP sampling 同样保留各自原请求与用途，按实际任务归属汇总。

提供方报告值、本地估算、缺失和等待回执分别表达。已返回但答案校验失败的调用仍保留 usage；
取消或断连不等于零消耗。缓存读取、缓存写入、推理 token 与输入/输出可能存在包含关系，
由协议适配器解释后提供统一语义，不能在 UI 或任务统计中把所有字段直接相加。

本地计数复用已有运行时与检索组件，记录模型/tokenizer 或估算方法。精确 tokenizer 可用时使用它；
否则保持估算标记，媒体和提供方专有内容未测得的部分保持未知。
请求容量以实际序列化的文本、工具声明和协议结构为依据，材料片段计数不能代替整个请求的容量。
已有校准与增量复用按真实输入、模型和协议身份生效，不为统一接口重复加载 tokenizer 或重算未变内容。

已有成本展示可保留为用量的可选投影：供应商报告值与按明确价格估算分别标注。
没有价格不影响模型接入、token 统计或容量计算，也不据此建设网关定价和扣费服务。

[容量估算与校准](../kernel/crates/varin-runtime/src/context_capacity.rs)、
[Goal 用量](../kernel/crates/varin-runtime/src/catalog_goals.rs)、

## 4. 认证服务

认证服务独立管理账号身份、凭据来源、登录、刷新、退出与授权范围。模型渠道和 MCP 引用它的账号或凭据，
各自绑定目标服务、所需权限和执行 Host。API Key、OAuth、云凭据链及已有环境/命令来源使用专门的解析器。

凭据存储采用轻量的 Host 本地文件，复用文件锁与原子保存；文件组织不沿用 Pi 的硬性约定。
模型账号与 MCP 授权分别保存，避免 MCP 的客户端发现、授权中间状态及 token 刷新触发无关的模型配置更新。
认证解析、账号身份和交互合同保持统一，不因文件分开而复制存储服务或引入额外进程。
新建文件使用私有权限，保留已有文件和目录的权限。
读取不创建文件，相同内容不重复保存；配置、登录或刷新需要持久化时才写入。
桌面、headless 和远端 Host 使用相同存储方式，也可显式引用环境变量，不要求系统钥匙串或额外密钥服务。
渠道配置保存凭据引用，认证服务按实际请求目标解析敏感值。
项目配置不能自行取得未获准的用户凭据；远端执行沿现有授权连接取得所需服务，不广播用户的全部账号。

同一账号的刷新由服务合并执行，独立账号并行。一个调用取消等待不取消其他调用共用的刷新；
已轮换的 token 仍由原认证服务完成保存。正常刷新保持账号身份，换账号、重新授权和退出登录更新相应绑定。
旧刷新结果不能覆盖用户随后完成的换号或退出。

MCP OAuth 与模型 OAuth 共用存储和交互基础，保留各自 issuer、resource、scope 和客户端身份。
登录交互进入现有工作台交互机制，只使相关调用等待，不阻塞其他渠道、MCP 服务或设置页面。
云认证库直接依赖，不再借助 Pi 包的依赖树加载。

## 5. MCP 服务

### 配置与实例

配置发现与来源展示参考插件实现，解析和覆盖合同由 Varin 管理：用户配置、受信任项目的 `.mcp.json`，
以及用户显式启用的外部来源。其他软件的配置可以扫描、展示并选择导入，不自动变成活动服务器。
项目同名定义覆盖用户定义时以完整条目替换，避免把一个来源的命令与另一个来源的凭据拼接。
针对已有定义的启停、工具筛选和暴露方式属于策略覆盖，引用其原身份，不通过拼接部分连接字段实现。
界面能查看实际来源、覆盖项和执行 Host；保存回选定的原来源并检查 revision。

分开保存三个概念：服务器定义、能力目录、在线实例。定义的来源和条目身份用于区分同名服务器；
实例另外绑定配置版本、实际 Host、账号、执行目录和状态共享范围。名称只是呈现与选择入口。
同一执行环境中可共享的实例由多个消费者引用；私有工作树、不同账号或需要独立状态的任务使用独立实例。
不能仅凭 URL 或显示名称共享，也不因 Thread 不同就无条件复制实例。
每个服务器的连接定义作为整体校验；不合法的单个条目只影响自己的实例，仍可访问独立的有效条目。
整个来源无法解析时保留该来源的上次有效快照并显示错误，不将其解释为所有服务器已被删除。

本地 stdio 进程通过现有 Rust 进程服务管理，远端进程保留真实 Source 和 Host 身份。
传输采用通用 MCP 客户端，直接支持 stdio 与 Streamable HTTP；其他传输按实际接入需求注册。
协议版本、能力发现与通知机制由客户端适配，不把所有服务都假定为必须拥有 `initialize` 会话。
实现依据 [MCP 版本与能力合同](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning)。

### 目录、预热与连接生命周期

能力目录缓存工具、资源和提示模板的声明，支持未连接时搜索。缓存是可重建的发现材料，
不代表服务器在线或旧 schema 仍可直接执行。目录按服务器定义及授权范围区分，避免账号间串用声明。
设置面板分别展示已配置、已有缓存与在线状态；需要登录、连接失败和成功返回空目录分别呈现。

目录按受影响条目更新，由同一 Host 的 MCP 服务合并变更并异步持久化，搜索与派发不每次同步重写全部目录。
缓存身份使用非敏感配置版本、账号和授权范围。正常 token 刷新不等同于换账号；实际权限或服务声明变化仍需刷新目录。
环境/命令来源无法确认身份连续性时，由认证服务重新解析与绑定，不以密钥值的哈希代替账号身份。

同一实例的预热与实际调用共享准备结果，由实例自身持有取消控制和消费者引用。
首个调用者与后来的调用者一样，只能取消自己的等待；没有消费者或预热持有者后，才按实例生命周期结束准备。
常用或固定工具的服务可以提前连接；其他服务按需启动。预热不执行工具、不自动发起交互登录。
工具、资源和提示模板目录独立刷新，只有调用依赖的部分需要等待；可用工具不等待无关目录完成。
维护、重连与释放按实例独立推进，一个服务的清理或发现未完成不阻止其他服务更新状态。

实例保留实际调用、任务、订阅和状态会话引用。空闲释放只适用于可重建且没有这些引用的实例；
需要保持业务状态的服务可以常驻。具体空闲策略由生命周期配置表达，不照搬参考项目的固定分钟数或批次数。
一个消费者离开或取消连接等待，不关闭其他消费者仍使用的实例。

普通断连后的新调用可以重新准备连接。收到协议明确的未受理拒绝时，可由原 Operation 在同一配置和授权下重新准备；
适配器返回拒绝事实，不在调用回调外套一层自行重放。已派发而结果不明、工具已执行但返回错误、用户取消等情形
不能被当作未执行。恢复时不读取同名新配置来替换原目标。
配置替换准备新实例，旧实例服务其已受理工作后释放。禁用、移除、退出账号按现有撤回与取消合同处理。

### 工具暴露与结果

默认提供紧凑的发现与调用入口，支持将常用工具固定到模型工具列表，以及发现后在下一请求加载完整 schema。
所有模式最终解析到同一服务器、真实工具名、声明版本和执行绑定，使用同一权限与 Operation 路径。
代码模式复用现有脚本执行能力，单次调用不强制写脚本。

列表变化更新目录，在原组合发布边界准备新的工具集合；已经发出的模型请求不被重写。
调用前核对绑定声明与实际服务，无法履行旧声明时报告相应变化，不将旧参数直接送给新定义。
原 JSON Schema 与模型可接收的 schema 视图分开保存，派发按原声明验证。协议投影不得悄悄删除执行约束、
把数组转成字符串或修改原参数；转换由已有模型协议层承担。不能表达的部分使用原发现/调用入口说明，不使整个服务器失效。
服务器 annotations 用于描述与展示，不能替代权限决定或证明操作没有副作用。

结构化结果、文本、图片、资源链接和 UI 专用数据按原内容合同投影。模型收到完成任务所需的内容；
界面专用元数据不展开成提示词。大内容和媒体沿既有资源机制读取，不以 base64 文本灌入上下文。
投影不修改收到的原始结果；图片、二进制和结构化正文存入既有资源存储，历史保留原内容关联。
上下文中的片段或摘要提供可继续读取的引用。插件中的固定字节数、文件数、临时目录和输出提醒不成为新的产品合同。
服务器使用说明按选择与发现范围提供，不把全部服务器说明反复注入系统提示词。

### 长期任务、资源与交互

| MCP 能力 | Varin 接入 |
| --- | --- |
| 资源读取、模板与订阅 | 原资源授权和内容服务；订阅寿命独立于一次读取，断连如实记录通知缺口 |
| 提示模板 | 用户选择后获取并作为本次输入材料，保留参数和来源 |
| Tasks | 原 Operation/Job、进度、等待、结果与取消；仅在协议实际支持时使用 |
| sampling | 原模型服务与请求记录，按请求归属处理模型选择、权限和用量 |
| elicitation | 原用户交互记录与工作台表单/链接，不依赖 Pi 弹窗 |
| MCP Apps | 原工作台隔离 Surface 与受控 bridge，资源和工具访问仍经过原授权 |

借鉴参考项目的协议处理与界面实现，复用 Varin 已有的任务、订阅和反向请求管理。
协议读取回调只分发消息，不等待用户回答、模型生成或目录重建，避免长交互阻塞同连接的其他响应。
资源与后台任务保留实际持有者，关闭聊天视图不等于终止它们。

## 6. 配置更新、并发与扩展

配置服务在既有 Varin 设置存储上承担校验、原子保存与变更通知，每个领域只有一个写入者。
UI、Agent 设置工具和后台功能访问同一 API。文件外部编辑同样经过读取与校验，失败候选保留上次有效状态，
界面显示保存状态与生效状态的差异。读取不清空、修复或保存异常配置；首次加载没有有效快照时，
明确报告对应配置不可用，保留原文供编辑，不合成一份空配置继续运行。

| 变化 | 生效边界 |
| --- | --- |
| 渠道、模型与普通用途参数 | 后续执行准备；已受理 Run、排队输入和请求保留原选择 |
| 图像工具配置、MCP schema 与暴露方式 | 下一模型请求的工具组合发布边界 |
| 正常凭据刷新 | 同账号下的后续认证解析，保留原请求和账号身份 |
| 明确禁用或撤销授权 | 按原权限与取消机制停止新的访问，并处理相关在途工作 |

缓存和准备结果按实际依赖更新，不用整个配置文件的全局 revision 让所有服务失效。
配置更新不重新拼接无关提示词，也不往每轮上下文加入服务状态说明。

配置提交、目录发布和组合提交保持短操作。登录、网络、进程启动和推理在这些提交之外执行。
独立服务器、账号和工具各自等待，取消与状态查询可独立处理；同一资源需要串行时，由真正拥有该资源的服务协调。
启动加载本地目录和配置，后台更新远端元数据并准备已选依赖。预热失败影响对应能力，不形成全局启动门槛。

扩展通过既有 service、capability 和 composition 机制贡献渠道类型、模型目录、协议适配器、认证方式及 MCP 展示能力。
内置与外部实现使用相同合同；普通渠道配置无需编写扩展。Rust `ModelAdapterRegistry` 继续拥有协议实现绑定，
补齐产品扩展到该合同的注册与执行路径，不另建安装器或一套动态库加载系统。
跨进程适配器使用既有 broker 的类型化请求、结果与取消通路；网络与凭据访问遵循已审查的 Host 能力。

设置面板展示实际配置来源、可用性和需要处理的问题。工具失败只返回影响下一步的原因与必要操作，
请求 ID 和详细堆栈进入现有诊断通路，不把内部职责、调用阶段和恢复流程铺进正常工具结果。

## 7. 实施与完成边界

1. 接管设置 API、变更通知和认证服务，使设置与账号管理脱离 Pi worker；复用可用的文件事务和系统认证实现。
2. 实现渠道类型、实例、模型目录与用途绑定，连接 Rust 适配器及各用途推理；图像工具沿此路径完成。
3. 结合 MCP 参考项目替换配置、客户端与生命周期实现，连接原工具、资源、长期任务、交互与 Surface。
4. 接通扩展贡献，删除已被替代的 Pi SDK 调用与补丁。实际所有权转移后删除旧路径，不长期维护双写或同功能备用实现。

旧 Pi 数据与外部配置是用户资产。需要转移时采用明确的一次性处理，单独核对账号和配置去向；
不因本次内部重构自动导入历史或更改凭据。整体默认运行时切换与旧 Pi 会话退役仍按实际产品切换处理。
本设计要求新服务的依赖闭包不含 Pi SDK；旧会话尚未退役时的旧依赖不能反过来成为新服务的前置条件。

完成证据应覆盖以下真实使用链，具体测试选择与改动风险相称：

- 不加载 Pi SDK、不开 Pi worker，仍能编辑渠道、登录、发现模型并执行各已支持用途。
- 同类型多渠道、自定义端点、独立生图/编辑配置及未配置工具不加载，均从设置界面走通到执行。
- 原调用 usage、上下文估算、检索计数与 Goal 预算各自保持正确口径；取消、辅助调用和重复投影不会丢失或重复统计用量。
- MCP 的发现、调用、目录变化、资源、交互和长期任务使用正确原身份；一个慢服务不阻塞独立工作。
- 配置更新、凭据刷新、取消、断连与重启不会偷换绑定、重复派发或遗留无人负责的工作。
- 桌面与 headless/remote 使用同一 Host 服务；安装包无需从 Pi 的依赖树寻找认证或 MCP 组件。

与上述取舍直接相关的验证包括：两个消费者共同连接时取消首个，另一个仍能完成；工具目录已就绪而资源目录延迟时，
工具可以调用；保存了损坏的渠道配置后，读取不会改写原文件；恢复期间同名服务器换了地址，原调用不会被送到新地址。
这些场景验证实际行为，不把参考项目的测试名称或既有通过结果当作 Varin 的完成证明。

性能关注启动与首次调用延迟、重复准备、连接和进程数量、目录及 schema 的上下文成本。
以实际链路比较优化效果，不用文件数量、测试数量或预设倍率宣称完成。
