# 面向任务与资源的 Harness：工作区解耦与持续检索

Status: accepted direction / design recorded / not implemented (D-337)

Last updated: 2026-09-27

源码核查基线：`19c010d7`，Varin `0.9.19`。本文记录维护者确认的重设计方向，定义替代合同、实施顺序与验收场景；本次交付只有文档。代码仍运行现有工作区与会话工作上下文机制，实际交付统一记入 [能力状态矩阵](agent-harness-status.md)。

## 1. 设计判断

**工作区负责组织，任务负责推进，资源负责寻址，索引负责加速。**

用户经常同时处理代码目录、下载文件、论文、表格、网页和远程执行结果。它们无需拥有共同父目录，也无需为了使用工具先登记成同一个工作区。工作区在产品中主要是会话分类、项目入口和资源集合；它不再决定聊天是否可用、文件是否能被工具接受、任务存在哪里或索引属于谁。

Harness 的目标是减少 Agent 为环境做的准备工作：明确目标就能操作，指定位置就能搜索，已有计算持续复用，失败只影响真正依赖该资源的功能。日常任务不应要求 Agent 先维护目录镜像、切换检索作用域或修复工作区绑定。

本设计替代 D-330 及 RR2 的可变会话操作上下文目标，并替代 D-332/RR4 中以 `workspaceId → queryScope → operationDir` 组织检索和数据归属的部分。RR1 的恢复与停止、RR3 的命令执行/输出记录、RR5 的联网，以及已修复的数据正确性问题继续保留。RR 记录是既有实现事实，不表示其目录模型仍是下一阶段的设计目标。

## 3. 用户与 Agent 应获得的行为

### 3.1 没有项目也能工作

用户创建普通聊天，添加一份表格，让 Agent 分析、生成报告并安排后续事项。会话历史、todo、附件、子 Agent、产物和 follow-up 直接可用，不要求注册目录，也不制造一个假项目充当数据 owner。

只有运行进程或输出磁盘文件时才需要物理位置。用户指定输出位置就使用它；没有指定时，应用在自身数据目录中按需提供会话成果目录，并返回真实文件位置。这是成果存放位置，不成为会话的访问边界或整个任务的隐式搜索范围。

### 3.2 跨目录是普通操作

“对照 Varin 的实现与下载目录中的设计 PDF，更新另一份项目说明”可以在同一任务完成。Agent 直接引用这些文件和目录，无需 `discover → select → scope` 前置流程。会话仍可留在原分类中。

### 3.3 新位置立即可用

第一次搜索一个目录时，先提供文件名、文本搜索及按需结构读取；已有索引则直接加速。未建立向量索引会影响语义覆盖，不影响直接读取或普通搜索。当前请求不等待整个目录索引完成。

### 3.4 故障按依赖局部生效

目录被移动、外置磁盘离线或某种解析器不可用时，历史聊天、待办和其他资源仍然工作。访问失效目标的操作返回具体问题。不能静默换到父目录、另一份同名文件或另一台机器，也不能因此让整个会话卡在加载状态。

## 4. 概念与职责

这些是现有系统需要厘清的职责，不要求为每一行新增服务、Manager 或数据库。

| 概念 | 唯一职责 | 不再承担 |
| --- | --- | --- |
| 工作区/项目集合 | 会话分类，关联文件夹、材料、项目说明和显示偏好 | 文件权限边界、执行身份、所有工具的数据 owner |
| Session / Thread / Run | 用户意图、历史、任务关系、执行进度及成果归属 | 通过所在目录推断自身身份 |
| 资源位置与引用 | 指向某个环境中的文件、对象、材料或产物 | 隐式采用当前侧栏项目解释目标 |
| 本次执行参数 | 目标环境、命令 cwd、相对路径默认基准 | 同步整场会话中所有进程的可变目录 |
| 本次检索范围 | 当前查询要覆盖哪些资源 | 持久限制以后所有查询和文件操作 |
| 索引与缓存 | 加速资源的发现、定位、结构分析和语义召回 | 决定资源是否可读、是否可搜索 |

继续复用 Pi 的会话历史和 Agent loop、Host 的产品装配、Rust 的文件/进程/内容对象/计算实现。Electron、Web、远程和移动端使用相同合同，不新增 Electron 后端。

## 5. 会话、任务与存储脱离文件夹

### 5.1 数据归属

会话私有记录按 session 身份定位；子任务和执行记录按现有 thread/run 身份定位；项目知识按项目身份关联；用户知识保留用户归属。文件与材料作为这些记录引用的资源，不负责提供目录型 owner。

存储内部可以按实际规模分区，但 owner 的解析不应要求目录存在或成功打开 Documents workspace。需要解除的消费者包括 todo、知识块、Thread catalog、材料/产物、follow-up、实验记录以及它们的 UI 路由。项目知识在无项目任务中可以缺席，会话 todo 和用户材料不能随之不可用。

会话分类变更只调整关联，不搬移历史、重建知识库、改变文件身份或重启正在执行的任务。取消项目分组不删除其关联会话和成果。项目主动删除成果是另一项明确操作。

### 5.2 激活与能力准备

读取历史与建立会话身份优先完成；依赖磁盘、进程或索引的服务在被使用时准备。后台准备可提前进行，但不成为无关功能的全局就绪门槛。会话级 actor 注册不要求存在某个工作区目录。

Pi 原生 session JSONL 和会话目录格式继续由 Pi 管理。原生 header 中的 cwd 可以保留启动来源及初始默认值，但不再推导整个 Harness 的服务资格与存储归属。若 SDK 创建 worker 必须提供现存 cwd，由运行时装配提供应用管理的启动目录；它不进入 Agent 工具的静默路径回退链，也不从中加载无关项目配置。

## 6. 资源身份与操作入口

### 6.1 独立于项目的资源位置

磁盘目标首先由“实际执行环境 + 规范化位置”确定。相同主机、相同文件经多个项目入口访问时应落到同一资源协调路径；不同主机上的同名绝对路径保持不同。显示路径保留用户可识别的形式，不能把用于比较的路径键直接当作打开路径。

Documents 继续拥有文本读写、修订和编辑器交互，Rust 继续拥有受管磁盘写入和文件协调。它们对外接受资源引用/明确路径，不要求先创建用户可见的 workspace。底层若仍需要文件根注册，它只是后端寻址细节，不能再次承担项目身份或跨目录限制。

Windows 大小写、UNC、junction、symlink 和尚未创建的文件由现有文件层处理。新文件按实际父目录解析目标。路径别名、重命名与文件替换不能仅凭内容 hash 合并身份；同内容的两份文件仍是两个写入目标。

### 6.2 内容视图与位置分开

同一个位置可以有磁盘内容、未保存的编辑草稿或某个固定修订。读取结果携带实际来源及修订；下游引用保持该来源。固定 PDF 原件及解析版本继续沿现有材料合同处理。

独立 worktree 或实验副本位于另一个实际位置，不能因为源文件相同就合并可变文件状态。不可用的草稿或固定工作状态也不能自动退回磁盘。

### 6.3 一次解析贯穿执行

工具受理时解析相对路径、确定实际资源及视图，生成本次操作使用的结果。权限入口、资源锁、读取/写入、恢复记录和返回值消费同一解析结果；下层不再分别读取“最新操作目录”。资源内容后来发生变化时按现有修订/冲突语义处理。

Agent 可以传绝对路径或工具返回的资源引用。相对路径以本次执行已公开的默认目录为基准，工具也可接受本次调用的显式基准。只有多环境任务需要说明目标环境；本地常规调用沿已选运行环境，不增加反复选择步骤。

## 7. 执行目录与 shell

### 7.1 默认值的边界

一次 Agent 执行开始时，从用户明确选择的任务位置或既有明确默认值取得可选默认目录。该次执行使用固定默认值；跨目录调用直接填写目标路径或 cwd。侧栏导航不改变它，Agent 不需要为了操作另一处而先修改共享状态。

如果没有任务目录，按需创建的会话成果目录可以作为本次执行的默认位置；实际位置在调用前对 Agent 可见。这里没有需要 CAS、分支 journal 和响应 piggyback 同步的目录权威。运行中的工具始终使用自己已取得的参数。

一次典型执行可以直接包含：

```text
read(path="D:/project/opencr/Varin/package.json")
read(path="D:/Downloads/design-notes.md")
exec(command="bun run build", cwd="D:/project/opencr/Varin")
```

上例表示目标语义，不规定最终工具命名。协议形状由实施阶段在原有工具/API 上收敛，不增加一组平行工具。

### 7.2 普通命令与持久进程

普通命令每次使用明确 cwd；跨调用共享 shell 环境必须通过明确的持久 shell/进程句柄表达。持续交互进程的 `cd`、环境变量和输入流属于该进程，不改变文件工具及其他 shell。

实现可以复用底层进程，但普通命令不能意外继承前一条载荷留下的 cwd/env。需要保留这种状态的使用场景进入明确的持久 shell 路径，Agent 和 UI 都能看到句柄及当前状态。

杀掉进程即结束该执行环境，不凭空声称环境变量或 cwd 已恢复；后续新执行按自己的参数启动。继续保留 accepted execution、输出句柄、退出状态、取消、命令包装和 `waitMs` 的已有正确行为。重开聊天不要求重建所有历史 shell。

### 7.3 子任务与项目上下文

子 Agent 接收派发时的目标资源和执行默认参数，之后独立工作。父子/兄弟的目录选择不会互相改变。隔离分支仍使用现有物化、固定 baseline 和结果集成；其位置由具体 Run 的执行资源决定，不能通过一次目录参数改写 baseline。

项目说明、语言服务根和构建配置按实际目标读取。TypeScript 工程根、Git 仓库根或 Cargo workspace 仍有真实业务含义，应保留为对应工具的分析上下文。普通文件导航不隐式加载项目可执行扩展或更换 provider 配置。

## 8. 持续检索与资源索引

### 8.1 查询入口

查询接收问题及本次范围：文件、多个目录、材料集合或它们的组合。项目集合可以展开为这些资源，省略范围时由任务已有输入和关联资源提供默认线索。范围解析结果属于本次查询，不能变成以后所有工具的隐藏限制。

范围来源的优先顺序是显式目标、任务明确关联材料、项目提供的默认材料。附件、选中文件、近期有效引用来自现有会话/Run 输入，不建立另一套必须人工维护的 context 服务。缺少线索时先进行有针对性的位置发现；只有确实无法判断任务对象时才向用户澄清。

明确指定范围的查询严格在该范围内回答；建议扩大范围与实际扩大范围要能区分。Agent 可以自主发起跨目录查询，无需切换工作区。默认不进行无关全盘扫描。

### 8.2 根据问题选择已有能力

```text
问题 + 资源范围
    → 文件名 / 文本 / 符号关系 / 语义召回
    → 已有索引 + 变化部分与冷资源的直接查询
    → 合并候选、去重、必要的排序和正文读取
    → 可继续打开、引用、编辑的结果 + 实际覆盖情况
```

明确文件直接读，字面词直接搜索，符号问题利用结构/关系，语义问题使用已配置的语义能力。短查询不强制进入模型规划；已有快速决策模型继续按适用问题参与选材与进一步探索，不成为所有查询的前置请求。

语义、符号或某一外部来源失败，只影响依赖它的召回。仍可提供其他来源的真实结果，但不把失去语义覆盖的查询表述为完整的语义搜索。

### 8.3 索引身份

| 层次 | 标识依据 | 复用及变化 |
| --- | --- | --- |
| 资源目录 | 环境、实际位置或现有材料对象引用 | 提供存在性、来源、当前观察版本和可用性；不依赖会话分类 |
| 内容与结构 | 实际内容版本、格式/语言、解析器及其配置版本 | 同样输入可复用；内容或解析规则变化时失效 |
| 文本与向量条目 | 片段输入、切分/装饰规则、实际模型空间与配置 | 相同计算输入复用；不同模型空间分别检索 |
| 符号关系 | 资源版本、语言工程/依赖解析上下文 | 同文本在不同工程中可能绑定不同关系，不能仅按内容合并边 |
| 查询结果 | 问题、实际范围、所用资源视图与相关索引状态 | 不跨范围或内容变化复用过期结论 |

向量缓存继续按实际送入模型的文本计键；若片段装饰包含路径，不能只按原始文件内容声称可复用。文件位置与内容计算分离，不把内容去重变成文件身份去重。

索引由 Host 组织，解析/扫描继续复用 Rust 计算与现有派生存储。缓存键不含会话分类 workspaceId。存储允许按数据规模与维护需要分片，但分片不暴露为用户必须注册的项目。

### 8.4 冷、热与变化中的材料

| 情况 | 当前查询 | 后续维护 |
| --- | --- | --- |
| 最新索引已存在 | 直接召回，读取命中内容时核对版本 | 继续增量维护 |
| 有修改/新增/删除 | 有效索引与变化部分查询合并；屏蔽已失效条目 | 更新受影响文件，不重建整库 |
| 尚未索引的目录 | 文件名/文本直接检索，候选按需解析；语义按实际可用能力参与 | 对实际使用或明确纳入的材料逐步建立索引 |
| 索引构建中 | 使用已发布部分和直接查询路径 | 后台继续；不等待整次扫描完成 |
| 文件不可用或解析失败 | 返回仍可用结果及具体缺口 | 保留位置与来源记录，恢复时重检 |

冷搜索的文本命中不保证发现所有仅在语义上相关的内容。如果当前任务需要更完整语义覆盖，允许继续建立相关范围的索引或发起更深入检索；不能把冷搜索结果包装成与热索引等价的质量承诺。

失效检测同时利用受控写入通知、文件观察和查询时核对；仅靠 watcher 不能保证外部改动全被发现。查询命中后发现内容已变，重新读取并定位，或者舍弃该条旧命中并报告相关缺口。不能把旧行号套到新正文上。普通查询不要求先对整个目录固化快照。

### 8.5 多范围组合与排序

查询先确定范围，再在范围内取得候选，避免全库 top-k 后过滤而漏掉真正目标。父子目录重叠时按资源与视图去重；同名文件保留各自位置。

查询可以组合多个物理分片。相同向量空间可共享查询计算；不同空间的原始分数不直接比较，通过候选排名融合或已有统一重排形成最终结果。显式跨范围查询不能只等待最快来源后就宣称完成，其余来源的状态必须反映在覆盖说明中。

未保存编辑内容及固定工作状态继续沿现有 query view 参与：覆盖对应资源的磁盘候选，避免同时返回旧磁盘与新草稿的互相矛盾内容。不同 worktree 的内容仍分别标识。

### 8.6 索引生命周期与配置

检索服务可在无活跃聊天时读取已有索引。关闭聊天释放它的观察/查询需求，不自动删除仍可复用的派生数据；切换项目分组不重新创建索引实例。

embedding、rerank、快速决策配置通过已有设置和 Pi 推理/凭据接口取得，以实际配置身份复用，解除“先找 workspace worker 才能初始化检索”的装配依赖。明确的配置覆盖仍然生效；换模型时旧索引不会被错当成新模型索引。

目录监视按实际位置共享，任务活跃资源优先；其他材料按再次使用或明确维护需求更新。不在启动、打开聊天或读取一个文件时隐式扫描整台电脑。后台付费向量计算沿用户已配置的功能行为执行，不因去掉 workspace 就扩大为整盘远程 embedding。

扫描、结构分析和计算请求可以合并相容工作，一个查询取消只解除自己的等待；前台操作优先于背景补全。缓存淘汰影响复用率，不能让本来可直接搜索的目录变得不可搜索。不在本设计中猜测硬性容量、并发或时间上限；沿既有可取消、可分批机制按实测调整调度。

### 8.7 返回合同

常规结果包含问题相关片段、可直接使用的资源引用/位置、来源版本和简短覆盖说明。完整候选及诊断详情按需读取，不塞满模型上下文。

需要区分：零命中、未扫描到、尚未建立语义索引、内容已变化、来源失败与取消。扫描文件数来自执行事实，未知不填零。语义相似性排序本身不作“所有相关材料已找到”的承诺。

## 9. 工作区 UI 与最小访问边界

侧栏工作区继续作为会话分类与项目入口，可关联零个、一个或多个资源位置。用户可以把同一文件用于不同任务；打开/切换分类不触发文件访问资格变化、任务搬家或索引重建。需要展示时，UI 分别呈现会话分类、命令实际位置和产物位置，不再把它们压成一个“当前工作区”。

个人本机环境中，跨项目和跨目录是普通使用路径。文件入口遵循用户现有访问模式与操作系统能力，移除单纯因为目标不属于会话项目而拒绝的规则。目录中的 `..` 经正常解析处理，不因为语法本身拒绝合法目标。

Host/远程连接身份、已有明确用户决策和实际部署环境边界继续生效，但不再由会话分类推导。此轮不建设新的权限产品、审计系统或沙箱，也不把解除目录耦合变成删除写入冲突、进程归属和来源版本检查。它们直接关系到任务正确性与已有成果。

## 10. 需要替换、删除和保留的机制

| 现有机制 | 处理 |
| --- | --- |
| 必须有 workspace 才能注册 Harness、使用 todo/Thread/材料 | 由稳定会话/任务身份装配；资源能力按实际操作准备 |
| 可变 `operationDir`、`queryScope`、WorkContextMirror、目录 CAS 与响应 piggyback | 在实际消费者切换后删除；本次执行参数和查询范围接替职责 |
| 用 Pi 自定义 work-context journal 决定工具能否运行 | 移除该运行门槛与恢复协议；保留 Pi 原生历史，不改写历史正文 |
| `work_context` 的 get/select/scope/reset 控制流程 | 从 Agent 常规工具面移除；目录发现能力并入现有文件查找/资源浏览，保留可续查能力 |
| workspace-relative 路径在多层来回转换 | 在操作入口确定资源；后端若用相对存储路径，由后端局部映射 |
| workspaceId 决定 Documents 可变资源键 | 资源身份独立，项目树引用资源；编辑器与 Agent 共用协调路径 |
| workspace-scoped 语义实例和扫描生命周期 | 改为资源/配置驱动的持续服务，物理分片由内部管理 |
| shell anchor 与会话目录联动、目录多级静默回退 | 普通命令显式 cwd，持久进程明确句柄，缺失目标局部报错 |
| 关键词、符号、结构、语义及快速决策能力 | 保留算法与已有效的组合，统一资源输入、输出和生命周期 |
| 文档修订、草稿视图、固定原件、输出句柄、恢复与结果集成 | 保留实际语义；解除项目目录身份依赖 |

不能只在旧架构外套一个接受绝对路径的门面，内部仍通过临时 workspace 注册完成全部操作。也不能把原 workspaceId 整体改名为 resourceSpaceId，继续让会话、目录与索引共享同一个生命周期。

## 11. 实施顺序与源码归属

使用独立阶段前缀 **HR**（Harness resources），避免与已交付的 Rust R、可靠性 RR 混淆。阶段按用户行为形成纵切；每阶段替换实际生产消费者，不先建设一套无人使用的新框架。

| 阶段 | 交付行为与改动范围 | 主要归属 |
| --- | --- | --- |
| HR0：资源与归属基础 | 确定与项目无关的资源、session/thread 存储合同；以一个真实外部文件读写贯通 Host、Rust 和 Documents，并让无项目 todo/子任务找到稳定 owner | protocol、application-client、Host 装配、Documents、Thread/knowledge、kernel 合同 |
| HR1：会话与操作纵切 | 无项目聊天完整注册；文件工具/锁/恢复共用一次资源解析；命令 cwd 与持久进程分清；目录不可用不阻塞历史与其他工具 | broker、pi-host 工具与 mutation journal、service-host/router、shell、UI |
| HR2：直接检索与多资源范围 | 去掉关键词/文件名/结构查询的 workspace 前置，跨目录范围组合与统一结果引用可用 | search/content、文件发现、structure、explore/related、LSP 适配、kernel compute |
| HR3：持续索引 | 资源与版本驱动索引、配置复用、增量失效、冷/热混合查询、分片合并及草稿视图进入真实 explore 链 | knowledge/semantic、symbol graph、query views、Pi inference、Host 生命周期 |
| HR4：产品与旧机制收口 | 项目分类与执行位置分别呈现，子任务/科研/材料/后续工作/远程消费者完整切换，移除 work-context 同步和旧索引 owner | UI、runtime、研究与材料服务、follow-up、工作状态/集成 |
| HR5：真实使用验收 | 用下面的场景验证完整路径；核对阶段内仍保留的旧目录依赖，更新实现文档与状态，按实际差距返工 | 对应生产入口与平台夹具 |

HR0 应优先做可运行的窄纵切，借它检验合同后再推广。共享资源身份、操作受理合同和存储归属必须由明确整合者负责，不能分别改出几套形似但不相容的方案。相关内部协议变更连同客户端、Host、Rust 生成协议及测试夹具同步修改。

已有 [办公连续性设计](office-work-continuity-design.md)、[Web 与科研检索设计](web-research-search-design.md)、[Rust 内核设计](rust-kernel-design.md) 的领域目标保留；实施时把它们对目录型 workspace 的消费改为对应资源或数据 owner。不要为办公、科研各复制一套索引、存储或任务运行时。

内部格式按仓库约定直接替换，不建设永久双写、旧 schema reader 或兼容后端。派生索引可以重建；源文件、Git、Pi 历史、外部配置及尚未写回的真实成果不是可丢弃缓存。受影响成果在切换前具体保全，不能为了简化 owner 重构删除用户内容。

## 12. 验收场景与证据

| 场景 | 必须观察到的结果 |
| --- | --- |
| 无项目聊天处理附件并派发子任务 | 历史、todo、子任务、成果、后续事项可用；不制造目录型假项目 |
| 同一任务读 A、修改 B、输出到 C | 位置准确，无切工作区前置；返回引用可再次读取 |
| 父子项目同时展示同一个文件 | 共用正确的编辑缓冲/磁盘协调；分类变化不产生重复写入状态 |
| 第一次搜索新目录 | 普通搜索立即可用，不等待全目录索引；语义缺口如实可见 |
| 冷目录与热目录组合检索 | 范围在取候选前生效，合并结果与覆盖说明一致，不遗漏较慢来源而假称完成 |
| 外部修改、新增、删除、重命名以及草稿覆盖 | 旧条目失效，命中引用与实际正文一致，固定视图不串到磁盘 |
| 关闭/重开聊天、切换分类、Host 重启 | 既有索引与稳定任务记录可复用；无需恢复目录镜像才激活聊天 |
| 目录离线或原 cwd 消失 | 聊天和无关工具仍可用，具体文件/命令失败，不偷偷换目录 |
| 两个 Agent 并发操作不同位置 | 互不改变路径基准；同一目标按真实资源协调 |
| 杀掉持久 shell 后再次执行 | 原句柄状态明确；新命令 cwd 来自本次参数，不继承虚构环境 |
| 固定快照、隔离 worktree、远程同名路径 | 内容视图与执行位置准确区分，结果集成与来源可追踪 |
| embedding 或快速决策未配置/失败 | 直接搜索仍可使用，结果准确说明实际召回能力 |

性能验证关注首次结果可用时间、查询完成时间、重复计算/重复扫描、后台工作对界面与前台工具的影响。对代表性同一材料分别记录冷查询、热查询、变更后查询和跨目录查询；没有测量前不写提升倍数或毫秒承诺。相同问题下检查结果覆盖与片段质量，不能用更少结果换取虚假的速度提升。

验证按实际改动选择，优先已有夹具和能够揭示不同错误的行为测试；不要求每一阶段全仓测试、固定数量回归或新的通用评测平台。真实桌面重开/工具调用与安装包路径在相关交付时验证，源码测试不能代替它。状态记录明确区分设计、接线、实测和未测。

## 13. 交付边界

本次记录的是设计与 HR 实施顺序，所有 HR 阶段尚未实现。下一阶段按以上合同替换现有消费者；最终交付标准是用户和 Agent 减少目录准备、跨位置工作直接可用、计算持续复用，以及旧状态确实被删除，而不是新增类型和服务数量。
