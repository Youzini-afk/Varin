# Objetivos contínuos

Um objetivo pertence a uma branch de Thread e continua sua execução mais recente, mesmo que já tenha terminado. Enviar uma mensagem normal não cria um objetivo.

Primeiro envie uma mensagem. Em **Continuing goals → Create goal**, escreva um objetivo que faça sentido sozinho e um orçamento opcional de tokens de saída; selecione **Start goal**. Só pode haver um objetivo não encerrado por branch.

Uma resposta final comum encerra uma execução. O Agent pode informar explicitamente conclusão ou bloqueio pelo `goal_report`; o painel mostra o estado real.

Você pode editar, pausar, retomar, concluir ou cancelar. Esses controles alteram a autorização futura; chamadas já enviadas e processos independentes ainda precisam chegar ao resultado real. **Stop run** também pausa o objetivo. Uma pausa de política precisa da própria retomada. Um objetivo encerrado exige um novo objetivo para autorizar mais trabalho.

O orçamento verifica a saída reportada pelo provedor antes de outro envio. Em branco significa sem limite configurado; zero impede novos envios de saída. Trabalho em andamento pode excedê-lo. Estimativas e dados ausentes são separados: com orçamento, uso incompleto de inferências concluídas bloqueia novas inferências. Contagens de entrada, cache e raciocínio podem se sobrepor.

O Application Host precisa continuar executando. Veja [Tarefas agendadas e acompanhamentos](/pt-br/scheduled-tasks/).
