# Тривалі цілі

Ціль належить гілці Thread і продовжує її останній запуск, навіть уже завершений. Звичайне повідомлення не створює цілі.

Спочатку надішліть повідомлення. У **Continuing goals → Create goal** введіть самодостатню ціль та необов’язковий бюджет вихідних токенів, потім натисніть **Start goal**. У гілці може бути лише одна незавершена ціль.

Звичайна фінальна відповідь завершує один запуск. Agent може явно повідомити про завершення чи блокування цілі через `goal_report`; панель показує фактичний стан.

Можна редагувати, призупинити, відновити, завершити або скасувати ціль. Це змінює майбутній дозвіл; уже надіслані виклики й незалежні процеси ще мають отримати реальний результат. **Stop run** також призупиняє ціль. Пауза політики потребує окремого відновлення. Для подальшої роботи після завершення потрібна нова ціль.

Бюджет перевіряє вихід, повідомлений провайдером, перед новим надсиланням. Порожнє поле означає відсутність заданої межі; нуль забороняє подальше надсилання для генерації виходу. Поточна робота може перевищити бюджет. Оцінки й відсутні дані розрізняються: за наявності бюджету неповний облік завершеного виведення блокує наступне. Лічильники входу, кешу й міркування можуть перекриватися.

Application Host має працювати. Дивіться [Заплановані й подальші завдання](/uk/scheduled-tasks/).
