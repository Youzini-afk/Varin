# Заплановані й подальші завдання

## Завдання календаря

Відкрийте планувальник та виберіть проєкт. Задайте інструкцію, одноразовий, щоденний, щотижневий або cron-розклад, часовий пояс IANA та обробку пропущених моментів: пропустити чи виконати останній один раз.

**New work** створює Thread для кожного спрацювання. Виберіть зареєстровану модель, джерело й доступ: знімок лише для читання, ізольована редагована копія або активний робочий каталог. Можна додати **Continuing Goal** із бюджетом виходу. **Existing work** указує точні Thread і гілку та успадковує модель, джерело, дозволи й ціль.

Увімкніть розклад, коли все готово. **Run now** приймає одне спрацювання; результат перевіряйте в його розмові. Вимкнення визначення призупиняє недоставлену заплановану роботу. Зупинка запуску не вимикає майбутні моменти. Application Host має працювати.

## Цикли Markdown

Використовуйте `.agents/loops/` у проєкті або `~/.agents/loops/` для користувача. Замініть ID значеннями збереженого каналу:

```markdown
---
name: daily-review
runtime: agent
schedule: "0 9 * * *"
timezone: UTC
enabled: false
target:
  kind: new_work
  model: { providerId: my-channel, modelId: my-model }
  source: { kind: project }
  sourceMode: fixed_branch
  goal: null
---
Підсумуй зміни репозиторію від учора.
```

Обов’язкові назва, cron, явний часовий пояс, текст, `runtime: agent` і нативний `target`. Файл є джерелом визначення, редагування перевіряє ревізію. Виявлення не переписує файли й не імпортує непідтримувані старі визначення. Некоректна заміна утримує останнє коректне нативне завдання призупиненим до виправлення.

## Подальші завдання розмови

Використовуйте **Follow-ups** у планувальнику або **Schedule a follow-up** у розмові. Це продовжує ту саму розмову за часом, після зупинки процесу чи завдання, за умовою файла, артефактом або збиранням результатів дослідження, подією журналу чи порогом метрики машини. Умови можна поєднати як будь-яку або всі.

Виберіть один раз або кожну спостережену зміну для повторюваних умов. Паузи, питання без відповіді й межі цілей зберігаються; перерви спостереження можуть пропустити зміни. Переглядайте історію, призупиняйте, відновлюйте або скасовуйте. Скасування блокує майбутню й недоставлену роботу, зберігаючи результати та спостережувані завдання.
