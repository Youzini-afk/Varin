# Troubleshooting

Hit a snag? Find the symptom below and try the fix.

## Varin command exits or fails to start

- confirm Node.js `>=22.19` (Node.js 24 is the supported development baseline)
- from a source checkout, run `bun run dev` or `bun run start:web`
- if you have a published CLI, run `varin --version` and reinstall if needed

## Web UI is not reachable

- from a source checkout, read the terminal that started `bun run dev`
- if you have a published CLI, check server logs with `varin logs`
- verify the active port (development uses the Vite URL; the server default is `3000`)
- open `http://localhost:3000` directly first before testing tunnel links

## Remote/tunnel link does not work

- run `varin tunnel status --all` when the CLI is installed
- restart the tunnel from the same instance/port
- regenerate the connect link if the previous token was already used

See [Tunnels](/tunnels/) for the full setup, and [Reverse Proxy](/reverse-proxy/) if you run one.

## Storage and recovery

Open **Settings → Storage** on the intended Host. Choose the device and scope, then rescan. An incomplete scan is not a zero-byte total; these measurements cover Varin-managed data, not your original project folders or all physical disk usage.

Use **Inspect cleanup candidates**, review the device, scope and selected objects, then confirm. Cleanup preserves conversation history, attachments, original projects, active caches and managed working copies; it does not release recovery records. If the completion receipt is missing, rescan and use **Retry original confirmation** rather than starting another cleanup.

Open **Settings → History and recovery** to review recovery settings and pending workspace-edit records. Read any retained drafts before attempting a repair. Selecting a storage device does not switch the Agent Host; open the corresponding Host to inspect its history.
