# 计划任务与后续任务

## 日历任务

打开调度器并选择项目。创建任务时填写指令，选择单次、每天、每周或 cron 日程，指定 IANA 时区，以及错过时段的处理方式：跳过，或补跑最近一次。

**New work** 每次创建新的 Thread，需选择已注册模型、来源，以及只读快照、隔离可写副本或实时工作目录；还可启用 **Continuing Goal** 和输出 token 预算。**Existing work** 指向精确的 Thread 和分支，沿用其模型、来源、权限和目标。

准备完成后启用日程。**Run now** 表示受理一次执行，不表示已经完成；在对应对话中查看结果。禁用定义会挂起尚未交付的计划工作，停止某次运行不会禁用未来时段。Application Host 必须保持运行。

## Markdown 循环

项目 `.agents/loops/` 或用户 `~/.agents/loops/` 中的文件可定义 cron 任务。将示例 ID 替换为已保存模型渠道中的实际 ID：

```markdown
---
name: daily-review
runtime: agent
schedule: "0 9 * * *"
timezone: UTC
enabled: false
target:
  kind: new_work
  model: { providerId: my-channel, modelId: my-model }
  source: { kind: project }
  sourceMode: fixed_branch
  goal: null
---
总结昨天以来的仓库变化。
```

文件是定义的权威来源，编辑使用版本检查，发现过程不改写文件。必须提供 `runtime: agent`、原生 `target`、明确时区、名称、cron 日程和正文。不支持的旧定义不会自动导入或改写。原生定义被改成无效内容后，上一有效任务会暂停等待修复。

## 对话后续任务

使用调度器的 **Follow-ups** 或对话中的 **Schedule a follow-up**。可在指定时间、进程或作业停止、文件条件、科研产物或收集结果、日志事件、机器指标阈值满足时继续原对话，也可组合任意或全部条件。

选择单次，或对支持的重复条件选择每次观察到的变化。暂停、未回答问题和目标限额仍然有效；观察中断可能遗漏变化。可暂停、恢复、取消并查看发生记录。取消阻止未来及未交付工作，已有结果和被观察作业仍保留。
