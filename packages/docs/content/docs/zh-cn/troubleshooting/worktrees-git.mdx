# Worktree 与 Git

重试 worktree 操作前，先检查原 Host 和目录。失败或丢失的响应仍可能留下真实的 worktree 或 Thread。检查项目的 Worktrees 页面与 Git 状态；不要通过删除对话修复无关的目录问题。

目录移动后，恢复或修复 Git worktree 注册。合并、变基或 cherry-pick 未完成时，先检查本地变更再继续或中止。分支或目录名已被占用时，先检查已有工作再选择其他名称。

提交信息与 PR 描述生成使用 Host 的工具模型或默认模型。检查渠道、模型、凭据，以及所选暂存文件或 PR 提交范围，无需活动对话。先前请求结果未知时，应先检查再创建新请求。
