# 问题排查

遇到问题了？在下面找到对应的现象，试试相应的解决方法。

## Varin 命令退出或无法启动

- 确认 Node.js `>=22.19`（Node.js 24 是受支持的开发基线）
- 在源码检出中，运行 `bun run dev` 或 `bun run start:web`
- 如果你有已发布的 CLI，运行 `varin --version`，必要时重新安装

## 无法访问 Web UI

- 在源码检出中，查看启动 `bun run dev` 的那个终端
- 如果你有已发布的 CLI，用 `varin logs` 查看服务器日志
- 确认活动端口（开发使用 Vite URL；服务器默认是 `3000`）
- 在测试隧道链接之前，先直接打开 `http://localhost:3000`

## 远程/隧道链接无法使用

- 在已安装 CLI 时运行 `varin tunnel status --all`
- 从同一实例/端口重启隧道
- 如果之前的令牌已被使用，请重新生成连接链接

完整设置请参阅[隧道](/zh-cn/tunnels/)；如果你使用反向代理，请参阅[反向代理](/zh-cn/reverse-proxy/)。

## 存储与恢复

在目标主机打开 **设置 → 存储**，选择设备和范围后重新扫描。扫描不完整不代表零字节；这里统计 Varin 受管数据，不包含原始项目文件夹，也不等同于实际磁盘占用。

点击 **查看可清理项**，核对设备、范围和所选对象后再确认。清理保留对话历史、附件、原始项目、活跃缓存和受管工作副本，不释放恢复记录。若没有收到完成回执，先重新扫描，并重试原确认，不要另发一次清理。

在 **设置 → 历史与恢复** 检查恢复设置和待处理的工作区编辑记录，尝试修复前先读取保留的草稿。选择存储设备不会切换 Agent 主机；查看历史需要打开对应主机。
