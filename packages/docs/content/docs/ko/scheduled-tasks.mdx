# 예약 작업과 후속 작업

## 캘린더 작업

스케줄러를 열고 프로젝트를 고르세요. 지시, 일회성·매일·매주·cron 일정, IANA 시간대, 놓친 시점을 건너뛸지 최근 한 번만 실행할지 설정합니다.

**New work**는 발생 건마다 Thread를 만듭니다. 등록 모델, 소스, 작업 공간 접근 방식(읽기 전용 스냅샷, 격리된 편집용 사본, 실제 작업 디렉터리)을 고릅니다. **Continuing Goal**과 출력 예산도 추가할 수 있습니다. **Existing work**는 정확한 Thread와 브랜치를 지정하고 기존 모델, 소스, 권한, 목표를 이어받습니다.

준비되면 예약 실행을 활성화하세요. **Run now**는 한 건의 수락이며 완료가 아닙니다. 대화에서 결과를 확인하세요. 정의 비활성화는 미전달 예약 작업을 보류하며 실행 중지만으로 미래 일정은 꺼지지 않습니다. Application Host가 실행 중이어야 합니다.

## Markdown 루프

프로젝트 `.agents/loops/` 또는 사용자 `~/.agents/loops/`를 사용하세요. ID를 저장된 채널의 값으로 바꾸세요.

```markdown
---
name: daily-review
runtime: agent
schedule: "0 9 * * *"
timezone: UTC
enabled: false
target:
  kind: new_work
  model: { providerId: my-channel, modelId: my-model }
  source: { kind: project }
  sourceMode: fixed_branch
  goal: null
---
어제 이후 저장소 변경 사항을 요약하세요.
```

이름, cron, 명시적 시간대, 본문, `runtime: agent`, 네이티브 `target`이 필요합니다. 파일이 정의를 소유하며 편집은 리비전을 확인합니다. 검색은 파일을 다시 쓰거나 지원되지 않는 이전 정의를 자동 가져오지 않습니다. 잘못 수정된 네이티브 정의는 마지막 유효 작업을 복구될 때까지 보류합니다.

## 대화 후속 작업

스케줄러의 **Follow-ups** 또는 대화의 **Schedule a follow-up**을 사용하세요. 시간, 프로세스·작업 종료, 파일 조건, 연구 산출물·수집 결과, 로그 사건, 머신 지표 임계값에 따라 원래 대화를 이어갑니다. 일부 또는 모든 조건의 충족을 조합할 수 있습니다.

한 번 또는 반복 가능한 조건에서 관찰된 변화마다 실행하도록 선택하세요. 일시 정지, 미답변 질문, 목표 제한은 유지됩니다. 관찰이 끊기면 변화를 놓칠 수 있습니다. 기록을 보고 일시 정지·재개·취소할 수 있습니다. 취소는 향후 및 미전달 작업을 막으며 기존 결과와 관찰 대상 작업은 보존합니다.
