# 지속 목표

지속 목표는 Thread의 브랜치에 속하며 최근 실행을 이어갑니다. 이미 끝난 실행도 대상으로 삼을 수 있습니다. 일반 메시지를 보내는 것만으로 목표가 생기지는 않습니다.

먼저 메시지를 보내세요. **Continuing goals → Create goal**에서 독립적으로 이해할 수 있는 목표와 선택적인 출력 토큰 예산을 입력한 뒤 **Start goal**을 누르세요. 브랜치에는 끝나지 않은 목표 하나만 둘 수 있습니다.

일반적인 최종 답변은 한 실행을 종료합니다. Agent는 `goal_report`로 목표 완료나 차단을 명시적으로 보고하며, 패널이 실제 상태를 보여 줍니다.

편집, 일시 정지, 재개, 완료, 취소는 향후 허가를 변경합니다. 이미 전송된 요청과 독립 프로세스의 결과는 계속 확인해야 합니다. **Stop run**은 목표도 일시 정지합니다. 정책에 의한 정지는 별도로 재개해야 합니다. 끝난 목표 이후의 작업은 새 목표로 허가해야 합니다.

예산은 다음 요청 전송 전에 제공자가 보고한 출력을 확인합니다. 빈칸은 설정된 제한 없음, 0은 추가 출력 전송 금지입니다. 진행 중인 작업은 예산을 초과할 수 있습니다. 추정과 누락은 별도로 표시하며, 예산이 있을 때 완료된 추론의 사용량이 불완전하면 추가 추론을 차단합니다. 입력·캐시·추론 수치는 겹칠 수 있습니다.

Application Host가 실행 중이어야 합니다. [예약 작업과 후속 작업](/ko/scheduled-tasks/)도 참고하세요.
