# Zadania zaplanowane i kontynuacje

## Zadania kalendarza

Otwórz harmonogram z panelu rozmów i wybierz projekt. Podaj instrukcje, harmonogram jednorazowy, dzienny, tygodniowy lub cron, strefę IANA i obsługę pominiętych terminów: pomiń albo wykonaj ostatni jeden raz.

**New work** tworzy Thread dla każdego wystąpienia. Wybierz zarejestrowany model, źródło i dostęp: migawka tylko do odczytu, izolowana edytowalna kopia lub aktywny katalog roboczy. Opcjonalnie dodaj **Continuing Goal** z budżetem wyjścia. **Existing work** wskazuje dokładny Thread i gałąź, dziedzicząc ich model, źródło, uprawnienia i cel.

Włącz harmonogram, gdy będzie gotowy. **Run now** przyjmuje wystąpienie; wynik sprawdzisz w jego rozmowie. Wyłączenie definicji wstrzymuje niedostarczoną zaplanowaną pracę. Zatrzymanie uruchomienia nie wyłącza kolejnych terminów. Application Host musi działać.

## Pętle Markdown

Użyj projektowego `.agents/loops/` lub użytkownika `~/.agents/loops/`. Zastąp identyfikatory wartościami zapisanego kanału:

```markdown
---
name: daily-review
runtime: agent
schedule: "0 9 * * *"
timezone: UTC
enabled: false
target:
  kind: new_work
  model: { providerId: my-channel, modelId: my-model }
  source: { kind: project }
  sourceMode: fixed_branch
  goal: null
---
Podsumuj zmiany w repozytorium od wczoraj.
```

Wymagane są nazwa, cron, jawna strefa, treść, `runtime: agent` i natywny `target`. Plik jest źródłem definicji, a edycja sprawdza rewizję. Wykrywanie nie przepisuje plików ani nie importuje nieobsługiwanych dawnych definicji. Niepoprawna zmiana wstrzymuje ostatnie poprawne zadanie natywne do czasu naprawy.

## Kontynuacje rozmowy

Użyj **Follow-ups** w harmonogramie lub **Schedule a follow-up** w rozmowie. Kontynuacja uruchamia tę samą rozmowę po określonym czasie, zatrzymaniu procesu lub zadania, warunku pliku, artefakcie lub zbieraniu wyników badań, zdarzeniu logu albo progu metryki maszyny. Warunki można łączyć jako dowolny lub wszystkie.

Wybierz jeden raz lub każdą zaobserwowaną zmianę dla warunków powtarzalnych. Pauzy, pytania bez odpowiedzi i limity celów nadal obowiązują. Przerwy obserwacji mogą pominąć zmiany. Możesz sprawdzać historię, wstrzymać, wznowić lub anulować. Anulowanie blokuje przyszłe i niedostarczone prace, zachowując wyniki i obserwowane zadania.
