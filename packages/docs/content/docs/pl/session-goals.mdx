# Cele ciągłe

Cel należy do gałęzi Thread i kontynuuje jej ostatnie uruchomienie, również zakończone. Zwykła wiadomość nie tworzy celu.

Najpierw wyślij wiadomość. W **Continuing goals → Create goal** wpisz samodzielnie zrozumiały cel i opcjonalny budżet tokenów wyjściowych, a następnie **Start goal**. W gałęzi może istnieć tylko jeden niezakończony cel.

Zwykła odpowiedź końcowa kończy pojedyncze uruchomienie. Agent może jawnie zgłosić zakończenie lub blokadę celu przez `goal_report`; panel pokazuje faktyczny stan.

Możesz edytować, wstrzymać, wznowić, zakończyć lub anulować cel. Kontrolki zmieniają przyszłe zezwolenie; wysłane wywołania i niezależne procesy nadal muszą uzyskać rzeczywisty wynik. **Stop run** wstrzymuje także cel. Wstrzymanie przez politykę wymaga osobnego wznowienia. Zakończony cel wymaga utworzenia nowego, by zezwolić na dalszą pracę.

Budżet sprawdza raportowane przez dostawcę tokeny wyjściowe przed następnym wysłaniem. Puste pole oznacza brak limitu, zero blokuje kolejne wysłania generujące wyjście. Trwająca praca może przekroczyć limit. Szacunki i braki są osobne; przy budżecie niepełny pomiar zakończonego wnioskowania blokuje następne. Liczniki wejścia, pamięci podręcznej i rozumowania mogą się pokrywać.

Application Host musi działać. Zobacz [Zadania zaplanowane i kontynuacje](/pl/scheduled-tasks/).
