# Worktree 與 Git

重試 worktree 操作前，先檢查原 Host 和目錄。失敗或丟失的回應仍可能留下真實的 worktree 或 Thread。檢查專案的 Worktrees 頁面與 Git 狀態；不要透過刪除對話修復無關的目錄問題。

目錄移動後，恢復或修復 Git worktree 註冊。合併、變基或 cherry-pick 未完成時，先檢查本機變更再繼續或中止。分支或目錄名已被佔用時，先檢查已有工作再選擇其他名稱。

提交資訊與 PR 描述產生使用 Host 的工具模型或預設模型。檢查渠道、模型、憑證，以及所選暫存檔案或 PR 提交範圍，無需活動對話。先前請求結果未知時，應先檢查再建立新請求。
