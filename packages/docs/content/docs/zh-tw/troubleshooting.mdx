# 疑難排解

遇到問題了？在下面找到對應的現象，試試相應的解決方法。

## Varin 命令退出或無法啟動

- 確認 Node.js `>=22.19`（Node.js 24 是受支援的開發基線）
- 在原始碼檢出中，執行 `bun run dev` 或 `bun run start:web`
- 如果你有已釋出的 CLI，執行 `varin --version`，必要時重新安裝

## 無法存取 Web UI

- 在原始碼檢出中，檢視啟動 `bun run dev` 的那個終端機
- 如果你有已釋出的 CLI，用 `varin logs` 檢視伺服器日誌
- 確認活動埠（開發使用 Vite URL；伺服器預設是 `3000`）
- 在測試隧道連結之前，先直接開啟 `http://localhost:3000`

## 遠端/隧道連結無法使用

- 在已安裝 CLI 時執行 `varin tunnel status --all`
- 從同一實例/埠重啟隧道
- 如果之前的權杖已被使用，請重新產生連線連結

完整設定請參閱[隧道](/zh-tw/tunnels/)；如果你使用反向代理，請參閱[反向代理](/zh-tw/reverse-proxy/)。

## 儲存與恢復

在目標主機開啟 **設定 → Storage**，選擇裝置和範圍後重新掃描。掃描不完整不代表零位元組；這裡統計 Varin 受管資料，不包含原始專案資料夾，也不等同於實際磁碟占用。

檢查清理候選，核對裝置、範圍及所選物件後再確認。清理保留對話歷史、附件、原始專案、活躍快取及受管工作副本，不釋放恢復記錄。若沒有收到完成回執，先重新掃描並重試原確認，不要另發一次清理。

在 **設定 → History and recovery** 檢查恢復設定和待處理的工作區編輯記錄，嘗試修復前先讀取保留的草稿。選擇儲存裝置不會切換 Agent 主機；查看歷史需要開啟對應主機。
