# Dépannage

Un accroc ? Trouvez le symptôme ci-dessous et essayez le correctif.

## La commande Varin quitte ou ne démarre pas

- confirmez Node.js `>=22.19` (Node.js 24 est la base de développement prise en charge)
- depuis une copie source, exécutez `bun run dev` ou `bun run start:web`
- si vous avez une CLI publiée, exécutez `varin --version` et réinstallez si besoin

## L’UI web n’est pas joignable

- depuis une copie source, lisez le terminal qui a lancé `bun run dev`
- si vous avez une CLI publiée, consultez les journaux serveur avec `varin logs`
- vérifiez le port actif (le développement utilise l’URL Vite ; le serveur par défaut est `3000`)
- ouvrez d’abord `http://localhost:3000` directement avant de tester les liens de tunnel

## Le lien distant / tunnel ne fonctionne pas

- exécutez `varin tunnel status --all` quand la CLI est installée
- redémarrez le tunnel depuis la même instance / le même port
- régénérez le lien de connexion si le jeton précédent a déjà été utilisé

Voir [Tunnels](/fr/tunnels/) pour la configuration complète, et [Reverse proxy](/fr/reverse-proxy/) si vous en utilisez un.

## Stockage et récupération

Sur le Host voulu, ouvrez **Paramètres → Storage**, choisissez l’appareil et le périmètre, puis relancez l’analyse. Une analyse incomplète ne signifie pas zéro octet. Les mesures couvrent les données gérées par Varin, pas les dossiers de projet originaux ni toute l’occupation physique du disque.

Utilisez **Inspect cleanup candidates**, vérifiez l’appareil, le périmètre et les objets sélectionnés, puis confirmez. Le nettoyage conserve l’historique, les pièces jointes, les projets originaux, les caches actifs et les copies de travail gérées ; il ne libère pas les enregistrements de récupération. Sans reçu de fin, relancez l’analyse et utilisez **Retry original confirmation** au lieu de lancer un autre nettoyage.

Ouvrez **Paramètres → History and recovery** pour consulter les réglages de récupération et les modifications de workspace en attente. Lisez les brouillons conservés avant de réparer. Choisir un appareil de stockage ne change pas le Host Agent : ouvrez le Host concerné pour consulter son historique.
