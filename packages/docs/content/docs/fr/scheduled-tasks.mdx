# Tâches planifiées et suivis

## Tâches de calendrier

Ouvrez le planificateur et choisissez un projet. Définissez les instructions, une programmation unique, quotidienne, hebdomadaire ou cron, un fuseau IANA et le traitement des créneaux manqués : ignorer ou exécuter une fois le dernier.

**New work** crée un Thread par occurrence. Choisissez modèle enregistré, source et accès : instantané en lecture seule, copie modifiable isolée ou répertoire actif. Un **Continuing Goal** et son budget de sortie sont facultatifs. **Existing work** cible un Thread et une branche précis, avec leur modèle, source, permissions et objectif.

Activez la programmation quand elle est prête. **Run now** accepte une occurrence ; ouvrez sa conversation pour les résultats. Désactiver la définition retient les travaux planifiés non livrés. Arrêter une exécution ne désactive pas les prochains créneaux. L’Application Host doit rester actif.

## Boucles Markdown

Utilisez `.agents/loops/` dans le projet ou `~/.agents/loops/` pour l’utilisateur. Remplacez les ID par ceux du canal enregistré :

```markdown
---
name: daily-review
runtime: agent
schedule: "0 9 * * *"
timezone: UTC
enabled: false
target:
  kind: new_work
  model: { providerId: my-channel, modelId: my-model }
  source: { kind: project }
  sourceMode: fixed_branch
  goal: null
---
Résume les changements du dépôt depuis hier.
```

Nom, cron, fuseau explicite, corps, `runtime: agent` et `target` natif sont requis. Le fichier fait autorité ; les modifications vérifient sa révision. La découverte ne réécrit pas les fichiers et n’importe pas les anciens formats incompatibles. Un remplacement invalide suspend la dernière tâche native valide jusqu’à réparation.

## Suivis de conversation

Utilisez **Follow-ups** ou **Schedule a follow-up** dans la conversation. Le suivi reprend cette conversation après une date, un arrêt de processus ou de tâche, une condition de fichier, un artefact ou une collecte de recherche, un événement de journal ou un seuil machine. Combinez les conditions avec « une quelconque » ou « toutes ».

Choisissez une fois ou chaque changement observé pour les conditions répétables. Pauses, questions sans réponse et limites d’objectifs restent applicables ; une interruption d’observation peut manquer des changements. Consultez l’historique, suspendez, reprenez ou annulez le suivi. L’annulation empêche les livraisons futures et en attente, sans supprimer résultats et travaux observés.
