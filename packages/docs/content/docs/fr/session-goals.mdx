# Objectifs continus

Un objectif appartient à une branche de Thread et poursuit sa dernière exécution, même déjà terminée. Un message ordinaire ne crée pas d’objectif.

Envoyez d’abord un message. Dans **Continuing goals**, choisissez **Create goal**, saisissez un objectif autonome et un budget facultatif de tokens de sortie, puis **Start goal**. Une branche ne peut avoir qu’un objectif non terminé.

Une réponse finale ordinaire termine une exécution. L’agent peut déclarer l’objectif terminé ou bloqué avec `goal_report`. Le panneau affiche l’état réel et le motif de blocage.

Vous pouvez modifier, suspendre, reprendre, terminer ou annuler l’objectif. Ces actions changent les autorisations futures ; les appels déjà envoyés et processus indépendants doivent encore se terminer. **Stop run** suspend aussi l’objectif. Une pause de politique exige sa propre reprise. Un objectif terminé ou annulé nécessite un nouvel objectif pour poursuivre le travail.

Le budget vérifie la sortie déclarée par le fournisseur avant un nouvel envoi. Vide signifie sans limite configurée ; zéro interdit de nouveaux envois de sortie. Le travail en cours peut dépasser le budget. Les estimations et mesures manquantes restent distinctes : avec un budget, une mesure incomplète d’inférence terminée bloque la suite. Les compteurs d’entrée, cache et raisonnement peuvent se recouper.

L’Application Host doit rester actif. Voir [Tâches planifiées et suivis](/fr/scheduled-tasks/).
