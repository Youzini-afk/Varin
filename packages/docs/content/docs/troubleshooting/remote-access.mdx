# Remote Access

When you can't reach Varin from your phone or another machine, the fix depends on how you're connecting.

## Check the basics first

- open `http://localhost:3000` on the same computer first — if that fails, it's not a remote problem; see [troubleshooting](/troubleshooting/)
- confirm the server is running with `varin status`

## Paired device won't connect

- the QR code / pairing link is **single-use** — if it was already scanned (or expired), create a new one from **Add a device**
- if the device was paired with **Home network only**, it can't connect from outside that network — pair it again with **Anywhere**
- **Anywhere** needs a relay: if it is greyed out in **Add a device**, the server has no `VARIN_RELAY_URL`; if it is set, check that the relay it names is reachable from the server
- if a device was **revoked**, its token is gone for good — pair it again with a new QR code

See [Connect a Device](/connect-devices/) and [Private Relay](/private-relay/) for how these connections work.

## Tunnel link doesn't work

- run `varin tunnel status --all`
- restart the tunnel from the same instance and port
- regenerate the connect link if the previous one was already used

See [Tunnels](/tunnels/) for the full setup.

## Remote instance won't connect (desktop)

When a [remote instance](/remote-instances/) stalls, Varin names the step that failed:

- **auth** — your SSH or UI password was rejected; re-enter it
- **install / start** — Varin couldn't set up or start the server on the remote machine; check that machine's requirements
- **forwarding** — the connection is up but the port isn't reaching you; try a different local port

## Behind your own server

If you put Varin behind a reverse proxy and it loads oddly or won't connect, see [Reverse Proxy](/reverse-proxy/).
