# Model channels

Open **Settings → Model channels**. Add a channel, choose its type and endpoint, then configure an authentication method offered by that type. Depending on the channel, this can be a saved API key, sign-in, an explicit environment variable, a supported cloud identity, or anonymous access.

Add models by their IDs, or discover candidates on a saved channel that supports discovery. Review and save the models you want to use; discovery alone does not change the saved catalog. Enable the channel, model and required operation, such as chat. Choose the channel and model in the conversation composer.

The Application Host owns channel configuration and model accounts. Credentials are kept separately from model metadata and are not included in conversation history. Missing or withdrawn credentials do not silently select another account. Editing a channel affects later preparation; accepted work retains its original selection.

Use [Agent memory and instructions](/agent-personalization/) for standing instructions and [MCP](/mcp/) for additional tools. Model access does not itself grant file or tool permissions.
