# Objetivos continuos

Un objetivo pertenece a una rama de Thread y continúa su última ejecución, aunque ya haya terminado. Enviar un mensaje normal no crea un objetivo.

Envía primero un mensaje. En **Continuing goals**, pulsa **Create goal**, escribe un objetivo autosuficiente y, si quieres, un presupuesto de tokens de salida; pulsa **Start goal**. Solo puede haber un objetivo sin terminar por rama.

Una respuesta final ordinaria termina una ejecución. El agente puede comunicar que el objetivo está completo o bloqueado mediante `goal_report`; el panel muestra su estado real.

Puedes editar, pausar, reanudar, completar o cancelar. Estos controles cambian la autorización futura; las llamadas enviadas y los procesos independientes siguen hasta resolverse. **Stop run** también pausa el objetivo. Una pausa de política necesita su propia reanudación. Un objetivo finalizado requiere crear otro para autorizar más trabajo.

El presupuesto comprueba la salida reportada por el proveedor antes de otro envío. Vacío significa sin límite configurado; cero impide nuevos envíos de salida. El trabajo en curso puede excederlo. Las estimaciones y los datos ausentes no cuentan como cero: con presupuesto, el uso incompleto de inferencias terminadas bloquea nuevas inferencias. Las métricas de entrada, caché y razonamiento pueden solaparse.

El Application Host debe seguir ejecutándose. Consulta [Tareas programadas y seguimientos](/es/scheduled-tasks/).
