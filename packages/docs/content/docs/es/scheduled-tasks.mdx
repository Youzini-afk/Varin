# Tareas programadas y seguimientos

## Tareas de calendario

Abre el programador y elige un proyecto. Define instrucciones, una programación única, diaria, semanal o cron, una zona IANA y qué hacer con intervalos omitidos: saltarlos o ejecutar una vez el último.

**New work** crea un Thread por ocurrencia: selecciona modelo registrado, origen y acceso al espacio de trabajo (instantánea de solo lectura, copia editable aislada o directorio activo). Puedes añadir **Continuing Goal** y un presupuesto de salida. **Existing work** usa un Thread y una rama exactos, con su modelo, origen, permisos y objetivo.

Activa la programación cuando esté lista. **Run now** acepta una ocurrencia; abre su conversación para comprobar resultados. Desactivar la definición retiene trabajo programado aún no entregado. Detener una ejecución no desactiva futuros intervalos. El Application Host debe seguir funcionando.

## Bucles Markdown

Usa `.agents/loops/` en el proyecto o `~/.agents/loops/` para el usuario. Sustituye los ID por los de tu canal guardado:

```markdown
---
name: daily-review
runtime: agent
schedule: "0 9 * * *"
timezone: UTC
enabled: false
target:
  kind: new_work
  model: { providerId: my-channel, modelId: my-model }
  source: { kind: project }
  sourceMode: fixed_branch
  goal: null
---
Resume los cambios del repositorio desde ayer.
```

Son obligatorios nombre, cron, zona explícita, cuerpo, `runtime: agent` y `target` nativo. El archivo es la definición original y las ediciones comprueban su revisión. El descubrimiento no reescribe archivos ni importa definiciones antiguas incompatibles. Una modificación inválida retiene la última tarea nativa válida, bloqueada hasta repararla.

## Seguimientos

Usa **Follow-ups** en el programador o **Schedule a follow-up** en la conversación. Continúa esa conversación tras una hora, fin de proceso o trabajo, condición de archivo, artefacto o recopilación de investigación, evento de registro o umbral de máquina. Puedes combinar cualquier condición o todas.

Elige una vez o cada cambio observado cuando se admita repetición. Siguen vigentes pausas, preguntas pendientes y límites de objetivos; las interrupciones de observación pueden perder cambios. Puedes pausar, reanudar, cancelar y consultar el historial. Cancelar impide entregas futuras y pendientes, conservando resultados y trabajos observados.
