# 予定タスクとフォローアップ

## カレンダータスク

スケジューラーを開き、プロジェクトを選びます。指示、単発・毎日・毎週・cron、IANA タイムゾーン、逃した時刻をスキップするか直近分だけ一回実行するかを設定します。

**New work** は発生ごとに Thread を作ります。登録済みモデル、ソース、アクセス方法（読み取り専用スナップショット、隔離された編集用コピー、実際の作業ディレクトリ）を選びます。**Continuing Goal** と出力予算も指定できます。**Existing work** は正確な Thread とブランチを指定し、そのモデル、ソース、権限、目標を引き継ぎます。

準備後にスケジュールを有効化してください。**Run now** は一回分の受理であり、完了ではありません。会話で結果を確認します。定義の無効化は未配信の予定作業を保留し、実行の停止だけでは将来の予定を無効化しません。Application Host の稼働が必要です。

## Markdown ループ

プロジェクトの `.agents/loops/` またはユーザーの `~/.agents/loops/` に置きます。ID は保存済みチャネルの値に置き換えてください。

```markdown
---
name: daily-review
runtime: agent
schedule: "0 9 * * *"
timezone: UTC
enabled: false
target:
  kind: new_work
  model: { providerId: my-channel, modelId: my-model }
  source: { kind: project }
  sourceMode: fixed_branch
  goal: null
---
昨日以降のリポジトリの変更を要約する。
```

名前、cron、明示的なタイムゾーン、本文、`runtime: agent`、ネイティブ `target` が必須です。ファイルが定義を保持し、編集はリビジョンを確認します。検出はファイルを書き換えず、未対応の旧定義も自動取込しません。無効な変更は最後の有効なネイティブ定義を修復まで保留します。

## 会話のフォローアップ

スケジューラーの **Follow-ups** または会話の **Schedule a follow-up** を使います。指定時刻、プロセス・ジョブ停止、ファイル条件、研究成果・収集結果、ログ、マシン指標で元の会話を続けます。条件は「いずれか」または「すべて」で組み合わせられます。

単発、または対応する条件で観察した変化ごとの繰り返しを選びます。停止、未回答の質問、目標上限は維持され、観察中断中の変化は見逃す場合があります。履歴確認、一時停止、再開、取消が可能です。取消は将来と未配信の作業を止め、既存結果と観察対象のジョブは保持します。
