# トラブルシューティング

うまくいかないときは、下の症状を見つけて対処を試してください。

## Varin コマンドが終了する、または起動しない

- Node.js `>=22.19` を確認する（開発でサポートされる基準は Node.js 24）
- ソースチェックアウトでは `bun run dev` または `bun run start:web` を実行する
- 公開済み CLI がある場合は `varin --version` を実行し、必要なら再インストールする

## Web UI に到達できない

- ソースチェックアウトでは、`bun run dev` を起動したターミナルを読む
- 公開済み CLI がある場合は `varin logs` でサーバーログを確認する
- 使用中のポートを確認する（開発は Vite URL、サーバーのデフォルトは `3000`）
- トンネルリンクを試す前に、まず `http://localhost:3000` を直接開く

## リモート / トンネルリンクが動かない

- CLI がインストールされているときは `varin tunnel status --all` を実行する
- 同じインスタンス / ポートからトンネルを再起動する
- 前のトークンがすでに使われていたら、接続リンクを再生成する

セットアップ全体は [トンネル](/ja/tunnels/) を、リバースプロキシを使っている場合は [リバースプロキシ](/ja/reverse-proxy/) を参照してください。

## ストレージと復旧

対象 Host の **設定 → Storage** でデバイスと範囲を選び、再スキャンします。不完全なスキャンは 0 バイトを意味しません。測定対象は Varin 管理データで、元のプロジェクトフォルダーやディスク全体の物理使用量ではありません。

**Inspect cleanup candidates** でデバイス、範囲、選択項目を確認してから削除を確定します。会話履歴、添付、元のプロジェクト、使用中のキャッシュ、管理作業コピーは保持され、復旧記録も解放されません。完了記録が届かない場合は再スキャンし、新しい削除を始めず **Retry original confirmation** を使います。

**設定 → History and recovery** で復旧設定と未解決のワークスペース編集を確認します。修復前に保存された下書きを読んでください。ストレージのデバイス選択では Agent Host は切り替わりません。履歴は該当 Host を開いて確認します。
