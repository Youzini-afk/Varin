# 公开文档编写

面向正在完成具体任务的读者。先说明怎么做，步骤保持简短，并说明成功或可恢复失败的表现。
用当前 UI 和 Host 实现核实名称、命令、职责和行为。

对话使用原生 Thread 和分支。Application Host 管理模型渠道、账号、资源配置与 MCP 连接。
导航项目、对话和执行来源彼此独立；写清对应的选择，不要暗示切换文件夹会改变运行中工作的来源。
更新页面时保留仍然有用的说明。

## 页面与链接

英文源页位于 `content/docs/`；译本放在对应语种目录，文件名保持一致。
每页需要翻译后的 `title` 和 `description` frontmatter：

```mdx
---
title: 示例任务
description: 简短说明读者能够完成的事情。
---
```

- `example.mdx` 对应 `/example/`；`guides/example.mdx` 对应 `/guides/example/`。
- 页面链接保留结尾斜杠；译本正文链接使用语种前缀。
- 代码、路径、API 名称和产品标识符不翻译。
- 行为变化时同步已有译本。不要为满足页数生成空占位；确实缺少译本时可链接源文。
- `sidebar.config.json` 使用简短英文标签和无语种前缀的路由；译名放在 `translations`。

## 示例与图片

命令应与仓库脚本一致，用户特定的值要明确标出。不要包含凭据或用户私密数据。
说明有意义的限制和不确定性；响应失败不能证明操作没有执行。

只使用当前产品的真实截图。新文档图片放在内容目录内，使用相对路径引用，并提供有意义的译后
替代文本。删除过时截图及引用，不要把它们展示为当前界面。内容校验器不渲染图片或 MDX 组件。

## 检查修改

在仓库根目录运行：

```bash
bun run docs:validate
```

该命令检查 frontmatter、页面与侧边栏路由，以及工程文档本地链接。
行为、翻译和可执行示例需另行核对。渲染与发布见 [DEPLOYMENT.zh-CN.md](DEPLOYMENT.zh-CN.md)；
本包当前没有文档站渲染器。
