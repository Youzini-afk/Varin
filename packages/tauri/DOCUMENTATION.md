# Native desktop adapter

The public desktop contract remains in `@varin/application-client/desktop`. `src/bridge.ts` adapts that catalog to the native dispatcher without exposing Tauri APIs to React. `src/native.ts` is the only renderer module importing the Tauri API. Normal Web/mobile and embedded frames do not load it.

Every trusted top-level window independently obtains `varin_bootstrap` before RuntimeAPIs or persisted React stores initialize. Native role, application origin and per-window Host selection are authoritative. Unknown remote documents and decorative scene/stool surfaces receive neither the bridge nor Host credentials. Native errors remain errors, including unavailable capabilities and unobserved effects.

The private local-Host restart event contains only the previous origin. The adapter re-reads the authorized bootstrap and uses the existing guarded runtime switch, preserving document/draft guards and editor surfaces. It checks identity both before queued preparation and at commit. A window already switched to a remote Host retains that endpoint and its credentials. This event is not exposed through the public desktop event catalog and does not reload a renderer.

## OS links

The shared `web/application-host/lib/platform/desktop-deep-links.ts` owns the original desktop `varin://host`, `varin://thread` and v2 `varin://connect` vocabulary. Both shells use it. The on-demand native coordinator parses external activation privately; the renderer never receives raw pairing URLs or secrets. A native consent dialog lists the candidate servers before any probe, redeem request or host write. Decline, expiry and shutdown cannot silently connect later. An atomic update through the existing settings owner retains a matched host id and an existing default selection. SSH configuration import remains with the existing connection manager; external URLs do not become arbitrary SSH commands.

## Frontend state handoff

`packages/electron/bootstrap.mjs --varin-export-frontend-state` selects a standalone old-engine exporter before `main.ts`. It takes the existing Electron instance lock, opens an inert page at the original `varin-ui://app` origin and reads localStorage through main-process DOMStorage CDP. It starts no Application Host or Catalog and does not execute renderer export code. It obtains the same cross-language desktop data-root lease used by normal startup, or verifies the inherited native parent lease before reading any old profile.

`application-client/src/desktop-frontend-migration.ts` enumerates persisted product stores and their allowed fields. It covers UI/voice preferences, projects, explorer/editor snapshots, durable document owner identity, session presentation and review drafts. Disposable caches, PWA-only choices, transient surface identity, connection grants and unknown fields are excluded. There is no production IndexedDB owner in these UI modules, so the receipt records `no-product-owner`, not a fabricated database copy.

The original settings transaction stores the staged payload, canonical SHA-256, stable export identity and source version. Restaging preserves a pending generation so a partial target import cannot mix generations. Main-window bootstrap verifies the payload again, imports only absent destination keys and verifies writes before acknowledging every imported or retained key. Quota/write/validation failure leaves staging available for retry. The settings owner drops the temporary payload only after a complete matching receipt; old-origin storage is never deleted.

Queued messages do not enter the live auto-send queue. They become separately stored recovered drafts. The workbench recovery UI shows their original target, text and attachment metadata. A user may copy them or insert text into the current draft; this never submits a message or reuses attachment grants. Dismissal is explicit and persisted.

### Secret boundary

The old frontend credential slots are localStorage `openaiApiKey`, `openaiCompatibleApiKey`, `sttApiKey`, and those same three fields under JSON `config-store.state`. The UI exporter records slot names only. It never stages values, connection credentials, cookies, trust-device choices or authentication headers. Native settings/secure-store credentials remain with their existing owners.

The transition runtime manifest names a single bundled exporter-capable old Electron entry. The packaged inventory hashes its complete engine and exporter resources; the native parent revalidates them before launch. `--varin-export-private-state` starts only the controlled reader, verifies the live parent data-root lease, and exchanges bounded length-framed records over inherited private pipes. Each credential, cookie and origin requires a matching ordered acknowledgement. No arbitrary executable environment path, renderer export, secret-bearing log or plaintext transfer file is used.

`src-tauri/src/legacy_migration.rs` imports the six allowed credential slots into the trusted application's original target storage through native DOMStorage before bootstrap. Existing target fields win; JSON credentials merge with staged non-secret preferences rather than replacing them. BrowserUse gets its own `cef/browser` context, independent of the application and anonymous Web-render contexts. Original cookies retain host-only/domain, path, HttpOnly, SameSite, expiry, priority, source and partition identities. Native cookie/network readback and the CookieManager flush callback verify the effect. An incompatible or opaque partition never becomes an unpartitioned cookie. Existing destination authority wins.

Only initially absent cookie namespaces enter a non-secret provisional settings journal. After a process failure, native retry retracts those uncommitted owned namespaces before re-import. Original destination cookies are not journal-owned. Completion and journal removal use one transaction in the existing settings owner, after real exporter/process-scope termination and CEF close receipts. Failed or unknown outcomes do not become completion.

The old BrowserUse reader discovers origins from cookies, partition sites and saved browser pages. Both engines block live HTTP(S), website scripts and service-worker interception while loading an inert origin document for native localStorage reads/writes. Existing target localStorage keys are retained. This bounded discovery is not an inventory of every profile origin. IndexedDB names/availability are recorded, but IndexedDB contents, service workers and device-bound credentials are not copied. Their original profile remains available. The recovery UI accurately offers known sites for explicit manual checking; it never automatically opens sites or logs in. Cookie transfer is not advertised as complete session transfer.

A frontend UI receipt alone never claims secret or BrowserUse completion. Separate native receipts drive credential warnings and browser recovery. No private Chromium profile directory is copied, and no source data is deleted.

Installed companion packs are handed off by the original asset owner using the old process's actual `userData`, verified files and atomic publication. Linux's original `Varin` profile and the lowercase default Host data directory are not assumed to be the same path. The source cache is retained and an incomplete pack handoff is recorded separately, with per-pack failure categories. It does not block an otherwise confirmed private migration. Recovery offers an explicit retry through the original companion-download owner and opens its actual progress UI; accepting a download is never reported as completion. Unreadable original BrowserUse data or malformed individual voice credentials also produce explicit manual-recovery outcomes, distinct from protocol, lock, integrity and unknown target-write failures that prevent transaction completion.

A later single-engine package does not silently skip an unhandled original profile. Without the manifest-fixed exporter, startup checks only the default old Electron profile markers and the original settings receipt before starting any new Host. An unhandled profile or provisional cookie journal yields the fixed transition-required recovery screen and a link to the original Varin releases page. It neither accepts an arbitrary executable nor downloads or downgrades automatically. A recorded complete attempt with explicit partial/manual outcomes retains recovery UI without repeatedly blocking startup; a genuinely fresh single-engine install starts normally.

## Verification boundaries

`test/bridge.test.ts`, `test/frontend-migration.test.ts` and `test/local-host-restart.test.ts` exercise the real adapters, storage receipts and runtime-switch consumers. The shared native Browser/companion owner tests live beside their implementation in the Application Host; Electron policy tests consume the same source. Private-pipe fragmentation/UTF-8 tests, old native-reader consumers and real settings journal tests additionally cover migration refusal, cleanup, metadata-only persistence and explicit recovery. Type checks cover both shell adapters and shared React consumers. These tests do not replace installed CEF validation of platform transparency, input, session storage, sandboxing or installer migration orchestration.
