# Native workspace executor

`VarinWorkspace.app` contains a small control executable (macOS 13+) and a path-resource FSKit extension (macOS 26+). It is staged beside the Rust kernel, including in standalone Host distributions. The enclosing application's minimum OS remains 13. Older systems can use an already-installed macFUSE VFS backend.

The extension forwards namespace, binary I/O, attributes, links and synchronization to the original Rust workspace `Session`. It never opens Catalog/Storage or mirrors a project. The private Unix endpoint is created per mount under an owned mode-0700 resource directory; FSKit grants that directory as a security-scoped path resource. Admission checks the peer UID, mount token, protocol and original generation. Persistent worker connections permit concurrent file requests; bodies travel as raw bytes, independently of metadata JSON. A lost mutation reply fails without replay. Only a matching live extension can own the control connection.

The control program's `--inspect` uses `FSClient.fetchInstalledExtensions` and checks enabled state **and the exact staged extension URL**. Inspection neither registers nor enables an extension. Launching the app through the project settings button is an explicit user action: Launch Services registers its embedded extension and the control program opens System Settings. Enable **Varin Workspace** under General → Login Items & Extensions → File System Extensions, then refresh the Host status. A headless/remote Host needs its own enabled backend; the client's filesystem components cannot satisfy that requirement.

The native mount uses `/sbin/mount -F -t varin -o nosuid,nodev`, retaining the launch and service owners through readiness, cancellation and detach. Unmount failure retains the executor for another cleanup attempt. File data is synchronized through Darwin's volume-wait fence before the original Session freezes its namespace and private ranges. Disconnect invalidates the original source; it never substitutes the empty mount directory or a copied project.

Build with `node packages/workspace-driver/macos/build-helper.mjs <owned-staging-directory> [arm64|x64]`, using Xcode with macOS SDK 26+. Development/unsigned packages receive an explicit ad-hoc signature. Distribution can supply `VARIN_WORKSPACE_SIGN_IDENTITY` and `VARIN_WORKSPACE_PROVISIONING_PROFILE`; electron-builder signs the nested module with its FSKit/sandbox entitlements through `sign-mac.cjs`, retaining the enclosing notarization path. Enabling an ad-hoc build depends on macOS's signing policy; a compiled bundle alone does not mean the extension is enabled.

macOS CI compiles Swift and the real Rust transport without enabling a filesystem or changing system policy. The opt-in native mount test is separate. API references: [FSKit](https://developer.apple.com/documentation/fskit/), [Apple path-resource example](https://developer.apple.com/documentation/fskit/building-a-passthrough-file-system), [FSClient](https://developer.apple.com/documentation/fskit/fsclient). This executor is Varin code; it does not redistribute macFUSE binaries.
